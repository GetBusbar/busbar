## 2. Dialect catalogue

### 2.0 Registry — the complete dialect set

Six protocols, exactly. `KNOWN_PROTOCOLS = ["anthropic", "openai", "gemini", "bedrock",
"responses", "cohere"]` (`proto/mod.rs:1759-1766`). Name constants: `PROTO_ANTHROPIC="anthropic"`,
`PROTO_OPENAI="openai"`, `PROTO_GEMINI="gemini"`, `PROTO_BEDROCK="bedrock"`, `PROTO_COHERE="cohere"`,
`PROTO_RESPONSES="responses"` (`proto/mod.rs:1744-1749`). `ProtocolRegistry::with_builtins` builds
from that list with a `debug_assert_eq!` on the count (`proto/mod.rs:1777-1813`); `protocol_for(name)`
constructs a fresh `Protocol` (reader + writer vtable pair) per call because `GeminiWriter`,
`CohereWriter` and `ResponsesWriter` carry per-stream mutable state (`proto/mod.rs:1123-1144`).

Every dialect is both an ingress and an egress dialect (each is a `Protocol{reader, writer}`;
`proto/mod.rs:1028-1032`, `1093-1121`).

### 2.1 Ingress selection — path/header ladder

Two distinct classifiers exist and are deliberately kept separate:

**(a) `detect::protocol_id(path, headers)`** — the live Router (`proto/detect.rs:24-91`). Ladder,
order load-bearing:

| # | Test | Result | Cite |
|---|---|---|---|
| 1 | `authorization` starts with `AWS4-HMAC-SHA256` | `bedrock` | `proto/detect.rs:26-31` |
| 2 | header `anthropic-version` or `anthropic-beta` present | `anthropic` | `proto/detect.rs:32-34` |
| 3 | header `x-goog-api-key` present | `gemini` | `proto/detect.rs:35-37` |
| 4 | header `x-api-key` present | `anthropic` | `proto/detect.rs:41-43` |
| 5 | path contains `:generateContent`, `:streamGenerateContent`, `:embedContent`, `:batchEmbedContents`, `:predict` | `gemini` | `proto/detect.rs:45-52` |
| 6 | path starts with `/v1/models/` or `/v1beta/models/` | `gemini` | `proto/detect.rs:57-59` |
| 7 | path ends with `/v1/chat/completions` | `openai` | `proto/detect.rs:61-63` |
| 8 | path ends with `/v2/chat` or `/v1/chat` | `cohere` | `proto/detect.rs:64-66` |
| 9 | path ends with `/v2/embed` or `/v2/rerank` | `cohere` | `proto/detect.rs:67-69` |
| 10 | path ends with `/v1/responses` | `responses` | `proto/detect.rs:70-72` |
| 11 | path contains `/v1/messages` | `anthropic` | `proto/detect.rs:73-75` |
| 12 | path contains `/converse` | `bedrock` | `proto/detect.rs:76-78` |
| 13 | path starts with `/model/` and ends with `/invoke` | `bedrock` | `proto/detect.rs:79-81` |
| 14 | path ends with `/v1/embeddings`, `/v1/moderations`, or contains `/v1/images/`, `/v1/audio/` | `openai` | `proto/detect.rs:83-89` |
| — | otherwise | `None` → generic 404 fallback | `proto/detect.rs:90` |

**(b) `proto::proto_for_path(path)`** — the ERROR-SHAPE classifier used by `auth.rs::unauthorized_response`
and `main.rs`'s fallback/405 handlers (`proto/mod.rs:170-213`). Different ladder:
`/v1beta/models` → gemini; `/v1/models/` → gemini only if the last segment ends with one of the seven
`GEMINI_ACTIONS` (`:generateContent`, `:streamGenerateContent`, `:countTokens`, `:embedContent`,
`:batchGenerateContent`, `:generateAnswer`, `:batchEmbedContents`) else openai
(`proto/mod.rs:174-196`); `/model/...` requires a `/converse` or `/converse-stream` suffix to be
bedrock (`proto/mod.rs:197-200`); `== "/v1/messages"` or `.ends_with("/v1/messages")` → anthropic;
`== "/v1/chat/completions"` → openai; `== "/v2/chat"` → cohere; `== "/v1/responses"` → responses;
**default `openai`** (`proto/mod.rs:201-212`).

Dispatch: the axum fallback `protocol_dispatch` runs `detect::protocol_id`, rejects non-POST with a
405, then hands gemini/bedrock to their path-model arms and everything else to `operation_ingress`
(`ingress/dispatch.rs:292-428`). Additional explicit anthropic-dialect convenience routes:
`POST /<name>/v1/messages` (`ingress/mod.rs:1162-1289`) and
`POST /<provider>/<model>/v1/messages` (`ingress/mod.rs:1293-1413`).

### 2.2 Model / lane name resolution per dialect

| Dialect | Where the model string comes from | Cite |
|---|---|---|
| openai, responses, cohere, anthropic (bare `/v1/messages`) | body top-level `"model"` string, read off the LazyBody head projection | `ingress/dispatch.rs:131-137` |
| openai transcription (multipart) | `multipart_model(body)` — byte scan of the first 64 KiB for `name="model"` | `ingress/dispatch.rs:18-29`, `126-127` |
| gemini | URL: `/v1{,beta}/models/{model}:{action}`, split on the LAST `:` | `ingress/mod.rs:830-831` |
| bedrock Converse | URL path segment `{model_id}` from `/model/{model_id}/converse[-stream]`; already percent-decoded by axum | `ingress/mod.rs:1044-1062`, `1096-1102` |
| bedrock InvokeModel | URL path segment, passed as `model_hint` | `ingress/dispatch.rs:433-476` |

Missing/empty model on a body-model dialect → 400 `KIND_INVALID_REQUEST` with literal
`"Missing required parameter: 'model'."` (`ingress/dispatch.rs:138-156`).

**`models`/`pools` resolution** (`ingress/dispatch.rs:208-236`, mirrored in `ingress/mod.rs:1204-1265`):

1. `app.pools.get(model)` → the pool's `Vec<WeightedLane>`, `pool_name = model`.
2. else `app.by_model.get(model)` → a single `WeightedLane{idx, weight:1}`, `pool_name = ""`.
3. else → 404 `KIND_NOT_FOUND` with `not_found_message(model, gemini_api_version)`.

`not_found_message` (`ingress/mod.rs:1005-1013`): gemini gets
`"models/{model} is not found for API version {api_version}, or is not supported for the task you are
trying to perform."`; every other dialect gets
`"The model '{model}' does not exist or you do not have access to it."`

Metric-label safety: an unresolved model is stamped as the bounded sentinel
`POOL_LABEL_UNRESOLVED = "unresolved"` (`proxy/mod.rs:109`, `ingress/mod.rs:419-425`).

A budget `on_exhaust: downgrade` can re-point the dispatch pool after admission; routing follows the
charge (`ingress/mod.rs:191-229`, `ingress/dispatch.rs:204-206`).

### 2.4 Lossless passthrough (`extra`) rules

`lossless.rs` at 1.5.5 defines ONLY the type alias
`SourceScopedExtra = BTreeMap<String, Map<String, Value>>` — protocol-name-keyed extras
(`lossless.rs:17`). **It has no production caller in the chat path**; the live chat extras channel is
the flat `IrRequest.extra: serde_json::Map<String, Value>` (`ir/mod.rs:120`).

The universal rule per reader: sweep every TOP-LEVEL key that is not in that dialect's modeled-key set
into `extra`, verbatim. `extra` is re-emitted verbatim by the same dialect's writer (usually LAST, so
it overwrites typed fields), and is **cleared wholesale on the cross-protocol seam** by
`IrReq::prepare_for_egress` (`ir/variant.rs:295`).

| Dialect | Modeled (excluded from `extra`) keys | Cite |
|---|---|---|
| anthropic | `max_tokens, messages, model, stop_sequences, stream, system, temperature, tool_choice, tools, top_k, top_p` | `anthropic/reader.rs:298-314` |
| openai chat | `model, messages, tools, max_tokens, max_completion_tokens, temperature, top_p, stop, stream, tool_choice, frequency_penalty, presence_penalty, seed, n, response_format, user, parallel_tool_calls, logprobs, top_logprobs, reasoning_effort` | `openai_chat/mod.rs:363-396` |
| responses | `model, instructions, input, tools, max_output_tokens, temperature, top_p, stream, tool_choice, parallel_tool_calls` (`metadata` deliberately NOT modeled) | `openai_responses/mod.rs:458-481` |
| gemini | `contents, tools, systemInstruction, model, __busbar_gemini_json_array` (`generationConfig` and `toolConfig` deliberately NOT modeled — the writer overlays typed fields onto the raw objects) | `gemini/mod.rs:133-151` |
| bedrock | `messages, model, stream, system` only — `inferenceConfig`, `toolConfig`, `additionalModelRequestFields`, `guardrailConfig`, `promptVariables`, `requestMetadata`, `additionalModelResponseFieldPaths`, `performanceConfig` all ride `extra` | `bedrock/reader.rs:186-197` |
| cohere | `model, messages, tools, tool_choice, max_tokens, temperature, p, k, stop_sequences, stream, frequency_penalty, presence_penalty, seed, response_format` | `cohere/mod.rs:228-253` |

Busbar-internal `extra` sentinels (never on any backend wire):

| Sentinel | Meaning | Cite |
|---|---|---|
| `__busbar_anthropic_unmodeled_blocks` | raw anthropic content blocks (`document`, future types) stashed by `(m,i)` for verbatim splice on a same-protocol hop | `anthropic/mod.rs:71`, `92-106`, `writer.rs:144-149` |
| `__busbar_max_completion_tokens` | remembers the OpenAI request used `max_completion_tokens` not `max_tokens` | `openai_chat/mod.rs:45`, `reader.rs:110-111`, `writer.rs:246-258` |
| `__busbar_bedrock_cache_points` | raw `cachePoint` markers with positions | `bedrock/mod.rs:197`, `reader.rs:605-623` |
| `__busbar_bedrock_guard_content` | raw `guardContent` markers | `bedrock/mod.rs:221`, `reader.rs:629-647` |
| `__busbar_bedrock_doc_video` | raw `document`/`video` blocks | `bedrock/mod.rs:243`, `reader.rs:653-663` |
| `__busbar_top_k_camel` | remembers `topK` vs `top_k` spelling in `additionalModelRequestFields` | `bedrock/mod.rs:272`, `reader.rs:670-675` |
| `__busbar_gemini_json_array` | route-level JSON-array streaming shim; MODELED, so it never enters `extra` and can never leak | `gemini/mod.rs:20`, `reader.rs:582-589` |

Shim keys are stripped from every outbound body via the registry sweep
`array_stream_shim_keys()` / `proxy::strip_router_shim_keys` (`proto/mod.rs:1178-1191`).

Notable unmodeled fields that therefore ride `extra` and are LOST cross-protocol: anthropic
`metadata` / `thinking` (post-promotion) / `service_tier` / `mcp_servers`; openai `stream_options`,
`functions`, `function_call`; responses `store`, `previous_response_id`, `include`, `user`,
`metadata`, `truncation`; gemini `safetySettings`, `cachedContent`, `labels`; cohere `documents`,
`citation_options`, `safety_mode`; bedrock `guardrailConfig`, `promptVariables`, `requestMetadata`.

Two fields get an explicit LOUD warn when cleared at the seam: gemini `cachedContent`
(`ir/variant.rs:283-294`) and cohere `documents` (warned at READ time, `cohere/reader.rs:450-456`).

### 2.6 `default_max_tokens` injection

Only fires on the CROSS-PROTOCOL seam, only when the egress writer declares
`requires_max_tokens() == true` and the IR carries no `max_tokens`:

```
if ir.max_tokens.is_none() && prep.egress_requires_max_tokens {
    ir.max_tokens = Some(prep.lane_default_max_tokens.unwrap_or(prep.global_default_max_tokens));
}
```
(`ir/variant.rs:88-93`)

- `requires_max_tokens()` default `false` (`proto/mod.rs:386-388`); **overridden `true` only by
  `AnthropicWriter`** (`anthropic/writer.rs:19-22`). BedrockWriter deliberately does NOT override —
  Converse treats `inferenceConfig.maxTokens` as optional and injecting a default would silently cap
  output (`bedrock/writer.rs:135-137`).
- `lane_default_max_tokens` = per-model config `default_max_tokens: Option<u32>`, "Must be > 0 when
  set" (`config/mod.rs:1202-1206`).
- `global_default_max_tokens` = `limits.default_max_tokens`, default
  `DEFAULT_DEFAULT_MAX_TOKENS = 4096` (`config/mod.rs:3682`, `3816-3817`).
- The compiled-in fallback `proto::DEFAULT_MAX_TOKENS = 4096` (`proto/mod.rs:137`) is the
  documented value when a lane has no configured default.

A same-protocol passthrough NEVER reaches `prepare_for_egress` (body forwarded verbatim), so no
injection happens there.

### 2.7 Tool / function-calling mapping

`IrTool{name, description, input_schema, cache_control, hosted}` (`ir/mod.rs:625-649`);
`IrToolChoice{Auto, None, Required, Tool{name}}` (`ir/mod.rs:136-147`).

**Tool definitions:**

| Dialect | In | Out | Cite |
|---|---|---|---|
| anthropic | `tools[].{name, description, input_schema, cache_control}` | same shape; `hosted` never emitted | `anthropic/mod.rs:584-612`, `1118-1129` |
| openai chat | `tools[].function.{name,description,parameters}` OR flat top-level fallback; `input_schema` = `parameters` ‖ `input_schema` | `{"type":"function","function":{name,description?,parameters}}`, null schema → `{}` | `openai_chat/mod.rs:640-675`, `writer.rs:351-379` |
| responses | `type=="function"` ⇒ function; other `type` ⇒ HOSTED (`hosted: Some(raw)`, `name: ""`); absent `type` ⇒ function iff `name` key present | hosted re-emitted VERBATIM; function → flat `{"type":"function","name",...,"parameters"}` | `openai_responses/reader.rs:372-409`, `writer.rs:281-313` |
| gemini | `tools[].functionDeclarations[].{name,description,parameters}` | always exactly one `tools:[{functionDeclarations:[...]}]` wrapper; `parameters` = `sanitize_gemini_schema(resolve_gemini_schema_refs(schema))` | `gemini/reader.rs:436-467`, `writer.rs:270-300` |
| bedrock | `toolConfig.tools[].toolSpec.{name,description,inputSchema.json}` | `{"toolSpec":{name,description?,inputSchema:{json}}}` (typed tools CLOBBER the `extra` copy) | `bedrock/reader.rs:486-512`, `writer.rs:528-561` |
| cohere | `tools[].function.{name,description,parameters}` (entries lacking `.function` silently skipped) | `{"type":"function","function":{name,description?,parameters}}` | `cohere/reader.rs:369-394`, `writer.rs:276-296` |

**`tool_choice` projection (writer side):**

| IR | anthropic | openai / responses | gemini | bedrock | cohere |
|---|---|---|---|---|---|
| `Auto` | `{"type":"auto"}` | `"auto"` | `{"mode":"AUTO"}` | `{"auto":{}}` | key OMITTED |
| `None` | `{"type":"none"}` | `"none"` | `{"mode":"NONE"}` | OMITTED + warn | `"NONE"` |
| `Required` | `{"type":"any"}` | `"required"` | `{"mode":"ANY"}` | `{"any":{}}` | `"REQUIRED"` |
| `Tool{n}` | `{"type":"tool","name":n}` | `{"type":"function",...name}` | `{"mode":"ANY","allowedFunctionNames":[n]}` | `{"tool":{"name":n}}` + warn | `"REQUIRED"` (target LOST) |

Cites: `ir/mod.rs:126-131` (contract table), `anthropic/writer.rs:169-194`,
`openai_chat/writer.rs:388-406`, `openai_responses/mod.rs:369-378`, `gemini/mod.rs:391-400`,
`bedrock/mod.rs:680-702`, `cohere/writer.rs:312-331`.

**Universal rule: `tool_choice` is DROPPED with a warn when `req.tools.is_empty()`** on every writer
(`anthropic/writer.rs:175-180`, `openai_chat/writer.rs:390-394`, `openai_responses/writer.rs:322-326`,
`gemini/writer.rs:323-327`, `bedrock/writer.rs:592-597`, `cohere/writer.rs:314-318`).

**Parallelism:** the IR field is `parallel_tool_calls: Option<bool>` ("parallel allowed?",
`ir/mod.rs:113-118`). Anthropic reads/writes it INVERTED as
`tool_choice.disable_parallel_tool_use` (`anthropic/reader.rs:265-269`,
`writer.rs:183-206`). OpenAI reads/writes it directly, and only emits it when tools are present
(`openai_chat/reader.rs:368`, `writer.rs:307-312`). Gemini, Bedrock and Cohere have no analog and
drop it with a warn (`gemini/writer.rs:344-349`, `bedrock/writer.rs:607-614`,
`cohere/writer.rs:334-339`).

**Tool-ID reshaping** (cross-protocol only, `proto/mod.rs:1239-1348`): each foreign egress tool id is
rewritten to `<native_prefix><MARKER><hex(egress_id)>` where `TOOL_ID_REMAP_MARKER = "bb1"`
(`proto/mod.rs:1237`). Native prefixes: anthropic `toolu_`, openai/responses `call_`, bedrock
`tooluse_`; **cohere and gemini return `None`** so their ids pass through verbatim
(`proto/mod.rs:1209-1227`). The reverse decode (`decode_native_tool_id`) is gated on the INGRESS
protocol's OWN prefix, requires a non-empty even-length lowercase-hex tail that decodes to valid
UTF-8, and is applied at the request seam by `decode_request_tool_ids` (`proto/mod.rs:1332-1389`),
called from `prepare_for_egress` (`ir/variant.rs:94`).

Gemini synthesizes tool ids the wire does not carry:
`synth_tool_call_id = format!("call_{:016x}", SipHash(call_index, name, turn_salt))`
(`gemini/mod.rs:265-272`); the Gemini writer ignores `ToolUse.id` entirely
(`gemini/writer.rs:109-140`), and the Gemini `functionResponse` name is used AS the
`tool_use_id` (`gemini/reader.rs:348-388`).

### 2.8 Image / media handling

IR: `IrImageSource{Base64{media_type,data}, Url(String), Vendor{vendor:&'static str, value}}`
(`ir/mod.rs:516-526`). `parse_image_url` splits a `data:<mime>;base64,<payload>` URI into
`Base64{media_type, data}` and keeps anything else verbatim as `Url` (`proto/mod.rs:84-100`);
`image_url_from_ir` is the inverse and returns `None` for `Vendor` (`proto/mod.rs:106-115`).
`is_unresolvable_image_ref` is the drop predicate for foreign writers (`proto/mod.rs:121-123`).

## 3. Cross-dialect matrix

There are 6 ingress × 6 egress = 36 pairs. **All 36 are supported.** There is no pair-level refusal
anywhere in the code: `StreamTranslate::new(ingress, egress)` returns `Some` for any two registered
names when they differ (`proto/stream.rs:129-134`), `new_same_proto` for the 6 identical pairs
(`proto/stream.rs:143-145`), and `protocol_for` resolves any `KNOWN_PROTOCOLS` name
(`proto/mod.rs:1134-1144`). Losses are per-FIELD, degrade-with-warn, never a request refusal.

### 3.1 Same-protocol (6 diagonal pairs) — byte-verbatim

- Request: the pristine short-circuit re-emits the ORIGINAL bytes when the body is unchanged;
  invalidators are the shim keys, `stream` on a path-model egress, a model rewrite, and the
  Vertex-Anthropic body transform (`proxy/lazy_body.rs:208-228`).
- Response stream: `StreamTranslate` in `same_proto` mode runs the reader ONLY as a usage
  side-channel (`extract_usage_only`) and re-emits the original frame bytes verbatim
  (`proto/stream.rs:75-82`, `492-550`, `830-839`). Bedrock→Bedrock re-emits the original BINARY
  frames via the drain `consumed_sink` — never re-encoded, since a recomputed CRC/length would be
  undecodable to a native SDK (`proto/stream.rs:655-674`).
- `finish()` adds NOTHING in same_proto mode on the happy path (`proto/stream.rs:959-967`).
- Two exceptions that DO rewrite same-proto OpenAI bytes: `suppress_same_proto_frame` (drop the whole
  unsolicited trailing usage chunk) and `strip_same_proto_usage` (byte-level removal of the
  `"usage":null` member from content chunks) — both only when the client did NOT opt into
  `include_usage` (`openai_chat/mod.rs:792-844`, `proto/stream.rs:792-818`).
- Anthropic same-proto skips the DOM parse entirely for every frame except `message_start`,
  `message_delta`, `error` (`proto/stream.rs:756-773`).

## 4. Streaming

### 4.1 Framing per dialect

| Dialect | Content-Type | Framing | Terminator |
|---|---|---|---|
| anthropic | `text/event-stream` | `event: <type>\ndata: <json>\n\n` | `message_stop` event (no `[DONE]`) |
| openai chat | `text/event-stream` | bare `data: <json>\n\n` (no `event:` line) | `data: [DONE]\n\n` |
| responses | `text/event-stream` | `event: <typed>\ndata: <json>\n\n` | `response.completed` / `.incomplete` / `.failed` — **no `[DONE]`** |
| gemini (`?alt=sse`) | `text/event-stream` | bare `data: <json>\n\n` | last chunk carries `finishReason` |
| gemini (no `alt=sse`) | (JSON array body) | `[` `{...}` `,` `{...}` `]` | closing `]` |
| cohere | `text/event-stream` | bare `data: <json>\n\n` (event type carried in the JSON `type` field) | `message-end` event; no `[DONE]` emitted |
| bedrock | `application/vnd.amazon.eventstream` | binary framed, `:event-type`/`:content-type: application/json`/`:message-type: event`, CRC32 both prelude and message | `messageStop` + `metadata` frames |

Cites: `streaming_content_type()` default `TEXT_EVENT_STREAM` (`proto/mod.rs:535-537`), bedrock
override (`bedrock/writer.rs:1053-1059`); `emits_sse_done_terminator` only openai
(`openai_chat/writer.rs:696-700`); `SSE_DONE_SENTINEL = "[DONE]"`, `SSE_DONE_FRAME = b"data:
[DONE]\n\n"` (`proto/mod.rs:31-32`); SSE frame writer (`proto/mod.rs:1696-1708`); eventstream headers
(`eventstream.rs:396-411`, `329-355`); Gemini array framer (`gemini/mod.rs:1342-1494`).

**SSE frame parsing** (`proto/mod.rs:1394-1447`): `find_frame_terminator` accepts BOTH `\n\n` (2
bytes) and the spec-legal `\r\n\r\n` (4 bytes); `parse_sse_frame` concatenates multiple `data:` lines
with `\n`, strips exactly one leading space after the colon, and returns `None` when the frame carries
no `data:` line at all. The feed loop is linear (front cursor + `scanned` watermark with a 3-byte
straddle backup), never O(n²) (`proto/stream.rs:721-829`).

### 4.2 Event sequences per dialect

**Anthropic** (`anthropic/writer.rs:363-668`, `reader.rs:358-593`):
`message_start` → (busbar-injected `event: ping\ndata: {"type":"ping"}\n\n` on a CROSS-protocol
anthropic-ingress stream only, `proto/mod.rs:40`, `stream.rs:479-481`) → `content_block_start` /
`content_block_delta` (`text_delta`, `thinking_delta`, `input_json_delta`, `signature_delta`,
`citations_delta`) / `content_block_stop` → `message_delta` → `message_stop`. `ping` on the READ side
is NOT handled and is dropped (`anthropic/reader.rs:548`). Block index is clamped to
`MAX_ANTHROPIC_BLOCK_INDEX = 1023`; a missing/non-numeric index DROPS the event
(`anthropic/mod.rs:281`, `290-294`).

**OpenAI Chat** (`openai_chat/reader.rs:434-774`, `writer.rs:422-689`): a flat
`chat.completion.chunk` stream is fanned out via `StreamDecodeState`: MessageStart once; reasoning
block latches index 0; text block claims the next index; tool calls join on `tc.index` (clamped to
`MAX_TOOL_INDEX = 127`, capped at `MAX_OPEN_TOOLS = 128`) recorded in `tool_ir_index`; a `refusal`
delta sets `refusal_seen` and is routed through the text path; the finish chunk closes
thinking→text→tools in that order then emits `MessageDelta` + `MessageStop`; a trailing
empty-`choices` usage chunk emits a usage-only `MessageDelta`. `[DONE]` is recognized and produces no
events (`reader.rs:443-445`).

**Responses** (`openai_responses/reader.rs:530-1105`, `writer.rs:455-997`): `response.created` (also
`response.in_progress`) → `response.output_item.added` (function_call / reasoning; `message` emits
nothing) → `response.output_text.delta` / `.function_call_arguments.delta` /
`.reasoning_text.delta` (also `.reasoning_summary_text.delta`) → `response.output_item.done` (also
`.content_part.done`) → `response.completed` / `.incomplete` / `.failed`. Text indices are stored
offset by `TEXT_INDEX_KEY_OFFSET = 1000` in `open_tools` to avoid colliding with tool indices
(`openai_responses/mod.rs:48`). Every emitted frame carries a top-level `sequence_number` from a
per-stream `AtomicU64`, and suppressed events consume none (`writer.rs:982-996`).
`response.content_part.added` and `response.error` are NOT handled (`reader.rs:1103`).

**Gemini** (`gemini/reader.rs:637-1100`, `writer.rs:648-1019`): an inline `data.error` object short-
circuits to a single `Error` event with no MessageStart. Otherwise MessageStart once (id ←
`responseId`, model ← `modelVersion`); only `candidates[0]` is processed. Text index is claimed from
the monotone counter (NOT hardcoded 0); `functionCall` parts each claim an index, emit `BlockStart`
plus ONE `InputJsonDelta` carrying the whole args JSON; `citationMetadata` and `logprobsResult` become
`CitationsDelta` / `LogprobsDelta` anchored to the text index; `finishReason` closes
thinking→text→tools and emits `MessageDelta` + `MessageStop`.

**Cohere** (`cohere/reader.rs:499-870`, `writer.rs:427-672`): dispatch is on the JSON `data.type`, not
the SSE event name. `message-start` → `content-start` / `content-delta` / `tool-plan-delta` (both
mapped onto the TEXT block) → `content-end` (sets the one-way `text_block_closed` latch) →
`tool-call-start` / `tool-call-delta` / `tool-call-end` → `message-end`. `citation-start` /
`citation-end` have **no reader arm** and fall to the no-op catch-all (`reader.rs:859-867`). The
`TEXT_BLOCK_SEEN_SENTINEL = usize::MAX` in `open_tools` is the text-block-present marker used for the
tool index base offset (`cohere/mod.rs:39`, `373-374`, `398`).

**Bedrock** (`bedrock/reader.rs:712-1105`, `writer.rs:692-880`): `messageStart` →
`contentBlockStart` / `contentBlockDelta` (`text`, `toolUse.input`,
`reasoningContent.{text,signature,redactedContent}`) / `contentBlockStop` → `messageStop` (buffers
`state.pending_stop_reason`, emits NO IR event) → `metadata` (takes the pending reason and emits ONE
combined `MessageDelta{stop_reason, usage}` then `MessageStop`). Mid-stream exception frames
(`internalServerException`, `modelStreamErrorException`, `throttlingException`,
`validationException`, `serviceUnavailableException`) become `IrStreamEvent::Error`.
`modelTimeoutException` is deliberately NOT accepted mid-stream (`reader.rs:1048-1051`).

### 4.3 `[DONE]` handling

- Emitted ONLY by an openai INGRESS: `StreamTranslate::finish()` appends `SSE_DONE_FRAME` when
  `emit_done` (from `emits_sse_done_terminator()`) is true (`proto/stream.rs:1006-1008`), and also
  AFTER the error frame on an aborted stream (`proto/stream.rs:952-956`).
- On the READ side every reader treats `[DONE]` as a no-op: `anthropic/reader` (via the shared
  translate loop), `openai_chat/reader.rs:443-445`, `cohere/reader.rs:506-508`,
  `gemini/reader.rs:645-647`. The translate loop itself skips any frame whose data is empty or equals
  `SSE_DONE_SENTINEL` before parsing (`proto/stream.rs:749-755`).
- In SAME-PROTO mode `[DONE]` is never re-synthesized — the upstream's own terminator rides through
  in the verbatim byte run (`proto/stream.rs:959-967`, `830-839`).

### 4.4 Usage extraction from streams

| Dialect | Event that carries usage | Exact path | Cite |
|---|---|---|---|
| anthropic | BOTH `message_start` (`message.usage`, input + cache) AND `message_delta` (TOP-LEVEL `usage`, output) | `data.message.usage.*`, `data.usage.*` | `anthropic/reader.rs:378-393`, `503-521` |
| openai chat | any chunk with a top-level `usage` OBJECT (typically the trailing empty-`choices` chunk); `usage: null` filtered out by `is_object()` | `usage.prompt_tokens`, `usage.prompt_tokens_details.cached_tokens`, `usage.completion_tokens` | `openai_chat/reader.rs:677-696` |
| responses | terminal `response.completed` / `.incomplete` only | `response.usage.{input_tokens, input_tokens_details.cached_tokens, output_tokens}` | `openai_responses/reader.rs:1004-1035` |
| gemini | the chunk carrying `finishReason` (or the prompt-block chunk) | `usageMetadata.*` | `gemini/reader.rs:1067-1096` |
| bedrock | the `metadata` frame ONLY | `usage.{inputTokens, outputTokens, cacheWriteInputTokens, cacheReadInputTokens}` | `bedrock/reader.rs:996-1043` |
| cohere | `message-end` ONLY | `delta.usage.tokens.{input_tokens, output_tokens}` | `cohere/reader.rs:709-736` |

**The A-tap** — the production billing source. `StreamTranslate.last_usage` accumulates from every
`MessageDelta` AFTER the start-usage backfill, merging per-field (a non-zero/`Some` value overrides;
zero/`None` leaves the accumulator alone) so a backend that splits usage across two deltas is not
clobbered (`proto/stream.rs:83-90`, `258-284`). Same-proto streams populate it identically via
`extract_usage_only` (`proto/stream.rs:492-550`). Read by `StreamTranslate::usage()`
(`proto/stream.rs:881-883`).

**Anthropic start-usage backfill**: Anthropic puts `input_tokens` and the cache splits ONLY on
`message_start`. `translate_event` latches them into `start_usage` and backfills the terminal
`MessageDelta` whenever the delta left the field empty — so prompt tokens survive an Anthropic-egress
cross-protocol hop (`proto/stream.rs:52-63`, `232-257`).

**Usage absent → billing zero.** `last_usage` stays `None` until the first usage-bearing terminal
event (`proto/stream.rs:89-90`); a stream with no usage event bills nothing. There is no estimation
or token-counting fallback anywhere in the dialect layer. Additionally, `IrResp::Chat.usage()` maps
straight through to `Billing::Tokens` with whatever counts the IR holds (`ir/variant.rs:438-444`) —
zeros in, zeros billed. `terminal_error != None` suppresses token billing entirely
(`proto/stream.rs:91-97`, `889-891`).

Note the trailing bedrock `metadata` frame is emitted UNCONDITIONALLY even when it carries no `usage`
(zeros), so a bedrock-egress stream always produces a terminal `MessageDelta`
(`bedrock/reader.rs:996-1043`).

### 4.5 Terminal-usage fold / un-fold (the ordering machinery)

The `StreamFraming` vtable, keyed to the INGRESS writer, owns every per-stream wire quirk
(`proto/mod.rs:865-1018`; built once by `new_stream_framing()`, `proto/stream.rs:162`).

| Seam | Default (`PassthroughFraming`) | Overriders |
|---|---|---|
| `folds_terminal_usage()` | `true` (anthropic/gemini/cohere/responses fold) | openai → `false`, bedrock → `false` |
| `on_egress_chunk` | no mutation, `None` | openai: identity replay + include_usage un-fold |
| `on_combined_stop_delta` | `None` | bedrock: split into stop-only + usage-only |
| `on_usage_only_delta` | `None` | bedrock: enforce exactly-one-`metadata` |
| `on_finish` | `None` | bedrock: flush a deferred zero-usage `metadata` |
| `inject_streaming_metrics` | no-op | bedrock: `metrics.latencyMs` onto the `metadata` frame |
| `abort_exception_type` | `None` | bedrock → `Some("InternalServerException")` |
| `set_client_include_usage` | no-op | openai |
| `suppress_same_proto_frame` | `false` | openai |
| `strip_same_proto_usage` | `false` | openai |

Cites: `proto/mod.rs:963-965`, `876-878`, `890-897`, `907-909`, `918-920`, `930-936`, `945-947`,
`979`, `994-996`, `1015-1017`; `openai_chat/mod.rs:724-1013`; `bedrock/mod.rs:809-959`.

**FOLD (anthropic/gemini/cohere/responses ingress)**: the terminal `MessageDelta{stop_reason: Some}`
and its `MessageStop` are DEFERRED into `pending_terminal`/`pending_stop`; any trailing usage-only
delta is merged in via `merge_trailing_usage`; the pair is flushed at `finish()`
(`proto/stream.rs:363-409`, `986-1005`, `1151-1164`). A DUPLICATE stop-bearing delta merges into the
first rather than overwriting it (`proto/stream.rs:379-390`).

**UN-FOLD (openai ingress)**: `write_response_event` FOLDS usage onto the terminal chunk
(`openai_chat/writer.rs:615-640`); `on_egress_chunk` then either splits it back into a separate
trailing `{choices: [], usage}` chunk (client opted in) or STRIPS it entirely (client did not opt in —
otherwise a strict SDK `choices[0]`-IndexErrors) (`openai_chat/mod.rs:752-772`, `941-1013`).

**Bedrock ingress two-frame split**: one combined `MessageDelta{stop_reason, usage}` fans into a
stop-only delta (→ `messageStop`) plus, iff real usage rode with it, a usage-only delta (→
`metadata`); otherwise the metadata is DEFERRED and resolved by a trailing usage delta or flushed
zero-usage at `on_finish` — the always-exactly-one-`metadata` invariant
(`bedrock/mod.rs:867-958`, `proto/stream.rs:347-362`, `983-985`).

**Post-stop ordering guard**: on any non-eventstream ingress, once `MessageStop` has been emitted,
ANY trailing `MessageDelta` is dropped — a `message_delta` after `message_stop` is invalid framing and
a proxy tell (`proto/stream.rs:422-437`).

**INV-A open-block drain**: any block the egress reader left open is closed via synthesized
`BlockStop`s before the terminal frame, and again unconditionally at `finish()` — routed back through
`emit_ir_event` so each ingress writer applies its own projection
(`proto/stream.rs:316-329`, `608-615`, `968-975`).

**Multi-citation fan-out**: when the ingress writer declares `max_citations_per_delta()`
(anthropic → `Some(1)`), a `CitationsDelta` carrying N citations is split into N single-citation
deltas at the framing seam — a native Anthropic SDK `JSON.parse`s ONE object per `data:` line and
crashes on an array (`proto/stream.rs:452-469`).

### 4.6 `stream_options` handling

- `stream_options` is NOT a modeled OpenAI key, so it rides `extra` verbatim and is re-emitted on a
  same-protocol egress (`openai_chat/mod.rs:363-396`, `writer.rs:409-417`). `write_request` never
  injects it (`openai_chat/writer.rs:8-420`).
- It IS captured in the LazyBody head projection so the engine can read
  `stream_options.include_usage` without materializing the DOM (`proxy/lazy_body.rs:44-48`).
- The engine forwards the client's intent into the translator via
  `StreamTranslate::set_client_include_usage(include)` → `framing.set_client_include_usage`
  (`proto/stream.rs:189-196`).
- Busbar FORCES `include_usage` on the UPSTREAM request so it can bill; the two same-proto seams above
  then hide the resulting wire-shape difference from an opted-out client
  (`proto/mod.rs:984-987`, `998-1011`).

### 4.7 Keep-alive

- Anthropic INGRESS, cross-protocol only: a single `ANTHROPIC_PING_SSE_FRAME =
  b"event: ping\ndata: {\"type\":\"ping\"}\n\n"` is injected immediately after the translated
  `message_start` — a native Anthropic stream emits one and a translated stream did not, which was
  both a fingerprintable tell and closed part of the idle-timeout gap. Same-protocol passthrough is
  byte-verbatim and already carries the upstream's own pings, so it never double-emits
  (`proto/mod.rs:36-40`, `proto/stream.rs:471-481`).
- No other periodic keep-alive/heartbeat is generated by the dialect layer. Empty-data frames on the
  egress side are recognized and skipped as keepalives (`proto/stream.rs:749-755`).

### 4.8 Mid-stream errors and aborts

**Reader-sourced errors.** A reader emitting `IrStreamEvent::Error(IrError)` sets
`terminal_error = provider_signal ?? "upstream stream error"` (`proto/stream.rs:285-296`, and the same
capture on the same-proto path, `502-511`). The stream-end arm reads `terminal_error()` to record a
breaker transient and suppress token billing (`proto/stream.rs:885-891`).

**Client-facing framing of a mid-stream error:**
- Bedrock ingress: a real binary MODELED-EXCEPTION frame (`:message-type: exception`,
  `:exception-type: <Name>`, payload `{"message": ...}`) via `write_response_exception` +
  `encode_exception_frame` — writing SSE text into a binary eventstream body yields an undecodable
  prelude/CRC for the SDK's decoder (`proto/stream.rs:297-314`, `eventstream.rs:361-390`).
- SSE ingress: the ingress writer's OWN streaming error event via
  `write_response_event(&IrStreamEvent::Error(..))`, framed exactly like every other event —
  `event: error` for anthropic, `event: response.failed` for responses (wrapping the error in a
  `response` object so `event.response` resolves), bare `data:` for openai/cohere/gemini
  (`proxy/wire.rs:757-822`).

**Abort paths.** `StreamTranslate::abort()` fires on (a) the reassembly buffer exceeding
`MAX_BUF = 16 MiB` with no frame terminator, or (b) `DrainStatus::MalformedPrelude` from the binary
decoder (`proto/stream.rs:697-701`, `845-847`, `893-904`). `finish()` then emits:
- Bedrock ingress: `encode_exception_frame("InternalServerException", STREAM_ABORT_DETAIL)`
  (`proto/stream.rs:920-934`);
- SSE ingress: the ingress-native in-band error frame with
  `IrError{class: ServerError, provider_signal: STREAM_ABORT_DETAIL}`, followed by `[DONE]` for an
  openai ingress (`proto/stream.rs:936-957`);
- Gemini JSON-array ingress: the close arm reads `translate.aborted()` and calls
  `finish_for_translate(true)`, which emits a trailing `{"error":{"code":500,"message":"Internal error
  encountered.","status":"INTERNAL"}}` element then `]` (`proto/stream.rs:851-873`,
  `gemini/mod.rs:1452-1494`).

`STREAM_ABORT_DETAIL = "The response stream was interrupted."` — one const so the text is identical
across every framing (`proto/mod.rs:154`).

Malformed frames NEVER abort the stream: a frame with no `data:` line, non-UTF-8 bytes, or malformed
data JSON is SKIPPED (`proto/stream.rs:745-748`, `776-778`); a non-JSON eventstream payload is skipped
(`proto/stream.rs:676-678`).

An oversized eventstream header value causes `encode_frame`/`encode_exception_frame` to DROP the whole
frame (returning an empty `Vec`) and emit an observable `tracing::warn!`, rather than emit a
CRC-valid-but-corrupt truncated header (`eventstream.rs:302-312`, `343-352`, `375-381`).

## 5. Usage extraction

`IrUsage{input_tokens, output_tokens, cache_creation_input_tokens: Option<u64>,
cache_read_input_tokens: Option<u64>}` (`ir/mod.rs:652-663`).

**The normalization contract** (`ir/mod.rs:653-658`): `input_tokens` is UNCACHED input. Providers
whose wire prompt total already INCLUDES the cached prefix (OpenAI, Gemini, Responses) SUBTRACT the
cached count on read; providers whose cache fields are already additive (Anthropic, Bedrock) store the
wire value as-is. That makes both cache fields uniformly ADDITIVE across all six dialects, so
`billable_tokens() = input + cache_read + cache_creation + output` (all `saturating_add`) is
provider-agnostic (`ir/mod.rs:665-683`).

## 6. Error mapping

### 6.1 The `kind` vocabulary

`kind` is the protocol-agnostic discriminant each writer maps to its native category. Canonical
values (`proxy/mod.rs:74-88`, aliasing `proto/openai_family.rs:41-62`):

| Const | Literal value |
|---|---|
| `KIND_INVALID_REQUEST` | `"invalid_request_error"` |
| `KIND_AUTHENTICATION` | `"authentication_error"` |
| `KIND_PERMISSION` | `"permission_error"` |
| `KIND_NOT_FOUND` | `"not_found_error"` |
| `KIND_RATE_LIMIT` | `"rate_limit_error"` |
| `KIND_SERVER_ERROR` | `"server_error"` |
| `KIND_INSUFFICIENT_QUOTA` | `"insufficient_quota"` |
| `KIND_API_ERROR` | `"api_error"` |
| `KIND_REQUEST_TOO_LARGE` | `"request_too_large"` |
| `KIND_OVERLOADED` | `"overloaded"` (bare — distinct from the Anthropic wire spelling `overloaded_error`) |
| `KIND_TIMEOUT` | `"timeout"` (bare — distinct from `timeout_error`) |
| `PROVIDER_CODE_CONTEXT_LENGTH` | `"context_length_exceeded"` (`proxy/mod.rs:117`) |
| `SIGNAL_IR_PARSE` | `"ir_parse"` — the breaker/metrics LANE label for an IR-parse failure (`proto/mod.rs:26`) |

`ERR_TYPE_OVERLOADED = "overloaded_error"` (`proto/openai_family.rs:56`) is the Anthropic WIRE
spelling and deliberately not the same const as `KIND_OVERLOADED`.

Upstream-status → kind, shared by the main and degraded forward paths
(`cross_protocol_error_kind`, `proxy/wire.rs:190-215`): 401→`authentication_error`;
403→`permission_error`; 429→`rate_limit_error`; 503→`overloaded`; 504→`timeout`;
any other 5xx→`api_error`; everything else→`invalid_request_error`.

Every client-facing error goes through the ONE builder `proxy::ingress_error(ingress, status, kind,
msg)` — it resolves the ingress writer (falling back to the OpenAI writer for an unknown name), calls
`write_error(status, kind, msg)`, serves the body as `application/json`, and then calls
`attach_error_response_headers` (`proxy/wire.rs:130-159`).
`ingress::ingress_error` is a thin delegation to it (`ingress/mod.rs:595-597`).

### 6.3 kind → native type mapping tables

**Anthropic** (`anthropic/writer.rs:29-72`). Status override FIRST: `503 || 529` →
`overloaded_error` regardless of kind. Then: `invalid_request`/`bad_request`→`invalid_request_error`;
`authentication`/`unauthorized`→`authentication_error`; `permission`/`forbidden`→`permission_error`;
`not_found`→`not_found_error`; `request_too_large`/`payload_too_large`→`request_too_large`;
`rate_limit`/`too_many_requests`→`rate_limit_error`; `KIND_OVERLOADED`→`overloaded_error`;
`KIND_TIMEOUT`→`timeout_error`; `api_error`/`KIND_SERVER_ERROR`/`internal`→`api_error`; already-native
values pass through; **any other value is emitted verbatim** (no `_` swallow).

**OpenAI Chat** (`openai_chat/writer.rs:731-776`): the OpenAI vocabulary maps to itself;
`overloaded`/`overloaded_error`/`service_unavailable`/`unavailable`/`transient`/`timeout`/`network`/`5xx`
all → `server_error`; `context_length_exceeded` → `invalid_request_error`; an EMPTY kind →
`server_error` when `500 <= status < 600` else `invalid_request_error`; any other value passes
through verbatim (note: bare `not_found` is NOT mapped and passes through).

**Responses** (`openai_responses/writer.rs:1180-1216`): same family, plus
`billing`/`insufficient_quota`→`insufficient_quota`; `bad_request`/`context_length_exceeded`
→`invalid_request_error`; `KIND_API_ERROR`/`KIND_TIMEOUT`/`network`/`connect`/`5xx`/`transient`
→`server_error`; any other value verbatim.

**Gemini** (`gemini/writer.rs:521-644`). Two tables plus a consistency gate.
kind→`status`: `invalid_request_error`/`invalid_argument`/`bad_request`→`INVALID_ARGUMENT`;
`authentication_error`/`unauthenticated`/`auth`→`UNAUTHENTICATED`;
`permission_error`/`permission_denied`/`forbidden`→`PERMISSION_DENIED`;
`not_found_error`/`not_found`→`NOT_FOUND`;
`rate_limit_error`/`resource_exhausted`/`rate_limit`→`RESOURCE_EXHAUSTED`;
`overloaded_error`/`KIND_OVERLOADED`/`unavailable`→`UNAVAILABLE`;
`deadline_exceeded`/`KIND_TIMEOUT`→`DEADLINE_EXCEEDED`;
`KIND_API_ERROR`/`internal`/`KIND_SERVER_ERROR`→`INTERNAL`;
`unimplemented`/`not_implemented`→`UNIMPLEMENTED`; anything else → fall through to the status table.
HTTP→status: 400→`INVALID_ARGUMENT`, 401→`UNAUTHENTICATED`, 403→`PERMISSION_DENIED`,
404→`NOT_FOUND`, 409→`ABORTED`, 429→`RESOURCE_EXHAUSTED`, 499→`CANCELLED`, 500→`INTERNAL`,
501→`UNIMPLEMENTED`, 503→`UNAVAILABLE`, 504→`DEADLINE_EXCEEDED`, other 4xx→`INVALID_ARGUMENT`,
other 5xx→`INTERNAL`, else `UNKNOWN`. **Consistency gate** (`gemini/writer.rs:597-600`): the
kind-derived name wins only if `http_for_status_name(name) == Some(status)`, so `code:503 /
status:INTERNAL` can never be emitted. `error.code` always echoes the HTTP status verbatim.
A bad-key 400/`INVALID_ARGUMENT` whose message equals `GEMINI_BAD_KEY_MESSAGE` also gains
`"details":[{"@type":"type.googleapis.com/google.rpc.ErrorInfo","reason":"API_KEY_INVALID","domain":"googleapis.com","metadata":{"service":"generativelanguage.googleapis.com"}}]`
(`gemini/writer.rs:618-636`).

**Bedrock** (`bedrock/mod.rs:52-77`): `invalid_request_error`/`invalid_request`/`validation`/`bad_request`
→`ValidationException`; `rate_limit_error`/`rate_limit`/`too_many_requests`/`throttling`
→`ThrottlingException`; `authentication_error`/`permission_error`/`auth`/`forbidden`/`unauthorized`
→`AccessDeniedException`; `not_found`/`not_found_error`/`model_not_found`→`ResourceNotFoundException`;
`KIND_TIMEOUT`/`model_timeout`→`ModelTimeoutException`;
`KIND_OVERLOADED`/`overloaded_error`/`service_unavailable`/`unavailable`→`ServiceUnavailableException`;
`quota_exceeded`/`service_quota_exceeded`/`insufficient_quota`→`ServiceQuotaExceededException`;
`api_error`/`internal_error`/`server_error`→`InternalServerException`; **anything else →
`ValidationException`** (so `__type` is always a real AWS name).

**Cohere**: no mapping table exists — `write_error` ignores `kind` entirely
(`cohere/writer.rs:781-785`).

### 7.2 Response and stream IR

`IrResponse{role, content, stop_reason, usage, model, id, created, system_fingerprint,
stop_sequence, logprobs}` (`ir/mod.rs:263-296`).

**Synthesized-ID contract** (`ir/mod.rs:276-283`): on a cross-protocol non-stream response the
foreign-format `id` is stripped and the ingress writer mints a NATIVE-format id when `created` is
`Some` (the cross-boundary signal); a same-protocol response preserves the native id verbatim.

`IrStreamEvent` (`ir/mod.rs:176-227`): `MessageStart{role, usage, id, created, model}`,
`BlockStart{index, block: IrBlockMeta}`, `BlockDelta{index, delta: IrDelta}`, `BlockStop{index}`,
`MessageDelta{stop_reason, stop_sequence, usage}`, `MessageStop`, `Error(IrError)`.

**Stream synthesized-ID contract** (`ir/mod.rs:188-196`): `translate_event` clears ONLY `id` and
`created` on `MessageStart`; `model` is DELIBERATELY PRESERVED because it is the format-neutral lane
model name and ingress writers use a populated `model` as the anchor for synthesizing the full native

`id`/`type`/`content`/`stop_reason`/`stop_sequence`) and a Gemini frame missing `modelVersion`
(`proto/stream.rs:227-239`).

`IrBlockMeta{Text, Thinking, ToolUse{id,name}, Image}` (`ir/mod.rs:685-691`).

### 7.3 `extra` / passthrough semantics

`IrRequest.extra` is a FLAT `serde_json::Map` holding the source dialect's unmodeled top-level keys
verbatim (see §2.4). The agnostic core never interprets it. It is re-emitted verbatim by the same
dialect's writer — usually LAST, so it OVERWRITES the typed fields written above it (anthropic
`writer.rs:357-359`, openai `writer.rs:409-417`, gemini `writer.rs:497-502`, bedrock
`writer.rs:649-687`, cohere `writer.rs:420-422`, responses `writer.rs:441-450`). It is CLEARED
wholesale on the cross-protocol seam (`ir/variant.rs:295`).

Two writers deliberately EXCLUDE specific keys from the trailing overlay so the typed overlay is not
clobbered: gemini skips `generationConfig` and `toolConfig` (`gemini/writer.rs:497-502`); bedrock
skips `inferenceConfig`, `toolConfig`, `additionalModelRequestFields` and all four sentinels
(`bedrock/writer.rs:654-683`). OpenAI skips `MAX_COMPLETION_TOKENS_SENTINEL`
(`openai_chat/writer.rs:409-417`); responses skips `text` when a typed `response_format` exists
(`openai_responses/writer.rs:441-450`).

The opaque per-block escape hatch is `IrImageSource::Vendor{vendor: &'static str, value: Value}` —
the agnostic core never interprets it, the producing protocol recognizes its own tag and re-emits
`value`, any other writer drops it with a warn (`ir/mod.rs:507-526`).

`lossless.rs`'s `SourceScopedExtra` (protocol-name-keyed extras) exists as a type alias with a unit
test and **no production caller** on the chat path (`lossless.rs:17-35`).

### 7.4 `IrUsageDetail` / `service_tier`

**`IrUsageDetail` does not exist at v1.5.5.** A repo-wide grep over `crates/busbar/src` finds no such
identifier. The only usage type is `IrUsage` with the four fields documented in §5.

**`service_tier` is not a modeled field on any dialect.** It appears only in test fixtures
(`proto/anthropic/tests/anthropic_hardening_tests.rs:2300-2311`, which asserts that an unmodeled
`service_tier` "must flow into extra"; and
`proto/tests/translate_parity_golden_tests.rs:153`). Behaviourally: an Anthropic (or OpenAI) request
carrying `service_tier` rides `extra` verbatim, round-trips byte-faithfully same-protocol, and is
DROPPED at the cross-protocol seam along with the rest of `extra`.

### 7.5 `Value`-level rewrite hooks (`ensure_dom`)

`ensure_dom` is not in the IR — it belongs to `proxy::LazyBody` (`proxy/lazy_body.rs`), the lazy
request-body DOM the ingress hands the forward engine.

- `LazyBody::Head{bytes, head}` — validated pristine bytes plus a head projection of ONLY the
  captured top-level keys; `LazyBody::Dom(Value)` — the full tree (`proxy/lazy_body.rs:145-151`).
- `LazyBody::parse(bytes)` goes through `crate::json::parse` so the depth floor and the
  malformed-body reject set are IDENTICAL to the old eager `parse::<Value>` — every byte is still
  parsed, uncaptured values scanned via `serde::de::IgnoredAny` (`proxy/lazy_body.rs:154-164`).
- `captured_head_keys()` = `["model", "stream", "stream_options", "system"]` plus every registered
  protocol's array-stream shim key, sorted+deduped in a `OnceLock` (`proxy/lazy_body.rs:40-55`).
- `probe()` returns the DOM when materialized (always authoritative — it may have been mutated by
  rewrite hooks), else the head; valid ONLY for the captured keys
  (`proxy/lazy_body.rs:172-180`).
- `ensure_dom(&mut self) -> Result<&mut Value, ()>` memoizes the full parse and returns it MUTABLY —
  this is THE `Value`-level rewrite point. The `Err` is surfaced (never unwrapped) even though the
  bytes were already validated (`proxy/lazy_body.rs:182-196`). `into_value()` is the consuming form
  (`proxy/lazy_body.rs:198-205`).
- Production call sites: `proxy/engine/mod.rs:170, 749, 817, 957, 1148, 1330`. The paths that force
  materialization are cross-protocol translation, rewrite hooks, taps, gates/routing policies, and
  failover hops 2+ (`proxy/lazy_body.rs:20-22`).
- Path-model ingress (gemini/bedrock) already parsed and mutated the body to inject `model`/`stream`/
  the shim key, so it hands the engine an eager `LazyBody::from_value(v)`
  (`ingress/mod.rs:762-763`).
- SAFETY CONTRACT: any new top-level key read through `probe()` MUST be added to
  `captured_head_keys` (or the site must call `ensure_dom`); the equivalence is pinned by
  `head_matches_dom_for_captured_keys` (`proxy/lazy_body.rs:24-31`).

Other `Value`-level rewrite helpers in the dialect layer:
`ProtocolWriter::rewrite_model_if_needed(&mut Value, model) -> bool` — the pristine-tracking hook that
reports `true` ONLY when the value truly changes (`proto/mod.rs:363-374`);
`inject_response_metrics(&mut Value, elapsed_ms)` — bedrock's `metrics.latencyMs`
(`proto/mod.rs:645`, `bedrock/writer.rs:1105-1119`);
`strip_top_level_usage_member(&str) -> Option<String>` — a structural single-pass byte-level JSON edit
that removes exactly one top-level `"usage"` member (string-aware, brace-depth-aware, refuses any
shape it cannot classify with certainty) (`proto/mod.rs:1469-1589`), with the frame-level wrapper
`rewrite_frame_strip_usage` that preserves key ORDER and the original CRLF/LF terminator
(`proto/stream.rs:1033-1085`).

## 8. Headers

### 8.1 Client → upstream (request)

**No client request header is forwarded to the upstream.** The outbound request is constructed from
scratch with exactly four header groups (`proxy/engine/mod.rs:1670-1681`, mirrored on the degraded
path at `proxy/engine/walk.rs:580-591`):

1. `convert_headers(auth)` — the lane's credential headers (§8.2).
2. `content-type` — `application/json` for a JSON body; the caller's own CT verbatim (boundary
   preserved) for a SAME-protocol opaque body; the egress operation handler's declared wire CT for a
   CROSS-protocol opaque body (`proxy/engine/walk.rs:568-578`).
3. `user-agent` — `writer.egress_user_agent()` (§8.3).
4. `accept` — `writer.egress_accept(wants_stream)`: `text/event-stream` when streaming else
   `application/json` for five dialects; bedrock overrides to
   `application/vnd.amazon.eventstream` when streaming (`proto/mod.rs:563-569`,
   `bedrock/writer.rs:1067-1075`).

Everything else the client sent — `anthropic-version`, `anthropic-beta`, `x-api-key`,
`x-goog-api-key`, `authorization`, `x-session-id`, arbitrary custom headers — is CONSUMED at the
ingress and never relayed. `x-session-id` (or the pool's configured `affinity.header_name`) is read
for sticky routing only (`ingress/mod.rs:131-145`, `ingress/dispatch.rs:244-247`).

Router shim keys injected into the BODY are stripped before the upstream call
(`proxy::strip_router_shim_keys`, driven by `proto::array_stream_shim_keys()`,
`proto/mod.rs:1178-1191`); the body `model` field is stripped for a same-protocol path-model egress
(`has_model_in_url()`, `proto/mod.rs:583-585`).

### 8.2 Egress auth headers per dialect

Resolved once at boot by `egress_auth::resolve(protocol_name, auth)` (`egress_auth/mod.rs:162-190`):

| Dialect | Credential scheme | Headers emitted |
|---|---|---|
| gemini | `ApiKeyHeader{header: "x-goog-api-key"}` | `x-goog-api-key: <key>` (`egress_auth/mod.rs:182-184`) |
| anthropic | `AnthropicNative` | see below |
| bedrock | `SigV4` | `authorization`, `x-amz-date`, `x-amz-content-sha256` [, `x-amz-security-token`] (`bedrock/writer.rs:79-99`) |
| cohere | `StaticBearer{proto:"cohere"}` | `authorization: Bearer <key>` |
| responses | `StaticBearer{proto:"responses"}` | `authorization: Bearer <key>` |
| openai / anything else | `StaticBearer{proto:"openai"}` | `authorization: Bearer <key>` |
| any provider with `auth: api-key` (Azure OpenAI) | overrides the protocol's native scheme | `api-key: <key>` (`egress_auth/mod.rs:166-168`) |
| `jwt-bearer` / `oauth-client-credentials` reaching the SYNC resolver | `NoCredential` — fail closed | NO auth header (upstream 401) (`egress_auth/mod.rs:170-179`, `195-201`) |

**Anthropic** (`anthropic/mod.rs:1220-1282`), classified by key prefix
(`classify_credential`, `anthropic/mod.rs:1159-1168`):

| Key shape / creds mode | Headers |
|---|---|
| `sk-ant-api…` (ApiKey) | `x-api-key: <trimmed key>` + `anthropic-version: 2023-06-01` |
| `sk-ant-oat…` (OAuth) | `authorization: Bearer <key>` + `anthropic-version` |
| ambiguous + `UpstreamCreds::Passthrough` | `authorization: Bearer <key>` + `anthropic-version` |
| ambiguous + `UpstreamCreds::Own` | `x-api-key: <key>` + `anthropic-version` |
| ambiguous + no mode | **BOTH** `x-api-key` and `authorization: Bearer` + `anthropic-version` |

`anthropic-version` is `HeaderValue::from_static("2023-06-01")` and is ALWAYS pushed last
(`anthropic/mod.rs:10`, `1254-1265`).

**Bedrock SigV4** (`bedrock/writer.rs:7-100`): key format `ACCESS:SECRET[:SESSION]`; empty access or
secret → `vec![]` (no headers). Signed headers are `content-type`, `host`, `x-amz-content-sha256`,
`x-amz-date` [+ `x-amz-security-token`]; note `content-type` and `host` are SIGNED but not returned
(the HTTP stack supplies them). Region derived from the endpoint host, falling back to `us-east-1`
with a warn. The SigV4 canonical path is DOUBLE-URI-encoded (non-S3 rule) while the wire path is
single-encoded (`proxy/egress.rs:100-117`).

**Universal invalid-bytes policy**: a credential containing an ASCII control byte causes the header to
be OMITTED entirely (never emitted empty) with a `tracing::warn!` that names only the protocol/header,
never the key (`proto/mod.rs:62-74`, `egress_auth/mod.rs:214-227`, `anthropic/mod.rs:1227-1241`).

headers are the route-policy debug pair, gated off by default
