## 2. Listeners

busbar 1.5.5 **always** runs exactly **two** TCP listeners. There is no single-listener production
mode and no separate metrics listener.

| ID | Listener | Config key | Default | Router mounted | TLS/mTLS | Citation |
|---|---|---|---|---|---|---|
| LST-001 | Data plane | `listen` | `"0.0.0.0:8080"` (`DEFAULT_LISTEN_ADDR`) | `base_data_router` + `none`/`key`-auth plugin routes + `apply_common_layers` + `apply_inbound_concurrency_limit` | `tls:` block; mTLS iff `tls.client_ca` set | `config/mod.rs:2426`, `main.rs:896`, `main.rs:919-925`, `main.rs:1104-1126` |
| LST-002 | Admin plane | `admin_listen` | `"127.0.0.1:8081"` (`DEFAULT_ADMIN_LISTEN_ADDR`) | `Router::new().route("/healthz", get(endpoints::healthz))` + `admin::transport::mount(…, &admin::JsonV1)` + `admin`-auth plugin routes + `apply_common_layers` (NO concurrency layer) | `admin_tls:` block; mTLS iff `admin_tls.client_ca` set | `config/mod.rs:2437`, `main.rs:902-903`, `main.rs:3926-3941`, `main.rs:1049-1056` |

**Bind and serve.**
- Both bind through the same `bind_listener` (`main.rs:1079-1083`); a bind error calls
  `die(format!("cannot bind listen address '{addr}': {e}"))`.
- Both are served concurrently by `tokio::join!` over `serve_listener` (`main.rs:1040-1057`).
  `serve_listener` (`main.rs:1096-1127`): `tls_cfg == None` ⇒ `tls::serve_plain` with log
  `"busbar listening"`; `Some` ⇒ `tls::build_server_config` then `tls::serve`, logging
  `"busbar listening (TLS)"` with `mtls = tls.client_ca.is_some()`. Any serve error `die`s:
  `"server error on '{label}': {e}"`; a TLS-config error `die`s:
  `"TLS configuration error for '{label}': {e}"`.
- One shutdown broadcast fans out to both listeners (`main.rs:1008-1019`); `POST /api/v1/admin/restart`
  triggers the same drain via `admin::restart::publish_shutdown` (`main.rs:1012`).

**mTLS requirement.** A network-exposed (non-loopback) `admin_listen` **refuses to boot** without
`admin_tls.client_ca`, unless the operator explicitly sets `admin_require_mtls: false`. Boot-guard
lives in `config::resolve` (`config/mod.rs:4222-4232`), message: `"admin_listen '{admin_listen}' is
network-exposed but the admin plane has no mTLS …"`. Default `admin_require_mtls` is `true`
(`config/mod.rs:2446`, `:2608`).

**What is physically absent from each router.**

| Router | Absent |
|---|---|
| Data (LST-001) | The entire `/api/v1/admin/*` surface (never mounted on it — `main.rs:3902-3904`, `:3917-3918`). All `RouteAuth::Admin` plugin routes (`mount_plugin_routes(…, admin=false)`, `main.rs:3842`; `plugin_routes.rs:157-165`). |
| Admin (LST-002) | `/stats`, `/v1/models`, `/v1beta/models`, `/metrics/hooks`, `/auth/token`, `/{name}/v1/messages`, `/{provider}/{model}/v1/messages`, the `ingress::protocol_dispatch` catch-all fallback, all `none`/`key`-auth plugin routes (incl. `/metrics`), and the inbound-concurrency layer. Only `/healthz` + `/api/v1/admin/*` + `admin`-auth plugin routes exist. (`main.rs:3926-3941`) |

**Shared.** Both planes carry the identical middleware stack via `apply_common_layers`
(`main.rs:3859-3899`) and share **one** `Arc<AppHandle>`, so a config-apply hot-swap reaches both
(`main.rs:3916`).

**Layer order** (`apply_common_layers`, innermost→outermost, `main.rs:3865-3898`):
1. `auth::auth_middleware` (`from_fn_with_state`, `main.rs:3869-3872`)
2. `DefaultBodyLimit::max(request_body_max_bytes)` (`main.rs:3877`)
3. `reshape_body_limit_413` (`main.rs:3881`)
4. `request_activity_tick` — always installed (`main.rs:3884`)
5. `server_timing` — **composed in only when** `advanced.response_headers.server_timing` (default `false`) (`main.rs:3893-3897`)
6. (data plane only) `InboundAdmissionLayer` when `limits.max_inbound_concurrent > 0` (`main.rs:3977-3985`)

**Config-derived limits at boot** (`main.rs:904-905`):
- `limits.request_body_max_bytes` — default 32 MiB (`config/mod.rs:3650`, `:3702`, `:3775`)
- `limits.max_inbound_concurrent` — `DEFAULT_MAX_INBOUND_CONCURRENT = 8192` (`config/mod.rs:3658`, `:3711`); `0` removes the layer entirely.

**Plugin route confinement** (`plugin_routes.rs:199-253`):
- `/api` and `/api/*` are reserved: `"plugin {owner:?} cannot register {path} — the /api/* admin surface is reserved"`.
- Reserved exact paths (`reserved_exact_paths()`, `plugin_routes.rs:49-59`): `"/healthz"`, `"/stats"`, `"/metrics/hooks"`, `"/v1/models"`, `"/v1beta/models"`, `"/auth/token"`. Error: `"plugin {owner:?} cannot register {path} — it is a reserved core route"`.
- `RouteKind::Hook` ⇒ confined to `/hooks/{owner}` or `/hooks/{owner}/*`; else `"hook plugin {owner:?} cannot register {path} — hook routes are confined to /hooks/{owner}/*"`.
- `RouteKind::Export` ⇒ may claim exactly `/metrics`, else confined to `/exports/{owner}` or `/exports/{owner}/*`; else `"export plugin {owner:?} cannot register {path} — export routes are confined to /metrics or /exports/{owner}/*"`.
- Collision: first-to-claim owns `{path, method}`; a second claim fails loud with `"plugin {owner:?} cannot register {METHOD} {path} — already registered by {existing:?}"` (`plugin_routes.rs:266-276`, mirrored in `build_route_table` `:285-306`).
- `HEAD` maps to `RouteMethod::Get` in `route_method_of` (`plugin_routes.rs:346-355`); `CONNECT`/`TRACE`/`OPTIONS` map to `None`.
- Forwarded request headers strip `authorization` and are capped at 64 (`plugin_routes.rs:442-455`).

### 3b. Catch-all protocol dispatch (`ingress::protocol_dispatch`)

`protocol_dispatch` (`ingress/dispatch.rs:292-425`) is the sole entry for every protocol endpoint.

**Step 2 — method gate.** `None` protocol ⇒ `fallback_error_response(path, 404, ERR_TYPE_NOT_FOUND, "the requested resource was not found")` (`dispatch.rs:302-309`). Non-`POST` on a protocol path ⇒ `fallback_error_response(path, 405, ERR_TYPE_INVALID_REQUEST, "method not allowed for this resource")` (`dispatch.rs:311-318`).

**Step 3 — universal no-handler gate.** If `resolve_operation` names an operation the protocol has no `OperationHandler` for ⇒ `ingress_error(proto, 404, KIND_NOT_FOUND, "This endpoint does not support that operation.")` (`dispatch.rs:320-337`).

**Step 4 — arms.** `gemini` and `bedrock` delegate to their path-model arms (boxed futures); everything else goes to `operation_ingress` (`dispatch.rs:338-425`).

## 4. Every admin operation

**Mount.** `admin::transport::mount` computes the prefix algorithmically:
`format!("{}/{}/{}", API_ROOT, transport.version(), transport.area())` = `"/api" + "/v1" + "/admin"`
= **`/api/v1/admin`** (`admin/transport.rs:54-70`; `API_ROOT = "/api"` `admin/v1/contract/mod.rs:34`;
`ADMIN_PREFIX = "/api/v1/admin"` `:39`; `JsonV1::version()/area()` `admin/v1/json/mod.rs:46-52`).
Mounted with `router.nest(&prefix, transport.router())` (`admin/transport.rs:69`).

**Router-level fallbacks** (`admin/v1/json/mod.rs:148-149`):
```rust
.fallback(|| async { err_json(&AdminError::not_found("resource")) })
.method_not_allowed_fallback(|| async { err_json(&AdminError::MethodNotAllowed) });
```
Unmatched path under the prefix ⇒ `404 {"error":{"code":"not_found",…}}`; wrong method on a matched
path ⇒ `405 {"error":{"code":"method_not_allowed",…}}`. `fallback_error_response` in `main.rs`
additionally forces the admin envelope for **any** path equal to `/api` or starting with `/api/`
(`main.rs:1195-1205`).

**OpenAPI document.** `crates/busbar/src/admin/v1/json/openapi.json`:
`openapi: "3.1.0"`, `info.title: "Busbar Admin API"`, `info.version: "1.5.4"`, no `servers` block.
**Confirmed count: 49 paths, 66 operations** (`paths` keys = 49; method entries = 66). 77
`components.schemas` keys. Served verbatim at `GET /api/v1/admin/openapi.json`
(`admin/v1/json/mod.rs:120`).

**Security schemes** (`components.securitySchemes`): `adminToken` =
`{"type":"apiKey","in":"header","name":"x-admin-token"}`; `bearerAuth` =
`{"type":"http","scheme":"bearer","description":"The same operator credential via Authorization: Bearer"}`.
No document-level or per-operation `security` array is declared.

**Scope declaration.** The only `x-` extension in the whole spec is **`x-busbar-required-scope`**,
present on all 66 operations with value `"read-only"` or `"full"`. There is **no** `x-dual-control`,
`x-idempotent`, or `x-scope`. In code, the required scope is *derived*, never per-handler declared:
`required_scope(method, path)` (`admin/v1/contract/mod.rs:231-247`) — `GET`/`HEAD` ⇒ `ReadOnly`;
`POST /config/validate` and `POST /plugins/inspect` ⇒ `ReadOnly`; every other mutation ⇒ `Full`;
unknown methods fail closed to `Full`. Scope literals are exactly `"read-only"` and `"full"`
(`Scope::as_str`, `admin/v1/contract/mod.rs:84-89`); `Scope::allows` (`:131-138`) — `ReadOnly` is
satisfied by anything, `Full` only by `Full`.

**Dual control.** **There is none.** No approval record, second-principal requirement, four-eyes gate,
or equivalent exists anywhere on this surface. Authorization is single-principal, scope-based only.
The `dual-control` column below is therefore `none` for every row and is folded into the scope column.

**Idempotency** (only `POST /keys` and `POST /keys/{id}/rotate` read it):
- Header literal `"idempotency-key"` — `IDEMPOTENCY_KEY_HEADER`, `admin/mod.rs:586`.
- TTL `IDEMPOTENCY_TTL_SECS: u64 = 600` (~10 min) — `admin/mod.rs:588`.
- Store: `app.idempotency_cache`, an in-process `Arc<Mutex<HashMap<(String,String),(u64, Value)>>>`
  (`admin/mod.rs:618-624`), swept lazily per use with
  `cache.retain(|_, (t, _)| now.saturating_sub(*t) < IDEMPOTENCY_TTL_SECS)` (`admin/mod.rs:743`, `:1552`).
- **Keying — create**: `(actor, <header value>)` (`admin/mod.rs:734-736`).
- **Keying — rotate**: `(actor, format!("rotate:{id}:{k}"))` — additionally scoped by operation **and
  key id**, explicitly so a create and a rotate sharing a header value can never replay each other's
  response (`admin/mod.rs:1538-1545`).
- **Replay**: create returns `201` with the cached JSON verbatim (`admin/mod.rs:746-747`); rotate
  returns `200` with the cached JSON (`admin/mod.rs:1554-1555`). **No replay marker header is added.**
- **Same key, different body**: the cache is keyed purely on `(actor, key)` — no body hash is
  computed or compared — so the **first** response is replayed verbatim (`admin/mod.rs:744-767`, `:1553-1569`).
- **In-flight collision**: a `Null` sentinel reservation is stored; a concurrent request gets
  `409 {"error":{"code":"conflict","message":"a request with this Idempotency-Key is already in flight"}}`
  tagged `Cond::IdempotencyInFlight` (`admin/mod.rs:753-767`, `:1557-1569`).
- **Reservation lifecycle** (`IdemReservation`/`IdemState`, `admin/mod.rs:598-652`): states
  `Reserved`/`InFlight`/`Committed`. `Reserved` is cleared on `Drop` (disconnect before the mint
  began). Once handed to the uncancellable `spawn_blocking` mint the state becomes `InFlight`, and a
  `Drop` intentionally does **not** clear it — it must age out with the 10-min TTL so a retry sees the
  honest 409 rather than risking a double mint.
- The OpenAPI spec declares **no** formal `Idempotency-Key` parameter; it appears only in prose on
  `PostKeys` (`openapi.json:6717`) and `PostKeysIdRotate` (`openapi.json:7239`).

**Optimistic concurrency.** `If-Match` is a declared (optional) header parameter on the config-plane
mutations: *"Optimistic concurrency: the resource's ETag from a prior read … Stale = 409
`version_conflict` (re-read and retry), nothing changes; absent or `*` = unconditional."* Code:
`with_config_etag` stamps `ETag: "<config_version>"`; `if_match_version` parses `*`, bare, quoted, or
weak-tagged versions (else `400` `Cond::MalformedIfMatch`); `stale_if_match` yields
`AdminError::VersionConflict` (`admin/v1/json/mod.rs:352-404`). There is **no** `X-Busbar-*` version header.

**Admin mutation rate limiting** (`admin/rate.rs`), enforced in the auth middleware *before* any
handler so failed attempts also count:
- Fixed 60 s windows: `MUTATION_RATE_WINDOW_SECS = 60` (`admin/rate.rs:16`).
- Classes (`admin/rate.rs:36-59`): `Config` = **10/min**; `Crud` = **60/min**; `PluginInspect` = **30/min**; `Forbidden` = 0 (denial counter only).
- `Config` class membership (`CONFIG_CLASS_RULES`, `admin/rate.rs:84-101`, classifier `:108-136`):
  `/config/*` prefix, `/admin-auth` exact, `/overlay/*` prefix, `/plugins/reload` exact,
  `/plugins/rollback` exact, `/restart` exact, plus every `NamedMapSection::ALL` path root
  (`/identity-providers`, `/export`). `/config/validate` and `/plugins/inspect` are carved out to
  their own classes before the prefix match.
- Only the **first** denial per `(principal, class, window)` is durably audited
  (`RateCheck::Denied { first_in_window }`, `admin/rate.rs:145-153`).
- Wire result: `429`, code `"rate_limited"`, message
  `"admin mutation rate limit exceeded; retry next minute"` (`admin/v1/contract/mod.rs:288-289`,
  `:329`, `:372-374`). `Retry-After` is emitted by `auth.rs`'s `rate_limited_response`, derived from
  `MUTATION_RATE_WINDOW_SECS` so the advertised back-off always equals the real window
  (`admin/rate.rs:13-15`) ⇒ `Retry-After: 60`.

**Pagination.** `LIST_LIMIT_MAX = 1000`, `LIST_LIMIT_DEFAULT = 200`, `VERSIONS_LIMIT_DEFAULT = 100`
(`admin/v1/contract/mod.rs:54-62`). Envelope `Page<T> { items, next_cursor }`
(`admin/v1/contract/mod.rs:980-991`, schemars-renamed `Page_{T}`), plus hand-rolled twins with the
identical `{items, next_cursor}` shape: `KeyPageView`, `AuditPageView`, `ConfigVersionPageView`
(`admin/v1/contract/schema.rs:129-133`, `:442-455`). Cursor is opaque hex of `"o:<offset>"`
(`encode_offset_cursor`/`decode_offset_cursor`, `admin/v1/contract/mod.rs:1007-1035`); handlers fetch
`limit+1` to detect a further page (`page_cursor`, `admin/v1/json/mod.rs:334-350`); a malformed cursor
is a `400 invalid_request` tagged `Cond::MalformedCursor`.

## 5. Cross-cutting HTTP behaviour

### 5.1 Inbound shed / overload 503

`InboundAdmissionLayer` is the **outermost** layer on the data plane only, installed when
`limits.max_inbound_concurrent > 0` (default `8192`) — `main.rs:3977-3985`, `config/mod.rs:3658`.
Admission never queues: `try_enter` either takes a permit synchronously or sheds
(`limits/admission.rs:157-180`). The permit is held for the whole inner call and released on `Drop`,
including on client-disconnect cancellation.

Shed response — **verbatim** (`limits/admission.rs:73-89`):
```
HTTP/1.1 503 Service Unavailable
Content-Type: application/json
Retry-After: 1

{"error":{"type":"overloaded","message":"The gateway is at capacity. Please retry shortly."}}
```
This is a **generic** envelope (not protocol-native) — the layer sits outside protocol routing, so the
caller's dialect is not yet known. `Retry-After` is the static string `"1"`. Each denial increments
`ADMISSION_DENIED_TOTAL` with label `gate` (`limits/admission.rs:61-62`).

### 5.2 Request-body size limit and 413

- Cap: `axum::extract::DefaultBodyLimit::max(limits.request_body_max_bytes)` (default 32 MiB)
  (`main.rs:3877`). Coupled with the egress translate-body cap (same knob) so an accepted request is
  always buffer-translatable.
- axum rejects with `413` and a bare `text/plain` body whose inner error text contains
  `"length limit exceeded"` (`AXUM_BODY_LIMIT_413_MARKER`, `main.rs:1273`) — matched as a **substring**,
  because axum-core 0.5 renders it as `"Failed to buffer the request body: length limit exceeded"`.
- `reshape_oversized_413` (`main.rs:1437-1481`):
  - non-413 ⇒ pass through;
  - 413 with `Content-Type` starting `application/json` ⇒ pass through untouched (already native);
  - 413, non-JSON, body **does not** contain the marker ⇒ pass through with the buffered body re-attached (a relayed upstream 413);
  - 413, non-JSON, body **contains** the marker ⇒ replaced by
    `fallback_error_response(path, 413, KIND_REQUEST_TOO_LARGE, "request body exceeds the maximum allowed size")`
    — i.e. the path-inferred protocol's native JSON envelope, with Bedrock `x-amzn-*` headers when applicable;
  - 413 whose body fails to buffer ⇒ the original parts with an **empty** body.
- Config floor/ceiling on the knob exist (`config/mod.rs:3616`, `:3619`) — exact values UNVERIFIED (see §7).

### 5.5 Error JSON envelopes

**Two disjoint envelope families**, split at the `/api` boundary.

**(a) Admin / native-API root (`/api`, `/api/*`)** — the frozen envelope:
`{"error":{"code":<string>,"message":<string>}}`, `Content-Type: application/json`.
Even 404 (unmatched) and 405 (wrong method) on this root are forced into it by
`fallback_error_response` before any protocol shaping runs (`main.rs:1195-1205`).

**(b) Data plane** — protocol-native, chosen by `proto_for_path` for fallback shaping and by the
resolved ingress protocol on the hot path. The `kind` argument is a canonical token; each writer maps
it into its own vocabulary.

- Plugin route dispatch: `authorization` is **never** forwarded to a plugin; the rest are projected

  from `Authorization` so the vendor-SDK carriers can never present an operator token
  (`auth/mod.rs:1279-1284`); `x-admin-token` is the alternative admin header (`securitySchemes.adminToken`).

`x-session-id`) for session pinning (`ingress/mod.rs:131-145`, `:1205-1207`).

### 5.8 Auth-exempt paths (data plane)

Exactly three exemptions exist in `auth_middleware` (`auth/mod.rs:1217-1245`):
1. `path == "/healthz"` (exact) — `HEALTHZ_PATH` (`auth/mod.rs:29`).
2. `path == "/auth/token"` (exact, never a prefix) — the handler runs the chain itself.
3. A plugin route whose declared `RouteAuth` is `None`.

`/metrics` is **deliberately not exempt** — the exposition is treated as an information-disclosure
surface and goes through the normal client-token check (`auth/mod.rs:1207-1213`).

Admin detection is path-boundary-safe: `path == ADMIN_PATH || path.starts_with(ADMIN_PATH_PREFIX)`,
so `/apix/v1/messages` is **not** treated as admin (`auth/mod.rs:1250-1256`).

## 6. Admin audit chain

**Record shape** — `AuditEntry` (`admin/audit.rs:20-57`):

| Field | Type | Meaning |
|---|---|---|
| `seq` | `u64` | monotonic, 1-based, process-lifetime-unique |
| `ts` | `u64` | unix seconds |
| `action` | `String` | `noun.verb`, e.g. `hook.register` |
| `resource` | `String` | e.g. `hook:compress` — "never a secret" |
| `outcome` | `String` | `applied` / `rejected` (`OUTCOME_APPLIED` / `OUTCOME_REJECTED`) |
| `principal` | `String` | actor id, or `"admin"` / `"anonymous"` |
| `prev_hash` | `String` | preceding entry's `hash` |
| `hash` | `String` | this entry's digest |
| `recorded_here` | `bool` | `#[serde(skip)]` provenance flag — never wire-visible |

**Hash chaining** (`admin/audit.rs:61-73`):
```rust
let canonical = format!("{}|{}|{}|{}|{}|{}|{}",
    self.prev_hash, self.seq, self.ts, self.action, self.resource, self.outcome, self.principal);
crate::sigv4::sha256_hex(canonical.as_bytes())
```
SHA-256 hex over the `|`-joined canonical string. Genesis `prev_hash` is the **empty string**
(`admin/audit.rs:319`: `let prev_hash = q.back().map(|e| e.hash.clone()).unwrap_or_default();`).

**Storage.** In-memory bounded ring: `MAX_AUDIT_ENTRIES = 1000` (`admin/audit.rs:83`), a
`VecDeque<AuditEntry>` FIFO-pruned at the cap. Write-through to a durable `Store`
(`sqlite`/`postgres`/`valkey`) when configured; best-effort with gap backfill
(`durable_write_through` / `rebase_nondurable_suffix`, `admin/audit.rs:397-460`) so a transient store
failure self-heals rather than leaving a permanent chain gap. Default `store: memory` ⇒ ephemeral.

**Boot restore.** `restore_from_store` (`admin/audit.rs:208-297`) re-verifies the restored tail's
digests and links, floors the sequence counter to the durable max via `fetch_max`, and **seals** the
durable write-through (`durable_unreconciled`) on any digest/link failure.

**Redaction.** No field-level redaction inside the record. The constraint is enforced by convention
at every call site: `resource` is never a secret (e.g. `KEY_RESOURCE_NONE = "key:-"` for a refused
mint that has no key id yet, `admin/mod.rs:323`). No credential or body value is ever a record field.

**Read-back.** `GET /api/v1/admin/audit` (`admin/v1/json/mod.rs:106`; handler `handlers.rs:1756`),
backed by `AuditLog::list_filtered(offset, limit, action, resource)` (`admin/audit.rs:731-747`) —
newest-first, filterable on exact `action` and exact `resource`, `skip(offset).take(limit)`.
Response `AuditPageView { items: Vec<AuditEntry>, next_cursor: Option<String> }`
(`admin/v1/contract/schema.rs:444-448`). Query params: `action`, `resource`, `limit` (default 100,
max 1000), `cursor`. Cursor = opaque hex of `"o:<offset>"`; a malformed cursor is `400 invalid_request`
tagged `Cond::MalformedCursor` (`taxonomy.rs:493`).

**Verification.** `AuditLog::verify()` (`admin/audit.rs:711-726`) recomputes every digest and checks
`prev_hash == predecessor.hash`. It is `#[cfg(test)]`-only in 1.5.5 — **there is no live tamper-alert
endpoint**; the in-code comment names it as a follow-up.

**What each mutating admin operation writes.** Complete set of `action` literals observed at
`AUDIT.record_by(...)` call sites across `admin/mod.rs`, `admin/v1/json/handlers.rs`, and
`admin/v1/json/named_map.rs`:

`admin.restart`, `auth.admin_chain_put`, `auth.cache_flush`, `config.apply`, `config.reload`,
`config.rollback`, `config.settings`, `group.create`, `group.delete`, `group.patch`,
`group.provision`, `group.replace`, `hook.delete`, `hook.register`, `hook.replace`, `hook.settings`,
`key.create`, `key.delete`, `key.patch`, `key.revoke`, `key.rotate`, `overlay.reset`,
`plugin.install`, `plugin.reload`, `plugin.remove`, `plugin.rollback`, `signing_key.report`.

Plus the named-map family, composed at runtime as `format!("{}.{}", section.singular(), mutation.verb())`
(`named_map.rs:307`), where `singular()` ∈ {`"identity-provider"`, `"exporter"`}
(`config/named_map.rs:65-66`) and `verb()` ∈ {`"replace"`, `"settings"`, `"delete"`}
(`named_map.rs:171-177`) ⇒ six more actions:
`identity-provider.replace`, `identity-provider.settings`, `identity-provider.delete`,
`exporter.replace`, `exporter.settings`, `exporter.delete`.

**Rejections are audited too.** Every one of the above appears at both `OUTCOME_APPLIED` and
`OUTCOME_REJECTED` call sites (e.g. `hook.register` at `handlers.rs:760` / `:783`;
`plugin.install` at `:210` / `:183`,`:214`; `admin.restart` at `:2428` / `:2397`,`:2408`,`:2419`;
named-map rejections at `named_map.rs:310`, `:317`, `:341`). Admin **rate-limit denials** are also
durably audited, but only the first per `(principal, class, window)` (`admin/rate.rs:145-153`).

**Adjacent ring — config version history.** `VersionLog` (`admin/versions.rs`) is a separate,
bounded (`MAX_VERSIONS = 100`, `versions.rs:42`) RAM-only `VecDeque` on `App` behind an `Arc` (so it
survives config-apply swaps). `ConfigVersion { version, ts, principal, summary, #[serde(skip)]
hook_registry, #[serde(skip)] global_hooks }` (`versions.rs:23-38`). `record()` is idempotent
(replaces on re-record) and FIFO-prunes; `list(offset, limit)` is newest-first; `get(version)`
returns the full snapshot for rollback. Explicitly **not** persisted across restarts
(`versions.rs:97-103`); re-seeded at its boot floor via `app.versions.record(0, …)` (`main.rs:969`).
