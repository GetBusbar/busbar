## 2. Request lifecycle (ordered, route match → response end)

### 2.1 Name resolution (pool vs model), precedence

| # | Step | Behaviour | Citation |
|---|---|---|---|
| 1 | Governance admission runs **before** routing; a budget "downgrade" may **re-point** the dispatch model | `let model = downgraded.as_deref().unwrap_or(model);` | `crates/busbar/src/ingress/dispatch.rs:199-206` |
| 2 | **Pool name wins first** | `if let Some(c) = app.pools.get(model) { (c.clone(), model) }` — candidate set = the pool's `Vec<WeightedLane>`, `pool_name = model` | `crates/busbar/src/ingress/dispatch.rs:208-210` |
| 3 | **Then single model** | `else if let Some(&i) = app.by_model.get(model)` — candidate set = one synthetic `WeightedLane { idx: i, weight: 1, reasoning: None, attempt_timeout_ms: None }`, `pool_name = ""` (the **lane-default breaker cell**) | `crates/busbar/src/ingress/dispatch.rs:211-220` |
| 4 | **Else 404** | `ingress_error(proto, StatusCode::NOT_FOUND, KIND_NOT_FOUND, &not_found_message(model, gemini_api_version))` | `crates/busbar/src/ingress/dispatch.rs:221-235` |
| 5 | Same precedence on the named anthropic-dialect route | `app.pools.get(&name)` then `app.by_model.get(&name)` | `crates/busbar/src/ingress/mod.rs:1204`, `:1232` |

- `App.pools: HashMap<String, Vec<WeightedLane>>`, `App.by_model: HashMap<String, usize>` —
  `crates/busbar/src/state.rs:258-260`.
- There is **no separate model-alias map** at this tag. The "alias" concept is per-lane
  `upstream_model` → `lane.wire_model()`, applied at translate time
  (`crates/busbar/src/proxy/wire.rs:520-523`), and it is **not** an accounting key
  (`crates/busbar/src/proxy/usage.rs:61-76`).
- Session affinity key: the pool's configured affinity header, else the operation's body-derived key
  (chat: top-level `system`) — `crates/busbar/src/ingress/dispatch.rs:243-248`,
  `crates/busbar/src/proxy/engine/mod.rs:856-863`.

### 2.3 Hook stage 1 — REWRITE / transform (`prompt: rw` gates)

| Fact | Detail | Citation |
|---|---|---|
| Ordering | **Globals first** (`app.rewrite_hooks`), then the **pool's** `rewrite_hooks`; each chain internally sorted **ascending by `priority`** (stable sort ⇒ config order breaks ties) | `proxy/engine/mod.rs:719-781`; `hooks/mod.rs:435-460`, `:991-1016` |

| Reject shaping | status clamped to `400..=499` else `403`; message sanitized + capped 300 chars; log line `"rewrite gate rejected the request"` | `proxy/engine/mod.rs:731-745`; `hooks/wire.rs:546-596` |

#### Failover is no longer allowed after the first byte

- The rule is stated at `proxy/engine/mod.rs:865-871`: *"Failover is allowed ONLY until the first
  upstream byte reaches the client."*
- Enforced structurally by `FirstByteBody`: once headers are 2xx the response is returned to axum;
  a mid-stream failure emits an **in-band** error frame in the ingress framing and ends the stream —
  it never re-enters the dispatch loop (`proxy/response_body.rs:279-345`).

### 2.9 Retries

There is **no intra-lane retry**. Every failure either fails over to the **next lane**
(`continue` in the loop) or terminates. `max_cap` (`failover.max_hops`, default 3) bounds hops;
`RequestCtx.deadline` (`failover.timeout_secs`, default 120s) bounds wall clock.

### 3.5 Breaker-tripped

There is **no distinct client-facing "breaker tripped" status**. A tripped lane is simply not
admitted by `try_admit` (`Unavailable::BreakerOpen{until}`); the request either fails over to a
healthy lane or reaches the pool's `on_exhausted` terminal — most commonly the 503 +
`Retry-After = soonest genuine cooldown` (`engine/walk.rs:49-65`).

### 3.6 Budget-exhausted (lane `max_requests`)

Also not a distinct status: `Unavailable::BudgetExhausted` removes the lane from admission
(`store/mod.rs:167-169`), so the request fails over, and an all-exhausted pool reaches the
`on_exhausted` 503 (with the 2s at-capacity `Retry-After` floor, since a budget-exhausted lane
reports cooldown 0 and is filtered out by `lane_admissible` — `engine/walk.rs:50-57`).

### 6.2 Metadata denylist and defaults (`config_validate::ssrf_blocked_host`)

Threat model stated in code: a client can never influence a provider `base_url`, so the guard is a
**metadata DENYLIST** — *"block a comprehensive metadata DENYLIST and ALLOW EVERYTHING ELSE —
loopback, RFC-1918, CGNAT, and public are all legitimate upstreams"*
(`config_validate/mod.rs:2063-2071`).

| Denylist entry | Kind | Citation |
|---|---|---|
| `169.254.0.0/16` (link-local: IMDS `169.254.169.254`, ECS `169.254.170.2`, Tencent `169.254.0.23`) | IPv4 range | `config_validate/mod.rs:2148-2162`, `:2197-2216` |
| `100.100.100.200` (Alibaba ECS) | IPv4 literal | same |
| `168.63.129.16` (Azure WireServer) | IPv4 literal | same |
| `192.0.0.192` (Oracle Cloud IMDS) | IPv4 literal | same |
| `fd00:ec2::254` (EC2 IMDSv6) | IPv6 literal | same |
| `metadata.google.internal`, `metadata.internal`, `metadata.tencentyun.com`, `metadata.platformequinix.com`, `instance-data`, `instance-data.ec2.internal` | hostnames, matched case-insensitively | `config_validate/mod.rs:2125-2136` |

**Precedence (the locked one-rule matrix):** blocked IFF `!allow_all` **AND**
on-denylist(hardcoded ∪ `security.blocked_metadata_hosts`) **AND NOT** in `allow_overrides`.
Allow always wins (`config_validate/mod.rs:2089-2121`).

- `security.allow_all_metadata: true` ⇒ the guard returns `None` unconditionally
  (`config_validate/mod.rs:2108-2111`).
- `allow_overrides` = **union** of the provider's `allow_metadata_hosts` and the global
  `security.allow_metadata_hosts` (`config_validate/mod.rs:325-330`).
- `security.blocked_metadata_hosts` **extends** the hardcoded denylist, matched through the same
  canonicalizer (`host_matches_any`) so an IP entry also blocks its mapped-IPv6 and
  alternate-encoding spellings (`config_validate/mod.rs:2138-2145`).
- CIDR entries in the allow/block lists are rejected (`reject_cidr_metadata_entries`,
  `config_validate/mod.rs:69-76`, `:320-324`).

### 6.3 Per-provider override: **replace, not merge**

`ProviderDeploy.allow_metadata_hosts: Option<Vec<String>>` — `Some` **REPLACES** the catalog
(`ProviderDef.allow_metadata_hosts`) default; `None` falls back to the catalog list
(`config/mod.rs:2557-2560`, `:2518-2521`; resolution at `config/mod.rs:4167-4171`:
`deploy_cfg.allow_metadata_hosts.clone().unwrap_or_else(|| def.allow_metadata_hosts.clone())`).

The **effective** allow set at check time is then the **union** of that resolved per-provider list
with the global `security.allow_metadata_hosts` (`config_validate/mod.rs:325-330`) — i.e. replace
within the provider layer, union across the provider/global layers.

### 6.4 DNS / IP handling

- Host extraction is canonicalized once (`extract_normalized_host`, `config_validate/mod.rs:1868`),
  including percent-decoding (`percent_decode_host`, `:1770`) and trailing-dot stripping.
- Obfuscated IPv4 literals are **expanded** (`expand_alternate_ipv4`, `config_validate/mod.rs:2229-2310`
  — inet_aton parts forms `a`, `a.b`, `a.b.c`, `a.b.c.d`, each component decimal/hex/octal) and
  re-checked against the metadata predicate. A non-metadata obfuscated form (e.g. decimal loopback)
  is **allowed** — only metadata targets are blocked (`config_validate/mod.rs:2164-2173`).
- IPv6 literals embedding IPv4 (`::ffff:a.b.c.d`, `::a.b.c.d`) get the identical metadata predicate
  via `v6.to_ipv4()` (`config_validate/mod.rs:2179-2186`).
- A hostname that is not an IP and not on the lists is **allowed** — there is **no runtime DNS
  resolution check**; the guard is a boot/apply-time string/IP check
  (`config_validate/mod.rs:2175-2177`).
- The composed `base_url + path` is re-run through the same guard, and a `path` override must begin
  with `/` (else it can fuse into the authority) — `config_validate/mod.rs:378-400`.

### 6.5 TLS verification options

- The provider `base_url` **scheme rule** is keyed off whether the host is private/loopback:
  a **public** host MUST use `https://`; a private/loopback/RFC-1918/CGNAT host MAY use plain
  `http://` (local Ollama/vLLM "just works", no flag). Case-insensitive scheme check.
  Error literals: `"provider '{}' base_url must use https for a public host (got '{}'); plaintext
  http is permitted only for a private/loopback local-model upstream"` and
  `"provider '{}' base_url must use http or https (got '{}')"` — `config_validate/mod.rs:305-357`.
- **No `danger_accept_invalid_certs`, custom CA bundle, or TLS-verification toggle exists for the
  upstream data-plane client** — no such call appears in the tag's `main.rs` client builder
  (`main.rs:3179-3243`).

## 7. Hook plugin ABI as seen by a hook author

### 7.1 Transport

At 1.5.0 the out-of-process socket/webhook transports were retired; a hook is a **signed, trusted,
in-process `kind: hook` dlopen plugin** opened as a `busbar_plugin_loader::DlopenPolicy`
(`hooks/mod.rs:1-23`, `:627-682`). The engine installs shared `HookProjectors` so the payload is
**byte-for-byte** `wire::build`'s output and the reply is parsed by the engine's own fail-closed
normalizers (`hooks/plugin.rs:23-78`).

### 7.2 Ops and stages

| `op` | Fired at | Blocking? | Citation |
|---|---|---|---|
| `"decide"` (`OP_DECIDE`) | phase-2 decision gates + base routing policy | **yes**, bounded by the hook's `timeout_ms` | `hooks/wire.rs:19`; `proxy/hooks.rs:1066-1069` |
| `"transform"` (`OP_TRANSFORM`) | phase-1 rewrite chain (`prompt: rw` gates) | **yes**, bounded by the hook's deadline | `hooks/wire.rs:20`; `proxy/hooks.rs:239` |
| `"notify"` (`OP_NOTIFY`) | taps at stages `request`, `candidate`, `routing`, `response` | **no** — fire-and-forget, detached task, reply ignored, errors swallowed | `hooks/wire.rs:21`; `proxy/engine/mod.rs:2463-2547`; `proxy/hooks.rs:1318-1375` |

Management ops (`configure`, `describe`, `status`) stay key-discriminated, not `op`-tagged
(`hooks/wire.rs:13-18`). Unknown ops **must be ignored** (append-only vocabulary).

Tap stages carry a `stage` object present **only** on stage taps (absent for request-stage taps and
every gate, so the pre-stages wire is byte-identical) — `hooks/wire.rs:36-65`:

| Stage | Fields present | Citation |
|---|---|---|
| `candidate` | `remaining_candidates` (post-reconcile candidate count) | `proxy/engine/mod.rs:1341-1357` |
| `routing` | `model`, `attempt_number` (1-based), `remaining_candidates`, `previous_failure` (`None` on attempt 1) | `proxy/engine/mod.rs:1436-1458` |
| `response` | `outcome` ∈ `"ok" | "failed" | "rejected_by_gate"`, `status` (u16) | `proxy/engine/mod.rs:198-221` |

`rejected_by_gate` is the **synthetic** outcome set from the `GateRejected` response extension so
audit taps see denials (`proxy/hooks.rs:1407-1417`).

`#[serde(flatten)]`ed as flat top-level keys; empty ⇒ zero extra keys.

### 7.4 Candidate view (`HookCandidate`, `hooks/wire.rs:145-178`)

`idx` (the stable handle a hook echoes back in `order`), `model`, `provider`, `weight` (the SWRR

### 7.5 Reply / outcome types (`HookResponse`, `hooks/wire.rs:428-461`)

| Field | Meaning |
|---|---|
| `order: [idx]` | ranked preference, most preferred first |
| `abstain: true` | explicit no-opinion |
| `reject` | untyped `Value`, **fail-closed** |
| `restrict` | untyped `Value`, **fail-closed** |
| `rewrite` | untyped `Value`, **fail-closed**; requires the `prompt: rw` grant |

Unknown JSON fields are ignored (append-only schema).

**Decide-path precedence** (`wire::normalize`, `hooks/wire.rs:666-695`):
`reject` > `restrict` > explicit `abstain` > `order` (absent order ⇒ Abstain; order normalized
against valid idxs, dedup, empty ⇒ Abstain).
**Transform-path precedence** (`wire::transform_outcome`, `hooks/wire.rs:531-543`):
`reject` > `rewrite` > abstain; `restrict`/`order` are **ignored** on the transform path.

| Rule | Detail | Citation |

### 7.7 Ordering among multiple hooks at one stage

| Stage | Ordering |
|---|---|
| Rewrite (`transform`) | globals **first**, then pool rewrites; each chain **stable-sorted ascending by `priority`**, config order breaks ties; each hook sees the previous hook's output (`hooks/mod.rs:435-460`, `:991-1016`; `proxy/hooks.rs:226-239`) |
