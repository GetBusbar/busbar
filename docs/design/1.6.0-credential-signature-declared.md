# The credential signature is DECLARED

*1.6.0 · the authenticate step and the egress-auth step stop holding a list of vendors*

## The fact

Two units acted on credentials by knowing which wires exist.

`busbar-unit-auth` read a client credential out of one of three named headers, in a fixed
precedence, with the header names written into the unit as constants. `busbar-unit-egress-auth`
decorated an outbound request from a three-variant `Scheme` enum whose variants were named after
the vendors that motivated them, one of which (`SigV4`) carried a vendor's own configuration
fields.

Neither unit spelled a dialect name in code, so the plane-purity DIALECT row said nothing. But the
owner rule is not about spelling. *Core knows its plugin kinds and that's it*, and *every core step
is served ONCE by a kind-neutral unit*. A unit that would have to be edited to mount a seventh
dialect is not kind-neutral, whatever it calls its constants.

## The declaration

One type on the ABI, in `busbar_contract::kinds`:

```rust
pub struct CredentialSignature {
    pub alt: SchemeAlt,
    pub arrivals: &'static [CredentialArrival],
    pub presentation: CredentialPresentation,
}

pub struct CredentialArrival {
    pub at: ArrivalLocation,
    pub prefix: Option<&'static str>,
}

pub enum CredentialPresentation {
    Header { name: &'static str, prefix: Option<&'static str> },
    Query { name: &'static str },
    RequestSignature,
}
```

Both halves of one fact, in one declaration. `arrivals` is the ingress half — where a client of
this dialect carries its credential, and the scheme word (if any) the value must begin with.
`presentation` is the egress half — how a request to one of this dialect's upstreams carries ours.
They are not one field because one dialect in the shipped six sends its key on its own header and
receives ours behind a scheme word: the two directions are genuinely two wire facts.

`ArrivalLocation` is reused rather than reinvented. It is already the contract's grammar for *where
a credential is* — it is what `AuthScheme::locations()` answers with — so a signature's arrivals are
resolvable at arrival like every other location the kernel knows, including the `Signed` form that
says the credential is a signature over the request rather than a value in a header.

`CredentialPresentation::kind()` names the presentation KIND an egress-auth plugin registers under
(`bearer`, `api-key`, `request-signature`). It names a SHAPE of carriage: two dialects that carry
theirs the same way resolve to the same plugin and are indistinguishable from it.

## Who declares, who composes, who asks

**Each dialect declares its own.** The six rows of `busbar-plane-llm`'s dialect table each carry a
`credential:` field beside the locations they already declared for the model, the ceiling and the
four metered quantities. The two loose `&'static str` name fields that stood in for this
(`scheme_alt`, `egress_scheme`) are deleted; `codec.rs` reads the declaration instead.

**The root composes the set it mounts.** A unit is handed `&[CredentialSignature]` — the signatures
of the dialects that are actually mounted, in the order the root composed them.

**The unit iterates.** It never asks for a name and has none to ask with.

## The order the ladder is read in

The historical ladder read the scheme-worded carrier first and the two verbatim ones after it. That
ordering survives as a rule the unit derives from the declarations themselves, not as a ranking of
vendors:

> A scheme-worded arrival is read before an un-worded one, because a value carrying its own scheme
> word says what it is and a bare header value does not.

Within each band the declared order stands, which is the order the root composed the set in. Over
the shipped six that reproduces the old ladder exactly, which is what the golden table cell proves.

## What "absence" buys

The point of the cut is a refusal the old shape could not express. Under the old ladder, a build
that mounted no dialect using a given header still read that header — the constant was in the unit
whether or not anything spoke that wire. Under the declarations it cannot: a dialect the root did
not mount contributes no arrival and no presentation, so its credential is unreadable and
unpresentable by the declaration's ABSENCE.

Each unit carries a red-first cell for exactly that (`carrier_tests.rs`,
`a_credential_whose_dialect_is_not_mounted_is_refused_by_the_declaration_s_absence`; `tests.rs`,
`a_presentation_no_mounted_declaration_carries_is_unreachable`). Both were proven red against a
restored fixed ladder and green against the declarations, while the golden table's rows — the same
fixtures, the same bytes — stayed green under both. That is the shape a relocation of an authority
is supposed to have: the behaviour is byte-identical and the refusal is new.

## SigV4 is a presentation kind, not a vendor

`sigv4` stays exactly where it was and computes exactly what it computed. What changed is how it is
selected: the declaration's `RequestSignature` kind selects it, and the three non-secret signing
parameters (`access_key_id`, `region`, `service`) moved to a `SigningParams` argument because they
are CONFIG rather than a wire fact — two upstreams speaking one dialect sign in different regions
under different key ids, so a declaration carrying them would be a declaration per upstream instead
of per dialect.

## What is not done

- **`busbar-core`'s own `AuthMiddleware::extract_client_token`** is the live 1.5.5 path and still
  carries its own three-header ladder. It is legacy due for deletion, not a second home for this
  rule; nothing here builds beside it.
- **The root does not compose the set yet.** Both units' entry points take
  `&[CredentialSignature]`, and the root does not call either of them for the LLM plane today —
  they are relocated units awaiting their wiring. The composition point is where the root mounts
  the dialect set, and it is one call when that wiring lands.
- **The query presentation** is declared and refused closed. Writing the request target is the
  egress unit's job, no declaration in the tree carries the kind, and inventing a substitution
  grammar nothing exercises is how a shape that is never proven ends up wrong.
