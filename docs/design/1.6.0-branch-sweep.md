# 1.6.0 — branch↔trunk symbol sweep: the instrument, its proof, and its blind spots

**Tool:** `scripts/branch-symbol-sweep.py` · **Owner of this file:** the branch-sweep agent.
**Trunk pin for the calibration run:** `d2548391bc3a76b4a01c3dfa4c486efebe93a172`.
This file is the contract five agents share. If you are one of them, read §2 and §6 and nothing else.

---

## 1. What this measures and why paths cannot be the unit

819 remote branches, every one cut after `v1.5.5` (`a71b21e9f`, 2026-08-20), so all are in scope.
The defect class is **code that lives on a branch and not on trunk** — half here, half there.

Three cheaper methods are already known to fail, and are not to be retried:

| method | why it fails here |
|---|---|
| `git patch-id` | the rename waves moved essentially every path, so identical work carries different patch-ids on branch and trunk |
| `git log trunk..branch` / "is it merged" | only **3 of 819** branches are ancestors of trunk |
| comparing file paths | **paths do not survive a rename. Names do.** |

So the unit of comparison is the **symbol**: a declaration, a test name, or a string literal.

### The known false-negative this tool exists to close

The inherited instrument's "found in trunk" verdict was **wrong 4 times in 12 (33%)** because its
trunk-side grep never excluded `docs/`. An audit document *describing a gap* names the missing
symbol, so **the prose about the absent code read as the code being present.**

This is not hypothetical in this repo. `docs/design/1.6.0-LEDGER.md` is itself a survivor ledger
whose rows literally read *"…SURVIVOR … 9 absent; e.g. `RecordSink`, `SinkRecordLegs`"*. Grep trunk
without excluding docs and `RecordSink` is "found" — **in the sentence that says it is missing.**

`docs/**` and every `*.md` are therefore excluded from the trunk haystack by construction. They are
indexed *separately*, so every absent symbol carries a `docs_only` flag. `docs_only: true` is not a
false alarm — it is the strongest finding shape available: **trunk documents this and does not
implement it.**

## 2. Method

For each branch, against `merge-base(trunk, branch)`:

1. `git diff <merge-base> <branch>` — take the lines the branch **adds**.
2. Extract **needles** from those lines: named declarations (`fn` `struct` `enum` `trait` `type`
   `const` `static` `mod` `macro_rules!`, plus shell/python/js/toml/yaml/json/proto equivalents),
   test names, and string literals. **Comments are stripped first** — prose that mentions `fn walk`
   is not a declaration of `walk`.
3. Drop any needle already present anywhere in the merge-base tree. What remains is what the branch
   **named into existence**.
4. Look each up in a **haystack** built from the whole trunk tree — every identifier and every
   string literal in every trunk file, **code only, docs excluded**.
5. Bucket.

### The asymmetry is deliberate

- **Needle side is narrow** (declarations only) so a finding is a real named thing.
- **Haystack side is as broad as possible** (every token, anywhere, any path) so work that landed
  under a different path — or survives only as a call site — still reads FOUND.

Errors are pushed toward HARVESTED, because a false SURVIVOR wastes an auditor's day while a false
HARVESTED loses the work forever — *except* on the docs axis, where the trade is inverted on purpose.

### Buckets

| bucket | meaning |
|---|---|
| `EMPTY` | the branch adds no novel named source content at all (commonly: docs-only branches) |
| `HARVESTED` | every novel symbol is present in trunk code, possibly at a different path |
| `SURVIVOR` | ≥1 novel symbol absent from trunk code — **a finding**; real work that may never have landed |

**HARVESTED is a name-level verdict, not a behaviour-level one.** It means "trunk contains these
names", not "the same code landed". Depth beyond that is a human read.

## 3. Ledger format

One JSONL row per branch, append-only, `flock`-guarded so five agents can share one file.

```jsonc
{
  "v": 1, "tool": "branch-symbol-sweep", "tool_version": "1.0.0",
  "trunk": "<sha>",                 // the pin; rows with different pins are NOT comparable
  "trunk_docs_included": false,     // true only for the falsification run
  "branch": "origin/delete/keep-x", "branch_sha": "<sha>", "merge_base": "<sha>",
  "bucket": "SURVIVOR",             // EMPTY | HARVESTED | SURVIVOR | ERROR
  "symbols_in": 24,                 // novel symbols the branch adds
  "symbols_found": 0,               // of those, present in trunk CODE
  "symbols_absent": 24,
  "docs_only_absent": 1,            // absent from code but present in trunk DOCS
  "money_hits": 3,                  // absent symbols on a money path or with a money-shaped name
  "files_scanned": 5, "files_doc": 2, "files_binary": 0, "files_generated": 1,
  "added_lines": 610, "diff_bytes": 41233, "needles_raw": 57, "mb_code_tokens": 221689,
  "absent": [                       // capped at 500; "absent_truncated" holds the overflow count
    {"sym": "release_drain", "kind": "fn",
     "path": "crates/busbar/src/root/units_admin.rs", "line": 2286,
     "docs_only": false, "money": true}
  ],
  "notes": [], "elapsed_ms": 4021, "ts": "2026-09-23T..."
}
```

`ERROR` rows carry `error` and are always re-swept on the next run — they never count as done.

## 4. Falsification

An instrument that cannot produce a NO is not a check. `selftest` runs **38 checks** and is the
gate on the tool itself. It creates **no ref, deletes nothing, and never touches the working tree**:
scenarios are built with `hash-object` / `update-index` (throwaway index under `$TMPDIR`) /
`write-tree` / `commit-tree`, producing dangling commits.

```
python3 scripts/branch-symbol-sweep.py selftest --trunk <TRUNK_SHA> --base v1.5.5
```

| § | proves | outcome |
|---|---|---|
| T0 | haystack floors — a small haystack manufactures false SURVIVORs | 262,573 code tokens / 3,629 files; 91,583 doc tokens / 225 files |
| T1 | **known SURVIVOR** — 5 constructed symbols, each pre-verified absent from trunk code *and* docs | `SURVIVOR`, all 5 named, the test fn classified `test` |
| T2 | **known HARVESTED at renamed paths** — every file trunk gained since `v1.5.5` (3,197) re-added at a *different* path | **68,777 novel symbols, 68,777 found, 0 absent → `HARVESTED`** |
| T3 | **the docs trap** | `SURVIVOR` docs-excluded ↔ `HARVESTED` docs-included — **the bucket changes** |
| T4 | **negative control** | trunk-vs-itself `EMPTY`; 60 trunk files re-added at new paths `EMPTY` |
| T5 | prose is not code | the one real declaration is reported; three symbols named only in comments are not |
| T6 | **the blind spots, demonstrated** | see §7 |

**T2 is the strongest check in the battery.** It is a full-corpus symmetry proof: if the needle
extractor and the haystack extractor disagree anywhere, a symbol that is provably on trunk comes
back absent. It found two real bugs on first run (118 false absences, 0.17%):

- **compound names** — yaml/TOML/JSON keys carry `-`, `.` and `/` (`self-hosted-runner`,
  `rules.loc-ceilings.kernel_files.teller`). A bare identifier regex split them into unrelated
  words, so they could never be found. Fixed with `EXT_IDENT_RE` on the haystack side.
- **raw-string capture** — `r(#*)"` with zero hashes matched the `r` of ordinary words
  (`..._number"`), and `re.DOTALL` let its non-greedy body **swallow real raw strings further down
  the file**, so literals genuinely present in trunk were extracted on the needle side and missed on
  the haystack side. Fixed with a `(?<![A-Za-z0-9_])b?r` lookbehind.

Both were **false-SURVIVOR** generators. Neither was visible from bucket counts alone.

## 5. What this tool CANNOT see

Every item below is **demonstrated** by `selftest` §T6 on real money-path code, not asserted.

| # | blind spot | verdict it produces | proof |
|---|---|---|---|
| 1 | **a behaviour change that adds no new symbol** | `EMPTY` | deleting `reported.min(k)` from `crates/busbar-kernel-ledger/src/usage/meter.rs` — **a removed clamp on a money path** — yields `EMPTY` with `added_lines=1`, `symbols_in=0` |
| 2 | **an arithmetic downgrade** | `EMPTY` | `acc.saturating_add(…)` → `acc + …` in `crates/busbar-kernel-ledger/src/cost/rate.rs` yields `EMPTY` |
| 3 | **work that landed on trunk under a different name** | **false `SURVIVOR`** | an identical file body with one `fn` renamed reports `SURVIVOR` naming the renamed fn. The tool **cannot distinguish "never landed" from "landed under another name."** |
| 4 | **a deletion on the branch** | `EMPTY` | only `+` lines are read |
| 5 | **whitespace / formatting only** | `EMPTY` | 213 re-indented lines yield `EMPTY` — correctly ignored |
| 6 | **new struct fields and enum variants** | `EMPTY`/`HARVESTED` | deliberately not needles: field-position regexes collide with struct-literal initialisers and match arms, which generated more false SURVIVORs than they caught |
| 7 | **multi-line string literals** | under-extracted | needles are read one added line at a time, so a literal opened on one line and closed on another is missed |
| 8 | **`impl` blocks** | no needle | `impl Trait for Type` introduces no new name, so pure wiring work is invisible |
| 9 | **generated artefacts** | not scanned | `Cargo.lock`, `*.snap`, `openapi.json`, schema snapshots are excluded from the needle side |
| 10 | **a symbol deleted from trunk but present at merge-base** | filtered out | the novelty filter drops it, so trunk *regressions* are under-reported |
| 11 | **generic names** | false `HARVESTED` | a short or common name is "found" wherever it occurs; HARVESTED is name-level only |

### Read #1, #2 and #3 before using any output

This repo's defects are frequently **exactly** #1 and #2 — a removed `.min()`, a missing clamp, an
`acc +` that should be `saturating_add`. **This tool does not see them. At all.** A branch carrying
nothing but a removed money clamp buckets `EMPTY`, and `EMPTY` here means *"adds no new name"*, never
*"is safe"*. A symbol sweep is a **coverage instrument, not a correctness instrument**.

#3 is the dominant false-SURVIVOR source and is why **every SURVIVOR needs a human read.** Use
`locate` to check whether the concept landed under a new spelling before filing anything.

## 6. Invocation contract — for the five agents

**Pin trunk once, share the SHA, share the ledger.** The tool refuses to append rows pinned to a
different trunk than rows already in the ledger (override with `--allow-trunk-drift`, which makes the
ledger incomparable — don't).

```sh
TRUNK=<agreed SHA>            # resolve ONCE; HEAD moves, ~9 agents share this tree
LEDGER=/tmp/bsweep-1.6.0.jsonl

# 1. prove your copy of the tool first — 38 checks, ~3 min, creates no refs
python3 scripts/branch-symbol-sweep.py selftest --trunk "$TRUNK" --base v1.5.5

# 2. take a disjoint slice.  Agents 1..5 pass --slice 1/5 .. 5/5 over the SAME selection.
python3 scripts/branch-symbol-sweep.py sweep \
    --trunk "$TRUNK" --ledger "$LEDGER" \
    --glob 'origin/delete/*' --slice 3/5 --verbose

# 3. read the ledger
python3 scripts/branch-symbol-sweep.py report --ledger "$LEDGER" --top 25

# 4. triage a survivor: where does the name live on trunk, code vs docs?
python3 scripts/branch-symbol-sweep.py locate --trunk "$TRUNK" RecordSink
```

`--slice K/N` splits the **name-sorted** selection into N contiguous blocks, so slices are disjoint
and reproducible. Within a slice the tool re-sorts by merge-base so each merge-base tree is indexed
once. `--branches-file FILE` takes an explicit list; `--branches` accepts whitespace- or
comma-separated names.

> **Strongest form of the contract — use this for the real run.** `--slice` only aligns across
> agents if every agent resolves the *same* selection, so a `git fetch` between two agents' starts
> would silently shift the block boundaries. Freeze the list to a file once, then slice the file:
>
> ```sh
> git -C <repo> for-each-ref --format='%(refname:short)' refs/remotes/origin/ >   | grep -v '^origin/HEAD$' | sort > /tmp/bsweep-corpus.txt   # 819 refs, do this ONCE
> python3 scripts/branch-symbol-sweep.py sweep --trunk "$TRUNK" --ledger "$LEDGER" >   --branches-file /tmp/bsweep-corpus.txt --slice 3/5
> ```
>
> Verified: `--slice K/5` over all 819 yields 164/164/164/164/163, disjoint, union == corpus.

### Properties you can rely on

- **Resumable and idempotent.** A branch already in the ledger under the same trunk pin, tool version
  and docs mode is skipped. Kill it and re-run; `--force` re-sweeps.
- **Concurrency-safe.** Rows are whole lines appended under `flock`. Five agents, one file.
- **Read-only.** `git show` / `diff` / `cat-file` against refs. **No checkout, no worktree, no write
  to the repo tree, no ref created, no ref deleted.**
- **Never returns a silent zero.** An empty branch selection, a too-small haystack, an unresolvable
  rev, or a failed `git diff` is an abort or an `ERROR` row — never a quiet `EMPTY`.

### Shell hazards this tool defuses for you

Every one of these produced a false zero in this repo this week. The tool does all matching in
Python with `subprocess` list-args, so none of them can reach it:

- **zsh does not word-split an unquoted `$VAR`** — `--branches $LIST` arrives as *one* argument.
  Hit live during this work. The tool now splits on whitespace/commas itself.
- **`"$var:crates/…"` parses `:c` as a zsh modifier** — hit live; it silently ate the `c` and turned
  a path into garbage. Use literal SHAs in shell, or stay in Python.
- **POSIX ERE has no `\b`** — `git grep -E '\b…'` exits 0 with empty output.
- **`grep -c` counts LINES, not occurrences**; `git grep -c` counts *files*.
- **`git grep -F` is a SUBSTRING match.** Verifying absence needs **`-w`**. Three "tool is wrong"
  alarms during hand-verification were this mistake: `BUILTINS` occurs only inside
  `TEST_BUILTINS_HOOK`, `installed_plane_decls` only inside a longer test name, `InForce` only inside
  `NoCardInForce`. All three whole-word counts are 0 — **the tool was right, the hand-check was wrong.**
- **macOS `xargs -a` is unsupported**; `re.findall` without `re.MULTILINE` silently under-matches.

### House rules that bind the output

- **Money is binary.** A survivor on a money path (`money: true` / `money_hits > 0`) is a **PARK**
  with cell, branch, symbol, root cause and recommendation. Never self-approve a billed byte.
- **Delete nothing.** The 819 branches are the audit subject. This tool only reads.

## 7. Calibration — 50 branches of `delete/*`

**Sample:** deterministic and reproducible — the 508 `origin/delete/*` refs sorted by name, then
every 10th taken (`awk 'NR%10==1'`, first 50). A stride sample rather than the first 50, because the
names cluster by prefix (`keep-a2a-*`, `keep-k8-*`) and a contiguous block would measure one work
stream rather than the corpus.

**Trunk pin:** `d2548391bc3a76b4a01c3dfa4c486efebe93a172`. Trunk moved to `beaa56d16` during the run
(~9 agents share this tree); every row carries the pin it was measured against, and the tool refuses
to mix pins in one ledger.

### Bucket distribution

| bucket | count | share |
|---|---:|---:|
| `SURVIVOR` | **45** | 90.0% |
| `HARVESTED` | 3 | 6.0% |
| `EMPTY` | 2 | 4.0% |
| `ERROR` | 0 | 0% |

22,031 absent symbols in total; **896** of them `docs_only` (trunk documents, trunk does not
implement); **888** on a money path or carrying a money-shaped name.

90% SURVIVOR is consistent with the prior sweep's 669/816 (82%), and must be read with blind spot
#3 in §5 in mind: **an unknown share of these are work that landed on trunk under a different name.**
SURVIVOR is a queue for human reading, not a defect count.

### The docs trap, measured on the same 50 branches

Same branches, same pin, only `--trunk-include-docs` differs:

| | docs excluded (correct) | docs included (inherited) |
|---|---:|---:|
| absent symbols | **22,031** | 20,999 |
| `docs_only` findings surfaced | **896** | **0** |
| money-flagged absences | 888 | 855 |
| branches affected | — | **39 of 50** |

**1,032 symbols (4.7%) are hidden by the docs hole, and every one of the 896 "documented but not
implemented" findings disappears.** 33 of the hidden ones are money-flagged. Worst single branch:
`delete/keep-k9`, 1,801 → 1,676 absent (125 hidden).

No bucket flips *in this 50*, because these branches carry hundreds of absences each and hiding a
few dozen cannot empty the list. At this scale the damage is not mis-bucketing but **symbol-level
erasure of exactly the highest-value finding class.**

### A real branch that DOES flip — and it indicts the hole in one line

Bucket flips need a branch whose absences are few and all documented, so a second pass swept the 27
`delete/*` branches that touch 1–2 non-doc files. One flips:

| branch | docs EXCLUDED | docs INCLUDED |
|---|---|---|
| `origin/delete/keep-stepown-soc` | **SURVIVOR** — 1 absent | **HARVESTED** — 0 absent |

The single absent symbol is `KEY_MCP`, a `pub(crate) const` declared at
`crates/busbar-core/src/config/prepass.rs:54` on the branch — *"the ONE spelling of the frozen wire
KEY"*. Whole-word `git grep` on the pinned trunk:

- trunk **code**, `docs/` excluded: **0 hits** (positive control `KernelSeal` in the same command
  shape: 335)
- trunk **docs**: **1 hit**, and it is this —

```
docs/design/1.6.0-LEDGER.md:1435:
| `origin/delete/keep-stepown-soc` | … · SURVIVOR · … · 1 absent; e.g. `KEY_MCP` |
```

**The only occurrence of `KEY_MCP` anywhere in trunk is the audit row recording that `KEY_MCP` is
absent.** Include `docs/` in the trunk search and the sentence that reports the gap becomes the
evidence that the gap is closed — the branch buckets HARVESTED and the finding is deleted by the act
of having written it down. That is the 33% false-negative, on a real branch, in one line.

`selftest` T3 reproduces the same flip on a constructed branch whose novel symbols are `RecordSink` /
`SinkRecordLegs` — also real, also present only in trunk `docs/` — so the check is gated in CI-able
form, not just observed once.

> `EMPTY` does not mean "nothing of interest". `delete/keep-rate-card-history` is EMPTY and carries

## 10. Operational proofs

Properties the five-agent fan-out depends on, verified rather than assumed:

| property | proof |
|---|---|
| slices are disjoint and complete | `--slice K/5` over the 508 `delete/*` refs: sizes 102/102/102/102/100, sum 508, union == selection, no duplicates. Over all 819: 164×4 + 163 = 819, disjoint. |
| one ledger, five writers, no torn rows | 5 concurrent processes × 200 rows × ~3 KB payload (far above `PIPE_BUF`, so `O_APPEND` alone would not suffice): **1000 lines written, 1000 parseable, 0 torn.** `flock(LOCK_EX)` is doing the work. |

## 11. Residual holes, named

These are not fixed. They are bounded and recorded so the next agent does not rediscover them.

1. **The trunk code haystack includes code comments — and this repo's comments are enormous.**
   A symbol named only in a Rust doc-comment reads as present, which is the docs trap one layer in.
   `IDENT_RE` tokenises comment prose along with everything else, so this is not closed by ignoring
   backticks.

   **Measured on the pinned trunk: the code haystack holds 262,573 tokens; stripping comment text
   leaves 187,001. 75,572 tokens — 28.8% — exist ONLY inside comments.** That is an upper bound on
   exposure, not an error rate: most symbols occur in both code and prose, so only a symbol whose
   *sole* trunk occurrence is a comment can be mis-harvested. It is nonetheless the largest
   unclosed hole in the instrument, and it is the same disease as the 33% docs false-negative,
   one layer in.

   The mitigation available today is asymmetric and deliberate: the *needle* side **does** strip
   comments (proved by `selftest` T5), so the tool can never manufacture a finding out of prose —
   it can only fail to report one. Closing this properly means stripping comments from the haystack
   too; that change would only ever *add* SURVIVORs, so it must be made with a fresh T2 run to prove
   it adds no false ones.
2. **`qa/*.toml` registries and `xtask` gate rules quote banned or missing symbol names as string
   literals.** `xtask/src/gates/unconstructed.rs` quotes `Ledger::dual_writing(` six times as a test
   fixture. These are code by path and are therefore in the haystack, so a symbol whose only trunk
   occurrence is a *rule that forbids it* reads as HARVESTED. Same family as the docs trap; not
   excluded, because excluding real gate code would manufacture false SURVIVORs at a larger rate.
3. **`symbols_in` is not comparable across branches of different size.** It counts novel names, which
   scales with diff volume. Use it to rank within a bucket, never as a severity score.
