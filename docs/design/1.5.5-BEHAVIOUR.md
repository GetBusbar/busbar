# busbar 1.5.5 — Behavioural Inventory (the parity contract for 1.6.0)

> **Purpose.** 1.6.0 is a ground-up rebuild. From a user's perspective it must be **identical to
> 1.5.5 in every way** — config, wire behaviour, refusals, billing figures, admin API, metrics,
> operations — with exactly three additions: the `mcp`, `a2a` and `voice` planes. This inventory is
> the checklist that "identical" is measured against. Every fact in it was read from the code at the
> `v1.5.5` git tag and carries a `file:line` citation; nothing comes from memory or from the
> 1.6.0-dev tree.
>
> **Precedence.** Code at the tag wins over 1.5.5's own README and CHANGELOG (two contradictions are
> recorded in the ops file). For user-observable behaviour this inventory wins over
> `ARCHITECTURE.md`; where the design disagrees with an inventory row, the design changes. Facts the
> extractors could not pin to a line are listed under UNVERIFIED in each file and must be resolved
> against the running 1.5.5 binary by the oracle before they are relied on.
>
> **How it is used.** Every inventory row maps to one or more oracle cells (§8.1 of the design). The
> coverage matrix below is the gate: an inventory section with no cell family, or a cell family with
> no green run against the published 1.5.5 binary, is a freeze failure.

## 2. Parity traps — facts the rebuild must reproduce deliberately

These are the rows the extractors flagged because a natural clean-room implementation would get
them wrong. Each is a required oracle cell.

**Admission and billing**
- The `/usage` admin read uses the admission `requests` count as the flat-fee base; the enforcement
  path uses `billable_requests` (admitted − non-2xx refunds). `/usage` therefore overstates by
  `per_request_fee × refunded_requests`. Reproduce both figures exactly.
- The admission `requests` counter is never refunded; only `billable_requests` is.
- Quota refusal is HTTP 429 on every dialect except Bedrock, where it is 400.
- `derive_spend_cents` clamps at 0; `derive_spend_micros` does not.
- Bucket-id membership is an identity test against `capped_bucket_ids`, never a parse of the id.
- Fee is decided on the 2xx headers and never reversed; a post-first-byte SSE cut does not refund
  and does not bill tokens; a client disconnect mid-stream refunds the lane unit and bills partial
  tokens; cross-protocol truncation by our cap does not refund; transport error and untranslatable
  2xx do.
- `flush_metering` writes `key_group_at_use: ""`, `pricing_version: ""` and
  `billable_requests: counts.requests` unconditionally.
- Failover runs `max_hops + 1` attempts.
- The pool-empty 503 carries no `Retry-After`; the exhausted-lanes 503 does (never bare `1`; a 2 s floor).
- Auth hard-down never echoes the upstream status; it returns the ingress-native auth status with a
  vendor-plausible message. Passthrough 401/403 is relayed verbatim with no breaker penalty.
- `budget_remaining` is projected to hooks but no shipped native consumes it.

**Config and boot**
- There is no `--config` flag (only `BUSBAR_CONFIG`), no SIGHUP handler, no file watch; reload is the
  admin endpoint only. `--migrate-config` writes nothing to disk and destroys comments.
- `config-schema.waivers` is empty of waivers; its rules are documented.
- `groups.<g>.child_default.limits` is exempt from the amount-zero refusal that `groups.<g>.limits` gets.
- `profile.rs` is an env-guarded latency profiler (`BUSBAR_PROFILE`), not a config-profile system.
- For `BUSBAR_WORKER_THREADS`, `BUSBAR_UPSTREAM_*` and `BUSBAR_PROVIDERS` the env var wins over the
  config key (the CHANGELOG says the opposite).

**Routes and admin**
- Two listeners always: data `0.0.0.0:8080`, admin `127.0.0.1:8081`; admin routes are physically
  absent from the data router and the data surface from the admin router.
- No dual control exists on the admin surface; scope is derived from method+path
  (`x-busbar-required-scope` ∈ {`read-only`, `full`}).
- Idempotency: exactly `POST /keys` and `POST /keys/{id}/rotate`, header `idempotency-key`, TTL
  600 s, in-process map keyed `(actor, header)` for mint and `(actor, "rotate:{id}:{k}")` for rotate;
  no body hash — same key with a different body replays the first response.
- `POST /signing-key/rotate` rotates nothing (audits and returns instructions); `POST /restart` is 202.
- No CORS; no generated `x-request-id`; `openapi.json` `info.version` is `"1.5.4"`.
- `revoke_key` uses `get_key().is_some()`, so revoking a tombstoned key returns 200 and audits;
  PATCH/rotate/DELETE 404.

**Auth, keys, secrets, TLS**
- Rotate has no grace period; on the serving node the old token dies immediately via the generation gate; on PEER nodes (corrected, parity audit 6 — the earlier "fleet-wide" wording repeated a code comment) the old token keeps verifying and the newly minted token is refused until that node's next local mutation or restart (`by_id` is refreshed only then; see auth-secrets :551 note);
  rotate takes no body, no `If-Match`, always re-mints at the 90-day default.
- `VirtualKey.expires_at` has no enforcement site; token `exp` is the only live expiry.
- `SecretRef` has exactly three spellings (`{env:}`, `{file:}`, module); built-ins short-circuit the
  plugin; there is no TTL, cache, watcher or in-place refresh.
- mTLS is a handshake gate only; no client-cert-to-principal mapping; no cert hot reload.
- This subsystem emits zero Prometheus metrics.
- `key_id` is logged in full by design.

**Dialects**
- No client request header is ever forwarded upstream; the egress request is credential +
  `Content-Type` + pinned native-SDK `User-Agent` + `Accept`.
- All 36 ingress×egress pairs are supported; there is no pair-level refusal; 48 literal drop/clamp
  sites define what is lost.
- `service_tier` is unmodelled (rides `extra`, dropped cross-protocol); `IrUsageDetail` does not
  exist; `IrUsage` has four fields.
- Usage absent from a stream bills zero.

**Plugins, stores, export**
- Loader windows: store `[2,2]`, secret `[1,1]`, auth `[1,2]`, hook `[1,1]`, export `[2,2]`;
  transport version 1.
- Signatures are opt-out (`allow_unsigned`, `allow_third_party`), first-party key embedded at build
  time; `UntrustedFloored` is never relaxed. `plugins.enabled` defaults `false`.
- `plugins/reload` is a true hot swap with the store instance reused; `rollback` pins before swapping.
- Only `TransportErrorKind::Unsupported` may open a safe default, on four ops.
- Export is at-most-once, no retry/batching/ack; `durable: true` is a config error; no engine call
  site for `DynExport::deliver`.
- The memory store persists nothing, has no `db_path`, retains 31 days swept every 256 writes.

**Operations**
- `busbar_request_duration_seconds` is a Prometheus summary (quantiles), not a histogram.
- No JSON log mode; `RUST_LOG` accepts a bare level word only.
- `/metrics` is served by the built-in `prometheus` export plugin with key auth; `/metrics/hooks` is a
  core route with a different content type.
- No drain deadline on shutdown; streams run to completion.
- `busbar --safe-mode` as the first argument exits 2 (latent bug; reproduce or fix — owner decision).
- Five counters have no `describe_*` and therefore no `# HELP`.

## 4. UNVERIFIED roll-up

122 items across the eight files could not be pinned to a line by static reading. Each is resolved
by the oracle against the running 1.5.5 binary during M1, and the inventory row is then amended with
the observed behaviour and the cell id. No UNVERIFIED item may be silently assumed.

## 5. What this inventory is not

It is not the design. It says what 1.5.5 does, not how 1.6.0 should be built. The design
(`ARCHITECTURE.md`) may change every internal model — one journal, holds, chains, dual control,
units, planes — as long as every row above remains true from outside.
