# 1.6.0 Protocol-Plugin ABI — Design

**Status: PROPOSED (step-1 deliverable of GOAL-1.6.0).** This is the professional, on-paper ABI
design the code freeze waits on. It is the *signed plugin ABI* for protocol planes — frozen,
minimal, documented. It governs the seam between the neutral core and the LLM/MCP/A2A plugins.

> **NOT YET FREEZABLE — see `1.6.0-abi-solidification.md`.** An LLM/MCP/A2A/**VPN** capability-matrix
> pass found three structural incompletenesses that must close first: the plugin→host inbound vtable
> is unbuilt (G2); chat/request-response assumptions are load-bearing in "neutral" shapes the VPN
> plane breaks (PlaneFacts/Shape/Role, terminal disposition, bounded-buffer codec, HTTP-only ingress —
> G6–G9/G14); and two 2+-plane primitives (itemized cost G1, cross-plane lineage G4) are unwired. That
> doc holds the gap list (G1–G16) and the ordered gate-to-freeze. Harden the ABI to freezability,
> proven against a non-LLM plane, THEN extract on the frozen seam.

**Authority.** `busbarAI-private/goals/GOAL-1.6.0.md` is the authority; this doc implements its
model and does not amend it. Its analysis input is the step-1 read-and-report
(`busbarAI-private/harvest/1.6.0/STEP1-READ-AND-REPORT-2026-08-19.md`) and the three harvest
inputs. Where a harvest mechanic is adopted, the reversal edit ("IR root trait stays in
busbar-core; concrete IRs live in the plugins") is already applied.

**Assumptions flagged.** Decisions that are genuinely the owner's are marked
**`[RATIFY]`** inline and collected in §9. They are resolved here with a decisive default so the
design is complete; the owner overrides any before code moves.

**Review status.** This doc was run through an 8-dimension adversarial verification pass (each
finding independently refuted against the live tree). The confirmed defects — the neutral seam
needs role/slot/shape (§2), the cost ledger stays in core (§4.3.1), the vtable installer is
`C-unwind` (§5.1), `ProtocolWriter` drops the dialect param (§3), config regen is not a no-op
(§6), and the step-1 acceptance grep is scoped (§10) — are folded in. Withdrawn (checked, doc was
right): rewrite-writeback is served by the neutral `ProtocolWriter`; `magnitude` is only a coarse
over-reserve; 1.5.4 already rejects `tools:`/`agents:` via `deny_unknown_fields`; step-1b has no
dependency cycle.

## 0. What this ABI freezes (and what it does not)

**Frozen by this doc** (changing these later is a breaking, signed-ABI event):
- The **`PlaneFacts`** neutral read surface (the IR root trait) — §2.
- The **`PlaneDecl`** registration vocabulary and the **router contract** over it — §4.
- The **crossing/transport** contract: the eighth optional symbol, the host vtable shape, the
  token/grant model — §5. `TRANSPORT_VERSION` **stays 1**.
- The **config seam**: raw-section → plugin `parse_section` — §6.

**NOT frozen / owned by each plugin** (a plugin may change these freely; core never sees them):
- The concrete IR types (`IrRequest`/`IrResponse`/… for LLM; MCP's; A2A's).
- The dialect codecs and wire shapes.
- The plugin's own config grammar (`providers:`/`models:` for LLM, `tools:` for MCP, `agents:`
  for A2A).

**Nothing is inherited-frozen from 1.5.4 (owner ruling, 2026-08-19).** 1.6.0 designs the ABI fresh
and **fully protocol-agnostic**: no `llm`/`mcp`/`a2a` name appears anywhere in the ABI surface — not
in `PlaneFacts`, `PlaneDecl`, the vtable, config, OR `busbar_api::Store`. The Store trait's
protocol-named methods (`append_mcp_call`/`McpCallRecord`/`list_mcp_calls`/`put_task`/
`append_task_event`/…) are **genericized** into opaque per-plane records (§6.1); deleting any plane
then touches no core trait. The ABI must accommodate an arbitrary future protocol — the owner names
"VPN" as a deliberately-wacky validation foil, a stress test the ABI must satisfy, **not** an
implementation target. The 1.6.0 ABI *is* the freeze point going forward; it is simply not
constrained by 1.5.4's names. The plugin KINDS `store`/`secret`/`auth`/`hook`/`export` are
capability categories, not protocol names, and stay. (Fallout: genericizing Store is a breaking
change to the four store plugins — store-sqlite/postgres/valkey/mysql — updated in lockstep; this is
in-scope 1.6.0 work.)

## 1. The model

```
wire  →  ProtocolReader  →  plugin IR  →  [core reads PlaneFacts only]  →  ProtocolWriter  →  wire
(plugin)                    (plugin)        (busbar-core)                   (plugin)
```

Core is a **protocol router / auditor / authenticator / authorizer over a neutral trait**. It
routes, fails over, budgets, costs, audits, authn's, authz's — uniformly, over neutral signals,
with **zero protocol knowledge and zero knowledge of which plugins are present**. A new protocol
supplies new members + a codec and inherits all of it.

Two layers (adopted from the harvest, retargeted to authority):
- **Layer 1 — universal, IR-free.** What core does *to* a request: govern, meter, admit, screen,
  audit, route. Core reads **`PlaneFacts` and nothing else**. `PlaneFacts` is the **IR root trait**
  and lives in **`busbar-core`**.
- **Layer 2 — family vocabulary.** The concrete IR (messages, roles, tools, `max_tokens` for LLM;
  tool-calls for MCP; tasks for A2A). Opt-in per plugin. Lives **in the plugin**. Core never
  interprets it.

**The principle (from authority, verbatim intent):** core is *maximally dumb and maximally
capable* — one property. Every gate that matters, including which dangerous knobs exist (failover,
cost, rate, concurrency), lives in the plugin's own config surface. Core special-cases nothing.

## 2. The IR root trait — `PlaneFacts` (the signed neutral read surface)

Declared in `busbar-core` (proposed `crates/busbar-core/src/plane/facts.rs`). This is the single
family-blind projection the shared pipeline (hooks, governance, taps, router, audit) is allowed to
read. It replaces today's chat-shaped `IrFacts` (`ir/facts.rs:273`), whose `content()` leaks
`IrRole`/`Slot` and whose `shape()` is a chat body.

```rust
/// The family-blind view of a unit of work. Core reads THIS and nothing else about a request.
/// A plane implements it in its own words; core interprets none of the strings as protocol.
/// NOTE: this surface is WIDER than the harvest's minimal PlaneFacts — review proved the shared
/// gate/tap/routing seam reads role, slot, and discrete shape scalars on ALL planes today, so
/// byte-identity requires them here. They are neutral (the shared hook-wire vocabulary), not
/// LLM-only concepts.
pub trait PlaneFacts {
    /// The plane's own verb — an OPEN string, not a core enum. Bounded for safety by
    /// PlaneDecl.verbs (finite, known at load) so it is safe as a metric/audit label.
    fn verb(&self) -> &str;

    /// Streaming intent. For a duplex-forever plane, `true` means "continuously".
    fn wants_stream(&self) -> bool;

    /// The acting principal, if any (for authz + audit subject).
    fn end_user(&self) -> Option<&str>;

    /// A coarse unit+amount for pre-admission budget refusal / cost OVER-reserve only (see
    /// §4.3.1). NOT the true cost — that settles later. Unit-agnostic: "tokens","bytes","tasks".
    fn magnitude(&self) -> Magnitude;

    /// The discrete request-shape signals the shared gate/tap/`RoutingRequest` seam reads. Neutral
    /// counts, not an LLM body: a plane with no such notion returns zeros.
    fn shape(&self) -> Shape;

    /// The screenable content. Each item carries a NEUTRAL role + slot (the frozen hook-wire
    /// vocabulary, shared by LLM/MCP/A2A today) plus the plane's own label. Opaque bytes never
    /// leave the plane; the marker stands in for governance/taps.
    fn screenable(&self) -> Vec<Screenable<'_>>;
}

/// Neutral role — the frozen hook-wire vocabulary shared by LLM/MCP/A2A traffic. FOUR labels:
/// collapsing User+Assistant would change the frozen hook wire and fail the byte-identical gate.
pub enum Role { System, User, Assistant, Tool }

/// Which structural slot content occupies — the gate reads this to build HookPrompt.system vs
/// HookMessage. A packet/task plane uses `Turn` for everything.
pub enum Slot { System, Turn }

/// Discrete shape scalars the shared seam reads (today off IrRequest); a plane with no such
/// notion returns zeros/None. `size_hint` is the neutral analogue of `max_tokens`.
pub struct Shape {
    pub turn_count: u32,
    pub has_tools: bool,
    pub tool_count: u32,
    pub text_chars: u32,
    pub system_chars: u32,   // slot-derived; feeds RoutingRequest
    pub size_hint: Option<u32>,
}

pub struct Magnitude { pub unit: &'static str, pub amount: u64, pub caller_cap: Option<u64> }

pub enum Screenable<'a> {
    Text { label: &'static str, role: Role, slot: Slot, text: &'a str },
    Opaque { label: &'static str, role: Role, slot: Slot, len: usize },
}
```

**Role/slot handling `[RATIFY Q1]` — CORRECTED after adversarial review.** An earlier draft dropped
role/slot from the neutral seam as "chat concepts." **That is wrong and would fail the byte-identical
gate.** `hooks::gate::decide` — fired by LLM, MCP, *and* A2A traffic today — builds the frozen hook
wire from `role_label(item.role())` and `Slot::System`; a label-only `screenable()` cannot reproduce
`HookPrompt.system`/`HookMessage.role`. So the neutral seam **must** carry a neutral `Role` (four
labels — System/User/Assistant/Tool; a 3-value collapse of User+Assistant breaks byte-identity), a
`Slot` signal, and the discrete `Shape` scalars the gate/tap/`RoutingRequest` seam reads. These are
the shared hook-wire vocabulary across all three planes, so they are genuinely neutral core types,
not an LLM leak; `busbar-llm` maps its `IrRole`→`Role`. **This is the single most important
correction before the surface is frozen.**

**Implementation note (verified against dev).** This surface is NOT built from scratch — it already
largely exists as `IrFacts` in `crates/busbar-core/src/ir/facts.rs`, with `verb()->Operation`,
`wants_stream()`, `end_user()`, `shape()->Shape` and `content()->Vec<ContentItem>`, and a richer
real `Slot` (`System`/`Turn(idx)`/`ToolArgs`/`ToolResult`) than the simplified `{System,Turn}` above
— carrying the protocol as *provenance on the item*, never a branch (the module already forbids
`PROTO_*`/`match ingress_protocol`). It has production callers (`proxy/hooks.rs`, `hooks/gate.rs`)
and a second family already implements it (`ir/invoke.rs`). So the `PlaneFacts` unit is: **(1)**
neutralize `IrRole`→a 4-label core `Role`; **(2)** relocate the trait + `Slot`/`ContentItem`/`Shape`
out of `ir/` (which moves to `busbar-llm`) into a neutral home; **(3)** move the LLM walk (`project`
+ `impl IrFacts for IrRequest`) to `busbar-llm`. A rename/relocate/neutralize, not a green-field
build. (Adopt the real `Slot`; the `{System,Turn}` sketch above is illustrative.)

## 3. The codec contract — `ProtocolReader` / `ProtocolWriter`

Each plugin supplies a reader (wire → its concrete IR) and a writer (its concrete IR → wire). The
concrete IR type is the **plugin's**, named nowhere in core. Core obtains a `&dyn PlaneFacts` off
the plugin IR and reads only that.

```rust
// In busbar-core (the trait); implemented in each plugin against ITS concrete IR.
pub trait ProtocolReader {
    /// Parse wire bytes into the plugin's IR, exposed to core only as PlaneFacts.
    fn read<'a>(&self, wire: &'a [u8]) -> Result<Box<dyn PlaneFacts + 'a>, IrError>;
}
pub trait ProtocolWriter {
    /// Serialize the plugin IR (carried opaquely) back to wire. Core never inspects the body and
    /// never names a dialect — target-dialect selection is the plugin's internal concern (a
    /// `target` param would leak an LLM Layer-2 concept into this universal trait and be
    /// meaningless to MCP/A2A).
    fn write(&self, ir: &OpaqueIr) -> Result<Vec<u8>, IrError>;
}
```

**The translation model (owner ruling Q4, 2026-08-19).** Core knows **nothing** about LLM dialects
— not even that an OpenAI request can translate to Anthropic. That mapping (wire dialect ↔ the
plugin's IR ↔ wire dialect) lives **entirely in `busbar-llm`**; cross-dialect fidelity (ADR-0005) is
a plugin-internal contract, not an ABI concern. What core *may* hold is the **generic, protocol-blind
concept**: "plugin X owns IR Y and can translate among the N wire formats it declares (1:n), to/from
its one IR." Core routes a request to the owning plugin's reader/writer by `(kind, wire-format)`
without knowing what the formats are or how they map — the `wire_format_names` a plane declares are
opaque routing labels, and the translation is a black-box call into the plugin. So core carries the
*shape* of translation (a plugin has one IR and many wire formats) but never a single dialect name
or mapping. This is why the six codecs sit in `busbar-llm` and why `ProtocolWriter::write` takes no
dialect param.

## 4. The router contract — neutral machinery over a neutral header

Core resolves `(kind, name)` against the `PlaneDecl` registry and runs the neutral pipeline. The
registry is already built on dev (`plane/registry.rs`, a **15-field** `PlaneDecl` today, including
`wire_format_names` and `build`); this doc freezes its *contract* and adds `verbs`, `parse_section`,
and `set_plane_host` below.

### 4.1 `PlaneDecl` — what a plane declares (fn-pointers, never a plugin type)

Core stores `&'static PlaneDecl` fn-pointers + `Arc<dyn Any + Send + Sync>` slots; it never names a
plugin type (dependency-cycle constraint: `busbar-*` depend on `busbar-core`). Frozen fields
(vocabulary + surface + boot), abbreviated:

- `key`, `config_section`, `scope_kinds`, `subject_noun`, `audit_kind` — the neutral vocabulary.
- `verbs: fn() -> &'static [&'static str]` — the finite open-verb set (bounds `PlaneFacts::verb`).
- `parse_section: fn(&serde_json::Value) -> Result<Box<dyn PlaneCfg>, String>` — the config hook (§6).
- `claims`, `admission`, `mount`, `admin_routes`, `openapi` — surface contributions.
- `hydrate`, `start`, `on_swap` — boot/lifecycle hooks.
- `set_plane_host` — installs the capability vtable (§5).

### 4.2 The three admission ratchets (security invariants — frozen)

- **R1 — every declared path is claimed.** `admission_for` resolves the RFC 8707 audience through
  the mount table; an unclaimed path is a confused-deputy hole. Boot refuses on violation.
- **R2 — a mounted (non-residual) plane supplies admission or boot refuses.** The LLM plane is the
  residual and takes no audience; MCP/A2A are audience-bound OAuth resources.
- **R3 — no two planes share a scope kind, audit kind, or config section.** Sharing a scope kind is
  how one plane's grant admits another's traffic.

A plugin **may never lower its own admission bar.** These are core-owned and pinned by red-first
tests (already present on dev).

### 4.3 The neutral header — the seven signals core reads

Core reads only these off any plane; the payload is the plugin's opaque IR:

| Signal | Source | Status on dev |
|---|---|---|
| member key `(kind, name)` | `ScopeRef{kind,value}` + `PlaneDecl.key` | **EXISTS** |
| **cost — opaque scalar, reserve-then-settle** | `Magnitude` + §4.3.1 | **NEW — designed here** |
| authz scope `(member, operation)` | `scope_kinds` + `Operation::Verb{op,name}` | PARTIAL — unify |
| disposition (success/fail/breaker flags) | `StatusClass → Disposition` (exhaustive) | **EXISTS** |
| session / lifecycle handle | `AdmitGrant` RAII + per-plane `plane_slot` | PARTIAL |
| audit envelope + content digest | `ChainedRecord` + `Digest::seal` (engine-side) | **EXISTS** |

#### 4.3.1 Cost — accurate neutral ledger, reserve-then-settle (owner rulings Q5 + Q6)

**Owner ruling Q5: accuracy of accounting is the paramount invariant.** **Owner ruling Q6: the ABI
is protocol-agnostic — no token/tier/model naming in core.** These reconcile cleanly, and *reverse*
the review's "keep the token model in core" position (which assumed `TierTokens` was frozen in the
Store ABI — Q6 removes that assumption):

- **The token model moves to `busbar-llm`.** `CostModel`/`RateNanos`/`TierTokens` (input/output/
  cache-read/cache-write tiers) are LLM-shaped and cannot live in a protocol-agnostic core. The LLM
  plugin owns the per-model token accounting, the rate card, and reprice-on-reload.
- **Core keeps an ACCURATE, NEUTRAL cost ledger.** Core never estimates or prices the final charge —
  the **plugin computes the exact charge and hands it to core**, which records it faithfully against
  the scope. Accuracy (Q5) is met *because* the authority on cost is the plugin that actually knows
  the tokens; core is a faithful, protocol-blind ledger of an opaque `CostScalar` (plus an opaque
  usage record for audit-grade detail). The census confirms the billing decode (which needs the full
  IR usage body — billed tokens are NOT in `PlaneFacts`) moves to the plugin.

**Itemized granularity (owner, 2026-08-19 — "this is the granularity we need and more").** The
settled charge is **not** an opaque scalar — it is a **neutral itemized breakdown**: a total plus a
list of `(label, amount)` components the plugin supplies, where **the components sum to the total**.
Core surfaces the breakdown in **response headers** alongside the total (so a caller sees where the
money went — input / cache-write / tool / reasoning / … — with no private pricing table). The
labels are **plugin-supplied strings**; core never interprets them, so it stays protocol-agnostic
while delivering arbitrary granularity ("and more"). Sparse by construction (omit zero components);
a component may declare a `parent` for containment (e.g. reasoning ⊆ output).

```rust
/// Core-owned, protocol-blind. Reserve a coarse over-estimate at admit (from PlaneFacts::magnitude)
/// so a HARD pre-admission budget cap is possible; the plugin later settles the EXACT itemized
/// charge it computed. Core prices nothing and interprets no label.
pub trait CostReserve {
    fn reserve(&self, m: &Magnitude, scope: &ScopeRef) -> Result<CostHold, Denied>;
}
/// A neutral itemized charge. Core ENFORCES sum(components.amount) == total (the "parts add up"
/// guarantee — checkable with zero protocol knowledge). Labels/units are opaque plugin strings.
pub struct CostBreakdown {
    pub total: CostAmount,
    pub components: Vec<CostComponent>,   // sparse: only nonzero lines
}
pub struct CostComponent { pub label: String, pub amount: CostAmount, pub parent: Option<String> }

/// RAII, pinned to (bucket, window_start) so a refund lands in the SAME window it reserved.
/// The flat per-request fee is charged once at reserve, never re-charged on settle (no double-count).
pub struct CostHold { /* bucket, window_start, reserved, settled */ }
impl CostHold {
    /// Record an EXACT increment the plugin computed. Repeatable; components accumulate by label.
    pub fn settle_partial(&mut self, exact: CostBreakdown);
    /// Final reconcile; verifies the sum invariant, ledgers the itemized total, emits the response
    /// headers, and refunds reserved − total. (Drop refunds if not called.)
    pub fn finalize(self) -> LedgeredCost;
}
```

- **A-priori** (bounded request): reserve the over-estimate; the plugin settles the exact itemized
  breakdown once; `finalize` ledgers it and emits the header split.
- **Streamed**: the total is metered live per frame; per the owner's note the **itemized split is
  emitted at completion, not mid-stream** — `settle_partial` accumulates components and the header
  breakdown lands at `finalize`. Cache/reasoning lines appear only when nonzero.

**Accuracy guarantee (Q5):** the ledgered charge is the sum of the plugin's exact settlements and
core rejects a breakdown whose components do not sum to `total` — accuracy is a structural invariant,
not a best-effort. The reserve is coarse (gates admission only); the settlement is exact and itemized.
The LLM plugin owns the token→component mapping (input/output/cache-read/cache-write/reasoning⊆output);
core records opaque labeled amounts. ✅ owner-ratified.

**Worked example (owner-supplied, Claude Haiku, first turn):**
```
CostBreakdown {
  total: 0.0078345,
  components: [                       // sparse, nonzero only; sum == total (core-enforced)
    { label: "Prompt",      amount: 0.000012  },
    { label: "Cache write", amount: 0.0078025 },   // appears only because it is nonzero
    { label: "Output",      amount: 0.000020  },    // reasoning, if any, nests under Output
  ],
}
// Surfaced as response headers next to the existing total. "Prompt + cache write + output = total."
```
Core sees three opaque labeled amounts that sum to the total; it does not know "Cache write" is an
LLM concept — the LLM plugin authored those labels. A future protocol reports its own labels the same
way, and the same ledger/header machinery reports them unchanged.

#### 4.3.2 Authz unification

## 5. The crossing / transport contract

### 5.1 The bidirectional capability vtable — an eighth optional symbol

Capabilities are **inbound** (plugin→host: `admit`, `charge`, `append`). Today `plugin-abi` is
one-directional (six host→plugin symbols + the `busbar_set_log_sink` inbound precedent). The vtable
arrives as an **eighth optional symbol** `busbar_set_plane_host`, installed once after
`busbar_open` before any `busbar_call`. **This is not a transport bump: `TRANSPORT_VERSION` stays
1, and every already-signed store/secret/auth/hook/export plugin keeps loading.**

```rust
pub const PLANE_HOST_ABI: u32 = 1;
// C-unwind: this is a host->plugin INSTALLER frame (matches the SetLogSinkFn precedent). Under
// panic="unwind" a plain-"C" frame would abort the gateway and defeat the host's catch_unwind.
// The INBOUND HostCall (plugin->host) below stays plain extern "C" (no unwinding inbound, §5.2).
pub type SetPlaneHostFn = unsafe extern "C-unwind" fn(vt: *const PlaneHostVtable, token: u64) -> i32;

#[repr(C)]
pub struct PlaneHostVtable {
    pub size: usize,        // = size_of as the host compiled it; plugin refuses a field past `size`
    pub abi: u32,           // = PLANE_HOST_ABI (append-only growth)
    pub _reserved: u32,
    // eleven Option<HostCall> slots — NULL = capability not granted (grant is per-plane, core-decided):
    pub govern_admit: Option<HostCall>,
    pub meter_charge: Option<HostCall>,
    pub journal_append: Option<HostCall>,
    pub journal_read: Option<HostCall>,
    pub tasks_op: Option<HostCall>,
    pub approvals_redeem: Option<HostCall>,
    pub quarantine_op: Option<HostCall>,
    pub catalogue_op: Option<HostCall>,
    pub egress_open: Option<HostCall>,   // opens a duplex upstream by POOL, never a URL (SSRF closed core-side)
    pub metrics_emit: Option<HostCall>,
    pub clock_now: Option<HostCall>,
    // deliberately NO secrets_resolve — see 5.3
    pub free: Option<unsafe extern "C" fn(*mut u8, usize)>,
}

pub type HostCall = unsafe extern "C" fn(
    token: u64, req: *const u8, req_len: usize,
    out: *mut *mut u8, out_len: *mut usize) -> i32;
```

### 5.2 Five soundness properties (frozen)

1. **No unwinding inbound.** `extern "C"` + host-side `catch_unwind` → `STATUS_PANIC`. Inbound
   bodies use non-poisoning locks (a plugin panic must not poison a host lock). `catch_unwind` is a
   compatibility boundary, **not a sandbox** (abort/stack-exhaustion still kill the process).
2. **Host handle is a `token: u64`, never a pointer.** A generational slab index; every callback
   resolves token→slot, checks generation, returns `STATUS_GONE` if stale. **No host callback ever
   dereferences a plugin-supplied pointer as a Rust object** — every inbound arg is a scalar or a
   copied byte range, `req_len` checked against `MAX_PLUGIN_RESPONSE_LEN`.
3. **Scope is bound, never passed.** The slot the token resolves to *is* the scope. A plugin cannot
   name another plane's scope.
4. **Bounded re-entrancy.** The call graph is cyclic (core→`busbar_call`→plugin→`HostCall`→core).
   **Invariant: core holds no lock across `busbar_call`** (a `structure-lint.sh` row). A per-token
   depth counter refuses beyond depth 1.
5. **Grants are core-minted and unforgeable.** `PlaneGovernance::admit -> PlaneGrant{token}`,
   MAC'd/slab-indexed, single-use, validated at point of use. A plugin can hold but not construct.

### 5.3 Secrets by reference

`secrets_resolve` is **omitted from the vtable** — `Redacted<String>` survives no C boundary.
Resolution is by secret *reference* handed to `egress_open`; core resolves at the socket. Linked
(compiled-in) planes may keep a `PlaneSecrets::resolve` (satisfies R-K: capability available in both
packagings).

### 5.4 The read/transport shape and the borrow question `[RATIFY]`

Per the Crossing Theorem, a sound crossing is O(1) in payload bytes **iff both** (1) the host read
set is bounded (core reads `PlaneFacts`; the body rides as an untraversed `[ubyte]` in the same
buffer) **and** (2) the transport borrows rather than copies. Condition (1) is satisfied by this
design. Condition (2) — **borrow-not-copy transport** (`PlaneBorrow{ptr,len,cookie,align,_pad}` +
host-side RAII `release`) — is **unbuilt and unmeasured** and is the single largest open ABI risk.

**Default chosen: ship with the frozen copy-out transport (plugin allocates → host copies → host
calls `busbar_free`) for 1.6.0; specify `PlaneBorrow` as an additive, later, plane-kind-only
optimization behind a measured decision.** Copy-out is memcpy-bound (~linear, a real ~24× win over
JSON but not flat); that is acceptable for the cold-path protocol crossing. `[RATIFY]`: build
borrow transport in 1.6.0 vs defer. *Note: the perf numbers backing "flat vs linear" come from a
harness not in the deleted-branches bundle (see read-and-report Q10) — validate before quoting ns.*

### 5.5 Wire format `[RATIFY]`

Layer-1 facts cross as a verified FlatBuffers `Facts` table with the body as an untraversed
`[ubyte]`; the Layer-2 IR rides inside the body, built as the plugin's native output. The
store/secret/auth/hook/export ABI keeps JSON, untouched. *Default chosen: FlatBuffers for the
Layer-1 facts on the dlopen path (additive, negotiated by manifest `abi_version`); compiled-in
planes may pass the native `&dyn PlaneFacts` directly with no encode. `[RATIFY]`: FlatBuffers vs
keep JSON for facts too (simpler, no `flatc` in the graph, at a measured cost).*

## 6. The config seam

Core deserializes the top-level YAML generically and **hands each section it does not own to the
owning plugin's `parse_section`**; a section no compiled plugin claims is **rejected** (so a
`tools:` block on a `core+llm` build is refused, exactly as 1.5.4 refuses it). Core names no
`ToolsCfg`/`AgentsCfg`/`McpCfg`.

```rust
pub trait PlaneCfg: std::any::Any + Send + Sync {
    fn secret_refs(&self) -> Vec<(String, SecretRef)>;  // replaces the core exhaustive destructure
    fn hook_refs(&self) -> Vec<(String, String)>;       // cross-plane hook rule
    fn def_view(&self, name: &str) -> NamedDefView;      // admin projection
}
```

- `Config.planes: BTreeMap<&'static str, Box<dyn PlaneCfg>>` replaces the typed `agent_defs`/`tool_defs`/`mcp` fields.
- `NamedMapSection`'s hardcoded `Tools`/`Agents` variants become iteration over registered `PlaneDecl` fn-pointers.
- **The `#[deny] no-`..`` exhaustive-destructure safety** (adding a config field fails to compile
  until classified as secret) survives by **moving into the plugin's `secret_refs` impl** — the
  plane author's discipline, not core's compiler.
- **`config-schema.py` — regen is NOT a no-op `[RATIFY]`.** It supports plugin-owned config via
  `plane_dir()` + `relocated_only()`, but `relocated_only()` does **not** cover a typed-field→map
  replacement: turning DeployCfg's typed `mcp`/`tools`/`agents` fields into a generic `planes` map
  emits BREAKING field-REMOVED deltas. **Resolution:** keep the typed top-level *section* fields
  (each a raw `serde_json::Value`, dispatched to the plugin parse hook beneath — a section *string*
  is not a plugin *type*, so authority is satisfied) so the schema shape is unchanged; OR plan/waive
  a one-time BREAKING snapshot delta. Do **not** claim the identity gate verifies this — that gate is
  a runtime binary check, not the schema classifier.

### 6.1 Store genericization (owner ruling Q6)

The `busbar_api::Store` trait must **name no protocol.** The MCP/task-shaped methods
(`append_mcp_call`/`McpCallRecord`/`list_mcp_calls`/`put_mcp_demotion`/`redeem_ask_state`/`put_task`/
`append_task_event`/…) become **generic per-plane opaque-record operations** keyed by plane + record
kind:

```rust
// Core defines the shape; the ROW is opaque bytes core never interprets. A plane's record kind is
// a string it declares; deleting a plane removes its kinds and touches NO core trait.
fn append_plane_record(&self, plane: &str, kind: &str, row: &[u8]) -> Result<RecordId, StoreErr>;
fn list_plane_records(&self, plane: &str, kind: &str, q: &RecordQuery) -> Result<Vec<Record>, StoreErr>;
fn put_plane_record(&self, plane: &str, kind: &str, key: &str, row: &[u8]) -> Result<(), StoreErr>;
// The neutral, protocol-blind audit chain stays first-class (it is not a protocol concept):
fn append_audit(&self, rec: &ChainedRecord) -> Result<(), StoreErr>;
fn list_audit(&self, q: &AuditQuery) -> Result<Vec<ChainedRecord>, StoreErr>;
```

- The **row schemas** (what an MCP call record or an A2A task row contains) move into the owning
  plugin; core stores/returns opaque bytes. `ScopeRef` loses `mcp_server`/`mcp_tool`/`allowed_mcp_*`
  in favour of the generic kind-tagged `ScopeRef{kind,value}` (Q6 — these were never Store methods
  and are a real "core names MCP" breach).
- **Fallout (in-scope 1.6.0):** the four store plugins (store-sqlite/postgres/valkey/mysql) implement
  the current named methods; genericizing is a breaking change updated in lockstep. `PlaneStore`
  (the narrowing adapter) narrows to the generic record ops, so a plane still cannot reach
  `append_audit`/`GovCtx`.
- **Byte-identical is preserved behaviourally:** the same records are written and the same audit
  chain is produced; only the trait *shape* is generic. The `core+llm` acceptance test is about
  user-observable behaviour, not the internal Store method spelling.

## 7. Stability / versioning / signing (the 1.6.0 freeze point)

*This ABI — not 1.5.4's — is the freeze point going forward (owner ruling Q6). The Store
genericization (§6.1) is a one-time breaking change to the store plugins; after 1.6.0 the generic
surface is stable. The claims below concern the protocol-plane transport, which stays additive.*

- **`TRANSPORT_VERSION` stays 1.** The whole capability/secrets mechanism is added via *optional
  symbols*, which per the frozen contract are not a transport bump. No relink, no side-by-side
  migration, no already-signed plugin stops loading.
- **`PlaneHostVtable` growth is append-only,** gated by `size`. `abi: u32` starts at 1.
- **Grants** core-minted, opaque, MAC'd/slab-indexed, single-use, validated at use.
- **Tokens** generational slab indices; stale → `STATUS_GONE`.
- **Per-kind payload `abi_version`** over a contiguous `supported_abi` range, negotiated by manifest;
  FlatBuffers additive field-ID tolerance for the facts table.
- **Signing:** the only no-turning-back event in the ABI world is a `TRANSPORT_VERSION` bump; this
  plan avoids it entirely, so signed frozen-kind artifacts keep loading throughout.

## 8. The gating decision — where the translation layer lands `[RATIFY Q4]`

**This is the design's first premise.** `proxy/` (engine) + `handlers/` + `proto/` bind the concrete
LLM IR thousands of times (IrBlock ~226 in core alone, IrStreamEvent 164, IrReq 116). "`core+llm ≡
1.5.4` byte-identical" is only reachable if these land coherently.

**Recommendation (default): the LLM translation layer moves *wholesale into `busbar-llm`*, not
re-expressed against `PlaneFacts` in core.** Rationale:
- `PlaneFacts` is a *read* projection for governance; it is deliberately lossy (no roles/slots). The
  proxy/handlers layer needs the *full* IR to translate and stream — it cannot run on `PlaneFacts`.
- Keeping it in core would force core to keep naming the concrete IR — the exact violation.
- Byte-identical is then a *relocation* property: the same code runs, in `busbar-llm`, linked into
  the `core+llm` build; dual-compile keeps core's own test fixtures green through the move.

**What stays in core:** the neutral streaming *machinery* (`StreamTranslate` framing, SSE framing)
that is genuinely dialect-blind — with its one `PROTO_ANTHROPIC` fast-path branch and the breaker's
`529`/context-length specifics pushed into the LLM plugin's Stage-1 normalizer.

**Census verdict (DONE — 11 IR-binding files in `proxy/` + `handlers/`).** Wholesale-move is
**FEASIBLE**, but it is not "lift out the translation layer and leave the rest untouched" — it is
**4 clean moves/stays + 5 surgical splits**, gated on two neutral enablers core does not yet fully
have:
1. **A neutral `PlaneFacts` projection produced in the plugin's ingress reader** — so `proxy/hooks.rs`
   and `proxy/lazy_body.rs` stop naming `IrRequest`. Their routing already runs entirely on
   `RoutingRequest`/`Candidate`/`Shape` (`hooks.rs:522-576`); they only need the plugin to *hand
   them* a `PlaneFacts`. This is why §2's `Shape`/`Role`/`Slot` must exist.
2. **A neutral `Op`/`OpDispatch` handle stripped of IR-typed methods.** `handlers/mod.rs` is the
   **single hardest file**: the `OperationHandler`/`RequestHandler` traits (`:174-303`) *are* the
   concrete IR and move to the plugin, but `OpDispatch`/`Op` (`:357-443`) is the copy-threaded handle
   the **neutral** forward/stream engine is built around and calls for IR (`op.extract_usage ->
   IrUsage`, consumed at `response_body.rs:574`, `wire.rs:506/559`). Cleaving the IR-typed trait
   (moves) from the engine handle (stays) is the load-bearing cut every other split depends on.

Classification: **MOVE** — `handlers/chat.rs` (the chat codec) + the per-dialect billing decode in
`usage.rs`/`response_body.rs`. **STAY as-is** — `select.rs`, `reqlog.rs`, `egress.rs`, `proxy/mod.rs`
(name no live IR today). **SPLIT** — `hooks.rs` (IR→facts projection moves; all routing stays),
`wire.rs` (`translate_request_cross_protocol` + `mid_stream_error_bytes` move; header/error/shim/
`read_capped` machinery stays), `lazy_body.rs` (`ir`/`ensure_ir` memo moves), `usage.rs`
(the neutral `ledger_and_meter` stays, fed an exact `CostScalar`; the per-dialect usage *decode* and
the token model move to the plugin), `handlers/mod.rs` (the cut above).

**Confirms the cost design (§4.3.1, Q5+Q6):** `usage.rs`/`response_body.rs` provably need the **full
IR usage body** (billed token counts input/output/cache-creation/cache-read — NOT in `PlaneFacts`),
so the billing decode AND the token/rate model move to `busbar-llm`; the plugin computes the exact
charge and hands core an opaque `CostScalar` its neutral ledger records faithfully (accuracy via the
plugin, protocol-agnosticism in core). Minor relocations to bundle with the
dialects: the provider UA constants (`egress.rs:153-163`) and the `KIND_*`→`openai_family::ERR_TYPE_*`
aliases (`proxy/mod.rs:75-89`).

`[RATIFY Q4]`: adopt wholesale-move with the two neutral enablers above (recommended — census-backed),
vs. re-express-against-PlaneFacts. Either way the two enablers are required; the census makes
wholesale-move the lower-risk path.
