# 1.6.0 — what the shadow oracle covers, and what it is blind to

Status: **MEASUREMENT.** Read-only. Nothing in this document blesses, parks, waives or edits a
golden, an `accepted-differences.json` entry or an `accepted-gaps.json` entry. Every number below
was counted from the tree at `ab5bcb45c` (branch `consolidated/1.6.0`) on 2026-09-22, and every
claim names the file it was counted from so a reader can recount it.

**Why this exists.** The oracle is the release's central safety claim — *"prove no user-visible byte
changed."* Its **pass rate** has been measured on every commit for months. Its **coverage** never
has. A green run over a corpus that does not exercise a path is green over nothing, and the
difference between those two statements is the difference between a proof and a habit. This
document is the census. §5 is the one paragraph the release is allowed to quote.

---

## 0. What the oracle is, mechanically

Four moving parts. Getting these right is what makes the rest of the document checkable.

1. **The corpus** — `testing/shadow-oracle/cells.json`, **2,318 cells**. One cell is one
   `(request, response, effects)` triple the recorder drives against a booted binary. Generated,
   never hand-edited, drift-gated in CI (`ci.yml:1359-1371`, `./bin/oracle cells --check`).
2. **The subject** — the recorder boots the real release binary against a config it emits itself
   (`busbar-release-oracle/src/recorder/config_emit.rs`, pinned at
   `testing/shadow-oracle/oracle-rust.pin` → `release_ref=b8cb185`). There are exactly **four config
   variants**: `Baseline`, `QueueTimeout`, `InboundConcurrency2`, `Hooks` (`config_emit.rs:53-62`).
3. **The golden** — `testing/shadow-oracle/golden/1.5.5/`, a *committed* recording of the published
   1.5.5 binary (`meta.json`: `binary_sha256 84bde0a0…`, `recorded: 916`, 2026-09-16). CI copies it
   in and refuses to re-record it (`ci.yml:3116-3140`), because a reference re-derived on the
   machine under test is not a reference.
4. **The verdict** — `busbar-release-oracle/src/run.rs`. Two facts decide everything below:
   - **The owed set is exactly the cells whose GOLDEN LEDGER ROW SAYS `PASS`** (`run.rs:1607-1616`).
     Every other cell becomes a `gap`.
   - **`rc` is non-zero only if the owed set is empty or `diverging_total > 0`**
     (`run.rs:2366-2379`). **Gaps never touch the verdict.** A cell added to the corpus today with
     no golden row is a silent no-op that can never fail.

   There is **no assertion field in the cell schema.** All 28 keys across all 2,318 cells were
   enumerated; `why` is prose the engine reads once and never evaluates. A cell does not *assert*
   anything — it *records*, and the only question ever asked of it is "do these bytes equal the
   1.5.5 bytes."

**The corpus by plane, and the golden's answer to each:**

| plane | cells | golden PASS (compared) | golden SKIP (never compared) |
|---|---:|---:|---:|
| `core` | 789 | **776** | 13 |
| `llm` | 149 | **140** | 9 |
| `mcp` | 912 | **0** | 912 |
| `a2a` | 468 | **0** | 468 |
| `streaming` / voice | **0** | 0 | 0 |
| `decision` | **0** | 0 | 0 |
| **total** | **2,318** | **916** | **1,402** |

All 1,380 `mcp` and `a2a` cells carry one verbatim skip reason: *"UNSUPPORTED: mcp/a2a is proven by
its conformance rig, not recorded here."* That is correct and it is not a defect: 1.5.5 had no MCP
and no A2A plane, so **no 1.5.5 golden for them can exist, and no amount of re-recording creates
one.** The streaming/voice and decision planes are not in the corpus **at any status** — they are
not even enumerated as gaps.

## 1. The census — cells against product surface

### 1.1 The subject is a single, fixed, LLM-only deployment

This is the fact everything else follows from. The emitted config (`config_emit.rs:114-240`)
declares:

- **six providers / six models**, one per LLM dialect, all pointed at the recorder's mock upstream;
- **one rate card**, uniform: `input_utok: 100000, output_utok: 200000` on every model
  (`config_emit.rs:208-219`). No epochs, no per-class rates, no `per_request_fee`, one currency;
- **three budget groups**: `oracle` (budget 1,000,000/day), `broke` (requests 1/day *and* budget
  1/day), `broke-quota` (budget 1/day) (`config_emit.rs:165-178`);
- **one identity provider** (`admin-tokens`) and an ingress auth chain of exactly `[keys]`;
- **one export module** (`prometheus`);
- **eight pools** exercising failover, fallback, least-bad, per-lane concurrency, queueing and a
  breaker cooldown.

There is **no `agents:` block and no `tools:` block** — the subject the oracle boots cannot serve
A2A or MCP at all. That is by design (the spec's claim is "install 1.6.0, configure only the LLM
plane, and it is indistinguishable from 1.5.5"), but it must be stated out loud: the oracle does not
*skip* the new planes, it *never boots them*.

### 1.2 What the 916 compared cells actually drive

| what the cell drives | owed cells |
|---|---:|
| `http` — one served request | **480** |
| `exec` — a process: boot refusal, `--migrate-config`, CLI | **390** |
| `script` — a multi-step scenario | 41 |
| `concurrent` — N parallel requests | 5 |

`busbar-substrate-values/src/diagnostics/mod.rs` and the three plane diagnostic modules.)

### 1.7 Auth, the net guard, plugins, export

- **Auth modules.** `plugins.load|auth-github`, `|auth-ldap`, `|auth-oidc` prove that the process
  *loads* the module. The subject's ingress chain is `[keys]` (`config_emit.rs:137-146`), so **no
  credential is ever authenticated or refused *through* an auth plugin in any cell.** Loaded is not
  exercised. The OAuth 2.1 authorization-server surface (`busbar-kernel/src/oauth_as`) and the
  browser token-exchange actions (`busbar-kernel-identity/src/exchange.rs:18`) likewise have no
  cell. Key lifecycle is covered by exactly three cells (`auth.lifecycle|key-expiry`, `|key-revoke`,
  `|key-rotate`).
- **The SSRF / egress net guard** has **13 runtime refusal variants**
  (`busbar-kernel/src/net_guard.rs:393`: `MetadataName`, `LoopbackName`, `InternalAddress`,
  `CloudMetadataAddress`, `Redirect`, `TooManyRedirects`, `ObfuscatedHost`, …). The corpus covers it
  **only at boot/validate time** — 10 `boot.refusal` cells that refuse a *config* naming
  `169.254.169.254`. **No cell drives a request that the runtime guard refuses**: no redirect into
  link-local, no hostname that resolves private, no oversize upstream body.
- **Plugin failure.** The 10 `plugins.load` cells are all happy-path loads. There is **no cell for a
  bad signature, a missing file, an ABI-version mismatch or a load that fails.**
- **Store failure.** The four `plugins.store-persist` cells record `store_errors: "0"` and
  `survived: "yes"`. They prove the ledger survives a restart on sqlite/postgres/mysql/valkey (and
  three of the four are `needs_fixture` SKIPs in the golden — only sqlite is compared). They do
  **not** exercise a store that errors mid-write; the effect is only ever compared against zero.
- **Export.** One export module is configured (`prometheus`). The others have no cell.

### 1.8 The denominator

`docs/design/1.5.5-BEHAVIOUR.md` enumerates the 1.5.5 user-visible surface across eight inventory
files: **≈2,900 cited behaviour rows, 11,256 lines.** Its own coverage matrix (§3) still reads
`UNMAPPED` for 30 of its 41 sections — every governance/billing row (G1–G7), every dialect row
(D1–D4), every auth row (A1–A6) and every plugin/store row (S1–S4).

**916 compared cells against ≈2,900 cited behaviour rows.** That ratio is not a failure — a cell is
worth more than a row, and many rows collapse into one cell — but it is the honest scale, and it is
the number that forbids reading "oracle green" as "1.5.5 reproduced."

## 2. The real size of the safety net

> **916.** That is the entire set of cells the oracle can ever fail on.

A cell with no golden row cannot detect a regression — it can only, at best, detect a change from
itself, and the engine does not even do that (`run.rs:1607-1616`: no golden `PASS` row, no
comparison). So:

- **2,318 cells in the corpus.**
- **916 compared.** 776 `core` + 140 `llm`.
- **1,402 never compared.** 1,380 of those are `mcp`/`a2a`.
- **60.4% of the corpus is decorative with respect to the verdict.**

### 2.1 And 545 of the 916 carry a pre-authorised change

`testing/shadow-oracle/accepted-differences.json` holds **41 entries** — 28 `improvement`, 10
`breaking`, 3 `additive`. Intersecting each entry's `cells` regex with the owed set:

| class | owed cells on which this class is pre-waived |
|---|---:|
| `body` | 100 |
| `headers` | 78 |
| `effects.usage` | **23** |
| `effects.stderr` | 9 |
| `effects.metrics` | 6 |
| `status` | 6 |
| `effects.readback` | 4 |
| `effects.egress` | 1 |
| `norm.rules` | 1 |
| **any class** | **545 of 916** |

Read this precisely, because it is easy to overstate. A waiver forgives **a class on a cell**, not
the cell: the other classes are still compared byte for byte. But the register is **class-wise, not
value-wise** — there is no expected-value field anywhere in the schema (`run.rs:1747-1790`). Once an
entry's regex matches a cell and names a class, **any** divergence in that class is accepted,
whatever the new bytes say.

So the accurate form of the claim on those 545 cells is *"changed only in ways already written
down"* — not *"byte-identical."*

The one real control here is worth crediting: a **money class** (`status`, `effects.usage`,
`effects.usage_after_restart`, `effects.store_errors`, `missing.candidate`, `effects.egress`,
`effects.readback`, `effects.files`, `effects.script`, `ws`) can only be waived by an entry that is
`kind: breaking` **and** carries a `changelog` line (`run.rs:1152`, `run.rs:1170-1178`). A money
change cannot be self-approved into the register as an "improvement"; it has to become a published
breaking change. That guard works, and it is why the ten `breaking` entries exist.

## 3. The money path

### 3.1 The first thing to know: there are two money books, and the oracle reads the old one

`crates/busbar-kernel-ledger/` is the 1.6.0 "one book": integer, single-sited, currency-aware, with
an append-only dated rate-card `History` resolved at the posting's `arrived_ms`. It is thoroughly
unit-tested (≈180 test fns across `cost/tests`, `usage/tests`, `tests`).

It is **not** the book the oracle's money cells read. `crates/busbar-kernel/src/cost.rs`
(`CostModel`, `RateNanos`) is a second, model-keyed, undated, currency-less book, and it is what
drives `GovState::try_admit`, `derived_bucket_usage`, `get_group_usage` and `GET /keys/{id}/usage`.
The comment at `crates/busbar-core-admin/src/keys.rs:1789-1790` says so in the product's own words:

> *"DERIVED at read time: spend_cents = ledger × CURRENT rate card (+ fee × requests) — a rate-card
> correction changes this number on the very next read (tokens are the truth)."*

And the crate's own money-read roster records the consequence rather than hiding it
(`crates/busbar-core-admin/src/v1/tests/service_tests.rs:2827-2852`): of the four registered money
reads, `get_group_usage` and `GET /keys/{id}/usage` carry `resolves: false` — *"a real, parked
divergence … it is not this test's job to hide it, it is this test's job to make it impossible to
forget."*

**Every `billing|key-usage|*` and `billing|group-usage|*` cell in the corpus drives one of those two
reads.** So the oracle's money coverage is coverage of the enforcement book, priced off the current
card. It is a genuine regression net for that arithmetic. It is not a witness for 1.6.0's headline
money change.

### 3.2 "20 money cells" is the wrong number, in both directions

Only **20 cells** match `^(billing|ledger|config)\|` — 19 owed, 1 SKIP. But the compared bytes that
carry a monetary amount are wider than the ids suggest. Scanning all 916 golden cell files for
`spend_cents|spend_micros|spend_nanos|budget_remaining|billable|refund`:

- **134 owed cells carry a money-shaped value in their compared bytes.**
- **3 are OpenAPI schema documents** (`admin.ops|GetOpenapiJson|ok`,
  `neutrality|routes|admin-openapi-paths`, `crosscut.traps|openapi-info-version`) — they carry the
  *field name* `budget_remaining_cents`, not an amount. Deduct them.
- **131 cells carry an actual amount**, by family: `llm` 67, `billing` 13, `admin.ops` 10,
  `route.failover` 9, `teller` 6, `documented` 5, `hooks` 4, `plugins.store-persist` 4,
  `concurrency` 3, `crosscut.traps` 3, `auth.lifecycle` 2, `ledger` 2, `neutrality` 2, `queue` 2,
  `cooldown` 1, `ops.scrape` 1.
- The amount lives in `effects.usage` + `effects.metrics` on 92 of them (the
  `busbar_key_spend_cents` / `busbar_bucket_spend_cents` / `busbar_bucket_budget_remaining_cents`
  series plus the `/usage` readback), in the response `body` on 24, and in a script effect on 11.

So the money net is **131 cells, not 20** — all of them core or LLM, none on any post-1.5.5 plane.

### 3.3 …and four of them are disarmed, and they are the wrong four

Cross-referencing where each amount lives against which classes are pre-waived on that cell:

- **127 cells** carry the amount in at least one class that is **not** waived. Armed.
- **4 cells** have **every** amount-bearing class pre-authorised to change:

| cell | waived by | changelog line |
|---|---|---|
| `billing\|rate-card\|epoch-mid-window` | D-3 (`breaking`; `body` + `effects.usage`) | *"rate cards are now a dated history, not a single mutable price."* |
| `billing\|rate-card\|history-mid-window` | D-3 | same |
| `ledger\|rate-history\|as-of` | D-3 | same |
| `route.failover\|fb\|member-down-stream-openai` | PR2-D4 (`breaking`; incl. `effects.usage`) | *"fallback-lane streams are now billed."* |

(A fifth, `ledger|currency|minor-unit-rounding`, has its `body` waived by D-4 — an `improvement`
entry, which cannot take a money class; its effects remain armed.)

**This is the single most important money-coverage fact in the release.** The three cells that
exercise a rate card mid-window, a two-card history in one window, and the `as_of` snapshot
selector — that is, *exactly the money behaviour 1.6.0 changes* — are the three cells whose money
bytes the register pre-authorises to move. The guard did its job: the change is `kind: breaking`
with a published changelog line and an owner signature. But nobody may then cite those cells as
evidence that the new pricing is *right*. They are evidence that the change was **declared**.

| `as_of` snapshot read | `ledger\|rate-history\|as-of` | **present, money bytes waived (D-3)** |
| a fee refunded across a window roll | `billing\|key-usage\|refund-across-window` | **SKIP — no golden, never compared** |
| a signed ledger amend | `ledger\|amend\|adjusting-entries` / `\|refused-unsigned` | **pins 1.5.5's 404 only** |
| a native second currency | `ledger\|currency\|native` | **pins 1.5.5's 400 only** |

**The money behaviours with NO cell at all.** Named explicitly, because "no cell" is the finding.
Each is cross-checked against the implementation and against every rig and unit test in the tree —
several *do* have a non-oracle witness, and that is said where it is true.

1. **Any money at all on a post-1.5.5 plane.** 0 of 912 MCP cells and 0 of 468 A2A cells name
   `billing`, `ledger`, `spend`, `rate_card`, `nanos`, `cents`, `micros`, `refund`, `invoice`,
   `fee` or `price` — independently re-grepped for this document — and all 1,380 are SKIP anyway.
2. **A per-declared-class price.** **14 of the 15 declared plane meter classes cannot be priced by
   any config a deployment can write.** The card's class keys are fixed at `input`, `output`,
   `cache_read`, `cache_write` (`busbar-kernel-ledger/src/cost/rate.rs:50-56`), keyed by *model*,
   and card keys are validated against `models:` — so `bytes` (a2a), `bytes` + `tool_calls` (mcp),
   `decision`, and the streaming plane's seven cannot be named at all, and the LLM plane's own
   `tokens_in`/`tokens_out` are declared under names the card cannot key. Witness:
   `h2-class-price.sh`, both planes, **gating and RED today** (`ci.yml:2112-2119`).
3. **The card in force at `arrived_ms`.** `GET /keys/{id}/usage` and `get_group_usage` reprice flat
   off the *current* card (§3.1). Witness: `h2-card-epoch.sh`, both planes, **gating and RED today**
   (`ci.yml:2114-2121`). The oracle cannot help even in principle — see §4.2.
4. **An unpriced class refusing rather than billing a silent zero.** Witness:
   `h2-unpriced-refuses.sh`, both planes, **gating and RED today** (`ci.yml:2116-2123`).
5. **A metered write on a plane with no rate card.** `plane_host/govern.rs:239` gates the entire
   metering write on `state.app.cost.pricing_enabled()`; ruled a defect 2026-09-22. Witness:
   `h2-ledger-unconditional.sh`, both planes, **gating and RED today** (`ci.yml:2135-2138`).
6. **A finite-but-overflowing configured rate, in the book that enforces.**
   `busbar-kernel-ledger/src/cost/rate.rs:42` clamps on `v <= u64::MAX as f64`;
   `busbar-kernel/src/cost.rs:138-144` — the *live* converter — **omits that term**, and
   `config_validate/mod.rs:1406` accepts any finite non-negative float. For `input_utok: 1e18` the
   two books answer `0` and `u64::MAX`. `rate_tests.rs:40` covers the ledger book;
   `cost_tests.rs:597` covers only `INFINITY` for the enforcement book; the agreement test
   (`busbar-kernel-ledger/tests/rate_conversion_agreement.rs`) never names
   `busbar_kernel::cost::RateNanos` at all. **No witness, oracle or otherwise.**
7. **Overdraft on a real unit.** The ledger unit tests cover it
   (`busbar-kernel-ledger/src/tests/settle_tests.rs:199,228`), but the plane-level witness cited
   twice as the behavioural half of binding PB-58
   (`crates/busbar/tests/money_never_ends_an_admitted_unit.rs:30`,
   `xtask/src/gates/design_bindings/tables.rs:606`) names
   `busbar-llm/src/unit/meter.rs::a_spend_past_the_reservation_is_carried_out_as_an_overdraft` —
   **a function that does not exist anywhere in the tree.** A design binding is resting on a
   citation to a missing test.
8. **Two nodes sharing one store each admitting the full cap.** Declared deliberate at
   `busbar-kernel-budget/src/cells.rs:11-15`. **No test, rig or cell measures the joint admission
   count.**
9. **Two requests racing the same budget cell at its cap.** The CAS path is unit-tested
   (`governance/tests/tests.rs:265`: 20 racing, exactly 5 admitted under a 5-concurrent cap). The
   corpus's `concurrency|ok|n8` runs on an *unbounded* lane by construction; the cap is never the
   contended resource end to end.
10. **What gets billed when a client disconnects mid-stream.** The drop-time partial tap exists
    (`busbar-llm/src/engine/response_body.rs:945`); the one rig that drives the scenario
    (`a2a.battery|adv.client_disconnects_mid_stream`, PASS) asserts task/connection hygiene and
    **nothing about the charge.**
11. **Billing idempotency.** There is an idempotency cache for **admin verbs** only
    (`root/kernel.rs:645`). There is no request-id dedupe on the money path for any plane, and the
    conformance leg that would ask (`a2a.battery|adv.duplicate_message_id`) is **SKIP**. The
    corpus's `idempotent-replay` cells are `PostKeys` and `PostKeysIdRotate` — admin mutations, not
    charges.
12. **A non-USD deployment.** The multi-currency machinery is present and well tested, but
    `crates/busbar/src/root/kernel.rs:113-114` returns `CurrencyCode::USD` unconditionally and the

    `unknown field 'currency'` 400 — the shape is still unreachable.
13. **A store that errors mid-ledger-write.** `store_errors` is only ever compared against `"0"`.
14. **Settle point on a stream** — first byte vs last byte. `teller|exit-terminal` pins "one
    terminal, one posting"; all six `stream_upstream_error` cells are SKIP.

### 3.5 Would 131 cells pass a bank auditor?

No — and the honest reason is not the count. It is three things:

1. **They price exactly one thing, one way, under one card.** The subject has a single uniform rate
   card, no epochs, no `per_request_fee`, one currency, one class pair, three budget groups. Every
   "covered" row in §3.4 is covered *in that one configuration.*
2. **They read the book that is being replaced.** §3.1. The reads the cells drive are the two the
   product's own roster marks `resolves: false`.
3. **The behaviours an auditor would ask about first — which card priced this line, what happens at
   the window boundary, can the same request be billed twice, what happens when the balance goes
   negative — are the ones with no cell, and in four cases with a gating witness that is red
   today.**

The parts of the book that *are* under test are under test **in the rigs and the ledger unit tests,
not the oracle**. Citing the oracle for them is citing the wrong instrument. The four red rig legs
at `ci.yml:2092-2138` are the most valuable money witnesses in the tree precisely because they name
their defect and fail loudly; items 6, 7, 8, 10 and 11 above are the obligations that are unmet
**and unmeasured**.

## 4. What the oracle structurally cannot see

The oracle diffs recorded bytes for recorded cells after normalisation. Five categories are out of
its reach by construction — not gaps to be filled, but properties it does not measure. Nobody may
cite a green oracle as evidence for any of them.

### 4.1 Anything with no golden row

`run.rs:1607-1616` iterates only cells the golden ledger marks `PASS`; `run.rs:2366-2379` sets `rc`
from `owed.is_empty()` or `diverging_total > 0` only. **Gaps do not contribute to the verdict.**
Consequence: an authored money cell added to the corpus today is a silent no-op that can never fail.
The oracle cannot be extended to cover a post-1.5.5 plane by adding cells; it can only be extended
by re-recording a golden, and the golden is 1.5.5.

(`run.rs:1152` additionally hard-refuses any accepted-difference naming `missing.golden` — a golden
ledger row claiming `PASS` for a cell the golden never wrote is a recorder bug, never an acceptable
difference. That guard is sound, and it is why the SKIP set cannot be laundered into the owed set.)

### 4.2 Time, in every form

`normalize.rs` zeroes or masks, before any comparison:

- **every timestamp** — `created`, `timestamp`, `ts`, `at`, `sealed_at`, `opened_at`, `closed_at`,
  `time`, **`as_of`**, `expires_at`, `created_at`, `updated_at`, `last_used_at`, `started_at` → `0`
  (`normalize.rs:93-107`, applied at `:338`);
- **the usage window's own boundaries** — `window.start`, `window.end` → `0` (`normalize.rs:108`,
  `:332`);
- **latency** — `latency_ms` / `latencyMs` dropped (`normalize.rs:111`, `:355`);
- **egress duration** — `elapsed_ms` replaced by a coarse bucket (`normalize.rs:580-586`);
- **all Prometheus timing series** — `_seconds`, `_seconds_sum`, `_bucket`, any `quantile=`, and
  `recovery_hint_ms`, dropped wholesale (`normalize.rs:180`, `:374`);
- **`Date`, `Server`, `X-Request-Id`, `traceparent`, `tracestate`, `X-Trace-Id`** stripped
  (`normalize.rs:41-48`); `Retry-After` seconds collapsed to `<RETRY_SECS>` except where a
  `crosscut.traps` cell deliberately pins it.

This is correct — without it nothing would ever be byte-identical twice — and the consequence must
be stated: **the oracle cannot see a wrong time.** It cannot see a billing window opening or closing
at the wrong instant, a rate-card epoch selected against the wrong clock, an `as_of` read resolving
to the wrong snapshot, a key expiring an hour late, or a response that got slower. A golden cell
reads `as_of: 0, window_start: 0`, and so does the candidate, whatever the binary computed.

### 4.3 Timing, concurrency, exhaustion, and everything that needs a second run

- **Performance.** Every duration series is normalised away. A build 10× slower is byte-identical.
  Latency is `perf-build-gate`'s job, not the oracle's.
- **Concurrency and races.** Five `concurrent` cells exist (`concurrency|ok|n8`, `|inbound-shed|n8`,
  `|lane-atcapacity|n4`, `queue|serve|n3`, `queue|timeout|n2`). They prove the *aggregate* outcome
  of N parallel requests under a pinned shape; they are not a race detector, and
  `mask_concurrent_metrics` (`normalize.rs:558`) deliberately blurs per-run ordering. No cell
  contends a budget cell at its cap, and no cell runs two nodes.
- **Resource exhaustion.** Pool exhaustion is covered (shed / queue / least-bad / fallback). The
  node-global ceilings — `SpillBudget`, `SessionBudget`, `CursorBudget`, `CredentialBudget`,
  `ScratchExhausted` — have no cell. Neither does memory pressure, fd exhaustion, disk-full, or
  connection-pool starvation against a real store.
- **Plugin load failure.** 10 happy-path loads, zero failure paths.
- **Long-run drift.** The longest scenario is a single restart. Nothing runs long enough to observe
  accumulator drift, a leak, a cache that degrades, or a window that rolls in real time. The
  `refund-across-window` cell — the one cell that needs a real window roll — is SKIP, and
  `accepted-gaps.json` names the reason: it *"needs a capability the oracle may not build for
  itself (a pinned-mock verb, a concurrent-window-roll driver)."*

### 4.4 Anything the subject is not configured to do

The four config variants (§1.1) are the whole deployment space the oracle has ever booted. Outside
it: MCP and A2A serving, the `agents`/`tools` admin surfaces, the voice/streaming and decision
planes, OIDC/LDAP/GitHub authentication on the request path, the OAuth authorization server, any
export module but Prometheus, any second currency, any rate-card epoch declared at boot, any
non-`chat` LLM operation, and the provider-origin webhook ingress.

### 4.5 And it is one recording of one binary on one machine

The golden is a single recording, `x86_64-unknown-linux-gnu`, 2026-09-16, of one binary
(`84bde0a0…`). Platform-specific behaviour on aarch64 or macOS is normalised (`-<TRIPLE>`) rather
than compared. The claim is parity with *that recording*, not with 1.5.5 in the abstract.

## 5. What a green oracle run proves

**A green oracle run proves this:** for the 916 cells the published 1.5.5 binary was successfully
recorded on — 776 core and 140 LLM-plane cells, of which 480 serve one HTTP request, 390 run a
process, 41 run a scripted scenario and 5 run concurrent requests — a 1.6.0 binary booted in one of
four LLM-only configurations produces, after timestamps, latencies, trace ids and volatile ids are
normalised away, **byte-identical** status, headers, body, WebSocket frames and named effects
(usage, metrics, audit, egress, readback, files, stderr, store errors) — except on 545 of those
cells, where one or more classes of byte were pre-authorised to change by one of 41 register
entries, ten of them published `breaking` changes, and on those cells the proof is the weaker one
that **the bytes changed only in a way already written down and signed off, not that they changed to
the right value**. Within that, it proves the money arithmetic of one flat rate card as computed by
the *enforcement* ledger: that 131 cells carrying a real monetary amount still carry the same
amount, that a 403 and a 429 charge nothing, that a 503 refunds the billable, that both budget
dimensions still bite, that key and group views still agree, that a failover hop is charged once,
that a tripped breaker bills nothing, and that the ledger survives a restart on SQLite.

**It does not prove any of the following, and a green run must never be cited for them.** It does
not prove anything whatsoever about the MCP or A2A planes — all 1,380 of their cells are SKIP, the
subject is never configured to serve them, their 15 admin operations have no cell, and no 1.5.5
golden for them can ever exist — nor about the voice/streaming and decision planes, which are not in
the corpus at any status; for those planes a green oracle is an *absence of evidence*, not evidence
of absence. It does not prove the new money semantics are correct: the cells read the enforcement
book, which the product's own roster records as pricing off the **current** card rather than the
dated history, and the three cells that do exercise a rate-card epoch, a two-card window and an
`as_of` snapshot are precisely the cells whose money bytes the register pre-authorises to move —
while per-class pricing, the card in force at arrival, an unpriced class refusing, and the
unconditional metering write are each owed to a gating rig leg that is **red today, on purpose**. It
does not prove correctness of any behaviour with no cell — an admin 403 or 500 (declared on all 81
operations, recorded on none), a cross-dialect refusal envelope (30 of 36 pairs), fourteen of the
twenty served (dialect, operation) pairs, WebSocket or gRPC streaming, a runtime SSRF refusal,
authentication through an auth plugin, a plugin that fails to load, a store that errors mid-write,
overdraft on a real unit, billing idempotency, a second node sharing one store, or a race on a
budget cell at its cap. It does not prove anything about **time**: every timestamp, every
usage-window boundary and every `as_of` is normalised to zero before comparison, so a wrong billing
window, a wrong rate-card epoch or a wrong expiry is invisible to it by construction. It does not
prove anything about **performance, concurrency safety, resource exhaustion or long-run drift**: all
duration series are discarded, the longest scenario is a single restart, and the one cell that needs
a real window roll is unrecorded. And it does not prove "1.5.5 reproduced": 916 compared cells stand
against ≈2,900 cited behaviour rows in `docs/design/1.5.5-BEHAVIOUR.md`, whose own coverage matrix
still reads `UNMAPPED` for every governance, billing, dialect, auth and plugin section.

**In one sentence, for quotation:** *a green oracle run proves that a 1.6.0 binary, configured for
the LLM plane only, reproduces the published 1.5.5 binary byte for byte on 916 recorded cells —
subject to 41 signed-off deviations affecting 545 of them — and it proves nothing at all about the
MCP, A2A, voice or decision planes, about time, about performance or concurrency, or about any
behaviour for which no cell was recorded.*
