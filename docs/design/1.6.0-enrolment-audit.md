# 1.6.0 ENROLMENT AUDIT — WHAT IS IN NO LIST

> *"A crate that is in no list is in no gate — and a KIND that is in no list is in no gate
> either. The census rows count the roster; neither can see a population that was never
> enrolled. ENROLMENT IS THE GAP NO COUNT DETECTS."* — `docs/design/BUSBAR-1.6.0.md`

Measured 2026-09-22 on `consolidated/1.6.0` at `956d0c122`. 47 registered gates
(`cargo xtask gate --list`), 51 workspace members (`cargo metadata --no-deps`).

**METHOD.** Every scope list was read from BOTH sides — the `qa/*.toml` tables and the Rust
constants — because scope often lives in Rust and not in the TOML
(`qa/plane-pricing-blindness.toml` is 100% comments with zero config lines; its real scope is
`xtask/src/gates/plane_pricing_blindness.rs::PLANE_CRATES`). Every claim of silence below was
PROVEN with a positive control: the SAME violation planted in an enrolled crate and in an
unenrolled one, and every plant grepped back off disk before the verdict was believed
(§6). Controls ran in a detached worktree at `/tmp/enrol-wt` with its own `xtask` built there,
because `Ctx::workspace()` bakes `env!("CARGO_MANIFEST_DIR")` in at compile time — a binary
copied into another tree scans the tree it was COMPILED in, not the one it is run from. The
first control round was silently invalid for exactly that reason, and the plants were only
believed after a rebuild made the root real. **That is this defect class wearing the clothes of
a positive control, and it is why the plants are grepped back.**

## 1. UNSCANNED — THE FINDINGS, IN ORDER OF WHAT IS NOT WATCHED

### U1. `testing/ws-conformance/subject` — a workspace member NO SOURCE SCAN REACHES

The one member that is not under `crates/`. **Every source-scanning gate in the tree roots its
walk at `crates`** — `kind_isolation` (`WalkSpec::new(["crates"])`), `instance_noun_neutrality`,
`no_deferral`, `tracing`, `money_invariants`, `seal_witness`, `plane_abi_neutrality`,
`structure_lint` (`roots::CRATES`), `gates::population` (the shared scan set behind
`settings-leak`, `response-header`, `blocking-ffi`), and `qa/construction.toml`'s
`gate.scan_roots = ["crates/*/src"]`, which is the Tree all ~30 construction rules grep.

Across all 47 gates on the clean tree, `testing/ws-conformance/subject` is named by **exactly one
row**: `kind-isolation:registry`, and only as `off-tree-crate` + `unknown-kind` — a finding about
where its MANIFEST sits, not a scan of its code:

```
off-tree-crate  testing/ws-conformance/subject/Cargo.toml  `ws-conformance-subject` resolves to
kind `?` and does not live at crates/<dir>/Cargo.toml. Every crate of a kind is a crate of the
tree, in the tree's own layout, on the member list — or it is a kind nobody censuses, nobody
scans and nobody scores.
unknown-kind    testing/ws-conformance/subject  `ws-conformance-subject` matches no kind in the
table — make a new plugin kind, do not fuse two
```

The registry row says the words; **nothing acts on them.** It is UNSCANNED for: transitive and
own-source I/O purity (`denylist`), `#![forbid/deny(unsafe_code)]` (`forbid-unsafe`), money
symbols (`plane-no-money`), **fee fields (`one-pricing-site:fee-fields` — the one whole-tree
money rule, which named the identical plant in all SIX `crates/` members and missed this one)**,
wall-clock reads, deferral markers, `#[instrument]` levels, instance nouns, seal sites, hold
escapes, secret-carrier `Debug`, and kind vocabulary.

This is not a hypothetical crate. `testing/ws-conformance/subject/src/main.rs` calls
`TransportKeyHandle::issue(&SubjectSeal, 0, "ws-conformance-subject")` — a **capability-seal
mint** — and binds a TCP listener. `seal-sites` and `seal-witness` scan `crates/*/src` and
`crates` respectively; neither can see it.

`xtask` is the other off-`crates/` member and is **correctly** out of scope: `segregation` owns
it as the instrument rather than the subject. Stated here so it is not mistaken for a gap.

### U2. THE `auth` KIND IS IN NO `manifest-allowlist` ROW — a live Rust-side phantom kind

`xtask/src/gates/construction/rules2.rs:307` still reads:

```rust
let kinds = [
    "plane", "store", "pure_auth", "hook", "export", "secret", "egress_auth",
];
```

`pure_auth` and `egress_auth` **are not keys of `[gate.plugin_kinds]`** — DECISION #3 collapsed
them into one `auth` key. `kind_crate_dirs(cx, cfg, "pure_auth")` resolves through
`Cfg::kind_globs` → `doc.table("gate.plugin_kinds").list_of("pure_auth")` → **empty**, so
`crates/auth-admin-tokens` and `crates/auth-static-plugin` produce no row at all. The gate emits
**12 rows and neither auth crate is one of them** (§6.2).

This is defects #3 and #4 from `xtask/src/gates/qa_names.rs`'s own header — the ones fixed in
`383f23875` and `ab5bcb45c` — **surviving on the Rust side of the same rule.** The TOML copies
were repaired (`[rules.source-denylist].kinds` and `[rules.forbid-unsafe].forbid_kinds` both name
`auth` today, and both hold the auth crates — proven in §6.1 and §6.2). The Rust copy was not,
and `qa-names` cannot see it because `qa-names` reads `qa/*.toml` and nothing else (§5).

### U3. `crates/plane-example` is in NO KIND LIST

`busbar-plugin-example-plane` matches no `[gate.plugin_kinds]` glob — not `plane` (that is an
explicit five-entry list), not `loader`, not `abi`. `plane_pricing_blindness::PLANE_CRATES`
excludes it in writing ("it is a fixture, not a plane"), and `kind_isolation` files it under
`plugin-tooling` by the `busbar-plugin-` matcher. The exclusion from `PLANE_CRATES` is reasoned;
the absence from EVERY kind list is not written down anywhere, and it is what takes the crate out
of `denylist`, `forbid-unsafe` and `manifest-allowlist` together. Proven silent in §6.1 and §6.5:
the identical `use std::net::TcpStream` / `use std::fs` / `use std::process::Command` that reds
`busbar-plane-streaming`, `hooks-ranking` and `auth-static-plugin` produces **nothing** here.

It is a `cdylib` loaded over the plugin ABI. "Fixture" is a statement about intent, not about
what the loader will `dlopen`.

### U4. `crates/busbar-timing` is in no kind list, no money scope, no unit scope

Reached only by the whole-tree walks. The identical `RateCard { fee_cents }` that reds
`plane-no-money` in `busbar-plane-streaming` is invisible here, and the identical
`SystemTime::now()` that reds `unit-no-wall-clock` in `busbar-kernel-scope` is invisible here
(§6.3, §6.4). `busbar-timing/src/lib.rs` is one of three `confined_to_paths` for a `hold-escapes`
symbol — it is trusted BY NAME by a rule whose scope it is otherwise outside.

### U5. NO `[[cell]]` ROW IN `qa/kind-isolation.toml` — 3 live crates

`busbar-core-admin`, `busbar-core-transport`, `busbar-plane-decision`. The matrix scores every
crate × every kind against per-cell ceilings in `[[cell]]`; a crate with no row is a crate with
no ceiling. (`ws-conformance-subject` and `xtask` also have none, per U1.) Note
`busbar-plane-decision` is the SAME crate that was found in no kind list on 2026-09-22 and fixed
in `2b2de9712` — it was enrolled in `[gate.plugin_kinds]` and still has no matrix row.

### U6. KIND ROWS AND MATRIX TABLES THAT DISAGREE

`[[cell]]` carries kinds `core` and `cleanliness` that **no `[[edge]]` row grants an edge to or
from**; `[[edge]]` carries `plugin-abi` and `root` that **no `[[cell]]` row counts**. All seven
plugin kinds are present in both, in both directions — the asymmetry is entirely in the infra
families.

## 5. THE `qa-names` BLIND SPOT, STATED EXACTLY

`cargo xtask gate qa-names` answers **"does every name in `qa/*.toml` resolve to something that
exists?"** It is 9/9 green on this tree. Here is precisely what that does and does not buy.

**WHAT IT CATCHES.** For every `.toml` under `qa/` (ten files), every value that is
* **path-shaped** — no whitespace, contains `/`, first segment is a live top-level directory
  (`:LINE` and `::function` tails stripped) → must exist on disk (`ROW_PATH`);
* a **glob** → must match ≥ 1 thing (`ROW_GLOB`);
* under a key with a `kind`/`kinds` token, **in `qa/construction.toml` only** → must be a key of
  `[gate.plugin_kinds]` (`ROW_KIND`);
* under a key with a `crate`/`crates` token and no path token and no `/` in the value → must be a
  package cargo resolves (`ROW_CRATE`);

plus three liveness rules over its own written exemptions, a package-universe floor of 40, a kind
floor of 7 and a name floor of 400.

**WHAT IT CANNOT CATCH — six holes, five of them load-bearing on this tree.**

1. **ENROLMENT ITSELF.** Stated by the gate in its own header: *"This gate answers 'does every
   name resolve', not 'is everything that should be named, named' — an omission is not a name."*
   Defect 1 of the five it was written for (the fifth plane in no kind list) was visible to it
   only by accident, because the same list also carried a path to a folded plane. Defect 2 was
   not visible at all. **This audit is that hole's report.**

2. **THE FILE SCOPE IS `qa/` AND EXTENSION `toml`.** `QA_ROOT = "qa"`, `QA_EXT = "toml"`. It
   therefore reads **none** of: the Rust scope constants (`PLANE_CRATES`, `PLANE_KEYS`, `KINDS`,
   `COUNT_READ_ROOTS`, `PERSISTED_RECORD_HOMES`, `manifest_allowlist`'s kind array,
   `structure_lint::roots`), the shell gates (`scripts/proto-deletion-gate.sh` and 80 siblings),
   the workflows, or the **non-`.toml` files in `qa/` itself** — `qa/audit-ledger.json`,
   `qa/teller-steps.json`, `qa/design-bindings.json`, `qa/field-inventory.json`,
   `qa/plane-hook-isomorphism.allow`, `qa/reachability-evidence.md`, `qa/WAIVERS.md`. Every entry
   in §3.3 and §3.4 lives in this hole.

3. **THE FRAGMENT VETO RUNS FIRST AND IS PURELY LEXICAL.** `classify()` returns `None` the moment
   a key carries any of `fragment(s)`, `pattern(s)`, `regex`, `symbol(s)`, `word(s)`, `needle`,
   `prefix`, `verb(s)`. The veto is right in general — `/testkit/` is a substring test — and
   wrong in particular five times on this tree: `verbs_crate` (a key ending in `_crate` whose
   `verbs` token vetoes the crate reading), `[rules.ports-only].needle`,
   `legacy-reach.prefixes.*.prefix` ×2, and `loc-ceilings.kernel_files.slice.patterns`. A dead
   crate spelled in a fragment-tokened key is unreadable **by construction**.

4. **A NON-PATH-SHAPED NAME IS NOT A NAME.** `forbidden_module_paths = ["busbar_core::cost::"]`
   is under a PATH-tokened key, but the value has no `/`, so the shape test rejects it. Rust
   module paths naming deleted crates are invisible.

5. **KEYS WITH NO TOKEN AT ALL ARE UNCLASSIFIED.** `reviewed_allowlist` (`busbar-grammar`),
   `[[dep]].from` / `[[dep]].to` / `[[transitional]].to` in `qa/kind-isolation.toml` — 29
   occurrences of 5 dead crate names, in a covered file, that the classifier never reaches.

6. **`ROW_GLOB` JUDGES `[gate.plugin_kinds]` PER KIND, NOT PER ENTRY.** A zero-matching entry is
   excused as long as a sibling entry in the same kind matches. `crates/busbar-export-*` is the
   live instance, excused by name in the gate's own doc. **`kind_isolation`'s `dead-kind` rule
   has the identical hole from the other side** — it tests `live.contains(def.kind)`, so
   `=busbar-substrate` and `=busbar-admin` hide behind their live siblings.

**ONE-LINE STATEMENT.** *`qa-names` proves that no name in a `qa/*.toml` is dead, for the subset
of values its four-way classifier admits. It proves nothing about names in Rust, names in shell,
names in `qa/*.json`, names under fragment-tokened keys, module-path names, untokened keys, or
about anything that was never written down at all. Five of the six gaps are occupied on this
tree, and the sixth — enrolment — is the subject of this document.*
