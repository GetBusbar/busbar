# busbar 1.5.5 — behavioural inventory: configuration schema and boot

## 1. Scope and sources

This document is the **parity contract** for the busbar 1.5.5 *configuration schema and boot*
subsystem: every config key an operator may write, its type, its literal default (and the serde
default fn that produces it), every refusal or clamp applied to it (with the exact message text
where the message is a literal), and what the user observes. It also inventories every boot-time
refusal and warning, the reserved-name and precedence rules, the config-schema additive-only
freeze and its waivers file, `--migrate-config`, and every accepted `SecretRef` form. All facts are
read from the code **at git tag `v1.5.5`**; nothing is from memory. Out of scope: the runtime
routing/dispatch behaviour these keys select, the admin API surface that mutates them, and the
governance ledger semantics — those are separate inventories.

**Structural index.** `crates/busbar/src/config/config-schema.snapshot.json` is the frozen
structural fingerprint of the whole config surface: **75 types, 247 fields**, described as
`"serde-Deserialize structs/enums (derived AND hand-impl'd) + the named-definition-map type aliases
under crates/busbar/src/config"`, `"frozen_at": "1.5.3"`, `"additive-only forever (enforced by the
config-stability gate)"`. The key table below is cross-checked against that snapshot for
completeness.

**Note on `profile.rs`.** Despite the name, `crates/busbar/src/profile.rs` is **not** a
config-profile system — there is no "profile" concept in the 1.5.5 config grammar. It is an
env-guarded hot-path *stage latency profiler*, enabled iff the `BUSBAR_PROFILE` environment
variable is **present with any value** (`std::env::var_os("BUSBAR_PROFILE").is_some()`,
`crates/busbar/src/profile.rs:113`), read exactly once into an `AtomicBool`
(`crates/busbar/src/profile.rs:111-114`). When enabled, `main` spawns a thread that prints
`BUSBAR_PROFILE stage=<name> n=<count> mean=<us> p50=<us> p99=<us>` to **stderr** every 20 s
(`crates/busbar/src/main.rs:692-697`; format string `crates/busbar/src/profile.rs:280`). It has 13
stages (`crates/busbar/src/profile.rs:34-68`) and a 4096-sample-per-stage reservoir
(`crates/busbar/src/profile.rs:107`). Nothing in it reads or affects config.

## 2. Every config key

Conventions: `citation` is `file:line` at `v1.5.5`. Paths under `crates/busbar/src/` are
abbreviated: `config/mod.rs`, `config/groups.rs`, `config/secret.rs`, `config_validate/mod.rs`,
`main.rs`. "Refusal" = a hard error that fails both `--validate` and boot unless noted;
`config_validate::validate` and `config_validate::validate_with_unset` share one body
(`config_validate/mod.rs:37`, `:47`), so **every validation below is enforced identically at
`--validate`, at boot, and on the admin config-apply/reload path**. The only exception is the
`is_env_placeholder` suppression (`config_validate/mod.rs:57-62`), noted per-row.

(`config/mod.rs:3030-3032`; sample at `config.yaml:328`). `admin-tokens` is not a key either: it is
the built-in operator-credential MODULE name (`ADMIN_TOKENS_MODULE = "admin-tokens"`,

## 3. Every boot-time refusal and warning

**Enforcement scope.** `config_validate::validate` (`config_validate/mod.rs:37`) and
`validate_with_unset` (`:47`) share one body, and `--validate` deliberately mirrors the boot
sequence (`main.rs:265-367`). Therefore **every `config_validate` refusal below is enforced
identically at `--validate`, at boot, and on the admin config-apply / `POST /config/reload` path**.
The scope column marks the exceptions:

- **`--validate` only** — `validate_builtin_secrets_resolve` (strict `env`/`file` resolution;
  boot/apply only WARN) — `main.rs:328-331`, `:2484-2498`.
- **`--validate` suppression** — the `is_env_placeholder` closure: under a Lenient load a URL field
  whose value lacks `://` and contains an UNSET env-var name is treated as an unresolved `${VAR}`
  and the https/SSRF *scheme* checks are skipped. Affects only `providers.<p>.base_url` and
  `providers.<p>.token_url` (`config_validate/mod.rs:57-62`, `:341`, `:466`).
- **boot / reload only** — anything reached from `build_app_from_config` after validation: plugin
  preflight, `plugins.fetch`, store open, governance hydration, listener bind. `--validate` never
  binds a listener, writes state, spawns a task, opens TLS, or makes a network call
  (`main.rs:258-263`); `plugins.fetch` is explicitly not reached (`main.rs:2726-2728`).

**Severity model.** There is no severity enum and no `strict`/`warn` flag. Severity is structural:
`errors.push(...)` ⇒ hard refusal returned as `Err(Vec<String>)` and collected all-at-once;
`tracing::warn!` / `eprintln!("[warn] …")` ⇒ warning. `config_validate` has **105 error checks and
exactly 4 warnings**. Boot fatality is `die()` — `eprintln!("[error] {msg}"); std::process::exit(1)`
(`main.rs:456-459`).

**Validation pass order** (single collect-all pass, `Err` returned at `config_validate/mod.rs:1372`):
CIDR global lists (`:68`, `:73`) → reasoning budgets (`:84-98`) → models loop (`:105-199`) → pool
name collisions (`:208-239`) → provider reserved names (`:244-251`) → providers loop (`:257-549`) →
pools loop (`:552-854`) → fallback-cycle walk (`:866-906`) → hooks (`:915-1057`) → `public_url`
(`:1073-1075`) → auth block A (`:1082-1186`) → `global_hooks` (`:1189-1195`) → pool-policy feature
gate (`:1201-1212`) → auth block B (`:1218-1321`) → `validate_limits` (`:1382-1514`) → webhook
timeouts (`:1332-1341`) → cross-pool `context_max` (`:1347-1366`) → `validate_cost_model`
(`:1565-1729`).

**Why `reserved_admin_name` is boundary-safe rather than a prefix check:** the auth middleware
classifies a request as admin with `path == "/admin" || path.starts_with("/admin/")` — deliberately
NOT a bare `starts_with("/admin")` — so sibling names like `adminx` / `admin_portal` are NOT admin
and are legal. A pool/provider/model name lands as a path SEGMENT, so it collides IFF the segment is
exactly `admin`; a name containing `/` could smuggle an `admin/` first segment, so that family is
rejected too (`config_validate/mod.rs:1731-1741`).

**No charset validation on names.** There is no regex or charset restriction on group names
(a group name may legitimately contain `@` and `#` — bucket ids are `group:<name>@<window>` with an
optional `#<kind>:<value>` scope suffix, matched anchored at both ends precisely because of this,
`crates/busbar/src/cost.rs:41-49`, `:56-62`, `:68-82`), on named-map entry names, or on hook names
beyond the reserved list. Length caps exist only on the **admin write path**:
`MAX_GROUP_NAME_LEN = 256` (`crates/busbar/src/admin/v1/service.rs:508`), `MAX_HOOK_NAME_LEN = 256`
(`:505`), `settings` ≤ 256 keys and ≤ 65 536 bytes (`:514-524`).

### 4.3 The config-schema additive-only freeze and the waivers file

The config grammar is **FROZEN after 1.5.3: additive-only forever**. The mechanism:

1. `crates/busbar/src/config/config-schema.snapshot.json` is a committed structural fingerprint —
   75 types, 247 fields, `"frozen_at": "1.5.3"`, generated by `scripts/config-schema.py gen`, whose
   surface is `"serde-Deserialize structs/enums (derived AND hand-impl'd) + the named-definition-map
   type aliases under crates/busbar/src/config"`.
2. `scripts/config-schema.py classify` diffs a freshly-extracted schema against the committed
   baseline and labels each delta `ADDITIVE` or `BREAKING`. `BREAKING` classes:
   `type/section REMOVED (a config referencing it now fails)`, `field REMOVED (breaks a config that
   sets it)`, field retype, optional→required, and enum-variant drop
   (`scripts/config-schema.py:375-471`).
3. `scripts/config-stability-gate.sh` runs the classifier and **fails RED** on any breaking delta —
   exit `3` (`scripts/config-schema.py:18-20`). The gate reads the **committed baseline, not the
   working tree**, so regenerating the snapshot cannot launder a break
   (`scripts/config-schema.py:369-371`).
4. Output lines: `"  additive OK   {path}: {reason}"`, `"  WAIVED        {path}: {reason}  <- waived: {waivers[path]}"`,
   `"  BREAKING  RED {path}: {reason}"` (stderr), and the summary
   `"non-additive config change ({n}); the config grammar is FROZEN after 1.5.3 — additive-only (new OPTIONAL key / section / enum …"`
   (`scripts/config-schema.py:543-568`).

**The waivers file** — `crates/busbar/src/config/config-schema.waivers`, 24 lines, **entirely
comments: it contains ZERO waivers at v1.5.5** and its own header says "EMPTY BY DEFAULT. It should
stay that way." Its rules, verbatim from the file:

- One waiver per line: `<exact-path> = <reason>`; paths are `Type.field` | `Type::Variant` | `Type`
  | `"type AliasName"`.
- **EXACT paths only.** No globs, no wildcards — `*` or `?` is a hard error. A waiver excuses ONE
  path and nothing else; any other break in the same change is still RED.
- **A reason is MANDATORY.** `path =` with no text is a hard error.
- **A STALE waiver** (one that no longer matches any break) is itself a hard error, so the file can
  never accumulate standing permission to break something later.
- Rationale for a file rather than an env var: "an env var can be set in a workflow edit and
  reviewed by nobody. A waiver here is a line in the PR diff, sitting right next to the break it
  excuses, and a reviewer sees it. The gate also prints every applied waiver loudly in its output."
- "A waiver is a LAST RESORT. The additive path — add a NEW optional key and deprecate the old one —
  is almost always available and is what 1.5.3 froze the grammar to guarantee."

Enforced by `scripts/config-schema.py load_waivers` and proven by the gate's self-test.

**Companion freeze pins in code** (tests that fail if a frozen value changes):
`pools_reserved_section_keys_are_frozen` (`config/mod.rs:1525`),
`reserved_hook_names_are_frozen` and `hook_name_word_space_is_frozen` (`config/mod.rs:1859-1860`,
`:1882-1884`), `omitted_phase_is_exactly_the_four_core_stages` (`config/mod.rs:1771`),
`breaker_cfg_default_matches_serde_default_fns` (`config/mod.rs:2214`).

### 4.4 `--migrate-config` behaviour

**There is no schema-version key in the config grammar** — no `schema_version`, `config_version`, or
`apiVersion`. Version detection is **structural marker sniffing** by
`config::migrate::detect_legacy_markers` (`config/migrate.rs:64-323`), which returns a `Vec<String>`
of 1.x markers; a non-mapping document yields an empty vec. It runs at boot AND at `--validate`,
**before** `DeployCfg` deserializes (`config/migrate.rs:61-63`, `main.rs:1620`). The migrator's
TARGET version is `CONFIG_TARGET_VERSION = env!("CARGO_PKG_VERSION")` (`config/mod.rs:791`) —
derived rather than hardcoded, because the previous literal `"1.5.0"` banner went stale.

### 4.5 Hot reload: what reloads, what needs a restart

**There is no SIGHUP handler and no filesystem config watch.** `shutdown_signal()` handles only
`ctrl_c` (SIGINT) and `SignalKind::terminate()` (SIGTERM, unix only); the non-unix `terminate` arm is
`pending()` (`main.rs:1133-1161`). No inotify, no mtime polling. The only reload mechanism is the
admin endpoint `POST /api/v1/admin/config/reload`, which re-runs the same `load_config_from_disk` +
`build_app_from_config` pipeline with `prior = Some(current)` — which is why both are `pub(crate)`
(`main.rs:1601`, `:2684`, doc `:762`, `:1517`, `:1755`). `POST /admin/restart` publishes to the same
shutdown broadcast a signal uses (`main.rs:1009-1013`).

**Boot vs reload discriminator:** `prior.is_none()`. At boot a `plugins.fetch` miss is FATAL; on
reload it only WARNs (`main.rs:2729`, `:2743`).

**Reload env caveat:** interpolation uses the **process's boot-time environment** — a live reload
cannot see edited env files (`main.rs:1515-1517`).

invariant: `(locked || read_only_backend) == path.is_none()` for a config that booted, and
`read_only_backend` is never `true` when `locked` is `true`.

| state | `locked` | `path` | `read_only_backend` | boot | mutations |
|---|---|---|---|---|---|
| default (`config:` absent) | `false` | `<config dir>/busbar-overlay.json` | `false` | OK | durable |
| `locked: true` | `true` | `None` (overlay ignored) | `false` | OK | **refused** with `NO_WRITABLE_OVERLAY_MSG` |
| `locked: false` + `overlay: false` (or `{file:}` absent) | — | — | — | **boot `Err`** (BOOT-125) | n/a |
| `overlay: true` | — | — | — | **boot `Err`** (BOOT-124) | n/a |

`NO_WRITABLE_OVERLAY_MSG` (`config/overlay.rs:32-36`), verbatim — used by all five
`persist_*` / `clear_section` `None`-path backstops and by the admin handlers' locked-config
refusals:

> ``config mutation refused: this busbar has no writable config overlay. This is expected when `config.locked: true` (an immutable/GitOps deployment) — edit config.yaml and POST /config/reload to change it. If the config is meant to be mutable, give it a writable `config.overlay` backend and reload.``

**Overlay durability invariants:**

- Writes are atomic + durable (temp → fsync contents → rename → fsync parent dir) at mode **`0o600`**,
  because the overlay can carry credential material verbatim (`config/overlay.rs:789-817`).
- **PERSIST-then-SWAP, fail-closed**: `commit_and_swap` does not swap a mutation it could not durably
  record (`config/overlay.rs:234-237`).
- **Never a silent `Ok`**: every `persist_*` returns `Err(NO_WRITABLE_OVERLAY_MSG)` on a `None` path
  (`:249`, `:338`, `:494`, `:535`, `:604`, `:975`), pinned by a regression test (`:1217-1255`).
- Read-modify-write per section write, so writing one section never clobbers another's entries or
  tombstones (`:251-262`, `:291-319`).
- Version gate: `read_state` classifies `Absent` / `Loaded` / `Unreadable` / `VersionTooNew(v)`;
  `OVERLAY_VERSION = 1` (`:223-226`). A too-new overlay is refused for both read and write, never
  ignored (`:757-787`).
- Refusal to overwrite a corrupt or newer overlay: `"config overlay exists but is unreadable/corrupt;
  REFUSING to overwrite it (would drop hook AND group deletion tombstones and could resurrect a
  deleted item). This apply is NOT persisted — fix or remove the overlay file to restore durability."`
  (`:301-306`) and `"config overlay was written by a NEWER busbar; REFUSING to overwrite it — this
  binary cannot represent everything it holds, so a write would silently discard whatever it does not
  understand. This apply is NOT persisted."` (`:310-315`).
- Tombstone pruning: a tombstone is retained only while the name is absent from the live registry
  AND still present in base `config.yaml`; otherwise it is permanently inert and pruned (`:280-286`,
  `:357-360`).
- Plugin pins write **both** `plugins.min_versions[name]` and `plugins.first_party_floors[name]` —
  per-plugin, never a single global first-party floor (`:845-875`).
- `GET /config/settings` runs `redact_settings_bags` over the whole tree (reducing `store.settings`
  etc. to key names), a consequence being the body is deliberately **not** a valid round-trip PUT
  payload (`handlers.rs:2816-2821`, `:2850-2858`).

## 5. Secret references

At v1.5.5 the `SecretRef` **type and its `Deserialize` impl live in the standalone
`busbar-secret-ref` crate** (`crates/secret-ref/src/lib.rs`) and are re-exported from
`crates/busbar/src/config/secret.rs:29`. `config/secret.rs` owns only *resolution*
(`SecretResolver`, `resolve_settings`, the built-in `env`/`file` I/O) and the `literal:` escape
hatch. Parsing is a hand-written `Visitor` (`crates/secret-ref/src/lib.rs:123-245`) whose
`deserialize_any` handles only a **map** or a **string**; a string is custom-rejected and every other
node kind falls back to serde's invalid-type error built from `expecting()`.

Key names: `SECRET_MODULE_ENV = "env"`, `SECRET_MODULE_FILE = "file"`,
`SECRET_ENV_SETTING_KEY = "key"`, `SECRET_FILE_SETTING_PATH = "path"`
(`crates/secret-ref/src/lib.rs:42-48`). A machine-readable `oneOf` schema is derived from exactly
these three shapes, each with `additionalProperties: false` and `minLength: 1`
(`crates/secret-ref/src/lib.rs:259-285`).

### 5.1 Accepted and rejected forms

| SEC-017 | `{}` (no keys at all) | **REJECTED** | ``"a secret reference needs `module:` (with optional `settings:`) or the `{ env: <VAR> }` / `{ file: <path> }` sugar"`` | `crates/secret-ref/src/lib.rs:235-238` |

### 5.3 Resolution semantics

| aspect | behaviour | citation |
|---|---|---|
| seam | `SecretResolver` with an optional boxed `PluginResolveFn = Box<dyn Fn(&str,&str) -> Result<Vec<u8>,String> + Send + Sync>`, wired at `build_app` so `config`/`tls` need no plugin-loader dependency | `config/secret.rs:49-59`, `:71-75` |
| built-ins | `env` / `file` short-circuit **inline**, no plugin needed — zero-plugin deployments still have secrets | `config/secret.rs:80-81` |
| when | at every `open`: boot, config apply/reload, and hot plugin reload. Explicitly **not** a per-request read path (it does blocking I/O) | `config/secret.rs:187-190`, `:209-215` |
| what is stored | the config/overlay keeps the **`SecretRef`**, never resolved bytes; only the returned map carries the secret, just long enough to hand to the plugin | `config/secret.rs:189-190` |
| the read-path twin | `classify_setting` classifies by SHAPE alone — no env read, no file read, no plugin call — so admin reads never resolve | `config/secret.rs:142-177` |
| `classify_setting` ordering (shared by both paths) | non-object → verbatim; single-key object whose key is `literal` → inner value verbatim (exactly one level deep); else if the whole object parses as a `SecretRef` → reference; else verbatim | `config/secret.rs:157-177` |
| whitespace | resolved string secrets have trailing `\r`/`\n` trimmed (`trim_end_matches(['\r','\n'])`); leading and interior whitespace is KEPT. Empty after trim ⇒ hard error | `config/secret.rs:121`, `:123-128`, `:325-331` |
| posture | **FAIL-CLOSED at every branch** — unknown module, unset env, missing/empty file, plugin error, and empty result are all hard `Err`; never a silently-empty secret | `config/secret.rs:19-20`, `:43-44`, `:192-194` |
| redaction | every resolve error names only `describe()` (`env:VAR` / `file:/path` / `secret module '<name>'`), never the value | `crates/secret-ref/src/lib.rs:112-120` |
