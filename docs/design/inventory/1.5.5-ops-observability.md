## 2. CLI and environment

### 2.1 Argument dispatch model

`handle_cli_flags()` runs **first in `main()`, before any runtime is built, before any env or file
access** — `crates/busbar/src/main.rs:135-256`, called at `crates/busbar/src/main.rs:638-640`
(`if let Some(code) = handle_cli_flags() { std::process::exit(code); }`).

It matches on **only the first argument** (`std::env::args().skip(1).next()`), `crates/busbar/src/main.rs:136-137`.
busbar takes no positional arguments.

| First arg | Behaviour | Exit code | Citation |
|---|---|---|---|
| *(none)* | run the gateway | — (proceeds to `run()`) | `crates/busbar/src/main.rs:138` |
| `--version` \| `-V` | prints `busbar {CARGO_PKG_VERSION}` to **stdout** | `0` | `crates/busbar/src/main.rs:139-142` |
| `--help` \| `-h` | prints the full help block (quoted in §2.2) to **stdout** | `0` | `crates/busbar/src/main.rs:197-250` |
| `--validate` | `validate_config_command()` | `0` valid / `1` any error | `crates/busbar/src/main.rs:193`, impl `:264-364` |
| `--list-plugins` | `list_plugins_command()` | `0` normally; `1` when `plugins.trust` is invalid | `crates/busbar/src/main.rs:195`, impl `:370-452` |
| `--migrate-config <path>` | `migrate_config_command(args.next())` | `0` success (even with TODOs); `1` unreadable/unparseable; `2` missing path | `crates/busbar/src/main.rs:196`, impl `:1523-1582` |
| `--generate-signing-key` | `generate_signing_key_command()` | `0`; `1` if OS entropy unavailable | `crates/busbar/src/main.rs:194`, impl `:2259-2278` |
| `--print-metadata-blocklist` | prints the effective cloud-metadata denylist, one entry per line, to stdout | `0` | `crates/busbar/src/main.rs:143-192` |
| anything else | `eprintln!("busbar: unrecognized argument '{other}'. Try 'busbar --help'.")` | `2` | `crates/busbar/src/main.rs:251-254` |

**`--safe-mode` is NOT a `handle_cli_flags` arm.** It is detected by `safe_mode_requested()`, which
scans the *whole* arg list for the exact literal `--safe-mode` (`crates/busbar/src/main.rs:547-549`;
test `crates/busbar/src/tests/tests.rs:2135-2145` pins exact-match only — `--safe-mode=true` is NOT
recognised). Consequence, from the dispatch above: `busbar --safe-mode` **as the first argument**
falls into the `Some(other)` arm and exits `2` with `unrecognized argument '--safe-mode'`. It is only
honoured when it follows a recognised first arg (e.g. `busbar --validate --safe-mode`) — see
`crates/busbar/src/main.rs:269` (`--validate`) and `:767` (`run()`). The `--help` text lists it under
a separate `Flags:` heading rather than in `USAGE:` (`crates/busbar/src/main.rs:229-230`).

### 2.3 `--validate` behaviour (exact)

Runs the same load → resolve → validate pipeline boot runs, **without** binding a listener, writing
state, spawning a task, opening TLS, or making a network call (`crates/busbar/src/main.rs:258-263`).

Order (`crates/busbar/src/main.rs:264-363`):
1. `providers_override_from_env()` (deprecated `BUSBAR_PROVIDERS`), `:265`.
2. Config path from `BUSBAR_CONFIG` else `/etc/busbar/config.yaml`, `:266-268`.
3. `safe_mode_requested(std::env::args())`, `:269`.
4. `load_config_from_disk(..., config::EnvSubst::Lenient)`, `:271-282`. Error → `eprintln!("[error] {e}")`, return `1`.
5. Overlay `root` section applied onto `DeployCfg` **before** resolve, `:290-292`.
6. `config::resolve` — error → `[error] config errors:\n  - …`, return `1`, `:293-299`.
7. Overlay `hooks`/`groups` merged post-resolve, `:302-304`.
8. `config_validate::validate_with_unset` — error → `[error] config validation failed:\n  - …`, return `1`, `:305-311`.
9. `preflight_plugins_and_secrets` (the exact pipeline boot runs; manifest-only, no `dlopen`, no store open) — error → `[error] {e}`, return `1`, `:312-323`.
10. **STRICT secrets, `--validate` only**: `validate_builtin_secrets_resolve(&cfg)` — an unresolvable `env:`/`file:` ref is an error here, though it only WARNs at boot, `:325-331`.

Success output to **stdout** (`:332-362`):
```
ok: config valid — {N} provider(s), {N} model(s), {N} pool(s)
  config:    {path}
  providers: {path}
```
then either
`  plugins:   enabled — {n} validated, {n} skipped (untrusted) in '{dir}'` plus one
`    skipped: {name} ({file}) — {reason}` line per skipped plugin, or
`  plugins:   disabled (plugins.enabled is false; no plugin will load)`;
then, when any `${VAR}` was unset,
`  note: {n} env var(s) referenced but unset here — required at runtime: {list}`.

Exit codes pinned end-to-end by `crates/busbar/tests/cli_validate.rs`: `0` on a valid config
(`:131`), `1` on unknown config key (`:180`), store-plugin-referenced-but-plugins-disabled (`:195`),
unresolvable auth-chain plugin (`:229`), invalid tarball (`:249`), sha mismatch (`:283`), trust-gate
refusal (`:312`), alias conflict (`:346`), non-store plugin kind (`:600`).

### 2.4 `--list-plugins` behaviour (exact)

`crates/busbar/src/main.rs:370-452`. Manifest-only; **never `dlopen`s**. Best-effort config read —
a missing/broken config falls back to `config::PluginsCfg::default()` with
`eprintln!("[warn] config not readable ({e}); using the default plugins block")` (`:392-399`).
Invalid `plugins.trust` → `[error] plugins.trust is invalid: {e}`, exit `1` (`:400-406`).

Output (`:408-450`):
- `plugins dir: {dir} (plugins.enabled: {bool})`
- `no plugin tarballs found` and exit `0` when the dir is empty.
- otherwise a header `{FILE:<34} {NAME:<24} {ALIAS:<12} {KIND:<6} {VERSION:<9} {SIGNATURE:<24} STATUS`
  and one row per tarball. Missing manifest fields render as `"-"`.
- STATUS is `LOADS (store.module: {store_ref})` when `plugins.enabled && row.status == "ready" &&
  (name == store_ref || alias == store_ref)`; else `ready (inert: plugins.enabled is false)` when
  `!enabled && status == "ready"`; else the raw `row.status`. Every conjunct pinned by
  `crates/busbar/tests/cli_validate.rs:393-457`.
- Always exit `0` (`crates/busbar/tests/cli_validate.rs:371` — "list-plugins is informational").

### 2.5 `--migrate-config` behaviour (exact)

`crates/busbar/src/main.rs:1523-1582`. **Zero side effects; nothing is written; no env interpolation**
(a `${VAR}` passes through verbatim) — `:1519-1522`.

- No path → `busbar: --migrate-config requires a path: busbar --migrate-config <old-config.yaml>` on stderr, exit `2` (`:1524-1529`).
- Unreadable → `busbar: cannot read '{path}': {e}`, exit `1` (`:1530-1536`).
- Failure → `busbar: --migrate-config failed: {e}`, exit `1` (`:1577-1580`).
- Success: migrated YAML to **stdout** (`print!`, `:1539`); to **stderr**: `migrated '{path}' to the

### 2.6 `--generate-signing-key` behaviour (exact)

`crates/busbar/src/main.rs:2259-2307`. Generates ed25519 via `TokenSigner::generate(DEFAULT_KID)`.
**The 64-hex secret goes to stdout ONLY** (`println!("{secret_line}")`, `:2275`); guidance goes to
stderr and is deliberately **secret-free** so a journal/CI capture never leaks the key (`:2270-2276`,
guidance string `:2288-2305`). Exit `0`; `1` with `busbar: could not generate a signing key: {e}` if
the OS entropy source fails (`:2262-2266`). Zero side effects — busbar never edits the config.

### 2.7 `--print-metadata-blocklist` behaviour (exact)

`crates/busbar/src/main.rs:143-192`. Prints the hardcoded denylist
(`config_validate::metadata_denylist_entries()`) UNION the operator's
`security.blocked_metadata_hosts`, one entry per line to stdout, exit `0`. Reads `BUSBAR_CONFIG`

(`warning: config at {config_path} did not parse; printing the built-in metadata denylist only

built-in set only (`:161-172`); if interpolation fails, the analogous
`warning: config at {config_path} failed to interpolate; …` (`:175-185`). Neither warning echoes the
underlying error (it could quote a config value).

## 3. Process lifecycle

### 3.1 `main()` — pre-runtime phase (order is exact)

`crates/busbar/src/main.rs:635-753`.

1. **CLI flags** (`handle_cli_flags`) — before any runtime, env or file access. `:638-640`.
2. **jemalloc background purge thread** — `background_thread::write(true)` then read back; on
   `Ok(false)` or `Err` prints `[warn] jemalloc background purge thread did NOT enable …` /
   `[warn] could not enable jemalloc background purge thread ({e}); …` to **stderr** (pre-subscriber)
   and spawns `spawn_jemalloc_idle_purge_fallback()`. `:657-688`. Skipped on `target_env = "msvc"`
   (system allocator; `#[global_allocator]` at `:51-53`).
3. **`BUSBAR_PROFILE` dumper thread** (every 20 s to stderr) if enabled. `:692-697`.
4. **Worker-thread resolution** (precedence above). `:723-747`.
5. `tokio::runtime::Builder::new_multi_thread().worker_threads(n).enable_all().build()
   .expect("failed to build the tokio runtime").block_on(run())`. `:748-753`. `run()` is therefore
   polled on the **main thread**, not a Tokio worker.

Idle-purge fallback (`crates/busbar/src/main.rs:1326-1367`): a named thread `"busbar-idle-purge"`
wakes every `IDLE_PURGE_SWEEP_SECS = 15` (`:1303`), and after a full window with **zero** requests
(`REQUEST_ACTIVITY_TICKS` unchanged; incremented once per request by the always-installed
`request_activity_tick` middleware, `:1297`, `:1388-1394`) writes `arena.<i>.dirty_decay_ms = 0` then
restores `opt.dirty_decay_ms` per initialized arena. Best-effort; mallctl errors skipped, never
panicked. If the thread cannot spawn: `[warn] could not spawn the jemalloc idle-purge fallback thread ({e})`
(`:1365`).

### 3.4 Signals

`shutdown_signal()` — `crates/busbar/src/main.rs:1133-1162`.

| Signal | Handled | Behaviour |
|---|---|---|
| `SIGINT` (ctrl-c) | yes, `tokio::signal::ctrl_c()` | triggers drain |
| `SIGTERM` | yes, unix only, `SignalKind::terminate()` | triggers drain |
| `SIGHUP` | **NOT handled.** No `SignalKind::hangup()` anywhere. Config reload is `POST /api/v1/admin/config/reload`, not a signal. | — |
| other | not handled | default OS disposition |
| non-unix | `terminate` is `std::future::pending::<()>()` — only ctrl-c works | `:1154-1155` |

`tokio::select!` over the two arms (`:1157-1160`), then
`tracing::info!("shutdown signal received; draining in-flight requests")` (`:1161`).

**Panic-free by construction:** a failed handler registration logs
`tracing::warn!(error = %e, "failed to install ctrl_c handler; SIGINT shutdown disabled")` (`:1136`) or
`… "failed to install SIGTERM handler; SIGTERM shutdown disabled"` (`:1148`) and then parks forever
(`std::future::pending()`), so the other arm still works and a registration failure can never abort a
worker.

**One signal fans out to BOTH listeners** via a `tokio::sync::broadcast::channel::<()>(1)`
(`:1008`); each `serve_listener` gets its own `recv_shutdown(tx.subscribe())` (`:1047`, `:1055`).
`recv_shutdown` treats *any* receive outcome — value, closed, or lagged — as "shut down now"
(`:1087-1089`).

### 3.5 Admin-triggered restart (same drain path)

`POST /api/v1/admin/restart` — `crates/busbar/src/admin/v1/json/handlers.rs:2386-2439`.

- Supervisor detection: `INVOCATION_ID` or `KUBERNETES_SERVICE_HOST` present
  (`crates/busbar/src/admin/restart.rs:46`, `:86-98`).
- No supervisor **and** no `confirm: true` in the body ⇒ 409 `Cond::NoSupervisor`, message
  `no process supervisor was detected, so exiting would leave busbar down; re-send with `confirm: true`
  if a supervisor will restart it`; audit `admin.restart` recorded as `OUTCOME_REJECTED`
  (`handlers.rs:2406-2416`).
- Shutdown sender not published ⇒ 409 `Cond::NotRestartable`, `this process cannot restart itself`
  (`:2418-2424`).
- Otherwise: audit `admin.restart`/`process`/`OUTCOME_APPLIED` recorded **before** the drain (the
  drain takes the connection that would carry it), then `begin_drain()` sends on the SAME broadcast
  channel a signal uses (`:2426-2429`, `crates/busbar/src/admin/restart.rs:37-41`).
- **Responds BEFORE the drain begins** (`:2384-2385`): `202 Accepted` with
  `{"restarting": true, "supervisor_detected": <bool>, "note": "draining now; in-flight requests
  finish first. The process exits when the drain completes and the supervisor restarts it."}`
  (`:2431-2439`).
- Malformed body ⇒ `Cond::MalformedBody` validation error `invalid body: {e}`, audit `OUTCOME_REJECTED`
  (`:2394-2403`).
- Restart-scoped settings (`listen`, `admin_listen`, `tls`, `admin_tls`, `admin_require_mtls`, `store`)
  are documented as the reason this seam exists (`crates/busbar/src/admin/restart.rs:4-18`).

### 3.6 Graceful shutdown and drain

Both planes use `hyper_util::server::graceful::GracefulShutdown`:
`tls::serve_plain` (`crates/busbar/src/tls.rs:573-603`) and `tls::serve`
(`crates/busbar/src/tls.rs:318-357`). On the shutdown future resolving, the accept loop `break`s
(`:334`, `:586`) — **no new connections are accepted** — then `graceful.shutdown().await` (`:355`,
`:602`) waits for in-flight connections to complete.

**There is NO drain deadline.** `graceful.shutdown()` is awaited unbounded; no `tokio::time::timeout`
wraps it at either site. In-flight requests, including SSE/streaming responses, run to completion.
The bounds that do exist are per-connection, not per-drain:

| Bound | Value | Citation |
|---|---|---|
| TLS handshake timeout | `limits.tls_handshake_timeout_secs`, default 10 s | `crates/busbar/src/tls.rs:49-53` |
| Header-read timeout | 30 s (`.header_read_timeout(Duration::from_secs(30))`) | `crates/busbar/src/tls.rs:564` |
| Body inter-frame timeout | `limits.request_body_read_timeout_secs` | `crates/busbar/src/tls.rs:62-66` |
| Minimum body throughput | `MIN_BODY_THROUGHPUT_BYTES_PER_SEC = 1024`, grace `BODY_THROUGHPUT_GRACE = 10s`; total body deadline = `cap_bytes / 1024` seconds | `crates/busbar/src/tls.rs:77`, `:82`, `:91-93` |
| Upstream request timeout | `limits.upstream_request_timeout_secs` | `crates/busbar/src/main.rs:3179-3181` |
| Upstream connect timeout | 10 s (hardcoded) | `crates/busbar/src/main.rs:3185` |
| Upstream TCP keepalive | 60 s (hardcoded) | `crates/busbar/src/main.rs:3189` |

### 3.7 What is flushed / persisted on shutdown

After `tokio::join!` returns (both planes fully drained) — `crates/busbar/src/main.rs:1058-1074`:

1. `gov.flush_budgets()` — **inline and synchronous** on the run task, so it cannot lose the race with
   process exit; logs `tracing::info!(flushed = n, "budget counters flushed on shutdown")` (`:1064-1065`).
2. `gov.flush_metering()` — same, `tracing::info!(flushed = m, "metering rows flushed on shutdown")`
   (`:1068-1069`).
3. `observability::shutdown_tracing()` — flushes the OTLP tracer so the final (most diagnostic) spans
   export rather than being dropped; a no-op when OTLP is off (`:1074`, `:1004-1006`).

The background write-behind flusher's own shutdown arm also flushes, but it is fire-and-forget and
could lose the race — the inline flush is the durability guarantee (`:1058-1070`).

**NOT persisted on shutdown** (`:1071-1073`):
- Reliability state — circuit breakers, cooldowns, latency EWMAs, hard-down latches — is **RAM-only**
  and re-learned from live traffic on the next boot (`:964-974`). "a lane that is down re-trips its
  breaker on request #1."
- The config version-history ring is RAM-only, re-seeded at its boot floor (version 0).
- The audit log is write-through to the durable governance store as it happens; there is no side-car
  state file to flush. With `store: memory` the audit log is ephemeral by design and starts fresh
  every boot (`:936-939`).
- **No state snapshot file of any kind is written.** Proven end-to-end by
  `crates/busbar/tests/no_state_persist.rs` (real binary, real SIGTERM, real clean drain, asserts no
  file at `$BUSBAR_STATE_FILE` or the default path).

### 3.8 Crash / panic policy

- `#![forbid(unsafe_code)]` — zero `unsafe` in the binary, enforced at compile time
  (`crates/busbar/src/main.rs:38`).
- Boot-time misconfiguration exits via `die(msg)`: `eprintln!("[error] {msg}")` then
  `std::process::exit(1)` — a one-line operator message, never a Rust backtrace
  (`crates/busbar/src/main.rs:456-459`). Used for: config load, config errors, app build, listener
  bind, TLS config, and any serve error.
- The only `expect` on the boot path is the runtime build:
  `.expect("failed to build the tokio runtime")` (`:752`).
- **`panic` is left at the default `unwind` ON PURPOSE**: "a panic in one request task must unwind
  that task, not abort the whole gateway. `panic = "abort"` would trade per-request isolation for a
  little size — the wrong trade for a service in the request path." (`Cargo.toml:32-34`). There is no
  panic hook anywhere; a panic in a request task is contained by Tokio/axum — the task dies, the
  connection is dropped, the process keeps serving.
- Release profile at the tag: `opt-level = 3`, `lto = "fat"`, `codegen-units = 1`, `strip = true`
  (`Cargo.toml:23-31`). `strip = true` means a panic backtrace in production carries no symbols.
- On an ungraceful crash the losses are bounded to: at most one budget-flush interval of accrued
  spend/requests (`:1021-1026`), the RAM audit ring beyond what was already written through, and all
  reliability state (which is RAM-only anyway).
- A crashed prior run's orphaned plugin staging directories are swept on the **next** boot
  (`:827-835`).

### 3.9 Config hot-swap without restart

`AppHandle` (`crates/busbar/src/state.rs:569-641`) is the swap seam. `swap()` replaces the `Arc<App>`
under a brief write lock and **re-spawns the health probers** against the new snapshot — probers hold
a `Weak<App>` and would otherwise silently stop after the first admin mutation
(`crates/busbar/src/state.rs:600-610`). `commit_and_swap()` is persist-then-swap, fail-closed: a
persist failure leaves the running engine untouched (`:612-641`). In-flight requests keep the snapshot
they already loaded.

Boot-once decisions a live config apply does **not** re-derive (restart-to-apply):
`advanced.response_headers.server_timing` (baked into router middleware composition) and
`advanced.response_headers.route_policy` (process-wide `OnceLock`) — `crates/busbar/src/main.rs:798-807`;
plus the restart-scoped settings listed in §3.5.

### 5.2 Levels and filtering

`log_levels()` — `observability.rs:420-436`.

- **stderr level** = `RUST_LOG` parsed as a **bare level word only**
  (`std::env::var("RUST_LOG").ok().and_then(|v| v.trim().parse::<tracing::Level>().ok())`),
  default `tracing::Level::INFO` (`observability.rs:425-428`).
- **`EnvFilter` is deliberately NOT used**: "Full `EnvFilter` directive syntax
  (`busbar=debug,hyper=warn`) would require the `env-filter` feature" (`observability.rs:408-409`).
  Consequence: `RUST_LOG=busbar=debug` fails to parse and **silently falls back to INFO** — see §9.
- **OTLP level** = `stderr.max(tracing::Level::DEBUG)` — floors at DEBUG independently of `RUST_LOG`,
  so enabling traces does not require flooding stderr (`observability.rs:429-430`, rationale `:405-416`).
- Both filters are attached **per layer** (`.with_filter(...)`), never on the registry — a
  registry-level filter would gate callsite enablement globally and make the OTLP filter inert
  (`observability.rs:417-419`, `:444`, `:465`; test `a_registry_level_filter_gates_the_otlp_layer`
  `observability.rs:1683-1715`).
- **Hot-path level policy:** `pub(crate) const HOTPATH_LEVEL: tracing::Level = tracing::Level::DEBUG;`
  (`observability.rs:395`). Convention: `debug!`/`trace!` on the happy path, `info!`/`warn!`/`error!`
  only for error, rare, degraded, boot and shutdown events.
- **CI-enforced:** `scripts/tracing-lint.sh` fails the build on any `#[instrument]` /
  `#[tracing::instrument]` whose attribute text lacks an explicit `level = …`, "so a span can never
  silently default to INFO (== always on, on the hot path)" (`scripts/tracing-lint.sh:2`, `:7-11`,
  `:44-73`, `:144-175`). It scans `crates/**.rs` excluding `*/tests/*` and has a `--selftest` with
  three RED and three GREEN fixtures. It deliberately does not lint `info!`/`warn!` event macros.

**There is no per-request happy-path log event.** busbar emits no `status`/`latency`/`model`/`provider`
success line; per-request facts go to the metrics bank and the `logs` export stream (§6).

## 7. `/stats` and other operational endpoints

### 7.1 `GET /stats`

`crates/busbar/src/endpoints.rs:25-140`. Data listener only (`main.rs:3805`). Auth-gated (not in the
bypass list). Governance-scoped.

**Body shape:** `{ "pools": { … }, "lanes": [ … ] }` (`endpoints.rs:139`).

- `pools` is a **`BTreeMap`, not a `HashMap`** — deliberately, so the serialized object has a stable
  sorted key order and `/stats` output is reproducible across restarts (`endpoints.rs:44-47`). Each
  value is an array of that pool's member lane **model** names, in lane-index order.
- `lanes` is an array; lane indices are built sorted-by-model, so order is deterministic (`:44-47`).

**Per-lane fields** (`endpoints.rs:104-135`):

| Field | Semantics |
|---|---|
| `model` | lane model name |
| `provider` | lane provider name |
| `max_concurrent` | the lane's concurrency limit |
| `limit` | **alias of `max_concurrent`**, kept for backward compatibility (`:108-110`) |
| `inflight` | in-flight requests |
| `free_slots` | free slots |
| `available` | free permit count for a bounded lane, or the **string** `"unbounded"` when `max_concurrent` is omitted (`:117-120`) |
| `at_capacity` | `true` iff a bounded lane is at its limit (`available == 0`) |
| `availability` | rendered from the shared `Unavailable` taxonomy that routing dispatches on: `Ok` → the sentinel `"available"`; `Err` → the variant name (e.g. `"at_capacity"`, `"breaker_open"`) (`:89-98`) |
| `recovery_hint_ms` | `reason.recovery_hint_ms(t)` or `null` when the reason has no self-recovery (dead / budget) |
| `breaker_state` | `"closed"` \| `"open"` \| `"half_open"` (`:99-103`) |
| `ok`, `err`, `client_fault` | outcome counters |
| `usable`, `dead`, `dead_reason` | health latches |
| `cooldown_remaining_s` | remaining cooldown |
| `streak` | consecutive-failure streak |
| `budget` | lifetime budget state |

**Orthogonality contract (explicit):** `breaker_state`, `at_capacity` and `availability` are SEPARATE
axes and are never collapsed. A saturated Open lane reports `breaker_state="open"` AND
`at_capacity=true` AND `availability="breaker_open"`, so an operator can see why its recovery probe
never fires (`endpoints.rs:83-88`; pinned by
`test_stats_surfaces_open_and_at_capacity_independently`, `endpoints.rs:489-532`).
`availability` classifies breaker-first (checked before capacity) (`:526-531`).
At-capacity `recovery_hint_ms` floors at `2000` — never a deceptive `1` (`:477-481`).

**Governance scoping** (`endpoints.rs:16-24`, `:31-76`):
- No key (governance disabled / operator default `GovCtx`) ⇒ full topology.
- A key with `allowed_scopes: None` (omitted at mint) ⇒ full topology.
- A key with an explicit `allowed_scopes` list (**even empty**) ⇒ `restricted`: `pools` filtered by
  `pool_allowed`, and `lanes` filtered to the union of lanes reachable via those visible pools.
  Pool-less lanes stay hidden from restricted callers, so the lane list cannot be used to re-enumerate
  the topology the pool filter removed (`:63-76`).
- Pinned by `test_stats_restricted_key_sees_only_its_pools_and_lanes` (`:346-374`),
  `test_stats_empty_allowed_pools_sees_full_topology` (`:379-391`),
  `test_stats_no_key_sees_full_topology` (`:395-402`).

### 7.2 `GET /v1/models` and `GET /v1beta/models`

`crates/busbar/src/endpoints.rs:151-267`; routes `main.rs:3833-3834`. Data listener, auth-gated,
governance-scoped with the **same rules as `/stats`** (`:148-150`).

**List contents:** pool names first (sorted), then direct model names (sorted), deduped — the names a
client may put in a request body (`:196-227`).

**Dialect selection by protocol fingerprint** (`:168-180`, `:229-266`), in order:
1. `anthropic-version` header present ⇒ Anthropic envelope:
   `{"data":[{"type":"model","id":…,"display_name":…,"created_at":"1970-01-01T00:00:00Z"},…],
   "has_more":false,"first_id":…,"last_id":…}`.
2. `/v1beta` path OR `x-goog-api-key` header ⇒ Gemini envelope:
   `{"models":[{"name":"models/<id>","displayName":<id>,
   "supportedGenerationMethods":["generateContent","streamGenerateContent"]},…]}`.
3. otherwise ⇒ OpenAI envelope:
   `{"object":"list","data":[{"id":…,"object":"model","created":0,"owned_by":"busbar"},…]}`.
   Cohere SDKs carry no reliable fingerprint and receive this shape (documented, `:176-177`).

### 7.4 Plane separation

`build_split_routers_with_limits` — `main.rs:3908-3942`.

- **Data plane** (`listen`): `/stats`, `/healthz`, `/metrics/hooks` (when metrics enabled), the
  auth-exchange path, `/v1/models`, `/v1beta/models`, `/{name}/v1/messages`,
  `/{provider}/{model}/v1/messages`, the `none`/`key`-auth plugin routes (including `/metrics`), then
  the protocol catch-all fallback (`base_data_router`, `main.rs:3801-3853`).
- **Admin plane** (`admin_listen`, default loopback `127.0.0.1:8081`): `/healthz` **plus** the admin
  API mount **plus** the `admin`-auth plugin routes. `/api/v1/admin/*` is **physically absent** from
  the data router — the data listener cannot serve it (`main.rs:3901-3904`, `:3926-3934`).
- Both planes share ONE `AppHandle`, so a config apply hot-swap reaches both (`:3916`).
- The inbound-concurrency cap applies to the **data plane only**; the admin plane is deliberately
  uncapped (`:3905-3906`, `:3925`). Worker-thread count (`MAX_WORKER_THREADS = 128`) is the informal
  upper bound some capacity arguments lean on as a result (`main.rs:739-747`).
- The exposed-admin-requires-mTLS boot guard runs in `config::resolve`, so by serve time
  `admin_listen` is loopback, mTLS, or carries an explicit `admin_require_mtls: false` waiver
  (`main.rs:898-903`).

## 9. UNVERIFIED

Items below are NOT parity requirements until resolved. Nothing here is a guess.

1. **`busbar_request_duration_seconds` bucket / quantile boundaries.** No `set_buckets` or
   `set_quantiles` call exists anywhere in `crates/busbar/src` (`recorder_builder` sets only
   `set_bucket_duration` + `set_bucket_count`, i.e. rolling *time* buckets, not `le` buckets —
   `metrics.rs:369-377`). Tests confirm the exposition renders `quantile=` lines
   (`crates/busbar/src/tests/telemetry_tests.rs:142-150`), i.e. it is exposed as a Prometheus
   **summary**. The concrete quantile values come from `metrics-exporter-prometheus`'s default and
   are not in this repo. **Resolve before the rebuild picks an exporter** — a dashboard that reads
   `quantile="0.99"` will break if 1.6.0 emits `le=` histogram buckets.

2. **Default `fmt` layer formatting details.** busbar sets only `.with_target(false)`
   (`observability.rs:443`). ANSI on/off, timestamp format, and thread id/name fields are
   `tracing-subscriber 0.3.23` defaults (declared with default features,
   `crates/busbar/Cargo.toml:148`) — inferred from the dependency declaration, not asserted in busbar
   code. The exact rendered log-line shape is therefore not pinned by this repo.

   not executed to confirm.
