## 2. Credential forms accepted on the DATA PLANE

### 2.1 Carriers and precedence

`AuthMiddleware::extract_client_token` — `crates/busbar/src/auth/mod.rs:593-616`. **Fixed precedence,
first non-empty wins:**

| # | Carrier | Form | Constant | Cite |
|---|---|---|---|---|
| 1 | `Authorization` | `Bearer <token>`, scheme match **case-insensitive**, split on the FIRST space, empty token ⇒ treated as absent | `AUTH_SCHEME_BEARER = "bearer"` | `auth/mod.rs:568-575`, `:601-608`, `:27` |
| 2 | `x-api-key` | raw token, no scheme prefix; **present-but-empty is treated as ABSENT** (`.filter(\|t\| !t.is_empty())`) | `X_API_KEY = "x-api-key"` | `auth/mod.rs:609-611`, `:21` |
| 3 | `x-goog-api-key` | raw token; same empty-filter | `X_GOOG_API_KEY = "x-goog-api-key"` | `auth/mod.rs:612-614`, `:22` |
| — | none of the above | `None` | | `auth/mod.rs:615` |

A non-Bearer `Authorization` (`AWS4-HMAC-SHA256`, `Basic`) **falls through** to the vendor carriers
and otherwise yields `None` here — `auth/mod.rs:586-590`.

**Per-dialect difference:** the extractor is dialect-agnostic — the value is validated identically and
in constant time regardless of which header carried it (`auth/mod.rs:580-583`). The only dialect-specific
credential form is Bedrock SigV4 (§2.5). The `x-api-key` carrier is the Anthropic SDK's; `x-goog-api-key`
is the Gemini SDK's — `auth/mod.rs:16-20`.

The extracted token is always threaded into request extensions as
`CallerToken(Option<String>)` for `upstream_credentials: passthrough` forwarding, inserted **before any
early return** so the `Extension<CallerToken>` extractor never 500s `MissingExtension`
— `auth/mod.rs:1264-1270`, type at `:62`. `CallerToken`'s `Debug` is hand-written and prints only
`"<present>"` / `"<absent>"` — never the value, never the length — `auth/mod.rs:69-79`.

| Path | Rule | Cite |
|---|---|---|
| `/healthz` (`HEALTHZ_PATH`) | exact match ⇒ auth bypassed entirely | `auth/mod.rs:29`, `:1217-1220` |
| `/auth/token` (`exchange::AUTH_TOKEN_PATH`) | **exact match only, never a prefix**; the handler runs the chain itself | `auth/exchange.rs:32`, `auth/mod.rs:1225-1228` |
| plugin HTTP route declaring `RouteAuth::None` | bypassed like `/healthz`; `RouteAuth::Admin` forces the admin chain; `RouteAuth::Key` flows normally | `auth/mod.rs:1235-1245` |
| `/metrics` | **NOT exempt** — goes through the same auth check as any other route (fingerprinting surface) | `auth/mod.rs:1207-1211` |

Admin classification: `path == "/api"` (`ADMIN_PATH`) **or** `path.starts_with("/api/")`
(`ADMIN_PATH_PREFIX`) **or** `plugin_admin` — `auth/mod.rs:32`, `:38`, `:1256`. The boundary-safe form is
deliberate: a bare `starts_with("/api")` would capture `/apix/v1/messages` — `auth/mod.rs:1250-1255`.

### 2.3 The chain and its verdicts

`ChainVerdict` — `auth/mod.rs:92-114`:

| Variant | Meaning |
|---|---|
| `Identified { module: String, principal: Principal, resolved: Option<Arc<VirtualKey>> }` | `module` is the **PROVIDER NAME** (the `identity-providers:` key), not the plugin's self-reported name — that is what `role_bindings.<name>` binds and `auth_scope_caps` keys off (`auth/mod.rs:97-101`). `resolved` is populated **only** by engine arms (`keys`, SigV4); a plugin can never construct a `VirtualKey` (`auth/mod.rs:104-110`) |
| `Open` | empty-chain anonymous admit |
| `Denied` | |

`run_chain_cached` — `auth/mod.rs:392-480`. Order = config order (`auth/mod.rs:382`, loop `:420`):

| Per-module outcome | Chain effect | Cite |
|---|---|---|
| `AuthOutcome::Identify(p)` | **first Identify wins** ⇒ `Identified { module: provider, principal: p, resolved: None }`; buffered `Pass` puts committed to cache here | `auth/mod.rs:440-463` |
| `AuthOutcome::Reject` | immediate `Denied`, chain STOPS | `auth/mod.rs:465` |
| `AuthOutcome::Pass` | continue | `auth/mod.rs:466` |
| all-`Pass`, `keys_in_chain` | run `keys_arm_verdict` | `auth/mod.rs:476-478` |
| all-`Pass`, no `keys` | `Denied` (fail-closed) | `auth/mod.rs:479` |
| `chain.is_empty() && !keys_in_chain` | `Open` — **the only fail-open path** | `auth/mod.rs:402-404`, `:509-511` |

There is **no per-module role filter**: the nested `role_bindings` table IS the allowlist — a role a
module asserts grants nothing unless `role_bindings.<module>.<role>` binds it — `auth/mod.rs:455-458`.

### 2.4 The `keys` engine arm — busbar-minted key format and principal mapping

`keys_arm_verdict` — `auth/mod.rs:642-661`.

| Condition | Verdict | Cite |
|---|---|---|
| no credential, or empty string | `Denied` | `auth/mod.rs:647-649` |
| no governance handle | `Denied` | `auth/mod.rs:650-652` |
| `gov.verify_token(token, now) == Some(key)` | `Identified { module: "keys", principal: principal_from_vkey(key), resolved: Some(key) }` | `auth/mod.rs:653-658` |
| unknown / expired / rotated / revoked / **disabled** | `Denied`; a disabled key is rejected HERE and never handed to the role-binding synth | `auth/mod.rs:636-641`, `:659` |

The arm is **CACHE-EXEMPT** — it never consults or writes the `CredentialCache`, because caching a
vkey verdict would widen the revocation window to the cache TTL — `auth/mod.rs:473-475`.

**Token format** (`crates/busbar/src/governance/signing.rs`):

| Element | Value | Cite |
|---|---|---|
| Token prefix | `TOKEN_PREFIX = "bbk_"` | `signing.rs:29` |
| Wire form | `bbk_<base64url_nopad(payload_json)>.<base64url_nopad(ed25519_sig_64B)>` | `signing.rs:148-154` |
| Claims | `sub: String` (the `vk_…` key id), `exp: u64` (Unix secs), `kid: String`, `g: Option<String>` (binding generation; `#[serde(rename = "g", skip_serializing_if = "Option::is_none")]`) | `signing.rs:38-56` |
| Default kid | `DEFAULT_KID = "k1"` | `signing.rs:34` |
| Key-id prefix | `VK_ID_PREFIX = "vk_"` | `governance/mod.rs:37` |
| Key-id hash prefix length | `VK_ID_HASH_PREFIX_LEN = 16` | `governance/mod.rs:40` |
| SigV4 secret prefix | `SK_SECRET_PREFIX = "sk-bb-"` | `governance/mod.rs:42` |
| Binding marker prefix | `BINDING_MARKER_PREFIX = "binding:"`; marker = `binding:<id>:<generation>` | `governance/mod.rs:49`, `signing.rs:47-53` |
| Self-key group prefix | `SELF_KEY_GROUP_PREFIX = "user:"` | `governance/mod.rs:56` |
| AWS access-key-id prefix | `AWS_ACCESS_KEY_PREFIX = "AKIA"` | `governance/mod.rs:91` |

**Verify order** (`TokenVerifier::verify`, `signing.rs:181-212`) — structural parse → `kid` lookup →
**signature** → expiry. Signature is checked BEFORE expiry so probing expiries on a forged token
cannot learn a real `sub` — `signing.rs:174-180`. `VerifyError` arms: `Malformed`, `UnknownKid`,
`BadSignature`, `Expired` — all collapse to one opaque 401 upstream (`signing.rs:58-61`).

**`GovState::verify_token`** — `governance/state.rs:95-137`:
1. `material.verifier.verify(token, now)`; on error `tracing::debug!(reason, "signed-token verify rejected")` ⇒ `None`.
2. `sync_revocations_if_stale(now)` then `if self.denylist.contains(&claims.sub)` ⇒ `debug!("signed-token rejected: subject is revoked")`, `None`.
3. `lookup_by_sub(&claims.sub)` (O(1) `by_id` index, `state.rs:142-144`):
   - `key.enabled && generation_matches(...)` ⇒ `Some(key)`
   - `key.enabled` but generation mismatch ⇒ `debug!("signed-token rejected: the binding was rotated after this token was minted")`, `None`
   - otherwise ⇒ `debug!("signed-token subject has no enabled binding")`, `None`

**Key → principal mapping** (`principal_from_vkey`, `auth/mod.rs:667-674`): `id = key.id`,
`name = Some(key.name)`, `roles = Vec::new()`, `ttl_secs = None`. A vkey is a **direct grant**, not a
group membership resolved through `role_bindings`.

### 2.5 Bedrock inbound SigV4 (dialect-specific credential)

Gated on **all three**: `app.auth.keys_in_chain` AND the ingress protocol's
`reader().uses_sigv4_ingress_auth()` AND an `Authorization` header starting with `SIGV4_ALGORITHM`
(`has_sigv4_authorization`, `auth/mod.rs:1573-1579`) — `auth/mod.rs:1438-1441`. An open `chain: []`
stays open even for a SigV4-shaped request — `auth/mod.rs:1433-1434`.

Structural gate BEFORE any body buffering: `parse_authorization_header` must succeed AND
`x-amz-content-sha256` AND `x-amz-date` must be present; else `unauthorized_response(&path)`
— `auth/mod.rs:1453-1463`. All three are attacker-satisfiable, so this is not an oracle
(`auth/mod.rs:1444-1452`).

Body buffered with the cap `crate::limits::translate_body_max_bytes()` (the same
`limits.request_body_max_bytes` knob), then the request is reconstructed from the same bytes
— `auth/mod.rs:1480-1486`. A buffering failure ⇒ the same opaque auth error.

`verify_bedrock_sigv4` — `auth/mod.rs:1624-1800`:

| Step | Behaviour | Cite |
|---|---|---|
| Signed-header prefilter | only headers named in `SignedHeaders` are collected, lowercased | `auth/mod.rs:1657-1673` |
| `payload_hash` | `x-amz-content-sha256`; absent ⇒ `Err(())` | `auth/mod.rs:1679-1686` |
| `UNSIGNED-PAYLOAD` | **explicitly refused** for governed ingress (`const UNSIGNED_PAYLOAD: &str = "UNSIGNED-PAYLOAD"`, `eq_ignore_ascii_case`) | `auth/mod.rs:1699-1705` |
| Body integrity | `sha256_hex(body)` constant-time-compared to `payload_hash.to_ascii_lowercase()` | `auth/mod.rs:1706-1712` |
| `x-amz-date` | absent ⇒ `Err(())` | `auth/mod.rs:1713-1720` |
| Canonical URI / QS | `uri_encode_path(path)`; `canonical_query_string` sorts raw already-encoded pairs, bare key ⇒ `foo=` | `auth/mod.rs:1598-1613`, `:1722-1723` |
| Credential lookup | `gov.lookup_credential("sigv4", &parsed.access_key_id)` | `auth/mod.rs:1741` |
| **Unknown AccessKeyId** | verification still runs against `DUMMY_SECRET = "AWS4-DUMMY-SECRET-FOR-CONSTANT-TIME-REJECT-PATH"` — no enumeration oracle | `auth/mod.rs:43`, `:1755` |
| Unrecognized credential envelope scheme | also falls back to `DUMMY_SECRET` | `auth/mod.rs:1745-1752` |

Admission matrix — `auth/mod.rs:1774-1799` (every failure is the same opaque `Err(())`; reasons are
`tracing::debug!` only):

| `(verify, resolved)` | Extra condition | Result / log |
|---|---|---|
| `(Ok, Some((key, true)))` | `key.enabled && !gov.is_revoked(&key.id)` | `Ok(key)` |
| `(Ok, Some((key, true)))` | `key.enabled`, subject revoked | `"inbound SigV4 rejected: subject is revoked"` |
| `(Ok, Some((_, true)))` | key disabled | `"inbound SigV4 rejected: virtual key disabled"` |
| `(Ok, Some((key, false)))` | credential not live (`CredentialMeta::is_live`) | `"inbound SigV4 rejected: this credential is revoked or expired"` |
| `(Ok, None)` | unknown AccessKeyId | `"inbound SigV4 rejected: unknown access key id"` |
| `(Err(e), _)` | | `"inbound SigV4 rejected"` with `reason = ?e` |

On success it yields the SAME `Identified { module: "keys", principal: principal_from_vkey, resolved: Some(key) }`
the bearer arm produces — `auth/mod.rs:1490-1495`.

### 2.6 The single data-plane gate (post-verdict)

`auth_middleware` — `auth/mod.rs:1521-1563`:

| Verdict | Effect | Cite |
|---|---|---|
| `Open` | insert `AuthPrincipal(None)` **and** `GovCtx::default()` (always, so no `MissingExtension` 500) | `auth/mod.rs:1525-1529` |
| `Denied` | `unauthorized_with_completion_taps(&app, &path)` | `auth/mod.rs:1530` |
| `Identified` | `gov_key = resolved.or_else(\|\| synthesize_principal_key(&principal, bindings))` where `bindings = app.role_bindings.get(&module)` | `auth/mod.rs:1541-1543` |

**The fail-closed re-key guard** — `auth/mod.rs:1556-1558`:
```rust
if gov_key.is_none() && !principal.roles.is_empty() && bindings.is_some() {
    return Err(unauthorized_with_completion_taps(&app, &path));
}
```
i.e. a role-carrying principal whose module HAS a `role_bindings` table but earned NO enforcement key
(unbound role, or explicit `allowed_pools: []`) is **denied**. With NO bindings table for the module,
a role principal is admitted **ungoverned** (`key: None`) — the pre-1.5.2 static/inert behaviour
(`auth/mod.rs:1544-1555`). A plain vkey (`resolved: Some`) or a roleless principal never trips it.

On admit: `AuthPrincipal(Some(principal))` + `GovCtx { key: gov_key }` — `auth/mod.rs:1559-1561`.

`AuthPrincipal(Option<Principal>)` — `auth/mod.rs:797-798`; `actor_id()` returns the principal id or
the literal `"anonymous"` — `auth/mod.rs:803-808`.

### 2.7 The anonymous / unkeyed path

Reached only when `auth.chain: []` **and** the `keys` arm is absent — `auth/mod.rs:402-404`.
It admits **every** request unconditionally with `AuthPrincipal(None)` and an EMPTY `GovCtx`
(no resolved key ⇒ no per-key `allowed_pools`, no budget, no RPM/TPM). Boot emits
`tracing::warn!("auth.chain is empty (open relay) - only acceptable for dev; reject in production")`
— `auth/mod.rs:338-342`. `AuthMiddleware::is_open()` reports it — `auth/mod.rs:374-376`.

Audit attribution for such a request is the literal `"anonymous"` — `auth/mod.rs:803-808`.

Interaction warning: `keys_in_chain` + `upstream_credentials: passthrough` emits a one-shot
`std::sync::Once` warning that keys supersedes passthrough — `auth/mod.rs:1417-1427`.

**The message is chosen PURELY from the inferred protocol and is deliberately independent of WHY auth
failed** (missing vs wrong token vs disabled vkey vs admin mismatch) — surfacing the distinction is
itself an oracle. Call sites pass no reason string; a busbar-internal reason ("virtual key",
"allowlist", "disabled", "passthrough") must never reach the wire — `auth/mod.rs:689-701`, `:745-751`.

Auth denials fire the synthetic `rejected_by_auth` response taps
(`unauthorized_with_completion_taps`, `auth/mod.rs:1166-1195`): projection
`outcome: Some("rejected_by_auth")`, `at: "response"`, `status` = the **protocol-native** status
(401/403/400 — hardcoding 401 made a gemini/bedrock tap contradict the client's response,
`auth/mod.rs:1160-1165`). No group binding is attached, so only unscoped taps fire
(`auth/mod.rs:1188-1191`). A fresh request id is stamped from the process-wide counter
(`auth/mod.rs:1170-1174`).

### 2.9 The credential cache (`crates/busbar/src/auth_cache.rs`)

| Rule | Value | Cite |
|---|---|---|
| Cache key | `(module_name, sha256_hex(credential_bytes))` — the credential itself is **NEVER stored** | `auth_cache.rs:49-50`, `:111-114`, `:146` |
| Key uses the **PROVIDER NAME**, not the plugin's self-reported name | two named providers on one module are different verifiers | `auth/mod.rs:425-428` |
| `DEFAULT_IDENTIFY_TTL_SECS` | `300` | `auth_cache.rs:26` |
| `MAX_IDENTIFY_TTL_SECS` (hard cap on a module-suggested TTL) | `3600` | `auth_cache.rs:29` |
| `PASS_TTL_SECS` (base) | `5` | `auth_cache.rs:32` |
| `Pass` jitter | `0..=2` s, deterministic: `u64::from(hash.as_bytes()[0] % 3)` (no clock, no RNG) | `auth_cache.rs:155-157` |
| `MAX_ENTRIES` | `4096` across all modules | `auth_cache.rs:34` |
| `Identify` TTL | `p.ttl_secs.unwrap_or(DEFAULT_IDENTIFY_TTL_SECS).min(MAX_IDENTIFY_TTL_SECS)` | `auth_cache.rs:148-153` |
| **`Reject` is NEVER cached** | `AuthOutcome::Reject => return` — an invalid credential re-runs the module every time | `auth_cache.rs:16`, `:159` |
| Eviction | at capacity: sweep expired (`retain(expires_at > now)`), then evict **oldest-inserted** by `inserted_seq` (bounded > perfect LRU) | `auth_cache.rs:170-182` |
| Expiry on read | an expired entry is REMOVED and reported as a miss | `auth_cache.rs:121-124` |
| A cache HIT is never re-`put` | doing so would refresh the TTL and extend the revocation window | `auth/mod.rs:410-411` |
| Only `cacheable()` modules participate | in-process modules report `false` and never touch the cache | `auth/mod.rs:422`, `api/src/auth.rs:69-71` |
| `Pass` puts are BUFFERED | committed only on the chain's `Identified` return, so unauthenticated traffic causes **no** admissions | `auth/mod.rs:406-412`, `:441-444` |

**Flush generation (invalidation on revoke)** — `CacheGeneration(u64)`, `auth_cache.rs:67-68`:
- `generation()` is captured **before** the first module is consulted — `auth/mod.rs:419`, `:862`.
- `put(..., gen)` drops the insert if `guard.flush_gen != gen.0` — `auth_cache.rs:162-166`.
- `flush_module(module) -> usize` bumps `flush_gen` **globally** (per-module partitioning would risk a
  missed revocation) and `retain(|(m,_),_| m != module)`; returns the count dropped — `auth_cache.rs:202-208`.
- `flush_all() -> usize` bumps `flush_gen`, `clear()`s, returns the count — `auth_cache.rs:214-220`.
- The generation check and the flush run under the SAME mutex, so they cannot interleave — `auth_cache.rs:70-79`, `:135-137`.

Admin endpoint: `POST /api/v1/admin/auth/cache/flush` — body `{"module": "<name>"}` flushes one
partition, empty/absent body flushes everything; responds `200 {"flushed": N}`; audits
`("auth.cache_flush", module_or_"*", OUTCOME_APPLIED, actor)`. Malformed body ⇒
`AdminError::Validation("body must be JSON with an optional string `module` (the auth module whose partition to flush)")`
— `admin/v1/json/handlers.rs:2194-2224`.

### 2.10 Off-reactor offload (data plane)

`AuthMiddleware::run_chain_on_request_path` — `auth/mod.rs:502-556`:

| Constant | Value | Cite |
|---|---|---|
| `AUTH_OFFLOAD_MAX_INFLIGHT` | `64` | `auth/mod.rs:155` |
| `AUTH_OFFLOAD_WAIT` | `Duration::from_secs(5)` | `auth/mod.rs:161` |
| `AUTH_OFFLOAD_PERMITS` | process-wide `LazyLock<tokio::sync::Semaphore>` | `auth/mod.rs:167-168` |

- `chain.is_empty() && !keys_in_chain` ⇒ `Open`, no offload — `auth/mod.rs:509-511`.
- `!has_plugin_module` ⇒ run **inline** (test stand-in and/or the keys arm are microsecond compares) — `auth/mod.rs:512-523`.
- Permit timeout / closed semaphore ⇒ `warn!("auth chain offload could not be started within {AUTH_OFFLOAD_WAIT:?} ({AUTH_OFFLOAD_MAX_INFLIGHT} already in flight); an auth plugin is not returning. Denying (fail-closed) rather than admitting unverified.")` then `Denied` — `auth/mod.rs:530-537`.
- Join error (plugin panicked) ⇒ `warn!("auth chain panicked; denying (fail-closed)")` then `Denied` — `auth/mod.rs:551-554`.
- The permit is released when the blocking work **finishes**, not when the awaiting future is dropped — `auth/mod.rs:542-545`.

### 2.11 Audience / scope checks on the data plane

There is **no audience (`aud`) claim** in the busbar token — `TokenClaims` carries only
`sub`/`exp`/`kid`/`g` (`signing.rs:38-56`). Data-plane "scope" is the resolved `VirtualKey`'s
`allowed_scopes` (pool refs), applied by governance, not by this subsystem. Admin scope is §6.

**The existence-only parent check — quoted verbatim** (`handlers.rs:1042-1050`):

enabled, non-leaf, or related to the caller's principal — any `full`-scope caller may root a new leaf

the literal `<root>`:
```

```

Base-config shadow guard (`handlers.rs:1054-1059`, `Cond::BaseDefined`) ⇒ 409:
`` group `{group}` is defined in the base config file; edit config.yaml (the API cannot silently shadow operator file config) ``

The provisioned leaf comes from `provision_child(&groups, parent)` — limits copied from the
nearest-ancestor `child_default` (empty when none up the chain), `parent: Some(parent)`,

### 3.8 REVOKE — `POST /api/v1/admin/keys/{id}/revoke`

`GovState::revoke(sub, reason)` — `governance/state.rs:150-215`. The ordering contract is stated at
`state.rs:151-168` (*"a failure partway leaves the STRONGER protection already in place"*):

1. `store.revoke_credential(&cred.id, reason)` for every non-revoked credential row (SigV4 today) — `state.rs:181-186`
2. `store.add_denylist(sub, reason)` — `state.rs:187`
3. bump `generation_hash` to a fresh generation — `state.rs:191-192`
4. `enabled = false`, `put_key` — `state.rs:193-194`

The whole function holds `refresh_lock` so a concurrent `refresh()` cannot revert the targeted cache
patch (`state.rs:169-179`). The cache patch is targeted, not a full refresh: `denylist.insert(sub)`,
`by_id.insert(sub, new_key)`, `by_credential.remove((kind, public_id))` — `state.rs:198-213`.
A revoke that did not durably persist propagates the error — never reports success (`state.rs:146-149`).

Reason strings: `"revoked via admin API"` (`admin/mod.rs:1691`); DELETE's revoke-then-delete uses
`"key deleted"` (`admin/mod.rs:1977`).

**Propagation timing:**

| Plane | Timing | Cite |
|---|---|---|
| Local node, signed token | **immediate** — `RevocationSync::insert` applies synchronously | `governance/revocation.rs:48-50` |
| Local node, `enabled=false` + new generation | immediate via the targeted `by_id` patch | `state.rs:204-209` |
| Local node, SigV4 credential | immediate — the `by_credential` entry is removed | `state.rs:210-212` |
| Peer nodes / out-of-band revokes | bounded by `REVOCATION_SYNC_TTL_SECS = 5` s, but honestly **~two windows (~10 s)**: the refresh is *scheduled* on the blocking pool, not performed inline, so the observing request is served against the previous set | `governance/mod.rs:302`; `revocation.rs:43-48`, `:76-82` |
| Sync bound | at most **one** outstanding refresh process-wide (`inflight: AtomicBool`) — a hung store costs exactly one pool thread | `revocation.rs:29-33`, `:72-75` |
| Staleness accounting | `attempted_at` (rate-limit anchor, advanced before the read) vs `synced_at` (advanced only on success), so a persistently failing store shows in `synced_age_secs` | `revocation.rs:34-40`, `:66-71` |

**Interaction with the auth cache:** the `keys` arm is **cache-exempt** (`auth/mod.rs:469-478`), so
`CredentialCache` / `POST /auth/cache/flush` are **irrelevant** to virtual-key revocation; that cache
serves external auth-module verdicts only (`auth_cache.rs:1-19`). Every request re-runs `verify_token`
(`auth/mod.rs:653`), so a revoke takes effect on the **next request** locally.
**In-flight requests are not aborted** — nothing in `revoke` cancels in-flight work.
The SigV4 admit path applies the identical denylist clause
(`key.enabled && !gov.is_revoked(&key.id)`) — `auth/mod.rs:1775`.

**Idempotency of revoke:**

| Layer | Behaviour | Cite |
|---|---|---|
| Endpoint doc | *"Idempotent - revoking an already-revoked key is 200."* | `admin/mod.rs:1651-1655` |
| `GovState::revoke` | idempotent; step 1 skips already-revoked credentials, steps 3–4 skip when `deleted_at.is_some()` | `state.rs:147`, `:182`, `:189-197` |

### 3.13 IDEMPOTENCY — the exact composite keys and TTL

```rust
/// The request header carrying a client-chosen idempotency token on the two replayable admin
/// mutations (key mint + key rotate).
const IDEMPOTENCY_KEY_HEADER: &str = "idempotency-key";
/// Replay window (seconds, ~10 min) for the idempotency cache; stale entries are swept on use.
const IDEMPOTENCY_TTL_SECS: u64 = 600;
```
— `admin/mod.rs:584-588`. **TTL = 600 s (10 minutes).** Only mint and rotate honour the header
(`admin/mod.rs:584-585`; `Conflict/IdempotencyInFlight` appears only for `POST /keys` and
`POST /keys/{id}/rotate` — `taxonomy.rs:509`, `:543`).

**MINT composite** — verbatim, `admin/mod.rs:729-736`:
```rust
    let idem_key = headers
        .get(IDEMPOTENCY_KEY_HEADER)
        .and_then(|v| v.to_str().ok())
        .filter(|v| !v.is_empty())
        .map(str::to_string);
    // The idempotency key is scoped to the PRINCIPAL: (actor, header). A different admin's identical
    // Idempotency-Key value must never replay this principal's response (which carries a secret).
    let idem_ckey: Option<(String, String)> = idem_key.as_ref().map(|k| (actor.clone(), k.clone()));
```
⇒ the 2-tuple **`(actor, header_value)`**. `actor = principal.actor_id().to_string()`
(`admin/mod.rs:717`) = `Principal.id` or the literal `"anonymous"` (`auth/mod.rs:800-809`).
**Nothing is concatenated and nothing is hashed** — a plain `HashMap` tuple key. The mint key carries
**no operation prefix**.

**ROTATE composite** — verbatim, `admin/mod.rs:1541-1545`:
```rust
    let idem_ckey: Option<(String, String)> = headers
        .get(IDEMPOTENCY_KEY_HEADER)
        .and_then(|v| v.to_str().ok())
        .filter(|v| !v.is_empty())
        .map(|k| (actor.clone(), format!("rotate:{id}:{k}")));
```
⇒ **`(actor, "rotate:" + id + ":" + header_value)`** — literal `rotate:`, the path `{id}`, `:`, then
the raw header value, in that order. Rationale (`admin/mod.rs:1538-1540`): *"scoped by operation + key
id so a create and a rotate sharing a header value can never replay each other's response."*

| Fact | Value | Cite |
|---|---|---|
| Storage | `Arc<Mutex<HashMap<(String,String),(u64, serde_json::Value)>>>` on `App`, Arc-shared across config swaps | `state.rs:360-369` |
| Sweep | `cache.retain(\|_, (t, _)\| now.saturating_sub(*t) < IDEMPOTENCY_TTL_SECS)` — prune-before-read on **every** use | `admin/mod.rs:743`, `:1552` |
| Empty header value | filtered out ⇒ treated as absent, no idempotency | `admin/mod.rs:732`, `:1544` |
| Reservation sentinel | `serde_json::Value::Null` inserted **under the same lock hold** as the "already cached?" check — closes the check+insert TOCTOU | `admin/mod.rs:762-767`, `:1566-1568` |
| Completed replay | mint replays verbatim with **201 CREATED**; rotate with **200 OK** — including the once-shown secret | `admin/mod.rs:745-748`, `:1554-1556` |
| In-flight collision | 409 `conflict` `"a request with this Idempotency-Key is already in flight"` | `admin/mod.rs:753-761`, `:1557-1565` |
| Reservation states | `IdemState::{Reserved, InFlight, Committed}` — a drop clears the sentinel **only** while `Reserved`; `InFlight` deliberately leaks the slot for the 10-min window rather than allow a double-mint on client disconnect | `admin/mod.rs:590-652` |
| Explicit `clear()` | on the transaction's own fail-closed outcomes (store error, cap rejection, not-found) where nothing committed | `admin/mod.rs:626-638`, `:1048-1050`, `:1063-1065`, `:1630-1647` |

| Bound | **unbounded map**, bounded only by the TTL sweep on use — explicitly acknowledged | `admin/mod.rs:587`; `admin/v1/service.rs:202-208` |

Shape asymmetry (functionally equivalent): rotate sets `IdemState::Committed` **inside**
`if let Some(ref ck) = idem_ckey` (`admin/mod.rs:1615-1624`), mint sets it unconditionally after the

## 4. Token exchange — `/auth/token`

Path constant: `AUTH_TOKEN_PATH = "/auth/token"` — `auth/exchange.rs:32`. Mounted on the **DATA
router only** (a test asserts it is absent from the admin router); the auth middleware bypasses it on
an **EXACT match, never a prefix** — `auth/mod.rs:1221-1228`.

### 4.1 `POST /auth/token` — the headless exchange (`auth/exchange.rs:35-91`)

**Request shape:** the body is **never read for identity**. Two routes:

1. **Credential-form completion**: if a `busbar_login` cookie is present, the body is read as
   `application/x-www-form-urlencoded` with a hard bound of `64 * 1024` bytes
   (`to_bytes(..., 64 * 1024).await.unwrap_or_default()`) and dispatched to
   `token::credential_submit` — `auth/exchange.rs:44-51`.
2. **Headless IdP-bearer exchange** (CI/BYOK, no login cookie): the candidate credential is taken from
   the SAME carriers as any data-plane token (`Authorization: Bearer` / `x-api-key` /
   `x-goog-api-key`) via `AuthMiddleware::extract_client_token`, and the handler runs the chain itself
   through `run_chain_on_request_path` — `auth/exchange.rs:53-61`.

*"Identity comes from the VERIFIED chain, never the body … so a caller can never self-scope a key to
another subject"* — `auth/exchange.rs:8-10`, `:52-53`; `auth/self_keys.rs:14-16`.

### 4.2 Which modules/roles grant the exchange — `resolve_exchange` (`auth/self_keys.rs:294-361`)

Input is the `ChainVerdict`; output is `(&Principal, team: String, allowed_pools: Option<Vec<String>>)`.

| Step | Rule | Cite |
|---|---|---|
| 1 | `ChainVerdict::Open \| Denied` ⇒ `ExchangeError::Unauthorized` | `self_keys.rs:358-359` |
| 2 | `Identified` with `resolved.is_some()` (a **static busbar key** was presented) ⇒ `ExchangeError::StaticKeyPresented` — token-exchange is for IdP identities minting THEIR OWN key, not re-wrapping an existing one | `self_keys.rs:305-308` |
| 3 | `role_bindings.get(module)` — bindings are **nested BY MODULE**; a role only grants under its identifying module. Absent table ⇒ `Unbound` | `self_keys.rs:309-310` |
| 4 | `granting` = **all** of the principal's roles that have a binding in that module (mirrors `synthesize_principal_key`'s scan, not just the first-matched role). Empty ⇒ `Unbound` | `self_keys.rs:311-322` |
| 5 | `team` = the **FIRST granting binding that carries a `group`** (scanning ALL granting bindings). None ⇒ `Unbound`. A self key MUST charge through a group — no unbounded self key | `self_keys.rs:323-329` |

### 4.4 Leaf-group derivation, provisioning and the one-key-per-sub invariant

**Leaf group** = `SELF_KEY_GROUP_PREFIX + principal.id` = `user:<sub>` — `governance/mod.rs:56`;
`self_keys.rs:107-113`.

`sanitize_self_sub` — `self_keys.rs:260-276`. An INTERNAL `:` is **allowed** (a module-namespaced sub
like `oidc:<sub>`, `github:<login>`, `ldap:<dn>` is legitimate and verified; the self group is always
`user:` + the WHOLE sub, so an internal `:` cannot escape the namespace, and the derived `vk_` id is
`HMAC(user:<sub>#epoch)` so it cannot alias another subject). **REFUSED (⇒ `BadSubject` ⇒ 403):**

| Refusal | Cite |
|---|---|
| empty sub | `self_keys.rs:263` |
| contains `/` (the route separator) | `:264` |
| any control character (`c.is_control()`) | `:265` |
| a **leading** reserved prefix: `vk_`, `user:`, `group:` | `:261-262` |

Log on refusal: `tracing::warn!(sub, "token-exchange: refusing a principal id unsafe as a self-serve subject (empty, a '/' route separator, a control char, or a leading reserved 'vk_'/'user:'/'group:' prefix)")` — `self_keys.rs:268-272`.

**`provision_child` / `child_default` inheritance** — `HandleProvisioner::ensure_leaf`,
`self_keys.rs:194-233`:
- routed through the ONE config-mutation choke point `admin::v1::json::config_transaction`, which takes
  `CONFIG_MUTATION_LOCK`, hands the body a **fresh post-lock snapshot**, and applies the plan as a
  single persist-then-swap — the same door the admin mint walks through, so a first-login provision and
  a concurrent admin `config/apply` cannot lose a swap to each other — `self_keys.rs:175-182`, `:197-201`
- **IDEMPOTENT no-op** when `current.cost.group_named(&leaf).is_some()` (the steady-state re-login path
  — no swap, no overlay churn, **no usage reset**) — `self_keys.rs:208-211`; contract at `:71-74`
- otherwise `plan_mint_group(current, &leaf, Some(&parent), &actor)` — the **same plan** the admin
  `POST /keys?parent=` auto-provision runs, so §3.3/§3.4 apply verbatim including the
  `max_auto_provisioned_groups` ceiling — `self_keys.rs:212-215`
- `plan_mint_group` returning `None` (a race with the `group_named` check) ⇒ nothing to commit — `:216-220`
- commit via `persist_provisioned_group(installed, leaf, actor)`, PERSIST-then-SWAP, fail-closed — `:221-228`
- errors map to the mint's `String` failure via `AdminError::message()` — `:230-231`
- `Err(msg)` **fails the mint closed** — a key with no resolvable budget group is worse than no key — `self_keys.rs:74`

Limits inheritance: `provision_child(groups, parent)` copies `resolve_child_default(groups, parent)`'s
`limits` (nearest-ancestor wins; empty when none up the chain), sets `parent: Some(parent)`, and leaves
`child_default` on the leaf unset — `config/groups.rs:499-511`.

This is the documented **1.5.2 bug fix**: before it, a self-serve exchange minted a key bound to
`user:<sub>` but never materialised that group, so the first request failed CLOSED with
`429 group '<user:sub>' is not configured` (`MissingGroup`) — `self_keys.rs:58-63`.

**`max_auto_provisioned_groups` counting**: the ceiling counts `current.groups_registry.len()` — the
**whole runtime group set**, not just auto-provisioned ones — and only auto-provisioning is gated;
explicitly configured groups are unaffected — `handlers.rs:1064-1076`. `0` = unlimited (default).

**The one-key-per-sub invariant** — `GovState::issue_self`, `governance/state.rs:502-561`:
- Serialized by `self_mint_lock` against a concurrent issue/refresh for the same sub — `state.rs:515-518`
- `current_self_binding(user_sub)` finds the single `k.enabled && k.deleted_at.is_none() && k.group == Some("user:<sub>")` row — *"At most one exists — the mint is an idempotent upsert and Refresh tombstones the prior row"* — `state.rs:383-393`
- **Existing binding, pools unchanged** ⇒ idempotent re-show: reuse the one binding, re-mint a fresh-`exp`
  token over the SAME id + generation. No new row, so the anti-sprawl cap can never trip — `state.rs:553-558`
- **Existing binding, `allowed_pools` CHANGED** ⇒ update **the existing row in place** with the fresh
  pools, keeping id + generation, and re-issue. It deliberately does **not** re-derive the id: `rotate_key`
  writes a random hex generation, so parsing an epoch back out fell to `unwrap_or(0)`, derived a
  DIFFERENT id, and wrote a SECOND enabled row — two valid self-serve tokens for one subject, breaking
  the at-most-one invariant — `state.rs:520-552`
- **No binding** ⇒ `write_self_binding(material, sub, pools, epoch=0, exp, now)` — `state.rs:560`
- No signing key ⇒ `StoreError("signed-token minting is unavailable: no signing key is configured")` — `state.rs:509-513`

**Deterministic id derivation** ("Model B") — `state.rs:353-379`:
```
subject id = vk_<hex( HMAC-SHA256(signing-key seed, "user:<sub>#<epoch>")[..16] )>
```
The HMAC is a **mint-time id SELECTOR, never a verification step**; the credential is still a standard
busbar signed token minted only by `TokenSigner::mint`, so `verify_token` is byte-for-byte unchanged
and a token whose signature segment is a literal HMAC is rejected `BadSignature` like any other forgery
— `state.rs:354-368`. The `epoch` is carried as the binding **generation**, so Refresh (epoch+1) rides
the existing `generation_matches` gate — `state.rs:366-367`, `:472-473`.

`first_free_self_epoch` — `state.rs:395-434`: skips **tombstoned** derived ids, stride **doubles**
(0, +1, +2, +4, +8, …), `MAX_PROBES: u32 = 64`. Doubling is load-bearing, not an optimization: a
one-at-a-time scan under a fixed cap means 64 refreshes plus one admin deletion permanently bricks the
subject's mint (`state.rs:404-421`). Exhaustion ⇒
`StoreError("self-serve binding: {MAX_PROBES} probes from epoch {from} all landed on tombstoned rows; refusing to reissue a deleted key id")` — `state.rs:430-433`.

`write_self_binding` — `state.rs:456-497`. The binding row: `id`,
`generation_hash = binding_marker(&id, &epoch.to_string())`, `name = format!("self-serve key ({user_sub})")`,
`allowed_scopes = allowed_pools.map(|list| list.into_iter().map(ScopeRef::pool).collect())`
("intent carried intact: `None` = all pools; `Some([])` = none"), `enabled: true`, `created_at: now`,
`group: Some("user:<sub>")`, `labels: {}`, `expires_at: None`, `deleted_at: None`, `revision: 0`.
Then `store.put_key(&binding)?`, `refresh()?`, `material.signer.mint(&id, exp, Some(&generation))`.
A tombstoned derived id is **skipped, never written over** — writing over it would silently undo an
admin's deletion and revive every token minted before it — `state.rs:459-480`.

**`refresh_self`** (the "Refresh key" action) — `state.rs:565-640`: same `self_mint_lock`; new epoch =
`binding_generation(existing.generation_hash).and_then(parse::<u64>).unwrap_or(0) + 1` (saturating), or
`0` with no live binding; write the new binding; then **tombstone the prior id** via
`store.delete_key(&old)`. On a tombstone failure it **ROLLS BACK** the just-written new binding so the
client keeps its working token and can retry:
`"self-serve refresh for '{user_sub}' failed to tombstone the prior binding '{old}' ({delete_err}); rolled back the newly-minted binding '{}' so the prior token remains the sole valid credential — retry the refresh"`.
If the rollback also fails: `tracing::error!(... "refresh_self: failed to tombstone the prior self-serve binding AND failed to roll back the newly-written one — subject may now have TWO live bindings; manual store inspection required")` and
`"self-serve refresh for '{user_sub}' left an INCONSISTENT store state: the prior binding '{old}' could not be tombstoned ({delete_err}) and the rollback of the new binding '{}' also failed ({rollback_err}) — both bindings may still be live; manual intervention required"` — `state.rs:601-635`.

Both `issue_self` and `refresh_self` are reached from the request path **only** via
`governance::mint_self_offloaded` (they hold a `std::sync::Mutex` across synchronous store I/O and must
never run on the reactor) — `self_keys.rs:126-138`, `:154-165`.

**TTL:** `ttl = Duration::from_secs(app.self_key_ttl_secs)`; `exp = now.saturating_add(ttl.as_secs())`
— `auth/exchange.rs:73`; `self_keys.rs:119-120`, `:148-149`.
`self_key_ttl_secs` is resolved from `auth.key_ttl` at snapshot build:
`cfg.auth.key_ttl.map(|s| parse_duration_secs(s).unwrap_or(DEFAULT_KEY_TTL_SECS)).unwrap_or(DEFAULT_KEY_TTL_SECS)`
— `main.rs:3716-3723`; field `state.rs:478-479`; default 90d (`admin/mod.rs:119`).

   - `LoginOutcome::Reject` ⇒ **401** `"Sign-in was declined"` / `"Your identity provider declined this sign-in. Check with your Busbar admin if this keeps happening."`

5. Loop exhausted with no principal ⇒ **502** `"Sign-in didn't finish"` / `"This sign-in didn't complete. Please head back and try again."`
6. `clear_and(issue_and_render(...))` — the cookie is cleared on **every** callback exit (`token.rs:775-781`)

**`issue_and_render`** — the SHARED identify→admit→mint→render tail used by BOTH the redirect callback
and the credential POST — `token.rs:578-630`. It builds
`ChainVerdict::Identified { module: method_name, principal, resolved: None }`, runs the SAME
`resolve_exchange`, and mints via the SAME `issue_key` seam (no second mint path):

| Failure | Status | Page |
|---|---|---|
| `resolve_exchange` `Err(_)` (any variant collapses to one page) | **403** | `"No access yet"` / `"Your account isn't granted a self-serve key yet. Ask your Busbar admin to assign you a role."` |
| governance absent | **502** | `"Key issuing unavailable"` / `"Busbar can't issue keys right now. Please contact your Busbar admin."` |
| `issue_key` `Err(_)` | **502** | `"Couldn't issue your key"` / `"We couldn't issue your key this time. Please head back and try again in a moment."` |
| success | 200 | `render_key_issued(principal.id, group, secret, base_url, module_name)`, `Cache-Control: no-store` |

**`credential_submit`** (POST with a login cookie) — `token.rs:637-719`:
undecodable cookie ⇒ 400; `__state` mismatch (constant-time) ⇒ `security_check_failed()`;
method gone ⇒ 400; **`m.login_kind != LoginKind::Credential` ⇒ 400** `"Sign-in unavailable"` /
`"This sign-in method can't be completed here. Please head back and start again."` (a redirect method
never completes via the form POST); every field EXCEPT `__state` is wrapped in
`busbar_api::Redacted<String>` the moment it is held; `Identify` ⇒ `issue_and_render`;
`Reject` ⇒ **401** `"Sign-in was declined"` / `"Those credentials weren't accepted. Please check them and try again."`;
anything else ⇒ **502** `"Sign-in didn't finish"`.

**`execute_hop`** — `token.rs:915-959`. The module DESCRIBES the hop; the **CORE executes it** and
injects the `client_secret` VALUE into the field the module named in `secret_form_field` (the module
only ever writes the KEY). Order:
1. `vet_hop_url(&hop.url, allowed)?` — **BEFORE the request is built**, so no secret leaves the process on a refusal (`token.rs:921-922`, `:867-888`): the host must be in the operator-derived allowlist (PRIMARY control); the scheme must be `https` for a public host (`http` tolerated only for loopback/private); a cloud-metadata/IMDS/link-local target is refused outright via `ssrf_blocked_host`
2. Secret injection: overwrite the plugin's placeholder value at `secret_form_field`, or push the pair if absent. **With NO secret configured the placeholder is DROPPED, not sent empty** — an empty `client_secret=` is not the same as an absent one; an IdP may read it as a WRONG secret and answer `invalid_client` rather than "public client" (`token.rs:925-946`)
3. `reqwest::Method::from_bytes(hop.method).unwrap_or(Method::POST)`
4. Each module header goes through `sanitize_hop_header`: CR/LF/NUL in name or value ⇒ refuse; `FORBIDDEN_HOP_HEADERS` ⇒ refuse; invalid `HeaderName`/`HeaderValue` ⇒ refuse. **Any invalid/forbidden header fails the WHOLE hop closed** (`token.rs:893-907`, `:950-953`)
5. Returns `(status: u16, body: String)`

Hop client — `hop_client()`, `token.rs:792-801`: ONE pooled `reqwest::Client` (connection pooling, not a
fresh client per callback), `.timeout(Duration::from_secs(10))`, and **redirects DISABLED**
(`Policy::none()`) — an auto-followed 3xx could bounce the core-injected secret/bearer to an
off-allowlist host.

Host allowlist — `collect_allowed_hosts(settings, issuer)`, `token.rs:830-860`: the `issuer` plus the
host of **any absolute `http(s)` URL anywhere in the method's opaque settings tree** (`api_base`,
`token_base`, `authorize_base`, …), recursively walked, lowercased. **NEVER derived from plugin output.**
Empty ⇒ no hop is permitted (fail closed) — `token.rs:81-87`.

### 6.3 The admin principal and scopes

`Scope` — the FROZEN authorization contract, `admin/v1/contract/mod.rs:72-101`:

| Variant | Wire token | Meaning |
|---|---|---|
| `ReadOnly` | `"read-only"` | every read (`GET`) across config, keys, hooks, versions, audit, usage, info — plus the two stateless dry-run POSTs |
| `Full` | `"full"` | everything: keys, config apply/rollback, auth chains, group_map, cache — every mutation |

`Scope::parse(token)` returns `Some` only for those two strings; the retired `hooks-register`/`mint`
tokens now parse to `None` (migrate maps them to `full`) — `contract/mod.rs:91-101`.
`allows`: `ReadOnly` satisfied by anything, `Full` only by `Full` — `contract/mod.rs:131-138`.
`Grants(u8)` is a bitset: `of(s)`, `with(s)` = UNION (not `max` — a principal holding two roles bound
to incomparable scopes keeps both), `capped_by(cap)` = pointwise `meet` (not `min`)
— `contract/mod.rs:183-207`.

`required_scope(method, path)` — the AUTHORIZATION MATRIX, derived from METHOD + PATH, **never from
the body** (a crafted request cannot escalate) — `contract/mod.rs:231-247`:
- `GET` or `HEAD` ⇒ `ReadOnly`
- `rel == PATH_CONFIG_VALIDATE || rel == PATH_PLUGINS_INSPECT` ⇒ `ReadOnly` (stateless dry-runs — reads in POST clothing, so a read-only CI token can lint configs)
- **everything else ⇒ `Full`**; a path outside `ADMIN_PREFIX` fails closed to `Full`

`admin_scope_for(module, principal, role_bindings)` — `auth/mod.rs:1062-1102`:

| Case | Result | Cite |
|---|---|---|
| `principal == None` (the explicit `admin_auth: []` OPEN posture) | `Grants::of(Scope::Full)` — dev-only | `auth/mod.rs:1068-1070` |
| roleless principal, `module == ADMIN_TOKENS_MODULE` **and** `p.id == ADMIN_TOKENS_PRINCIPAL_ID` | `Grants::of(Scope::Full)` | `auth/mod.rs:1085-1090` |
| roleless principal otherwise (incl. an **external** module returning the reserved id `"admin"`) | `Grants::default()` (empty) | `auth/mod.rs:1080-1091` |
| role-carrying principal, no `role_bindings.<module>` table | `Grants::default()` | `auth/mod.rs:1093-1095` |
| role-carrying principal with a table | UNION of `admin_scope` over the principal's bound roles: `p.roles.iter().filter_map(\|r\| table.get(r)).filter_map(\|b\| b.admin_scope.as_deref()).filter_map(Scope::parse).fold(Grants::default(), Grants::with)` | `auth/mod.rs:1096-1101` |

Full-by-reserved-id is gated on the identifying **MODULE** being built-in `admin-tokens`, **not merely
on the id string** — an external admin module returning a roleless principal carrying `"admin"` falls to
`Grants::default()`. The id is additionally reserved by `config_validate` (`reserved_admin_name`, §4.3)
— `auth/mod.rs:1071-1091`.

`module_admin_scope_cap(app, module)` — `auth/mod.rs:1011-1026`: `admin-tokens` is **exempt**
(`None`, full by definition — the root credential); every other module is capped at
`app.auth_scope_caps.get(module)` parsed as a `Scope`, **DEFAULT `Scope::ReadOnly`**. `full` through an
external chain is an explicit opt-in and is boot-warned in `config_validate`
(`config_validate/mod.rs:1160-1169`).

The middleware's admin branch — `auth/mod.rs:1279-1404`:
1. run the admin chain (offloaded if any module is a plugin)
2. `Denied` ⇒ `admin_unauthorized_response()` (see §6.5)
3. `scope = admin_scope_for(...)`, then `scope.capped_by(cap)` if a cap applies
4. `required = required_scope(req.method(), &path)`; `!scope.allows(required)` ⇒ `forbidden_response(required)` — **an identified principal with no grant is 403, never 401**
5. mutation rate limits (see §6.6)
6. insert `AuthPrincipal(principal)` and an **EMPTY `GovCtx::default()`**, then return

**INTENTIONAL governance bypass for the admin plane** — `auth/mod.rs:1390-1404`: a successful admin auth
attaches an empty `GovCtx` (no resolved virtual key) and returns BEFORE the virtual-key governance
resolution, so per-key controls (`allowed_pools`, budget, RPM/TPM) are deliberately NOT applied to admin
requests. Stated rationale: the admin token is an operator-only credential, `/admin` exposes only
key-management (never inference), and holding it already confers full authority over every key.

### 6.4 `dry_run_admin_scope` — the lock-out guard


| `admin_listen` loopback? | `admin_tls.client_ca` set? | `admin_require_mtls` | Outcome |
|---|---|---|---|
| yes | any | any | boots |
| no | yes | any | boots |
| no | no | `false` | boots (explicit waiver) |
| no | no | `true` (default) | **refuses to boot** |

**Fails CLOSED** — an unparseable hostname ⇒ `false` (treated as exposed). This is the **only** loopback

### 7.4 Resolution — order, precedence, timing, caching

`SecretResolver { plugin: Option<PluginResolveFn> }` — `config/secret.rs:49-54`;
`type PluginResolveFn = Box<dyn Fn(&str, &str) -> Result<Vec<u8>, String> + Send + Sync>` (`:59`);
constructors `builtins_only()` (`:65-67`), `with_plugin(f)` (`:71-75`).

**Dispatch order** (`resolve`, `:79-109`) — a strict two-way match, **no fallback chain**:
1. `module == "env" | "file"` ⇒ `resolve_builtin` **inline, short-circuiting the plugin** (`:81`, pinned `:539-543`)
2. any other module ⇒ the plugin closure, `settings` serialized as a JSON object string (`:84-85`)
3. plugin closure `None` ⇒ hard error

**Precedence:** built-ins are unconditionally first — a `kind: secret` plugin **cannot** shadow
`env`/`file` (`:81`).

`resolve_builtin` (`:254-282`): `env` ⇒ `std::env::var(&var)`, non-empty ⇒ `Ok(v.into_bytes())`;
`file` ⇒ `std::fs::read(&path)`, non-empty ⇒ `Ok(bytes)`.
`resolve_string` / `resolve_builtin_string` (`:113-130`, `:317-333`): decode UTF-8, then
`trim_end_matches(['\r','\n'])`; empty after trim = error. **This trailing-newline trim is the only
normalization applied.**

### 8.5 mTLS

- `client_ca: Some(_)` ⇒ `WebPkiClientVerifier` installed ⇒ **the client MUST present a certificate chaining to that CA or the handshake fails** — `tls.rs:202-204`, `:217-229`
- `client_ca: None` ⇒ `with_no_client_auth()` (server-only TLS) — `tls.rs:204`, `:230`
- **There is NO "optional client cert" mode.** `WebPkiClientVerifier::builder(...).build()` is used without `.allow_unauthenticated()` — the only two states are required-or-none — `tls.rs:220-222`
- **The client certificate is NEVER mapped to a principal, subject CN, SAN, or fingerprint.** `serve_one` obtains the `TlsStream` and hands it straight to hyper (`tls.rs:643-660`); nothing reads `peer_certificates` or any cert field anywhere in the crate. mTLS in 1.5.5 is a **binary handshake gate only**; authorization still flows entirely through the auth chain / admin token
- **There is no HTTP status for an mTLS rejection** — the connection dies during handshake, before any HTTP layer exists

Proven end-to-end: no client cert ⇒ rejected; cert from a different CA ⇒ rejected; the server survives
both and still serves a valid client — `tls.rs:890-951`.
