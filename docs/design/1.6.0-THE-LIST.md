# THE LIST — 1.6.0

**The single certified TODO list.** Every other `1.6.0-*.md` sweep is INPUT to this file. One row
per defect, deduplicated across sweeps, ranked by consequence.

**This file has ONE writer.** No other agent appends to it. Its companion is
[`1.6.0-DELETE-LIST.md`](1.6.0-DELETE-LIST.md) — what was swept, proven clean, and can go away.
The loop is **fix → delete → repeat** until only `dev` remains and it is green.

## HOW TO READ A ROW

| column | meaning |
|---|---|
| **ID** | `X-nnn`. Allocated here and nowhere else. **Never reused, never renumbered.** |
| **TITLE** | the defect, in one line. Not the file. |
| **CLASS** | money · auth/capability · missing-code · instrument-blind · config · abi · customer-surface · doc-drift |
| **CERTAINTY** | VERIFIED / ADJUDICATE / PARK — below |
| **EVIDENCE** | file:line + the command that reproduces it. `[proven here]` = I ran it. `[carried]` = the source ran it and I did not re-run. |
| **ACTION** | what to do, or the one sentence question that unblocks it |
| **SOURCE** | which sweep found it |

### CERTAINTY — the column that makes this list certifiable

- **VERIFIED** — proven with a runnable command or a red-before-green demonstration. An agent can
  pick this up and act on it today.
- **ADJUDICATE** — a symbol or behaviour is absent **by name**, the concept plainly exists on trunk,
  and nobody has read the behaviour. **This is a question, not work.** A sweep proved why this
  matters: `SessionDriver`/`DuplexWire` read as absent while `SessionPump`/`SessionLease`/
  `SessionView`/`DuplexReader` carried the same seam, and a test absent by name turned out proven on
  trunk **under a different name with a stronger guard**. Lumping renames in with real gaps poisons
  the list.
- **PARK** — needs an owner ruling. **Every money row is PARK, always.** Money is binary,
  bank-auditor standard, and a billed byte is never self-approved (#10/#59). Because PARK is
  mandatory on money it carries no evidential information, so every money row states its evidential
  grade inside EVIDENCE instead: `[proven here]`, `[carried]`, or `[asserted]`.

**CERTAINTY IS NEVER PROMOTED.** If a source says ADJUDICATE, the row says ADJUDICATE. It may be
DEMOTED with a reason. Promotion to VERIFIED requires a proof run here and printable.

### ID ALLOCATION

`X-1` … `X-180` were allocated before this file existed and live in
[`1.6.0-MAP.md`](1.6.0-MAP.md) §3.1. **They are carried here under their original numbers and are
never renumbered.** New rows are allocated from **`X-201`**. `X-181`…`X-200` is a deliberate
unused buffer: concurrent agents were still drawing in the 180s when this file opened, and three
X-numbers were already issued twice by agents sharing a number space. Numbering is a single-writer
job; the buffer is what makes that recoverable rather than an argument.

Rows that arrived carrying a LEDGER id (`M`/`R`/`G`/`S`/`T`/`ENG`/`DOC`/`DR`/`IA`/`GS`/`BR`) keep
that id in SOURCE and are cross-referenced, not renumbered.
