# busbar 1.6.0 — THE ENGINE SPLIT PLAN: `busbar-mcp` and `busbar-a2a` split three ways and die

Status: **PLAN**, 2026-09-22. This document is the work order for #19/#20/#21/#39/#40 as they apply
to the two fat engine crates. **It moves nothing.** Every number in it is measured; every placement
cites a definition; a later pass executes it.

Owner of the row: `BUSBAR-1.6.0.md` #20(c) and the GOVERNING DESIGN restatement of 2026-09-22.

---

## 0. THE RULING THIS PLAN EXISTS BECAUSE OF

A prior agent reported the drain as **UNLANDABLE**: `kind-isolation`'s `ARCHITECTURE_ALLOWED`
(`xtask/src/gates/kind_isolation.rs:527`) grants exactly one class that may name a plane —
`("root","plane")` — and there is no `("kernel","plane")`, so a `busbar-mcp`/`busbar-a2a` drain
into `busbar-kernel` cannot land.

**The premise was wrong, and the wall was right.**

#20(c) sends "the engine-proper" to the kernel and ENUMERATES it — App, state, session, secret,
plane-registry, cost, governance. **Not one of those names a protocol.** The fat engine crates do
not DRAIN into the kernel. They **SPLIT THREE WAYS AND DIE**:

| bucket | destination | #20 clause |
|---|---|---|
| protocol logic — dialects, codecs, wire constants, dispatch | the ONE `busbar-plane-<x>` crate | #20(a) / #21 / #39 |
| socket / pool / TLS / transport I/O | the transport plugin | #20(b) / #7 / #40 |
| generic loop / state / governance machinery, naming no protocol | `busbar-kernel` (+ the kernel-8) | #20(c) |

**There is no `("kernel","plane")` edge because nothing protocol-shaped may cross into core** —
Law 1, verbatim: *"Core speaks plugin ABIs only, and has ZERO instance logic… No plugin-instance
name ever appears in core logic."* The missing class is not a gap in the config. It is the config
correctly refusing an illegal move. **Anyone who hits that wall has put protocol logic on the kernel
side of the cut**, and the fix is the classification, never the gate.

### 0.1 The corollary the gate will enforce for you

`kind-isolation:matrix` counts, per crate, how many times it names each kind's vocabulary.
`busbar-kernel × plane` measures **1** today (`qa/kind-isolation.toml:1217-1219`). So:

> **A kernel-destined move that raises `busbar-kernel`'s `plane` cell is a misclassification.**
> The matrix is the oracle for this cut, and it is exact in both directions.

That is the whole safety net, and it is mechanical. Nobody has to argue.

## 1. THE TEST — four questions, asked in this order, first hit wins

Derived from the roster definitions (#83), not invented here. **The plane question is LAST, not
first** — asking it first is precisely the trap ("it lives in `busbar-a2a`, so it is A2A, so it is
plane").

| # | question | if yes | definition |
|---|---|---|---|
| **T1** | Does it **PRICE, ADMIT or DIAL**? | `busbar-kernel-{ledger,budget,egress,breaker}` | defs 5–8; #43; #71; defs 16–20's own last sentence: *"Nothing that prices, admits or dials."* |
| **T2** | Does it **open / pool / secure / move bytes on a carrier**, while naming no protocol? | `busbar-transport-<carrier>` | defs 21–27: *"One carrier's framing and connection lifecycle, driven blind. Moves bytes; names no plane, protocol or policy."* |
| **T3** | Could a **SECOND protocol** name this without absurdity? | `busbar-kernel` — it is generic machinery | def 2: *"The dispatch loop and the seams every step plugs into"* |
| **T4** | Residual — it is a fact about **THIS wire and no other** | `busbar-plane-<x>` | defs 16–20: *"Everything ONE protocol needs and no other protocol may name"* |

**T1 outranks T4 absolutely.** An admission decision expressed in a protocol's vocabulary is still an
admission. That single ordering rule disposes of `a2a/meter.rs`, `mcp/sampling.rs::SamplingSpend`
and `a2a/pushback.rs::PushLimiter` (§5).

**T2 outranks T4 too**, and in this tree it almost never fires — see §5.2, which is the plan's most
surprising measured result.

### 1.1 The hard constraint T4 carries

Measured 2026-09-22, both plane crates:

```
$ cargo tree -p busbar-plane-mcp --edges normal | grep busbar
busbar-plane-mcp v1.6.0   └── busbar-contract v1.6.0
$ cargo tree -p busbar-plane-a2a --edges normal | grep busbar
busbar-plane-a2a v1.6.0   └── busbar-contract v1.6.0
```

`busbar-plane-a2a` declares `busbar-contract` + `serde` + `serde_json`. `busbar-plane-mcp` adds
`bytes`. **That closure is #40(a)'s dep-wall and it does not widen.** Anything routed to T4 must
compile against it. Concretely, code that names `busbar_kernel::`, `busbar_api::`,
`busbar_plugin::`, `busbar_substrate_values::`, `axum`, `tokio`, `reqwest`, `tonic`, `rmcp` or
`std::{net,fs,process,env,os}` **is not plane-bound as written** — it is either kernel-bound, or it
is a SPLIT whose plane half is the part that names none of them.

`qa/construction.toml` `[rules.source-denylist]` bans
`std::{net,fs,process,os,env}`, `tokio::{net,fs,process}`, `async_std`, `libc`, `reqwest`, `hyper`
transitively in every plane crate. The only reviewed hole is the tree-wide edge exemption
`(dep = libc, via = cpufeatures)`, which is why `sha2` may move plane-side (§7.4).

## 2. THE METHOD — the worked examples, and what they establish

Two commits already cut this exact line for the codec halves. **Read them before moving anything.**

* **`5fbd891e0`** — `busbar-mcp-codec` dissolves. Dialect → `busbar-plane-mcp`; registry row +
  cells → `crates/busbar-mcp/src/codec/`; durable row STRUCTS stay engine-side.
* **`0e41eeb9e`** — `busbar-a2a-codec` dissolves, same line. Plus the meter finding (§5.1).

They establish five rules this plan inherits verbatim:

1. **Cut by DEFINITION, not wholesale.** A crate holding two definitions SPLITS (#83 step 5); the
   split is at ITEM granularity when the file is mixed.
2. **The record KIND STRING and the record STRUCT part company.** The kind string is the name the
   PLANE declares its schema under → plane. The struct names `busbar_api::PlaneRecord` →
   engine/kernel. `kind-isolation` refuses a new `plane -> api` edge outright and **no
   `[[transitional]]` row can cover one, because its `from` must be a LEGACY crate.**
3. **`legacy -> plane` is permitted by `[[transitional]]` and by nothing else.** A `[[dep]]` row
   RECORDS an edge; it never INTRODUCES one.
4. **#19 is measured in BOTH directions** — file count and test count, before and after, with every
   delta explained. `git show --stat -M -C` must show renames, not add+delete pairs.
5. **A rule the move trips is not waived; the code moves to where the rule does not apply.** The
   plane purity oracle forbids a clock in `src/`, so two timing guards went to `tests/` rather than
   earning an exemption.

## 6. THE ORDER

Rules that hold for every step below:

* **Move first, repoint second, two commits.** #19 requires byte-identical moves; a move that also
  edits is unprovable. `git show --stat -M -C` on the move commit must be all `R`, zero add+delete.

  SAME commit. The matrix ratchet is exact in both directions: a count BELOW its row is red too.

### 7.2 `[[dep]]` rows that APPEAR

**Ideally: none.** Every plane-bound item is going to a crate whose closure is already
`busbar-contract`, so no new `[[dep]]` row is owed. Every kernel-bound item is going to `busbar-kernel`
or a `busbar-kernel-*` crate, and `("kernel","kernel")` and `("kernel","contract")` are already in
`ARCHITECTURE_ALLOWED`.

Two exceptions, and both are real:

1. **`busbar-transport-stdio` may need new non-busbar deps** (`tokio/process`). That is a manifest
   change, not a kind edge — but `[rules.source-denylist]` scans `kinds = ["plane","hook","auth"]`
   and **transport is deliberately NOT scanned**, so `tokio::process` is legal there. Confirm before
   B4.
2. **`legacy -> transport`** if B4 is split across commits (§6.2). Avoidable, and the reason B4 is
   atomic.

### 7.3 Does any move need a `[[transitional]]` row?

**No new one, and this is the load-bearing answer.**

`[[transitional]]`'s `from` **must be a LEGACY crate** — `xtask/src/gates/kind_isolation.rs:1054`
refuses any other source **at load**, with the message *"This table exempts the DRAIN and nothing
else; a non-legacy source reaching a unit or a plane through it is the fusion wearing the drain's
coat."* The legacy set is exact-matched: `=busbar-llm`, `=busbar-mcp`, `=busbar-a2a`, `=busbar-voice`
(`:373`). That is how `busbar-mcp -> busbar-plane-mcp` landed and why a `plane -> api` edge could
NOT be covered by one at `0e41eeb9e`.

The two rows this plan needs **already exist** (`qa/kind-isolation.toml:50` and `:60`), and they
cover every `legacy -> plane` edge each engine will grow as its dialect drains out. They are struck
at Wave F, when their `from` crate is deleted — which is also their designed expiry:
`kind-isolation-ship` is RED for any `[[transitional]]` row whose `from` crate still exists at the
tag.

**The one row a careless implementer will reach for and must not:** there is no
`("kernel","plane")` class and no row that creates one. If a move appears to need it, the move is
misclassified. Re-run T1→T4.

### 7.4 The `libc`/`cpufeatures` edge, and why `card.rs` may still move

`a2a/card.rs` needs `sha2` plane-side. `sha2` 0.10.9 hard-depends on `cpufeatures` for every target
busbar ships, and `cpufeatures` reaches `libc` — which `[rules.source-denylist].patterns` bans in
every plane crate.

**This is already ruled and the ruling composes.** `qa/construction.toml`'s
`[[rules.source-denylist.edge_exemptions]]` states `(dep = libc, via = cpufeatures)` **once**, for
the pure kinds, carrying `symbols = ["getauxval", "sysctlbyname"]` — the enumerated surface. The
ruling's own scope note says it exempts **that path only**; a crate reaching `libc` by any other
route is still a hit.

Two consequences an implementer must know:

* `busbar-plane-a2a`'s and `busbar-plane-mcp`'s old per-crate waivers were **deleted as stale**
  (both crates reach `libc` by no route at all today). A1/A2 will re-create the `cpufeatures` path.
  **Do not re-add a per-crate waiver** — the edge exemption already covers it, and a seventh copy of
  a tree-wide rule is the exact defect that ruling was written to kill.
* `getrandom -> libc` is a **different edge and is NOT ruled on.** `busbar-plane-llm` and
  `busbar-plane-streaming` keep per-crate `via = "getrandom"` waivers for it. If a move drags
  `getrandom` into `busbar-plane-{a2a,mcp}`, that is a NEW question for the owner, not a waiver to
  copy.

## 9. SETTLED: `Admission` + `admit()` IS DEAD CODE

**Asked:** is the a2a fold's reported second admission implementation dead code to delete, or a live
path? **Answer: DEAD. Four independent pieces of evidence, none of them an inference.**

**1. The compiler is being silenced, module-wide.** `crates/busbar-a2a/src/a2a/meter.rs:35`:

```rust
#![cfg_attr(not(test), allow(dead_code))]
```

A module-scope `allow(dead_code)` gated on `not(test)` is a statement that in a non-test build the
compiler WOULD flag items here. Nothing else explains the attribute.

**2. Grep over `crates/**`: zero callers outside its own battery.** Every reference to `Admission`,
`Admission::`, or `meter::admit` in the whole tree is either inside `meter.rs` itself or inside
`crates/busbar-a2a/src/a2a/tests/meter_tests.rs`. The `admit(` hits elsewhere are different
functions — `receive.rs::admit` (the catalogue/authorise pair), `registry.rs::admit`
(`CatalogueItem`), `pushback.rs::PushLimiter::admit`, `route.rs`'s `engine_host.breaker_admit`. None
of them is this one.

**3. The file says so, in the same breath as the attribute** (`meter.rs:31-34`):

> *"`Attribution::delegating`, `Direction::Delegating` and `Admission` are the delegating direction's
> half: nothing delegates outward yet, and **`Admission` is this plane's own window arithmetic, which
> the ingress does not use because it meters through the shared governance ledger rather than a
> second one.**"*

**4. The live path is measured and is elsewhere.** The A2A receiving hot path meters through
`meter_request()` at `receive.rs:721`, which builds a `busbar_plugin::hot::Usage::with_attribution`
and calls `engine_host.meter_charge(cap_scope, &usage)`. Over-limit is decided in
`busbar-kernel-budget/src/decide.rs` and rendered `429` + `Retry-After` from
`Blocked::Limit { retry_after: window_end(…).saturating_sub(now).max(1) }`. **There is a complete,
live, shared implementation of exactly this ruling, and `meter::admit` is not on its path.**

### 9.1 The correction to the a2a fold's report, and it matters

The fold reported "`Attribution{billed_key_id,…}` and `Admission`/`admit()`" together as the
finding. **They are not the same case, and `meter.rs` is a SPLIT, not a single verdict:**

* **`Direction` and `Attribution` are LIVE.** `receive.rs:1847` calls `Attribution::receiving`,
  `:1860` calls `Attribution::delegating`, and the result is read at `:1947`
  (`hop.target_agent_id`) and `:2005` (`hop.billed_key_id`). The file header's claim that the
  delegating arm is unmounted is **stale**. They carry "whose budget this bills", which is defs
  5/6 under #43/#71 — kernel-side, and they MOVE (§6.1 step A7).
* **`Admission`, `Admission::status` and `admit` are DEAD.** They do not move.

### 9.2 The disposition — an owner ruling, not an agent's

**This task does not delete it, and this plan does not either.** Two honest options, with the
argument for each:

* **DELETE.** It is a second implementation of a ruling that already has one, it has no caller, and
  #43's own words are that duplication is *"the defect generator."* `busbar-kernel-budget` already
  answers this question with the same comparison and the same `Retry-After` floor.
* **PROMOTE ITS TEST.** `meter_tests.rs` (118 total) is the only thing asserting that reaching a
  limit is over it (`used < limit`) and that `Retry-After` floors at 1. `busbar-kernel-budget` also
  holds both properties, but the a2a battery states them in one place a reader can find. If the
  kernel battery does not cover the floor explicitly, delete the implementation and **move the two
  assertions to `busbar-kernel-budget`'s own tests**, so the deletion loses no proof.

**Recommendation for the ruling: DELETE, having first proved `busbar-kernel-budget`'s battery covers
both properties.** That is Wave D3 and it is shadow-oracle-gated like every money move.

**What must NOT happen, and this is the whole reason the finding is recorded:** `Admission` must not
be "fixed" by moving it into `busbar-plane-a2a` along with the rest of `meter.rs`'s neighbourhood. It
ADMITS. Defs 16-20 end *"Nothing that prices, admits or dials."* Folding it plane-side would put
"whose budget this bills" and "may this proceed" inside a pure plane on the day #43 says a plane is
pricing-blind — which is exactly what `0e41eeb9e` pulled it back out of the fold to prevent.
