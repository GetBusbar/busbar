# 1.6.0 SEAM FIX #1 (axis-C) — lift the neutral durable-handle engine out of busbar-a2a into busbar-substrate

Investigation notes. Base commit `e57f6413` (BACKWARDS purity base). Scope: `busbar-a2a` +
a NEW `busbar-substrate` module + an append-only `pub mod` line in `busbar-substrate/src/lib.rs`.
No other file is touched (concurrent agents hold busbar-llm/busbar-core).

## The property being fixed

Axis-C (stateful handles / async: the "park a handle at a 202 and resume it later" pattern) is a
**plane-agnostic capability** — busbar-a2a (tasks), busbar-llm (Responses-stateful / batch / Files),
and busbar-voice will all want it. Today the whole engine lives in `busbar-a2a/src/taskstore.rs`
and is reachable only as `busbar_a2a::taskstore::TASKS`. The 1.6.0 plan (T3) intends busbar-llm to
build Responses-stateful **on this engine** — which, as it stands, would force `busbar-llm ->
busbar-a2a`, a cross-plane dependency that breaks the plane-agnostic rule. The fix: the neutral
engine becomes a `busbar-substrate` capability; busbar-a2a becomes a **thin consumer** that layers
its task shape / statuses / vocab / digest over the neutral lifecycle. No busbar-a2a **public
behavior** changes.

Note: NO plane reaches into `taskstore` today (grep-confirmed: every `taskstore::TASKS` reference is
inside busbar-a2a). The seam violation is **latent** — it lands the moment busbar-llm's axis-C work
starts. Fixing it now keeps that work a substrate consume, not a busbar-a2a reach.

## The NEUTRAL / A2A split (audited against taskstore.rs @ e57f6413)

### Genuinely neutral (the engine to lift)

- **The registry**: `HashMap<handle_id, Entry>` working set; the process-wide `static TASKS`
  ("process state, not config-derived — a config apply must not destroy in-flight handles");
  `TASKS_SINK_LOCK` test discipline.
- **The durable sink plumbing**: `sink: Option<Arc<dyn PlaneStore>>`, `set_sink`,
  `clear_sink_for_test`, `upsert_row`/`append event` through the neutral `PlaneStore` seam
  (`PlaneRecord` envelope) — already substrate types, nothing A2A crosses the store ABI.
- **The chain POSITION**: `Position { tail_hash, next_seq }` — plain strings/ints; genesis +
  continue-from-tail. Neutral.
- **The lifecycle write-through ORDERING**: durable-row-upsert-then-seal-event, memory updated only
  after the durable write succeeds (`write_through`, `transition`, `submit`).
- **Retention / GC / sweep**: the three-rule submit-time `sweep` — abandon stale active, TTL-evict
  terminal, cap-evict oldest terminal first, never drop an active; the retained cap
  (`MAX_RETAINED_TASKS = 4096`), the TTL (`TERMINAL_TASK_TTL_SECS = 300`), the abandon ceiling
  (`ACTIVE_TASK_ABANDON_SECS = 86_400`). The POLICY is neutral; the abandon TRANSITION (which token,
  which event) is A2A.
- **Durable-store rehydration ORCHESTRATION**: `restore_from_store` — list rows, decode per-row
  (undecodable COUNTED, never `?`-aborts), skip terminal, reload the event chain, verify it, position
  the chain, insert into the working set; `Rehydrated { active, terminal, unreadable, chain_breaks }`.
  The orchestration + tolerance is neutral; per-row DECODE and chain VERIFY are A2A.
- **Inbound-push cursor**: `advance_cursor` (monotonic artifact cursor), and the cursor field itself.
- **Scoped anti-enumeration lookup**: `get_scoped` / `list_scoped` — one non-distinguishing
  `Denied::NotYours` for missing-or-foreign; scope keyed on the owner (`principal`). Neutral once the
  owner key is projected to a neutral position.
- **Compaction**: `compact(before)` — purge terminal durable rows older than `before` + drop matching
  working-set entries.

### A2A-specific (stays in busbar-a2a, layered over the neutral engine)

- **The task SHAPE**: `TaskRow` / `TaskEventRow` field sets (task_id, context_id, principal,
  direction, state, agent_id, artifact_cursor, push_callback, ...) and their `PlaneRecord`
  encode/decode. (`record.rs`)
- **The STATUSES**: the terminal token set `{completed, failed, canceled, rejected}` and
  `is_terminal_state`; the `canceled` token the abandon path writes.
- **The VOCAB**: the per-event kinds (`EV_SUBMITTED`/`EV_DELEGATED`/`EV_TERMINAL`/`EV_ARTIFACT`, from
  `busbar_substrate::audit::vocab` — already substrate, referenced by A2A).
- **The DIGEST**: `digest_event_v1`/`v2` (framing tag `busbar.a2a.taskchain.v2`, the exact A2A field
  order), `digest_of`, `verify_chain`, `ChainBreak`/`ChainBreakKind`. **Frozen by a golden**
  (`chain_golden.rs`): its bytes MUST NOT change — so event sealing stays plane-side.
- **Task-specific mutations**: `record_dispatch` (agent routing / `task.delegated`),
  `set_push_callback`, `record_push_delivery`, `verify_task_chain`, `to_row`/`from_row` glue,
  `readable_row`.

## Why the engine must store rows OPAQUELY — the dual-compile constraint

The handle store is destined to ride a per-plane opaque-state slot (`Box<dyn Any>`) that core reads
back; in the plane test binary substrate is single-compiled while a plane crate + its core copy can
be dual-compiled. For the `Any` downcast to survive, the **engine type must be substrate-single-
compiled and NON-generic**. That FORBIDS the obvious `Engine<TaskRow>` (a generic monomorphised
inside busbar-a2a is not substrate-single-compiled and its `TypeId` diverges across the two core
instances).

Design that satisfies it: the engine is **non-generic** and stores each handle's row **opaquely** as
`Arc<dyn Any + Send + Sync>` plus a **neutral projection** `HandleMeta { owner, updated_at, terminal,
cursor }` plus the neutral `ChainPosition`. The plane's concrete row type never appears in the
engine's type. busbar-a2a downcasts the `Arc<dyn Any>` back to `TaskRow` **inside busbar-a2a** (same
plane, same `TypeId`), so byte-identity is preserved (no re-encode round-trip) and no A2A noun leaks
into substrate. This mirrors the existing `scope.rs` precedent (`DispatchScope` holds resources
behind boxed `dyn Send` / `SettleAdmission` callbacks and never names a plane type).

## The substrate API surface (capability-class names, no A2A/voice noun)

New module `busbar-substrate/src/plane/handle_engine.rs`, exported append-only as part of the
existing `pub mod plane;` tree (`pub mod handle_engine;` inside `plane/mod.rs`), so
`busbar-substrate/src/lib.rs` needs NO new top-level line — but per the task the integrator note
records that `plane/mod.rs` gains one `pub mod handle_engine;` line (append-only).

- `pub struct DurableHandleEngine` — the registry + durable sink + GC + rehydration + cursor.
  Non-generic. Holds `Mutex<HashMap<String, HandleSlot>>` + `Mutex<Option<Arc<dyn PlaneStore>>>`.
- `pub struct HandleMeta { owner: String, updated_at: u64, terminal: bool, cursor: u64 }` — the
  neutral projection every plane provides for its row.
- `pub struct ChainPosition { tail_hash: String, next_seq: u64 }` — `genesis()` / `from_tail(..)`.
- `pub struct SweepBounds { abandon_secs, terminal_ttl_secs, max_retained }` — the retention knobs
  a plane supplies (A2A supplies its 86400 / 300 / 4096).
- `pub struct SealedEvent { record: PlaneRecord, tail_hash: String }` — what a plane's sealer returns
  (the event to append + the new chain tail). The engine advances `next_seq`; the plane owns the hash.
- `pub struct HandleUpdate { row: Arc<dyn Any+Send+Sync>, meta: HandleMeta, record: PlaneRecord }` —
  a mutation's new opaque row + projection + durable task-row record.
- `pub enum HandleDenied { NotYours }` — the neutral anti-enumeration refusal (A2A re-exposes as its
  own `Denied`).
- `pub enum HandleEngineError { NoSuchHandle(String), Store(StoreError) }`.
- `pub struct RehydrateCounts { active, terminal, unreadable }` — neutral; plane-typed chain-breaks
  accumulate plane-side via the verify callback.
- Methods (mechanics; no A2A noun): `new`/`default`, `set_sink`, `clear_sink_for_test`,
  `submit(update, seal, now, bounds)`, `apply(id, update, seal)` (the shared write-through +
  memory update), `sweep(now, bounds, abandon)`, `rehydrate(store, decode, load_position)`,
  `advance_cursor(id, cursor, now, seal)`, `touch_meta(id, meta, record)` (push-callback style
  row-only upsert), `scoped_get(owner, id)`, `scoped_list(owner)`, `get_unscoped(id)`,
  `contains`/`len`/`is_empty`, `evict_if_terminal(id)`, `compact(before, kind)`,
  and durable helpers `append_record`/`upsert_record`.
- Plane callbacks (the crisp seam): `seal: FnOnce(&ChainPosition) -> StoreResult<SealedEvent>`;
  `abandon: Fn(&str, &(dyn Any), u64) -> Option<(HandleUpdate, Sealer)>`;
  `decode: Fn(&[u8]) -> Result<DecodedHandle, ()>` (yields id + meta + opaque row);
  `load_position: Fn(&DurableHandleEngine, &str) -> ChainPosition` (plane lists events via the
  engine sink, verifies, records breaks in its own accumulator).

Confirmed: no `task`/`a2a`/`agent`/`voice`/`session`-plane noun appears in any of these names. `owner`
/`cursor`/`handle`/`durable` are capability-class words. `Handle` is the neutral noun (`SessionScope`
/`DurableScope` in `scope.rs` already establish the vocabulary).

## busbar-a2a after the lift (thin consumer)

`taskstore.rs` keeps: the digest (v1/v2/`verify_chain`/`ChainBreak`), `is_terminal_state`, the A2A
`Denied`/`Rehydrated`/`TaskStoreError` (re-exposed, mapped from the neutral ones for byte-identical
messages), and a `TaskRegistry` newtype that OWNS a `DurableHandleEngine` and implements every
current public method by translating `TaskRow` <-> (`HandleMeta` + `Arc<dyn Any>` row) and supplying
the A2A sealer/decoder/verifier/abandon callbacks. `static TASKS` becomes a `TaskRegistry` wrapping an
engine. All ~15 consumer call sites and the 598 test-support tests keep calling `TaskRegistry`'s same
methods and see byte-identical behavior.

## Verdict: PROCEED (clean capability/consumer split, not a contortion)

The neutral core separates along a crisp seam: substrate owns the **mechanics** (registry, durable
ordering, GC policy, rehydration tolerance, cursor, scoped anti-enumeration), busbar-a2a owns the
**shape / statuses / vocab / digest** via a small set of boxed callbacks — the same idiom `scope.rs`
already uses. The dual-compile rule is satisfied by the opaque-`Arc<dyn Any>` row store (non-generic
substrate type). A2A byte-behavior is preserved because rows are stored opaquely (no re-encode) and
the frozen digest stays plane-side. This is the intended fix-candidate #1.
