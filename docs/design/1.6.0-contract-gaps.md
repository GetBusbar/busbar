# busbar 1.6.0 — consolidated contract gaps

Every place where `busbar-contract` / `busbar-caps` or `ARCHITECTURE.md` (v1.30) did not fit what a
crate needed, collected from the crate docs, the `// contract:` markers, the module prose and the
commit bodies of `busbar-contract`, `busbar-caps`, `busbar-kernel`, the fourteen `busbar-unit-*`
crates, the five `busbar-plane-*` crates and the seven `busbar-transport-*` crates. Deduplicated
across crates: where four crates recorded the same finding it is one row with four witnesses.

This document proposes no new architecture. Where `ARCHITECTURE.md` already decides a question the
row cites the section and the recommendation is "do what the section says". Where the document is
silent, the row says so and the decision is the owner's (tracker row D21).

Scope note: this is a gap register, not a defect register. A row is here because a *seam* did not fit,
not because a crate is wrong. Several rows record a crate refusing to guess — that is the behaviour
the build asked for, and the row exists so the guess is made once, in the open.

**Counts.** 60 gaps. By the crate that must change: `busbar-contract` 22 (CG-01..22) · `busbar-caps` 7
(CG-23..29) · `busbar-kernel` 4 (CG-30..33) · `busbar-unit-*` 13 (CG-34..46) · `busbar-transport-*` 6
(CG-47..52) · `busbar-plane-*` / `busbar-llm` 6 (CG-53..58) · gate and tooling 2 (CG-59..60).
Twenty block the composition root; they are listed in §2.

Legend for the **kind** column: **C** = a change to `busbar-contract`; **K** = a change to
`busbar-caps`; **D** = a design amendment to `ARCHITECTURE.md`; **W** = a plane- or transport-side
workaround that stays where it is and is recorded rather than fixed.

## 2. The order in which these must land

The composition root (tracker D16: the `busbar` binary composing kernel + units + planes + transports,
retiring `busbar-core`) cannot be written while two crates spell one type two ways, while a unit
returns a shape the loop cannot receive, or while a seam has no implementation to bind. The twenty
rows marked **BLOCKS** below are those (twenty of them); the rest can land in any order after their
wave.

Waves are ordered by dependency, not by size. Everything in one wave is independent of everything
else in it.

### Wave 0 — decide (owner; blocks everything downstream)

Nothing can be built against an undecided seam. These are the D21 review items and they gate wave 1.

1. **CG-20 — `KernelSeal`: trait or token.** **BLOCKS.** Determines whether §3.7's honesty table
   claims compile-time or CI enforcement for the sealed constructors, and therefore what every
   contract-side constructor's signature is.
2. **CG-37 — the store trait's 22 method signatures.** **BLOCKS.** `busbar-unit-verbs`,
   `busbar-unit-wal` and `busbar-unit-ledger` all bind to them; commit `547ef64e` flags them as
   inferred from prose.
3. **CG-17 — the MCP mount: configured or fixed.** Decides whether `Claim` grows a registration-time
   selector (which is the same mechanism as CG-06).
4. **CG-22 — the 3k ceiling.** Decides whether wave 1 may add types to the pair at all.
5. **CG-41 — unreconciled: a move or a parallel tally.** Small, and it changes what the ledger
   endpoints report.
6. **CG-56 — the HTTP binding of the 17 new verbs.** Unblocks the admin plane's real claim table.
7. **CG-55 — the anthropic minted request id.** Spec fidelity versus plane purity; recommend the
   kernel supplies the entropy.
