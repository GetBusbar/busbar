## 1. CAN THE ENGINE SHIP 1.6.0?

**No — and the engine is right to say no.** The headline is not that the engine is broken. It
builds clean, it is fmt-clean, and **334 of 334 tests pass**. The headline is that the gate it
exists to enforce is **red on the candidate**, and that several of the fixes that would make it
green **exist only in an uncommitted working tree or on an unmerged branch**.

Blockers in order. Severity is "what happens if 1.6.0 is cut today".

### B1 — The conformance leg denies, 17 suites out of 17. *(measured)*

`busbar-turnstile admit` runs `cargo xtask conformance check --musts --sha <sha> --format=tsv` in
the busbar checkout (`crates/busbar-release-turnstile/src/command.rs:67-82`, called from
`src/turnstile.rs:175-182`).

**The brief's premise for this item is false in a useful direction.** The subcommand was suspected
not to exist (→ exit 2 → deny). It **does** exist — `xtask/src/cli.rs:87-88` dispatches
`Some("conformance")` into `xtask/src/conformance_check/`. But running it on the real candidate SHA
gives a worse answer than a missing subcommand would:

```
$ cargo xtask conformance check --musts --sha bb83912d5b6d4e908f71295b29dd9d3dcf2c2617 --format=tsv
EXIT CODE = 1 ; ROW COUNT = 17 ; PASS = 0 ; FAIL = 17
```

The 17 split into two genuinely different problems, and conflating them would misprice the work:

- **10 are STALE, not broken.** `a2a`, `mcp`, `llm-{anthropic,bedrock,cohere,gemini,openai,responses}`,
  `voice-{gemini-live,openai-realtime}` all carry a **passing** verdict whose commit is
  `67ee79103050`, not the candidate SHA. Per `CONFORMANCE-SYNC-DESIGN.md §5.2` a pass is honoured
  only if `commit == release sha`. These go green by **re-running the suites on the release SHA** —
  no product work.
- **7 are genuinely not-run** — `fapi2`, `h2`, `jev`, `oidf-oauth2`, `slsa-verifier`, `tls`, `ws`.
  Each manifest row says `status = not-run` with a "planned 1.6.0" note. These are real outstanding
  1.6.0 work and are the true content of this blocker.

A non-zero `CommandCheck` is `CheckOutcome::Red` (`command.rs:128-133`), `Board::admitted()`
requires all-green (`lib.rs:101-102`) → **DENY**. This is the engine working correctly. It is
blocker #1 only because it is the thing standing between today and a BOARD.

> **Do not "fix" this with `--no-conformance`.** The flag exists (`main.rs:68-69`) and is
> documented "Never for a real admission run", but **nothing enforces that**: with it set, the
> conformance check is simply absent from the board rather than red
> (`turnstile.rs:506 conformance_disabled_is_skipped_not_faked_green`). The production workflow
> correctly does not pass it (`.github/workflows/turnstile.yml:230-236`). A check that was removed
> is not a check that passed — this is the "zero is the passing answer to every ban" hazard in its
> cheapest available form.

### B2 — The money oracle's #56 alignment exists **only in an uncommitted working tree**.

See §6 for the full trace. In one line: **on committed HEAD, money/oracle jobs have no backend at
all.** `BackendToggles::default()` has `ec2: false` (`config.rs:53-57`), `LatchkeyConfig::default()`
has `allow_money_on_latchkey: false` (HEAD), and `route_overflow` sends money jobs to the EC2 bucket
whenever that flag is false (`control_loop.rs:366`). EC2 is off; so the money bucket is dispatched
to a backend `build_backends` never constructs (`main.rs:109`).

Decision **#56** is verbatim on the other side: *"money/oracle jobs MAY run on Latchkey
(`allow_money_on_latchkey` → true)"* (`docs/design/BUSBAR-1.6.0.md:387`). **HEAD contradicts #56.**
The fix — flipping the default to `true` plus the doc rewrite — is sitting **uncommitted** in
`crates/busbar-release-autoscaler/src/config.rs`. One `git checkout` and the only record of the
#56 alignment is gone.

## 3. Crate-by-crate map

### 3.1 `busbar-release-turnstile` — the admission board (2,888 src lines, 53 tests)

**Job.** Run the whole admission battery against a busbar checkout at one candidate SHA and fold it
into one BOARD/DENY. `Turnstile::admit` (`src/turnstile.rs:105`): (1) shell
`cargo xtask gate <name> --format=tsv` once per gate over a 39-gate list (`gate.rs:258`); (2) decide
by git-diff path-scoping whether the money oracle is required, and if so call the `MoneyJudge`
(`turnstile.rs:124-159`); (3) run optional `cargo build`/`test` plus the conformance subprocess
(`turnstile.rs:161-182`); (4) AND-fold via `report::assemble` (`report.rs:120`). Exit `0` BOARD /
`1` DENY / `3` could-not-run (`main.rs:119-127`).

**CLI.** One subcommand, `admit`, with 14 flags (`main.rs:35-108`): `--busbar-repo`/`--repo`,
`--sha`, `--artifacts`, `--gates`, `--discover-gates`, `--no-oracle`, `--build-test`,
`--no-conformance`, `--checkout`, `--base-sha`, `--oracle-paths`, `--needs-oracle`, `--skip-oracle`,
`--json`.

**Works.** `DEFAULT_GATES` is genuinely 39 entries (`gate.rs:23-63`). `--discover-gates` is proven
end-to-end against a fake `cargo` (`turnstile.rs:572`, and `gate.rs:455` proves a non-zero
`--list` is refused rather than trusted as a partial list). The change-scoped oracle decision has
14 unit tests **plus four hermetic real-`git` end-to-end tests** (`turnstile.rs:299/335/373/408`)
covering docs-only scope-out, the `[needs-oracle]` marker forcing it on, and `[skip-oracle]` being
**refused** on a money diff. Deny-safety of the conformance leg is proven by an actual `admit()`
run (`turnstile.rs:484`).

**Stubbed / dead.** Zero `todo!`/`unimplemented!`/`unreachable!` (counted: 0). `GateCheck`
(`gate.rs:305-324`) has **zero construction sites** — `admit()` calls `battery.run_all()` directly;
it survives dead-code lint only by being `pub`. `looks_like_checkout` (`command.rs:146`) has zero
callers workspace-wide. `NullMoneyJudge` (`oracle.rs:172-180`) is test-only and returns `Skipped`,
which is **not** green (`lib.rs:59-61`) — deny-safe by design. Gates run strictly sequentially with
no per-gate timeout (`gate.rs:286`).

**`REMAINING.md` is stale in two places** — `:48-49` lists conformance wiring as unchecked (it is
wired, `command.rs:67-82`), and the flag list at `:25-27` omits five flags that exist.

**Untested composition.** `RealJudge`'s eight tests all drive a hermetic `MockOracle`
(`oracle.rs:190-218`). The actual `RealJudge(HarnessOracle)` composition at `main.rs:172` has **no
test coverage** — only the compiler and a `no_run` doc example. Also, `RealJudge::judge` ignores its
`ctx` entirely (`oracle.rs:140`, `_ctx`): the `sha` is discarded, so the oracle does not
independently verify which SHA it is judging — it trusts the working tree.

**CLI (verified by running `--help`).** Exactly eight subcommands: `normalize`, `diff`, `cells`,
`owed-baseline`, `record`, `replay`, `harness-rev`, `fetch-golden`.

**Works.** 89 integration tests across 7 files + 7 inline, **all green**. The normalizer
(`normalize.rs`, 1,489 lines) and differ (`differ.rs`, 873 lines) are the load-bearing pieces and
are the best-covered: `normalize_core` 11 + `normalize_ws` 22, `differ_pointer` 10, `differ_run` 11
driving `run::run` over real on-disk recordings, `selftest` 13, `harness_orchestration` 12 (through
a mockable `HarnessRunner`, so the suite runs with no live docker), `harness_provenance` 10. The
`pyjson` module reproduces CPython `json.dumps` byte-for-byte and tests it against a live `python3`
differential.

**Reachability.** `HarnessOracle` is constructed from `main.rs:305`/`:322` (both with the real
`SystemRunner`) and from exactly **one** site outside the crate:
`busbar-release-turnstile/src/main.rs:172`. Note the two constructors differ — `HarnessOracle::new`

### 3.5 `busbar-release-autoscaler` — runner capacity (9,018 src lines, 114 tests)

**Job.** Size a pool of CI runner slots to GitHub queue depth and drive cloud capacity to match.

**Two binaries, two independent engines, no shared decision code:**

| | `busbar-autoscaler` | `busbar-fleet` |
|---|---|---|
| CLI | `plan` / `tick`, `--config`, `--dry-run`, `--empty-reads` | **none** — no clap at all; env-only |
| config | file or `Config::default()` | **hardcoded `Config::default()`** (`bin/busbar-fleet.rs:51`) — cannot read a config file |
| path | hand-rolled loop `main.rs:164-184` over `RunnerBackend` | `control_loop::run_tick` + the live impls in `control_loop_real.rs` |
| honours `backends.ec2`? | **yes** (`main.rs:109`) | **no** (B7) |
| can it provision? | **no** — see below | **yes**, but enforce is off |

**`busbar-autoscaler tick` cannot provision a single runner under the shipped defaults.** Defaults
are GH-hosted ON + Latchkey ON + EC2 OFF (`config.rs:53-57`), and **both enabled backends'

unchanged capacity (`latchkey.rs:582-596`); `GitHubHostedBackend::scale_to`/`reap_idle` are no-ops
with a hardcoded `busy_slots: 0` (`github_hosted.rs:66-83`). The only real mutation left is
Latchkey `reap_idle` cancelling orphans (`latchkey.rs:598`) — which, note, **still issues real
`POST /jobs/{id}/cancel` under `--dry-run`**, because `--dry-run` is EC2-only (`main.rs:59-61`;
`dry_run` is honoured only at `ec2.rs:249,282,429,583`).

**`--empty-reads` is a debounce counter that nothing ever increments.** It defaults to 0
(`main.rs:35-36`), the standing-controller loop calls `busbar-autoscaler $CONFIG_FLAG tick` with no

So the branch at `decision.rs:130` **always** fires on any teardown → `desired = current_total.max(busy)`.
No test covers `empty_reads == 0`.

**Works, and works well.** The pure decision engine (`decision.rs`, 10 tests), region infra
bootstrap/teardown behind a `CloudApi` seam (`region_infra.rs`, 14 tests against a `FakeCloud`,
including `teardown_all_never_reaps_a_busy_instance` and
`teardown_all_terminates_nothing_when_the_busy_set_is_unknown`), spot shopping and placement

unreadable market as empty), scale-down selection (8 tests), the async `run_tick` orchestrator
(17 tests including `report_only_mutates_nothing` and

## 7. Cost controls (DECISION #78) — can anything stop a runaway?

**#78 sets $50 soft-alarm / $80 review / $100 hard cap per period** (`BUSBAR-1.6.0.md:422`), with the
acceptance criterion *"cost-watch checks the LK Cost-Analysis each period"*.

### What exists — in **this** repo, and it only reports

`scripts/cost-watch.py` (71 KB) implements the bands exactly (`SOFT_ALARM_USD = 50.0`,
`REVIEW_USD = 80.0`, `HARD_CAP_USD = 100.0`) with a strict exit-code contract
(0 ok / 2 alarm / 3 review / 1 cap / 4 tool error) and a self-test. It is wired to
`.github/workflows/sched-cost-watch.yml`, which runs the self-test first, then the real read.

Its limits, by construction:

- **Weekly** — `cron: "0 12 * * 1"`. A runaway starting Monday afternoon is invisible for ~7 days.
- **Report-only** — it emits `::warning`/`::error` and fails *its own job* on cap breach. It
  cancels no workflow, terminates no instance, revokes no token, and flips no flag. It also
  deliberately holds `permissions: contents: read` and cannot mutate the repo it watches.
- **Estimating, and it says so** — GitHub's job wall-clock over-counts by ~2.4–3× (Latchkey bills
  execution only), and Latchkey has **no billing endpoint at all** (`/usage /billing /account
  /costs /me /whoami /quota` all 404; `GET /jobs` caps at the 100 most-recent jobs **org-wide** with
  no date filter or pagination). So it cannot reconstruct a period total from the source of truth —
  it is a cross-check, not a meter.

### What exists in the release engine — **nothing**

I grepped the sibling's `crates/` for `hard.?cap|soft.?alarm|budget|spend|usd|dollar|cost.?watch|
max_(monthly|spend|cost)`. **47 hits, and not one is a spend control.** Counted and classified:

- `cost-watch` / `cost_watch`: **0 occurrences in the entire repository.**
- `spend`: **0** in autoscaler `src/`. All `spend`/`budget` hits elsewhere are the **product's own**
  per-key budget feature appearing in oracle test fixtures and corpus cell descriptions
  (`over_budget`, `spend_cents`) — busbar's billing semantics, not the engine's spending.
- `budget` in the autoscaler: 7 hits, **all** meaning *slot* budget (`split_slot_budget`).
- `dollar` / `max_hourly` / `max_price` / `MaxPrice` / `spot_price_cap`: **0.** Neither
  `SpotOptionsRequest` builder sets a max price (`ec2.rs:341-343`, `control_loop_real.rs:405-407`).
- `usd`: 1 — a doc comment on a spot-price field.

**The only ceilings are unit counts, and they are not priced:**

| ceiling | value | implied cost at list price |
|---|---|---|
| `max_slots` (EC2) | 64 (`config.rs:96`) ÷ 4 agents = **16 × c7a.8xlarge** | ~$10.19/hr spot → **~$245/day** |
| `Ec2Backend::max_slots` | `(0 + 32) × 4` = 128 slots (`ec2.rs:474`) | higher still |
| `max_leases` (Latchkey) | 8 (`config.rs:235`) at `runner_size: "small"` | 8 × $0.15 = $1.20/hr → **~$29/day** |

**Even the cheapest ceiling breaches #78.** 8 Latchkey `small` leases held saturated cost ~$201 over
a 7-day period — **2× the $100 hard cap** — and nothing in code would notice, because the weekly
reporter runs after the fact and the engine has no price input at all. `region_shop` reads spot
prices only to *rank* pools and order teardown; `control_loop_real.rs:159-160` says outright that
pricing "is advisory". **There is no threshold anywhere that refuses a pool for being too
expensive.**

### So: can it stop a runaway?

**No, not by code.** Today's actual brakes are three accidents of deployment, each one flag-flip
from gone:

1. **`FLEET_CONTROL_ENFORCE` is unset** (`fleet-control.yml:98`) — every 3-minute scheduled tick is
   report-only, so `busbar-fleet`, the only binary that can launch an instance, mutates nothing.
2. **`busbar-autoscaler`'s enabled backends have no-op `scale_to`** (§3.5) — it *cannot* provision.
3. **EC2 is off by default**, so the expensive backend is not built.

Remove any one and there is no code-level spend ceiling behind it. **Recommendation for an owner:**
#78's cap is enforced by a weekly reporter in the wrong repository. If the cap is meant to bind, the
engine needs either a priced ceiling in `split_slot_budget` or a pre-flight cost check in
`run_tick` — and `cost-watch.py`'s own finding (Latchkey has no billing endpoint) means such a check
must be built on *slot-hours × list rate*, not on a queried bill.
