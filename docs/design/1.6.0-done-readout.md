93:begin_group() { CUR_GROUP="$1"; CUR_RED=0; CUR_FIRST_NOTE=""; hdr "$1"; }

The script's own count — the one that gates whether a verdict is rendered at all — is taken with a

`grep -c '^end_group$'` both agree at 23, and `DONE_GROUPS_DECLARED=23` matches, so
`floor_is_honest()` passes and the script will render a verdict rather than refuse one. There is no
lost 24th group to go looking for.

## FINDING 1 — THE INSTRUMENT REWROTE ITSELF WHILE IT WAS RUNNING

`scripts/verify-1.6.0-done.sh` was **982 lines** when this run started at 18:04. At **18:22:01**,
while the run was still inside its first group, the file on disk was **995 lines**, rewritten by
commits `e8ec4eaee` and `9cbb0f9c4`, which replaced the entire TELLER-STEPS rig-suites block.

This is not a nit. `bash` reads a script incrementally from a **byte offset**; a file edited
underneath a running interpreter can be resumed mid-token. The edit landed at ~line 874, far past
the offset the run had reached, and everything before it is byte-identical — so this particular run
will probably survive it. That is luck, not a property of the harness. On a shared checkout with
~12 concurrent agents it is a live hazard for **every** long-running gate script in the tree.

Consequence: the TELLER-STEPS row is measured against the **new** body, which differs materially
from the one the run began with (the new one restores and drives `rigs-ledger.sh`; the old one
declared it permanently absent and pointed the reader at another repository).

## FINDING 3 — PARITY'S CANDIDATE BINARY IS ANOTHER AGENT'S BUILD

`target/release/busbar` in this checkout is **a symlink another agent created at 18:09**:

```
target/release/busbar -> /tmp/t-rigs/release/busbar     (22,455,136 bytes, mtime 18:08:52)
```

PARITY deliberately runs `cargo build -p busbar --release --locked` immediately before recording,
and its own comment says why: *"on a tree that has never been release-built the record step below
either dies on a missing path or — worse — records a STALE binary from some earlier checkout and
calls the resulting zero divergences a parity proof of HEAD. This step makes the candidate HEAD's
by construction."*

**That guarantee does not hold here.** With `CARGO_TARGET_DIR` set, the freshly built binary lands
in `/tmp/t-readout2/release/busbar`, while `./bin/oracle record --bin target/release/busbar`
follows the symlink to `/tmp/t-rigs/release/busbar` — a different binary, built by a different
agent, from a different tree state. The anti-staleness guard is defeated by a `CARGO_TARGET_DIR` it
cannot see, and it fails **silently**, because the path exists and is executable. The same symlink
is what makes TELLER-STEPS take its `else` branch and run the rig suites against that same foreign
binary.

`.cargo/config.toml` sets no `build.target-dir`, so the hole is the interaction of the environment
variable with a hard-coded relative path, in exactly two places:
`step "record the candidate (target/release/busbar)"` and `elif [ ! -x target/release/busbar ]`.

**Nothing was touched to produce this** — the symlink was already there; it is reported, not
repaired. But **no PARITY or TELLER-STEPS number taken in this configuration is a parity proof of
HEAD**, and the fix belongs in the script (record from `${CARGO_TARGET_DIR:-target}/release/busbar`,
or refuse the run outright when `CARGO_TARGET_DIR` is set), not in the tree.

## FINDING 5 — CONFIG-STABILITY: the selftest is red while the gate it guards is green

Both arms run against the same tree, seconds apart:

- `xtask gate config-schema --selftest` → **exit 1**
- `xtask gate config-schema` (the real check) → **exit 0**

The selftest's failing case is *"a grammar type that MOVED between two core-kind roots is NOT a
break"*, and the reason it gives is not about its own fixture — it is about the **real committed
snapshot**, verbatim:

```
config-schema:snapshot-drift the committed snapshot is STALE
crates/busbar-kernel/src/config/config-schema.snapshot.json does not match the config source —
the surface changed and the snapshot was not regenerated. first difference at line 1204:
committed "\"OverlayDoc\": {" vs fresh "\"PinMechanism\": {".
config-schema:additive-only NON-ADDITIVE config change 2 non-additive delta(s):
OverlayDoc — type/section REMOVED (a config referencing it now fails)  |
RootSettings — type/section REMOVED (a config referencing it now fails)
```

The selftest re-takes its battery at `--jobs 1` and gets the identical answer, so it is **not** an
intra-harness concurrency race. Two readings remain open and this run cannot separate them:

1. **Harness drift** — that selftest case does not isolate from the real tree, so it inherits
   whatever state `crates/busbar-kernel/src/config/` is in when it runs. On a checkout where
   another agent is mid-edit in exactly that directory (Finding 2), a case that plants a *moved*
   type reads a snapshot stale for an unrelated reason and fails for it.
2. **Product state** — `OverlayDoc` and `RootSettings` really were removed, the snapshot really is
   stale, and the plain gate passes only because it reads the committed baseline rather than the
   working tree.

Reading 1 is the more likely, because the plain gate passed on the same tree in the same second.
**Neither was acted on.** This is the single most important thing in this document to re-run on a
quiesced checkout: a real non-additive config break after the 1.5.3 freeze is a release stopper,
and the instrument currently answers both ways.

## WHAT THIS DOCUMENT IS NOT

It is not `N / 23 GREEN`. Eleven groups are unmeasured — among them PARITY, BYTE-IDENTITY, KERNEL
and EQUALITY's loop column, the four that carry the money path — and on the evidence here at least
two of the seven reds (CONFIG-STABILITY, TEST) may not survive a quiet machine.

The single number this release wants does not exist yet, and the obstacle is not primarily the
tree. It is that **the done-oracle cannot be run to completion on a checkout that twelve agents are
writing to at a load average of 60**: the instrument rewrote itself mid-run (Finding 1), the tree
moved under it (Finding 2), its parity candidate is another agent's binary (Finding 3), one red
does not reproduce (Finding 6) and one gate's selftest contradicts the gate (Finding 5).

**The prerequisite to a spendable number is one quiesced checkout, one SHA, no other writers, and
one full run.** That is cheaper than any of the ten findings above, and until it happens every
figure in this file — including the five greens — is provisional in the sense that matters.
