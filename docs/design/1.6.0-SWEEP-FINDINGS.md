## Slice 4 — the release engine. **This is the most consequential slice.**

**22 of 26 registered workflows are `disabled_manually` at GitHub.** Only four are active: CI,
qa-gate, Dependabot, oracle-rebless. A disabled workflow fires on NO trigger, and the disable state
is keyed by PATH — so promoting a branch does not clear it.

Disabled: Release · Release stage · Prepare release · tag-on-main · Verify deploy · Docker ·
plugin-ci · **CodeQL** · **MCP conformance** · **A2A conformance** · **Voice conformance** ·
**OAuth Conformance** · gate-mutants · keep-proof · fleet-control · CI images mirror · monthly
refresh · oracle record store cells · a2a-hang-hunt · runner probe · Security.

Three consequences, none of which any todo item named:
1. **The whole release engine is off.** A push to `main` cuts no tag; a push to `qa` produces no
   staged record — so `main`'s required context `record the staged digest` can never report.
2. **Every plane conformance workflow is off** — mcp, a2a, voice, oauth. The four planes whose
   conformance is a C2 acceptance criterion have no CI leg running.
3. **Security scanning is off.** CodeQL and Security both disabled.

**`qa → main` cannot fast-forward and cannot legally be made to.** `origin/main` holds **7 commits
reachable from no other branch** (README badges, a Codecov job, a 1.5.5 openapi regen).
`merge-base --is-ancestor origin/main origin/predev` → NO. `promote.sh` refuses non-ancestors and
never forces; `release.yml:530` independently refuses any sha qa never saw, which rules out the
merge-commit workaround by design; live protection has `allow_force_pushes: false`,
`enforce_admins: true`. The content is already re-landed on predev, so this is ancestry-only — but
the remedy is an owner protection change, not a code change.

**`predev → dev` has no mover.** `TURNSTILE_DISPATCH_TOKEN` is absent from the repo's 3 secrets.

**`ship-ready` is RED on all four rows** under a shipping posture, not just `standing-reds` — the
existing items understated it. `ship-twin` alone is 10 red rows.

**`cargo xtask full-gate --selftest` exits 1** inside a required check, on two rows: three
registered-but-unrun gates, AND two unclassified cargo invocations that no item names.

> **The verdict that reorders the whole list: if all 51 items went green tomorrow, the train still
> would not move.** Three stops — a missing PAT, a divergent `main`, and 22 switched-off workflows —
> and all three are in the plumbing, not the tree. The list measured the code and never asked
> whether the machine that ships it was switched on.

Two corrections the slice made to its own brief, both in the repo's favour: `verify-1.6.0-done.sh`
has **no** drift (23 declared, 23 defined, guard is two-sided) and **no** group calls a retired

## Slice 7 — config and served surface

**The config contract HOLDS.** 26 top-level keys at v1.5.5 → 32 at HEAD; six added, **none removed,
none retyped**. An unmodified 1.5.5 `config.yaml` parses and boots. v1.5.3 carries the same 26, so
the surface has been stable across two releases.

**The SERVED contract does not hold.** Law 7 says every plugin is off until its config verb is used.
Measured per plane:

| plane | verdict | gating expression |
|---|---|---|
| llm | INERT | `build: \|_\| None` — it is the 1.5.5 surface itself |
| mcp | **LIVE at boot** | `mcp_hydrate`: `if !ctx.has_store()` — gated on `store:`, not `tools:` |
| a2a | **LIVE at boot** | `a2a_hydrate`: `ctx.plane_store()` — gated on `store:`, not `agents:` |
| streaming | **LIVE at mount AND boot** | `mount.rs:489`: `ctx.public_url?` — a 1.5.5 key |
| decisions | INERT | everything returns empty |

**Only 2 of 5 planes are genuinely inert, and the root cause is in CORE, not in any plane.**
`crates/busbar-kernel/src/boot.rs:70-77` folds `plane_decls()` and calls every `hydrate` hook with
**no slot and no config check**. Item 25 named the voice symptom; this is the disease.

**The dup-claim guard watches the wrong field.** The ratified contract's verb is `config_section`,
and resolution is `.find(...)` — **first match silently wins**, which is exactly the "ambiguity
resolved by picking a winner" the contract forbids. The guard that exists reads
`owned_config_sections`, which 3 of 5 planes declare as `&[]`, so it cannot fire on any shipped
build. `pools` is claimed twice — by the llm plane as its verb and by core as concretely owned.

**No transport dup-guard exists at all**: `TRANSPORT_DECL`, `load_transport`, `scheme_claim`,
`claims_scheme`, `owned_schemes`, `check_owned_scheme` → 0 hits (positive control: 532 files contain
"transport").

**The pragmas' back-compat justification is false.** Three suppressions exempt `mcp` / `tools` /
`agents` as "frozen since 1.5.3". **v1.5.3 and v1.5.5 both carry 26 DeployCfg fields and none of the
three exists at either tag.** They are 1.6.0-additive keys wearing a back-compat exemption.

**26 admin verbs are served and appear in NO OpenAPI document** (18 of them money-governance), and
11 new admin paths mount unconditionally because both admin mount loops iterate `plane_decls()`
(linked) rather than `plane_slots` (configured). A side-car OpenAPI document exists explicitly so
the pinned bytes need not move, and says so in its own source.
