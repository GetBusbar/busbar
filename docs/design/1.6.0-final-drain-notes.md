## STOP at the App cascade — residual **32**, one atomic unit

The remaining 32 (state 8, plane_host 7, ingress 3, governance 3, store 2, limits 2, egress_auth 2,
telemetry 1, proxy 1, cost 1, config 1, admin 1) are NOT independently drainable. Investigation firmed up
that each is coupled to `App` or a core-internal subsystem, so they can only fall as ONE whole-engine
retype (`&Arc<App>` → `&dyn EngineHost` + threaded `&NativeRuntime` from a substrate-owned ArrivalPayload):

* **state / plane_host / ingress / governance / cost**: `App` is the core god-object and is un-re-exportable;
  the only way to drop `use busbar_core::state::App` from health/mod/native_ingress is to stop typing the
  engine's `&Arc<App>` params — which forces the whole `operation_ingress_inner → forward_with_pool[_parsed]
  → walk/wire/select/hooks/response_body/usage` subtree at once. `engine_host_value(app)` (plane_host×7) is
  the transitional carrier that only disappears once the host is threaded from the arrival boundary; the
  carrier struct fields typed `Arc<GovState>`/`Arc<AdmitGrant>`/`Arc<CostModel>` must become opaque/host-held.
* **store (LaneRuntime×2)**: keystone §4 hoped to relocate the trait, but its method signatures name core
  `store` types (`LaneSnapshot`, `LaneHealthSnapshot`, `ProbeGuard`, `OutcomeWindow`) bound to the in-memory
  breaker engine → the trait CANNOT move to substrate. Must drain via a host `lane_store()` seam view.
* **limits×2 (health.rs)**: `default_probe_*` read the core `LIMITS` global; no substrate limits facade. Drains
  with the health leaf of the cascade (health also imports `App`).
* **egress_auth×2**: `MetadataSsrfPolicy`/`CredentialProvider` sit in the large core `egress_auth` module
  (SigningContext-coupled `resolve()` + all signer impls). A wholesale module move, not a single.
* **telemetry×1 / admin×1 (wire.rs)**: `translation()` + `AUDIT.record_by` are on the **surgical alloc==0
  path** (`wire.rs`, which has `app` but NO host in scope) and reach core metric/audit infra. Draining needs a
  host threaded onto the surgical path (alloc-gate exact-0 risk) or the metric/audit infra relocated.
* **proxy×1**: the stage-tap primitives (`fire_stage_taps`/`spawn_bounded_tap`/`StageShape`) are documented as
  deliberately core-resident and fire through `app.tap_hooks` — App-coupled, seam-only.
* **config×1**: `caller_in_hook_groups` needs `GroupCfg` (config-grammar, schema-tracked, nested LimitCfg/
  ChildDefault) relocated to substrate first; and its call site reads `app.groups_registry` anyway.

**Feasibility of the pivot (checked, GOOD):** the substrate-owned ArrivalPayload is achievable with NO TypeId
hazard — the payload's `gov` is `busbar_api::PlaneRequestCtx` (already neutral) and `caller_token` is
`Option<String>`, so a substrate `{ host: Arc<dyn EngineHost>, gov: PlaneRequestCtx, caller_token }` is a
single-compile type both sides name. The blocker is NOT the payload — it is (1) the EngineHost/EngineTables
substrate surface must first grow the app-facade seams the engine reads by type (store view, gov/cost/admit
opaque handles), and (2) the whole-engine `app.engine_tables()`(~79 sites)→ threaded `&NativeRuntime`
conversion must stay alloc-neutral (forward min ≤107; the surgical path exact-0). That is the single large
authorized commit; it was NOT forced here because it cannot be landed as a safe monotonic sequence and a
failed attempt yields a non-compiling tree with zero partial value. **Design decision needed:** grow the
EngineHost seam (store-view + gov/cost/admit opaque handles) and thread `EngineTables<'_>` once-per-request,
then land the ArrivalPayload pivot + native_ingress retype as the final commit.
