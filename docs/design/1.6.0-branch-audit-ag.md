# 1.6.0 branch audit — slice `ag` (103 remote branches)

Trunk audited: `consolidated/1.6.0` @ `897074b56f63c0e92dc2802097b407ac5d7413e5`.
Method: per branch, `base = merge-base(branch, HEAD)`, `git diff $base..$branch`, extract the
DISTINCTIVE things the branch ADDS (fn / type / const / mod names, CamelCase and SCREAMING
identifiers, `#[test]` names, and string literals ≥ 6 chars), then test each one for presence
anywhere in **HEAD's tree** (`crates xtask scripts docs testing qa tests conformance examples
.github fuzz bin assets`, `Cargo.lock` and binaries excluded). Symbols survive the 1.6.0 renames;
paths do not, so nothing here is concluded from a path.

**Instrument note (a correction that changed 1 445 verdicts).** The first presence pass used one
ripgrep run over a multi-pattern file. Ripgrep matches leftmost-FIRST and does not report
overlapping matches, so a short pattern (`https://`) silently shadowed every longer pattern that
began at the same offset — 1 445 of 9 570 candidates were reported absent while being present. The
numbers below come from the replacement instrument: an exact index of every maximal `[A-Za-z0-9_]+`
token in HEAD (identifier presence is then an O(1) set test, exact because `\bID\b` matches iff `ID`
is a maximal word run), plus, for each string literal, a rarest-token lookup followed by a literal
`index()` over only the files that can contain it. Every "absent" below is from that instrument;
every security- and money-relevant hit was then opened in the trunk and read, because a source scan
is evidence about SPELLINGS and not about BEHAVIOUR.

#### A3. `verify/keep-audit-digest` (and its superset `verify/keep-audit-digest-core`) — the admin-audit digest is not domain-separated by scheme

Missing: `DIGEST_SCHEME_2_TAG = "busbar.audit.adminchain.v2"`, `opt_text` / `opt_num`,
`AbsentVersusEmpty`, and the cells `an_entry_relabelled_from_one_scheme_to_the_other_stops_verifying`
and `an_absent_optional_and_an_empty_one_are_different_records`.

The *substance* of this branch — the pipe-join forgery fix — IS in the trunk, under renamed
constants: `AUDIT_SCHEME_PIPE` / `AUDIT_SCHEME_LENGTH_PREFIXED` in
`crates/busbar-kernel-audit/src/legacy/entry.rs` and, independently, in
`crates/busbar-kernel/src/audit_ring.rs` (I checked the second copy specifically, because a
duplicate that missed the fix is exactly the shadowing trap; both carry it). What is NOT in the
trunk is the branch's extra step: the branch prepends a fixed tag to every scheme-2 preimage so the
two schemes are disjoint preimage spaces, "the version is inside what is signed, not merely beside
it". The trunk's `digest_fields` (`entry.rs:284-292`) starts straight at `prev_hash`. Honest
severity: **defence in depth, not a live hole.** Relabelling a stored entry's `scheme` in the trunk
changes the framing and therefore the recomputed digest, and a length-prefixed preimage for a
non-genesis entry begins with `0x00…0x40` (the 8-byte BE length of a 64-char hex `prev_hash`), which
a pipe-joined preimage of text fields cannot begin with — so the collision is not reachable today.
It becomes reachable the moment a record type with a different first field is added. The
`opt_text`/`opt_num` half is likewise forward-looking: no `digest_fields` impl in the trunk feeds an
optional field, so nothing today can confuse absent with empty.

#### A4. `verify/keep-api-p1` — one foreign column makes a live credential's row unreadable

`malformed_scope_field_fails_the_read_rather_than_widening_to_wildcard`, `NoLedgerBackend`,

The trunk (`crates/busbar-contract/src/records.rs:165-166`) still declares

```rust
#[serde(flatten)]

```

`#[serde(flatten)]` routes EVERY unnamed field of the stored row into that map, so a single foreign

`assemble_scopes`, where a non-`allowed_*s` field is ignored and a malformed `allowed_*s` field is
still a hard `Err`. Note the safety property is NOT regressed in the trunk: today's failure is
fail-CLOSED (the row will not read at all), never a widening to the omitted-grant wildcard. This is
availability and forward-compat, not privilege. (The sibling cell
`redeem_plane_token_default_refuses_rather_than_claiming_a_first_redemption` is already satisfied —
the trunk's `RecordStore::redeem_plane_token` default is `Ok(false)`.)

#### A5. `spec/decisions-audit-gate` — the `clean` rule the row specifies is not the rule the gate implements

This branch adds one row (#41, "audit-clean") to `docs/design/DECISIONS.md`. **That file does not
exist in the trunk at all** — `docs/design/1.6.0-owner-decisions.md` is what survives — so rows
1-40 of that register are gone from this line too, which is worth an owner's eye independently of
this row.

The row's own rule: *"`clean` iff the TRAILING run of consecutive `zero` verdicts at the current
tree-hash is ≥ 2; any `findings` verdict resets the run to 0 — `Z→F→Z` = 1"*. The trunk's
`xtask/src/audit.rs::confirmed()` (line 754) implements only the other half — two zero rounds at the

rounds and looking for any qualifying pair. It never looks at what sits between them, so
`Z → F → Z` reads as confirmed and a scope goes `clean` with an unanswered findings round in the
middle of its run. The ship gate is built on `confirmed()`.
