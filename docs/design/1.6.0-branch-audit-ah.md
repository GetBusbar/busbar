# 1.6.0 branch audit — slice `ah`

Audit of the 95 remote branches in `/tmp/branch-slices/slice-ah` against the trunk
(`consolidated/1.6.0`, HEAD). **Audit only — no branch was deleted, no branch was checked out,
nothing was pushed.**

## Method

Ancestry and patch-id are useless here (the trunk was rebuilt; the 1.6.0 rename waves moved every
path: `busbar-core`→`busbar-kernel`, the `busbar-unit-*` crates folded into `busbar-kernel-*`,
codecs folded, planes extracted). So the instrument is symbol- and content-level, never path-level:

1. `base=$(git merge-base origin/<b> HEAD)`, then `git diff $base..origin/<b>` over
   `crates xtask scripts docs qa testing .github`.
2. From the ADDED lines, extract (a) **definitions** — `fn`/`struct`/`enum`/`trait`/`type`/
   `const`/`static` names; (b) **distinctive literals** — error codes, ids, CIDRs, wire tokens;
   (c) **verbatim code lines** (≥30 chars, non-comment), which catch behaviour changes that reuse
   an existing symbol name.
3. Check every extracted item against **HEAD's tree** (materialised once via `git archive HEAD`,
   so concurrent working-tree edits by other agents cannot contaminate the result), searched with
   `--no-ignore --hidden` so `.github/` and ignored paths are inside the window.
4. Anything absent is a candidate. **Candidates in security, auth, money, egress and crypto were
   then opened in the trunk and read**, because a source scan is evidence about SPELLINGS, not
   BEHAVIOUR.

That last step mattered: it demoted **eight** candidates that turned out to be real fixes already in
the trunk under different names (including the NAT64 SSRF unwrap and the stdio frame-delimiter
guard), and it is what promoted **seven** others to confirmed live gaps. See
[Verified NOT lost](#verified-not-lost-instrument-false-positives).

### Instrument caveats (read before trusting a row)

- **`SURVIVOR` is the mechanical verdict, not a claim of loss.** 94 of 95 branches have at least one
  absent definition. Most of that mass is the `busbar-unit-*` → `busbar-kernel-*` refold: the
  behaviour was carried across and the *prose test names* were rewritten. The table's `absent defs`
  count is a **search-ranking signal**, not a defect count.
- Only the findings in [Tier 1](#tier-1--confirmed-live-gaps-in-the-trunk-verified-against-head)
  were read against the trunk's real code. Tiers 2 and 3 are unverified at behaviour level.

#### 1. `origin/verify/keep-tests-plugins` — unbounded recursion in the plugin-pack schema resolver

**Absent symbols:** `MAX_RESOLVE_DEPTH`, `the_ref_resolver_caps_its_own_depth`
**Trunk file:** `crates/plugin-sdk/src/pack.rs`

The trunk caps the schema **walk** but not the schema **resolve**:

- `scan(...)` carries `depth: u32` and refuses past `const MAX_SCAN_DEPTH: u32 = 64;`
  (`pack.rs:321`).
- `resolve_effective(schema, defs, resolving)` (`pack.rs:218`) takes **no depth parameter**. It
  recurses into itself through `$ref` (`pack.rs:238`) and once per `allOf` member (`pack.rs:250`)
  **without ever returning through `scan`**, so `scan`'s counter does not advance for the whole
  duration of a resolve chain.
- The `resolving: &mut HashSet<String>` guard only catches a `$ref` that **repeats a name**
  (`if !resolving.insert(name.to_string()) { return Err("cyclic $ref…") }`). A chain of N
  *distinct* `$defs` entries — `L0 → allOf[$ref L1] → … → L(N-1)` — repeats nothing, so the cycle
  guard never fires.

The document that triggers this is **flat** (all `$defs` entries are siblings), so `serde_json`'s
own parse-recursion limit does not apply; only the resolve recursion is deep. This runs on
**operator-supplied input at pack time** (`--settings-schema-file`), and the failure is a stack
overflow — an abort with no diagnostic, which is the one answer a validator must not give.

The branch adds a `depth: u32` parameter and `const MAX_RESOLVE_DEPTH: u32 = 64;` to
`resolve_effective`, plus a 200-link non-cyclic regression test that asserts the refusal comes from
the resolver's own cap (`err.contains("while resolving")`) rather than from `scan`'s.

#### 2. `origin/verify/keep-tests-plugins` — `$BUSBAR_SIGN_KEY` hex error echoes a nibble of the ed25519 seed

**Absent symbols:** `sign_key_hex_error`, `a_malformed_sign_key_is_reported_without_echoing_it`
**Trunk file:** `crates/plugin-sdk/src/pack.rs:537`

The trunk builds the refusal as:

```rust
let seed = hex::decode(hex_seed.trim())
    .map_err(|e| format!("{SIGN_KEY_ENV} is not valid hex: {e}"))?;
```

`hex::FromHexError::InvalidHexCharacter { c, index }` **names the offending character and its

Narrow (one nibble, and only on a malformed key), but it is private key material on a path whose
whole purpose is handling private key material.

#### 3. `origin/verify/keep-transports-p2b` — `100-continue` is granted before the body cap is checked

**Absent symbol:** `a_request_expecting_a_continue_past_the_body_cap_is_not_told_to_send_it`
**Trunk file:** `crates/busbar-transport-http/src/lib.rs:1152`

The trunk writes the interim answer immediately after the transfer-encoding framing checks:

```rust
if raw::header(&headers, "expect").is_some_and(|v| v.eq_ignore_ascii_case("100-continue")) {
    let mut w = write.lock().await;
    let _ = w.write_all(b"HTTP/1.1 100 Continue\r\n\r\n").await;

```

The **declared `Content-Length` is not compared against `request_body_max_bytes` first** — that

`Expect: 100-continue` itself for any body past about a kibibyte, so this is the ordinary path, not
a crafted one: the client uploads in full and then gets a framing refusal.

Note the **chunked** arm is fine and was harvested — `if read_so_far > max_body_bytes { return
Err(TransportError::Framing); }` is checked before the done-test, exactly as the branch wants.
