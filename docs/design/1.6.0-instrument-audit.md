# 1.6.0 — THE INSTRUMENT AUDIT: can the DEFINITION OF DONE fail?

**Subject:** `scripts/verify-1.6.0-done.sh` (23 groups) and the 46 gates in the xtask registry
(`xtask/src/gates/mod.rs:1912-2247`).

**The question is not "does it pass?" It is "CAN IT FAIL?"** Every row below answers four things:
does the check open a non-zero population; does it name anything that no longer exists; was it shown
RED by a planted violation; and can its pass condition be told apart from an error.

**Method — the standing rule of this tree, applied literally:**

> *Keep one known instance OUT of the instrument's reach, and check the instrument against it. A gate
> that cannot be shown failing is not evidence.*

So every claim of the form "this cannot red" below is backed by a **matched pair**: the same planted
violation placed once IN the instrument's reach and once OUT of it, with the verbatim verdict for
both. Where a plant was impossible because the subject is not on disk, that is said instead of
guessed.

**Measured 2026-09-22 against a moving tree.** Eight agents share this checkout and HEAD advanced
four times during the audit (`6ab0bab93` → `a0b808b79`). Every measurement below names the SHA it was
taken at. One finding was **fixed by another agent mid-audit** and is recorded as a before/after pair
rather than edited out, because the before half is the evidence.

**A correction to my own method, recorded because it is the same disease.** The first attempt at the
`no-default-bodies` plant anchored on `s.index("pub trait Transport")`, which matched
`pub trait TransportMeta` 65 lines earlier. The plant landed in the wrong trait and the gate
correctly reported PASS — and I nearly wrote that up as "the gate cannot see it." **A plant that
silently fails to plant is indistinguishable from a gate that cannot see.** Every RED/PASS pair below
was re-run with an exact-string anchor and an assertion that the anchor occurs exactly once.

## 2. THE FOUR THAT MATTER — evidence

### 2.1 `replay-selftest` PASSES on a golden that does not exist — the txn-fence shape, reproduced

`scripts/verify-1.6.0-done.sh:715` is the first, trust-establishing step of the PARITY group:

```
step "replay-selftest (the differ can see a diff)" ./bin/oracle replay-selftest
```

`bin/oracle:184` resolves that to `busbar-oracle replay-selftest --golden "$DATA/golden/1.5.5"
--baseline "$DATA/owed-baseline.txt"`. The pinned engine (`oracle-rust.pin` ref `89718d8`) implements
it as `owed_ratchet_check`, at
`target/oracle/rust/89718d8/checkout/crates/busbar-release-oracle/src/run.rs:2673`:

```rust
pub fn owed_ratchet_check(golden_ledger: &Path, baseline: &Path) -> RatchetResult {
    let gold = fs::read_to_string(golden_ledger).unwrap_or_default();
```

**Measured, both halves, same binary, same baseline:**

```
=== control: real golden ===
PASS  replay-selftest (owed-baseline ratchet): every golden PASS id is named in owed-baseline.txt (the ratchet covers all of them)
RC=0

=== golden directory that does not exist ===
PASS  replay-selftest (owed-baseline ratchet): every golden PASS id is named in owed-baseline.txt (the ratchet covers all of them)
RC=0
```

**Byte-identical output.** A missing golden yields an empty `pass_ids`; `pass_ids.difference(&base)`
over an empty left side is empty; the function returns `pass: true`.

**The asymmetry is the tell.** The BASELINE side of the very same function has an explicit refusal at
`:2694`:

```rust
if base.is_empty() {
    return RatchetResult { pass: false, message: format!(
        "the golden owes {} PASS cell(s) and owed-baseline.txt is absent or EMPTY — the ratchet that
         stops the golden quietly ceasing to owe a cell has nothing in it", pass_ids.len()) };
}
```

One of the two inputs refuses being empty. The other does not. Nobody decided that.

**And the step's label is false in a second way.** `replay-selftest` is a set-containment check over
`owed-baseline.txt`. It plants no divergence and never invokes the differ. **Nothing anywhere in
`verify-1.6.0-done.sh` proves the differ can see a diff** — which is precisely the positive control
the label promises and which the spec singles out as one of only two gates in this tree that had one.

**Compounding, same group:** `bin/oracle:234` hardcodes `--allow-harness-skew` on every `diff`, so the
differ's same-revision guard cannot fire on any DONE run; and `verify-1.6.0-done.sh:724` reuses a
cached golden whenever `ledger.tsv` is non-empty, with no `else` and no freshness check.

**Not fixed here** — the read is in the pinned `busbar-release` engine, outside this repo. Owed: a
`golden_ledger` empty-refusal mirroring the baseline's, and a step label that describes what the step
does.

### 2.2 The excuse mechanism is a substring grep over text nobody stripped

`xtask/src/full_gate.rs:470-474` states the design, and it is the right design:

> *"An excuse used to be a name on a list. A name cannot be wrong, which is why the `denylist` entry's
> claim survived being false: nothing it asserted was ever compared with anything."*

`Excuse::holds` (`full_gate.rs:227-246`) checks the claim — by asking whether a **needle string**
appears anywhere in a named file:

```rust
Excuse::XtaskTest(_) => cx.walk(&WalkSpec::new(["xtask/tests"]).ext("rs").min_files(1))?
    .iter().any(|f| f.text.contains(needle)),
Excuse::ReleaseScript(_, _) => cx.read(path)?.contains(needle),
```

No comment stripping. **Both variants proven, on real shipped files:**

**Plant A — `Excuse::XtaskTest`.** Comment out the one real call site in
`xtask/tests/hot_path_gates.rs:21`, leaving only the spelling:

```rust
#[test]
fn the_hot_path_perf_gate_is_green_over_the_committed_instrument() {
    // PLANTED: the real call is gone; only the SPELLING run(&["gate", "hot-path-perf"]) remains.
    assert!(true);
}
```
```
  [ok]     each of the 10 registered-but-not-in-ci entries still names a place this tree runs the gate
full-gate selftest: discovery, floors, skip-reasons and registry equality all hold
```

**Plant B — `Excuse::ReleaseScript`, and this one needs no plant to be alarming.** Delete BOTH real
invocations of `no-deferral-strict-done` from `verify-1.6.0-done.sh`. The needle survives in the
file's own header comment, which is **already in the shipped tree**:

```
--- remaining occurrences of the needle ---
30:#   no-deferral      cargo xtask gate no-deferral-strict-done (nothing deferred; voice markers CLEARED).
--- selftest verdict ---
  [ok]     each of the 10 registered-but-not-in-ci entries still names a place this tree runs the gate
```

**The same file gets this right 300 lines away.** `full-gate --selftest` prints
`[ok] the echo, comment and name: lines quoting cargo commands are NOT discovered` — the ci.yml
discovery path strips comments deliberately, because a quoted command is not an executed one. The
excuse path does not. The two halves of the same check disagree about whether a comment is evidence.

**Blast radius.** `REGISTRY_NOT_IN_CI` carries 10 entries. Cross-referencing the registry against
both runners:

```
registered gates:                              46
invoked by name in verify-1.6.0-done.sh:       14
invoked by cargo xtask full-gate:              41
run by NEITHER:   denylist  hot-path-alloc  hot-path-perf  plane-pricing-blindness
```

For those four, **the excuse IS the coverage**. And they are not minor: `denylist` is the gate the
fifth-plane finding was about and the one that reds on `stale-waivers`; `plane-pricing-blindness` is
DECISION #87's witness and is RED on HEAD with 15 undocumented money references, none of which any
DONE run will ever see.

**Owed:** strip comments in `Excuse::holds` — the function that already exists in this file
(`scan::strip_comment_line` for Rust, the ci.yml discovery's own rule for shell) — and require the
needle to appear on an executed line. Not fixed here: it turns `full-gate --selftest` red for other
agents mid-flight, and the correct fix is a behavioural one (assert the test ran), not a tighter grep.

## 4. DoD CLAUSE 2 IS ENFORCED BY NOTHING ON THE DONE PATH

The spec's checklist item 2 reads *"Construction standing-reds are EMPTY — `ship-ready` green, **not
merely `--posture`-tolerated**."* Three independent mechanisms each remove it from a DONE run:

1. **Not invoked.** `scripts/verify-1.6.0-done.sh` never runs `cargo xtask gate ship-ready` or
   `cargo xtask gate construction` by name (14 gates are invoked by name; neither of these is one).
2. **Excused where it is invoked.** `full-gate` runs it, and `gates::REPORT_ONLY` (`mod.rs:172`)
   carries `ship-ready` with `Excused::ReleaseTime`, so its verdict prints and does not count.
3. **Self-disarming even if run.** `ship_ready.rs:73-91`: `standing_row` takes the pass arm whenever
   the posture is not `qa`/`main`. On `consolidated/1.6.0` it reports
   `PASS ship-ready:standing-reds  the standing-red list is a dev-line convenience, and this is the
   dev line`, and prints the 11 standing reds as an aside.

And `posture()` (`:62-64`) ends `…unwrap_or_default()` — a git failure becomes `""`, `is_shipping("")`
is false, and the refusal takes the pass arm. **The one row whose entire job is to refuse fails
open.**

This is defensible as designed — the excuses are written down and mechanically checked, which is more
than most trees manage. What is NOT defensible is that the document's Definition of Done names a
condition that the script the document calls "the real oracle" structurally cannot assert. Either
`verify-1.6.0-done.sh` runs `XTASK_SHIP_TARGET=qa cargo xtask gate ship-ready`, or clause 2 is not a
done condition.

## 8. THE RULE THIS AUDIT ADDS

> **AN EXEMPTION, A ROSTER ROW AND A SCAN ROOT ALL OWE AN EXISTENCE PROOF, AND THE PROOF MUST BE
> BEHAVIOURAL, NOT TEXTUAL.** A `package-selectors` gate for `-p` selectors landed today. There is
> still none for scan roots, allowlist prefixes, census keys, skip subjects, ledger scope ids or
> excuse needles — and the one mechanism that does check an excuse's claim checks it with
> `text.contains`, which a comment satisfies. **A name that cannot be wrong is the thing this tree
> has already been burned by four times; a name checked by grep is the same defect wearing the fix.**

And a second, from the self-correction in §0:

> **A PLANT THAT SILENTLY FAILS TO PLANT IS INDISTINGUISHABLE FROM A GATE THAT CANNOT SEE.** Every
> positive control owes an assertion that the plant landed — an exact anchor, matched exactly once,
> and a read-back. Without it a positive control produces the same green as the vacuity it was built
> to find.
