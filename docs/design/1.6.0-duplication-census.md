## 0. THE ONE-PARAGRAPH ANSWER

**The owner's hypothesis is half right, and the half that is wrong matters more than the half that
is right.**

Mechanical, copy-paste duplication is real, it is dangerous, and it is **~6,400 lines** —
7% of the excess. The 51-crate split itself costs almost nothing: the entire per-crate wiring tax
(`use`, `pub use`, `mod x;`) is 5,827 lines against v1.5.5's 1,326, and only **438** production
lines sit in files that are >75% re-export shim. **The crate count is not where the lines went.**

Where they actually went is a **third egress/breaker/identity architecture that is not on any
serving path** (~4,900 lines, plus ~3,000 more in a pre-switch composition root), a **plane host
and kernel unit loop that v1.5.5 had no counterpart for at all** (~14,600 lines of genuine new
capability), and **one subsystem — the LLM protocol codec — that grew 1.44× doing the same six
dialects**. Against those, five subsystems that everyone assumed had ballooned did not:
the admin surface is **1.21×**, config+validation **1.22×**, governance **1.23×**, ingress
**1.29×**, auth **1.40×**. Those are the honest negatives and they are worth as much as the
positives, because chasing them would have been wasted work.

## 3. THE FINDING THAT OUTRANKS ITS LINE COUNT — TWO SSRF GUARDS, ALREADY DIVERGED

**This is 1,593 production lines and it is not the biggest item in this census. Rank it first
anyway, because the two copies encode a SECURITY property and they have already drifted apart in a
way that leaves four cloud-metadata hostnames unblocked on three live outbound fetch paths.**

| | production `code` |
|---|--:|
| `crates/busbar-kernel/src/net_guard.rs` | **716** |
| `crates/busbar-kernel-egress/src/trust/net.rs` | **877** |

They are a verbatim fork with the comments reworded. Measured: after substituting only the error
type name (`GuardRefusal` → `AddressRefusal`), **625 of `net_guard.rs`'s 722 non-blank non-comment
lines appear identically in `trust/net.rs` (86.6%)**. Thirty-three functions share names, in the
same order: `ipv4_is_internal`, `ipv6_is_internal`, `ip_is_cloud_metadata`, `ip_is_internal`,
`dns_name_is_internal`, `is_unique_local_v6`, `is_link_local_v6`, `is_cgnat_shared_v4`,
`embedded_ipv4`, `is_alternate_ipv4_encoding`, `split_url`, `default_port`, `judge_scheme`,
`judge_host_name`, `judge_address`, `judge_addresses`, `pin_answer`, `resolve_and_pin`,
`refuse_redirect`, `refuse_hop_overflow`, `refuse_oversized_body`, `scheme_is`,
`extract_normalized_host`, `host_is_private_or_loopback`, `expand_alternate_ipv4`,
`ssrf_blocked_host`, `redact_userinfo`, `percent_decode_host`, …

### The divergence, exactly

```
crates/busbar-kernel/src/net_guard.rs:19
    pub const METADATA_HOSTS: &[&str] = &["metadata.google.internal", "metadata.internal"];

crates/busbar-kernel-egress/src/trust/net.rs:75-82
    pub const METADATA_HOSTS: &[&str] = &[
        "metadata.google.internal",
        "metadata.internal",
        "metadata.tencentyun.com",        // <- NOT in the kernel copy
        "metadata.platformequinix.com",   // <- NOT in the kernel copy
        "instance-data",                  // <- NOT in the kernel copy
        "instance-data.ec2.internal",     // <- NOT in the kernel copy
    ];
```

Both files' `dns_name_is_internal` (`net_guard.rs:158`, `trust/net.rs:221`) are **byte-identical**.
They differ only in which `METADATA_HOSTS` they read. So one guard blocks **two** metadata
hostnames and the other blocks **six**.

### Which one is live, and on what

**The two-entry copy is the one on the serving path.** `busbar-kernel::net_guard` is named by 19
files; the live outbound fetches that go through it:

| caller | what it fetches |
|---|---|
| `crates/busbar-a2a/src/a2a/fetch.rs:364` → `net_guard::resolve_and_pin` | the A2A agent-card fetch (operator-supplied URL) |
| `crates/busbar-oauth2/src/cimd.rs:109` → `net_guard::resolve_and_pin_async` | the OAuth2 client-ID-metadata fetch (**caller**-supplied URL) |
| `crates/busbar-mcp/src/mcp/client/ssrf.rs:235` → `net_guard::judge_host_name` | the MCP client's upstream precheck |
| `crates/busbar-a2a/src/a2a/pushnotify.rs:137` → `net_guard::ip_is_internal` | the A2A push-notification callback |
| `crates/busbar-voice/src/mount.rs:51`, `topology/mod.rs:36` | the voice provider dial |

The six-entry copy in `busbar-kernel-egress` is reached only from
`crates/busbar/src/root/units_{a2a,mcp,voice}.rs` — the **pre-switch** composition root (§4).

**So on a Tencent Cloud, Equinix Metal or EC2 host, the hardening exists in the tree and is not on
the path that dials.** An `instance-data` or `metadata.tencentyun.com` URL handed to the A2A card
fetch, the MCP client or the OAuth2 CIMD fetch passes `dns_name_is_internal`.

### Why this is the shape, not an accident

`crates/busbar-kernel-egress/src/trust/net.rs:9-13` — the file's own header:

> *"This check was written three times over — once on each fetch path that reached out to a
> configured URL … **Two implementations of one security control is the shape that produces a
> metadata bypass: somebody hardens one and the other keeps the hole.**"*

That sentence is in the copy that has the hardening. **It predicted its own defect and then became
the fourth copy.** `crates/busbar-oauth2/src/signer.rs:13` names the same class in prose.

**Recoverable: ~600 production lines.** But the reason to act is not the 600 lines.

### The second security-carrying duplicate, same shape, already drifted

`canonicalize_header_value` exists twice in the SigV4 signer:

- `crates/busbar-substrate-values/src/sigv4.rs:146-170` — tracks quoted-string state, does **not**
  collapse spaces inside a quoted value. **LIVE** (reached from `busbar-llm-codec/src/bedrock/writer.rs:49`,
  `busbar-kernel/src/auth/mod.rs:2007`, `auth_cache.rs:119,152`, `governance/state.rs:67,1114,1150,1211`,
  `busbar-core-admin/src/keys.rs:324`).
- `crates/busbar-kernel-identity/src/egress_auth/sigv4/mod.rs:110-125` — collapses unconditionally.

**A request carrying a quoted header value canonicalises differently on the two paths and therefore
signs to a different signature.** The identity copy additionally merges duplicate header keys with a
comma (RFC-correct) where the substrate copy does not, and returns an empty `Vec` where the
substrate copy emits `SIGV4_HMAC_INIT_FAILED`. Three behavioural forks in a signing algorithm.
~131–165 lines collapse; again, the lines are not the reason.

### The third — a money clamp that landed on one copy

`crates/busbar-kernel-budget/src/price.rs:59-74` writes the incident down:

> *"This used to be a second copy of the same three lines… They then drifted: a clamp for a
> finite-but-overflowing rate went onto one copy and not the other, and the two answered a config
> typo with too many zeros as 'nothing' on one side and 'the largest rate there is' on the other."*

The budget crate was rewired onto `busbar_kernel_ledger::cost::nano_rate`.
**`crates/busbar-kernel/src/cost.rs:138-145` was not** — its local `fn nanos(utok: f64)` still lacks
the `v <= u64::MAX as f64` clamp that `crates/busbar-kernel-ledger/src/cost/rate.rs:40-47` carries.

### And a fourth, cheap and exact

`CallerToken` and `Principal` are each defined **twice as independent structs**, not re-exported:

- `crates/api/src/auth.rs:69` and `crates/busbar-kernel-identity/src/carrier.rs:42` — `pub struct CallerToken(pub Option<String>);`
- `crates/api/src/auth.rs:16` and `crates/busbar-kernel-identity/src/principal.rs:26` — `Principal`

Both `CallerToken`s carry their **own hand-written redacting `Debug`** printing `<present>`/`<absent>`.
~40 lines. Redact one and the other still prints the caller's bearer token, with nothing forcing the
two to agree. **#84 already retires `busbar-api` into `busbar-contract`, which is this one's landing
place** — count it against that fold, not as separate work.

**RULE THIS CENSUS PROPOSES: a duplicate that encodes a SECURITY or MONEY property outranks any
duplicate that is merely bigger.** All four above are in that class, they total under 900 recoverable
lines, and three of the four have already produced a live behavioural divergence.

## 4. DEAD AND PRE-SWITCH CODE — 9,126 production lines that cannot execute

### 4.1 The structural cause, in one line

```
$ grep -n "busbar-kernel-" crates/busbar-kernel/Cargo.toml
(no output)
```

**`busbar-kernel` depends on NONE of its eight `busbar-kernel-*` satellites.** They are not beneath
the kernel; they are a **parallel stack beside it**, wired only at `crates/busbar` through
`crates/busbar/src/root/units_*.rs`. That is why the kernel keeps its own implementation of every
concern a satellite covers — and why a hardening can land on one side and not the other.

### 4.3b The one-line fix that finds most of it

```
crates/busbar/src/root/mod.rs:56   #![allow(dead_code)]
```

That inner attribute suppresses rustc's own dead-code detection across all **9,133** production
lines of `crates/busbar/src/root/`. Remove it and the compiler reports §4.3a's first five rows.
The comment above it says it *"comes off with the last plane switch"* — `main()` does call into the
module, but only for **llm and admin**. Three of the five planes' unit bindings run a `len()` check
at boot and nothing else for the life of the process.

### 4.4 What this means for the duplication numbers

**Most of what §6.1 and §6.2 describe is on the pre-switch side.** The two "THE ONE ATTEMPT"
implementations, the two exhaustion terminal sets, the two selectors, the two breaker FSMs — in each
pair, one is live (in `busbar-llm/src/engine/`) and one is pre-switch (in `busbar-kernel-egress` /
`busbar-kernel-breaker`).

**So this is a switchover decision, not a refactor.** If the intent is to finish the switch, none of
it collapses — it *replaces*. If the intent is to abandon it, all of it deletes. Counting ~3,000
lines of `busbar-kernel-egress` as "collapsible duplication" would be the inflated number this
census was told not to produce. **It is counted here, once, as pre-switch code.**

**But the drift has already happened in both directions, and that is the cost of leaving it:**

- `crates/busbar-kernel-egress/src/trust/net.rs` has **four cloud-metadata hostnames** the live
  `crates/busbar-kernel/src/net_guard.rs` does not (§3).
- `crates/busbar-kernel-breaker/src/cell.rs` has a **`clamp` panic guard** the live
  `crates/busbar-kernel/src/store/in_memory/breaker.rs` does not (§6.2).
- `crates/busbar-kernel-breaker/src/classify.rs` has a **gRPC status mapping** that does not exist
  live at all.

**A pre-switch copy that is ahead of the live one is not dormant — it is a fix nobody shipped.**

### 4.5 A parity test where a single implementation belongs

`crates/busbar/tests/net_guard_extraction_parity.rs` exists to assert the two SSRF guards agree.
Its own header records that **they already drifted silently once**: the WHATWG C0-and-space trim
landed on one copy and not the other, so `"https://10.99.99.99 "` (one trailing space) read as a
host matching no denylist entry while the connecting stack trimmed it and dialled the blocked host.

## 8. THE CRATE-SPLIT TAX — the owner's hypothesis, measured, and mostly refuted

> *"i bet the 2x is from having 54 [crates] and major duplication."*

**The crate count costs almost nothing in lines.** Measured over every production file:

| | v1.5.5 | trunk | delta |
|---|--:|--:|--:|
| `use` / `pub use` lines | 1,103 | 4,546 | +3,443 |
| bare `mod x;` lines | 223 | 1,281 | +1,058 |
| **combined wiring** | **1,326** (1.6% of file lines) | **5,827** (2.9%) | **+4,501** |
| files that are >75% wiring (pure shims) | — | **28 files, 438 prod lines** | |

Held at v1.5.5's 1.6% density, trunk would carry ~3,160 fewer wiring lines. **So the honest
crate-split tax is ~2,500–4,500 lines — 3–5% of the excess.** The biggest pure shim in the tree is
`crates/busbar-contract/src/lib.rs` at **83** lines. `crates/api/src/store.rs`, a total re-export
shim, is **9** production lines.

**6,403 is one hand-written file per plane** (§4.3). That is the per-instance-witness anti-pattern
the spec already rules against, applied to wiring: *"a plane that cannot pass it is not a plane."*

### 9.4 Things that look like duplication and are not

- **`pack_header_records`** (`crates/busbar-kernel/src/plane_host/egress.rs:342-424`, 83 lines) —
  the owner's trap, **confirmed**. It, and the four other length-prefixed record codecs
  (`egress/seam.rs:68`, `plane_host/pipe.rs:143`, `plane_host/journal.rs:989`,
  `busbar-plugin/src/hot/pod.rs:1050`), every one takes an *already-complete, in-memory* buffer or a
  live `(ptr,len)` borrow. **None takes a chunk, none carries a partial buffer, none is ever fed
  twice, none touches a socket.** ABI struct marshalling, not stream decoding. *(One real duplicate
  hides inside the family: `egress/seam.rs:70-78` and `plane_host/egress.rs:357-366` are the same
  encoder, same format, same crate — ~10 lines.)*
- **Six LLM dialect error unions** — Anthropic's `billing_error` is not OpenAI's
  `insufficient_quota`; Gemini answers in `google.rpc.Code` names. Six published third-party
  contracts, not one table written six times. The only shareable part — the `ERR_TYPE_*` input
  vocabulary — is **already** single-sourced at `busbar-substrate-values/src/proto.rs:15-50`.
- **Six per-provider usage extractors** — Gemini *adds* `thoughtsTokenCount` to output; OpenAI
  *subtracts* `cached_tokens` from prompt; Cohere lets `billed_units` win. Provider semantics, not
  boilerplate. *(The 2–4 copies **within** each provider are a different matter — §6.5.)*
- **Four "canonical" serialisers** — only `busbar-plane-a2a/src/a2a/canonical.rs` is RFC 8785 JCS.
  `mcp/client/catalogue.rs` sorts by UTF-8 (wrong for JCS, **correct** for drift detection);
  `units_admin/mod.rs:1235` is not JSON at all. Four documents, four threat models.
- **Six digest-input framings, three endiannesses** — every one is a **persisted wire format**.
  `busbar-kernel-audit/src/legacy/chain.rs:51-56` states the rule: *"Changing the framing of an
  existing stream would make every persisted chain in every deployment fail to verify at the next
  boot."* Zero collapsible lines.
- **Three newline framers** (`transport-stdio`, `kernel/ingress/byte_duplex`,
  `mcp/client/stdio`) — they differ precisely in *what an over-long or truncated line means*
  (stay usable / end the session / distinguish crash from truncation), and each difference is
  documented and load-bearing. ~15 lines of `read_until` mechanics are common; the other ~135 are
  policy.
- **`plane_host/` vs `plane/`** — two **layers**, not two engines. One shim module per capability:
  `plane_host/journal.rs` → `plane/auditlog.rs`; `plane_host/cost_host.rs` (107) → `plane/cost.rs`
  (217); `plane_host/trust.rs` → `plane/quarantine.rs` + `approvals.rs`; `plane_host/scope.rs` →
  `plane/handle_engine.rs`.
- **The wire-mirror ABI pattern** (`crates/busbar-plugin/src/cold/auth.rs`, 18 `From` impls,
  ~150 lines) — deliberate: the wire type must not move when the engine type moves. Defensible.
- **Four `legacy`/`compat` modules** — `busbar-kernel-audit/src/legacy/` (535),
  `busbar-kernel-ledger/src/legacy.rs`, `plugin-loader/src/legacy_usage.rs`, `admin/v1/` — **all
  four live**, all four load-bearing. `legacy_usage.rs` is the 1.5.x store-plugin wire shim;
  removing it silently loses usage and budget balances against published plugins.
- **`crates/store-memory` (599) and `crates/hooks-ranking` (165)** are **shipped products**, not
  examples. Both are normal dependencies in `cargo tree -p busbar`.

### 9.5 The kernel's size is mostly earned

A deliberate hunt for `match plane { "mcp" => … }` found **nine** plane-name references across all
52,948 kernel production lines, and every one carries a `// plane-purity: frozen-wire` marker
against a config key frozen in `config-schema.snapshot.json`. The registry indirection is real:
`PlaneDecl`, `fallback_key()` **derived rather than literal**, `Box<dyn PlaneCfg>`, type-erased

the thing being avoided. **The plane abstraction holds.** Its violations are the six twinned
struct fields in §8 and the one typed LLM carrier — ~200 lines, not thousands.

## 12. WHAT THIS CENSUS DOES NOT CLAIM

- **It does not claim the 2.44× is unjustified.** 21,620 lines (23.8%) are capability v1.5.5 had no
  counterpart for, *outside* the four new planes: a plane host, a kernel unit loop, a WAL, an
  OAuth2 authorization server, a diagnostics catalog, an owned HTTP egress stack. Whether those are
  worth having is an architecture question this census cannot answer.
- **It does not claim the crate count is the problem.** Measured, it costs ~2,500–4,500 lines. The
  per-plane *composition root* costs 6,403 — and that is a pattern, not a crate count.
- **It does not add up Tier 2 as "recoverable".** Items 7 and 10 are ~9,000 lines that would be
  *replaced* or *wired*, not deleted.
- **The honest recoverable total is Tier 1 + Tier 3 + Tier 4 ≈ 4,000–4,500 lines, plus 4,268 lines
  of dead code that can simply go. Call it ~8,500 — 9% of the excess.** Everything else is a
  decision about where the architecture is going.

**The owner's hypothesis, scored: "having 54 crates" — refuted, ~3–5%. "Major duplication" —
confirmed in kind, corrected in size: ~12,000–14,000 lines across duplication and dead code, not
91,000. And the most important finding in the document costs 600 lines and four hostnames.**
