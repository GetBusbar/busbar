## 2. The dual-compile / `Any` constraint (critical)

busbar-substrate is single-compiled across the two busbar-core instances in the plane test binary.
Anything crossing an `Any`/downcast boundary (as `LlmBuildInput` does at `build_runtime.rs:75-76`, and as
`plane_slots` entries do) MUST be a substrate type or the downcast fails across the two core instances.
Consequences: (a) the metrics registry singleton must LIVE in substrate (move, not re-export) — else two
core copies own two registries and the scrape splits; (b) any runtime-config struct riding a
`plane_slot`/`LlmBuildInput` must be substrate-typed (why Bucket B cannot be a re-export of
`busbar_core::config::*`); (c) Bucket A re-exports are safe only because those types never cross an `Any`
boundary in the plane path — where in doubt, prefer move over re-export.

## 4. Risk & effort

App) but volume × hot-path sensitivity (a wrong borrow / extra HostCtx mint per token shows in alloc-gate

**Effort ~14-20 commits, ~3-5 focused days, dominated by P6.** Confidence high: destination seams exist,
byte oracles make regressions loud.
