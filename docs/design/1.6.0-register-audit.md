## 0. WHY THIS DOCUMENT EXISTS

`testing/shadow-oracle/accepted-differences.json` holds 41 entries. Each is the owner's signed
statement that **a named class of difference from the published 1.5.5 binary is expected, on named
cells, FOR A STATED REASON.**

The register is **class-wise, not value-wise.** Its complete field set is `by, cells, changelog,
changelog_reason, classes, description_corrections, expected_cells, id, kind, rationale,
text_list_growth, transform` — verified against the pinned judge's loader
(`target/oracle/rust/89718d8/checkout/crates/busbar-release-oracle/src/run.rs:1116-1375`).
**No field pins an expected value.** The reason *is* the whole guarantee.

So: **if an entry's stated reason is false of the code, the signature covers nothing, and the entry
is silently pre-authorising a class of change on whatever cells it names.** That failure mode was
found once (F-011r, below). This audit asked the same question of all 41.

The stakes are the ones BUSBAR-1.6.0.md §"WHAT A GREEN ORACLE PROVES" already measured:
**545 of the 916 owed cells carry a pre-authorised change.** Reproduced independently here — the
41 regexes match exactly 545 of the 916 `PASS` rows in `golden/1.5.5/ledger.tsv`.

### Method

1. Every regex re-matched against `testing/shadow-oracle/cells.json` (2318) and
   `golden/1.5.5/ledger.tsv` (916 `PASS` = owed, 1402 `SKIP`).
2. Every falsifiable claim in every `rationale` and `changelog` traced to code, to the recorded
   1.5.5 golden, to the `v1.5.5` tag (which *is* in this repo — `git show v1.5.5:<path>`), or to the
   pinned judge/mock source, which is checked out locally at
   `target/oracle/rust/89718d8/checkout/crates/busbar-release-oracle/`.
3. Register mechanics read off the pinned judge rather than assumed.

### What could NOT be verified, for every entry at once

**There is no 1.6.0 recording anywhere in this repo.** `testing/shadow-oracle/golden/` contains
`1.5.5` and nothing else. Every register claim of the form *"1.6.0 emits X"* was checked against
**source**; every claim of the form *"this cell is byte-identical"* / *"metered identically"* /
*"no recorded cell moves"* is a claim about a **replay that cannot be performed read-only.** Those
are marked UNVERIFIABLE throughout and are not counted against an entry.

## 2. DEFECT 1 — `F-011r`, PARKED FOR THE OWNER

### The entry, verbatim in its load-bearing fields

```
id            F-011r hook write readback: `at` gives way to `fires_at`
kind          breaking
classes       ["effects.readback"]
cells         ^admin\.ops\|(PostHooks|PutHooksName|PatchHooksNameSettings|DeleteHooksName)\|ok$
expected_cells 4   (matches 4; all 4 owed)
by            owner (Matthew Jackson), 2026-09-04 parity triage; split out 2026-09-05 (round-3 audit)
changelog     1.6.0 Changed: the always-null `at` field on the hook view gives way to `fires_at`
              (rewritten for you by --migrate-config)
```

### The premise, and exactly which part commit `3c118f729` falsified

The premise is one sentence: *"the follow-up GET a hook write's cell performs … gains
fires_at/groups/phase and **LOSES the always-null `at` field**"*, and the removal is *"a declared
1.6.0 break named in the CHANGELOG's rewritten-spellings paragraph"*. The **removal** is the entire
reason the readback class is registered here as `breaking` instead of folded into F-011.

**Commit `3c118f729` (2026-09-04, "hooks: 1.5.5's plugin alias, hook-view at field and settings
persist accepted again"), an ancestor of HEAD, restored the field.** Today:

`crates/busbar-kernel/src/admin/v1/contract/mod.rs:420` —

```rust
    pub at: Option<&'static str>,
```

with the struct's own doc comment at `:419` stating the restoration as a standing rule:

> *1.6.0 owner rule: a 1.5.5 client reading this view must see this field byte-for-byte, so it is
> RESTORED alongside `phase`/`fires_at`.*

`HookView` derives `Serialize` (`:404`) and `at` carries **no `skip_serializing_if`**, so it is
emitted unconditionally — as `null` or as a string — on every read, including the write-readback
these four cells pin.

Corroborated from the other side: `golden/1.5.5/cells/admin.ops__PostHooks__ok.json`'s
`effects.readback[0].body.json` carries `"at": null` alongside ten other keys, and the current
`HookView` carries all eleven **plus** `phase`, `fires_at`, `groups`. **The readback diff these four
cells actually exercise is purely additive. Nothing is removed. The premise is false.**

### The cells it covers, and what it is currently authorising to move

Four owed cells, every one an **admin write**:

```
admin.ops|PostHooks|ok
admin.ops|PutHooksName|ok
admin.ops|PatchHooksNameSettings|ok
admin.ops|DeleteHooksName|ok
```

`effects.readback` is rated **10 — a money class** (`differ.rs:55-66, 74-88`). F-011's own rationale
says why: *"it is the proof that the write the cell made actually persisted, and as what."*

F-011r blankets that entire class. Concretely, on all four hook-write cells the following are
pre-authorised with **no true reason behind them**:

- the readback's **status** (whether the write persisted at all),
- the readback's **path** (whether it persisted at the resource the caller named),
- **every byte of the persisted object** — `on_error`, `timeout_ms`, `priority`, `transport.target`,
  `prompt`/`user` grants, `settings_keys`.

A hook write that persisted the wrong gate fallback, the wrong timeout, or the wrong plugin target
would report ACCEPTED under this entry.

### What would go RED if it were struck

**All four cells, on `effects.readback`.** The candidate readback is golden + `fires_at` + `groups` +
`phase`; `effects.readback` has **no superset proof** in the judge, so a superset still diverges.

And the obvious remedy does not work. `ADDITIVE_CLASSES` is `["body","headers","effects.stderr","status"]`
(`differ.rs:123`), and the loader refuses the fold in as many words (`run.rs:1189-1194`):

> *entry … is kind=additive but names … — additive may only ever take … **There is no superset
> relation for a status code, a usage figure, a readback or a missing cell.***

So the prior audit note's option A ("fold these four cells' effects.readback into F-011 as
`additive`") **is not available with the pinned judge**, and option B ("delete it outright") turns
four admin-write cells red. That is worth knowing before the owner rules.

### The CHANGELOG is also carrying the false break — in two places

`kind: breaking` requires a verbatim CHANGELOG line, and it is there:

- `CHANGELOG.md:402-405` — *"the always-null `at` field on the hook view gives way to `fires_at` …
  and **no longer carries `at`**, which was always `null` in 1.5.5 and told a caller nothing."*
- `CHANGELOG.md:458` — the same claim inside the prose summary.

**Both are false of the shipping code.** This is a published breaking-change notice for a break that
did not happen.

### Recommendation (owner decision; not made here)

1. **Do not delete.** Four owed admin-write cells lose their only readback cover.
2. **Re-sign with the true premise.** The readback gains three fields and keeps `at` byte-for-byte.
   Because `effects.readback` is money-rated and has no superset proof, the entry must stay
   `kind: breaking` — but its `changelog` must be rewritten to state the **additive** change, and
   `CHANGELOG.md:402-405` and `:458` must be corrected with it.
3. **The durable fix is upstream:** give `effects.readback` a superset proof in busbar-oracle, then
   fold these four cells into F-011 and retire F-011r. That is the only route to a *proof* rather
   than a signature on this class.
4. F-011's own rationale repeats the same falsified sentence in its `SPLIT 2026-09-05` paragraph and
   must be corrected in the same pass. (F-011r credits the correction to F-011; it is actually in
   **F-011b**'s `SECOND LEAF ADDED 2026-09-11` paragraph. F-011 was never updated.)

### A5. `F-011c` "openapi overlay-delete /paths prose" — **FALSIFIED against the pinned judge**

`kind: breaking` · `classes: [body, headers]` · 3 cells. `body` is rated **10** on `admin.ops`

> object … The durable fix is the upstream busbar-oracle `/paths`-pointer repair (RFC-6901 `~1`

**The repair has landed and is in the pinned judge.** `differ.rs:141-146` defines `ptr_escape`
(`~`→`~0`, `/`→`~1`) and `ptr_unescape`; `resolve_json_pointer` unescapes every token
(`differ.rs:158`); and `additive_superset` **builds** its pointers escaped
(`run.rs:171`, `differ.rs:197`).

Demonstrated against the actual golden document. Under the judge's own convention the three leaves
resolve:

```
/paths/~1api~1v1~1admin~1overlay~1{section}/delete/summary                     → resolves (string)
/paths/~1api~1v1~1admin~1overlay~1{section}/delete/responses/400/description   → resolves (string)
/paths/~1api~1v1~1admin~1overlay~1{section}/delete/responses/409/description   → resolves (string)
/paths//api/v1/admin/overlay/{section}/delete/responses/400/description        → does NOT resolve
```

All three leaves still differ from the golden, so the *divergence* is real — but it is now
**leaf-correctable on F-011b (`kind: additive`)**, which is exactly what F-011c's own rationale says
should happen once the tool is repaired.

**What it authorises, and the live cost.** F-011c's own text states it: *"breaking forgives whole
classes, not leaves, so this blankets `body`/`headers` on these cells and their document body is no
longer gated by the additive superset proof — a future regression in the rest of

**That cost is being paid right now.** In the working tree at the time of this audit,
`crates/busbar-core-admin/src/v1/json/openapi.json` carries an uncommitted change to

UNDER THIS RECORD'S OWN `scheme`") and `AuditEntry.required` gains `"scheme"`. That description leaf
is named by **no** `description_corrections` entry. Under F-011b alone it would be RED and would have

## 8. WHAT THE AUDIT FOUND ABOUT THE INSTRUMENT ITSELF

These are not entry defects. They are properties of the register + judge that make entry defects
cheaper to make and harder to see.

### 8.1 The register has ONE `by:` field, and edits accrete under it

`by:` is a single string. There is no per-edit provenance. Commit `48ea84225` (2026-09-21) changed
G-1's `kind` **and added `effects.usage` to its `classes`** while `by:` continued to read
*"owner (Matthew Jackson), 2026-09-07 ruling"*. Since 2026-09-15, the register has also had five
entries removed (`D-2`, two `F-013`s, `F-017`, `O-1`, by `19550dd90` — all by **fixing** the
divergence, which is fail-closed) and one added (`F-019`, owner-approved on a parked report). Nothing
in the file records which change was whose. **Recommendation: an append-only `amendments: [{date, by,
what}]` array, and a gate that reds a `classes` widening whose newest amendment is not the owner's.**

### 8.2 The money classes do not cover the money READS

`money_classes()` (`differ.rs:74-88`) and `BODY_IS_CONTRACT` (`differ.rs:91-98`) together decide what
is money-rated. `BODY_IS_CONTRACT` is `admin.ops, boot.refusal, boot.warning, config.migrate, cli,
ops.scrape`. **`billing` and `ledger` are not in it** — and measured across their goldens:

```
billing|admin-usage|past-day          body has spend_micros: True    effects.usage: {}
billing|rate-card|epoch-mid-window    body has spend_micros: True    effects.usage: {}
ledger|currency|minor-unit-rounding   body has spend_micros: True    effects.usage: {}
ledger|rate-history|as-of             body has spend_micros: True    effects.usage: {}
```

`effects.usage` is populated on the **proxy** path (`llm.wire`, `route.failover`) — the metering tap.
It is **empty on the admin money READS**, where the figure travels in `body`, rated **3**. So:

- D-3 pays `kind: breaking` for a class that is empty on its own cells;
- D-4 (an `improvement`) forgives `body` on `ledger|currency|minor-unit-rounding`, the exact cell its
  own text says *"must not move at all"*;
- **any `improvement` entry may forgive a wrong `spend_micros` in a `billing`/`ledger` response body.**

**Recommendation: add `billing` and `ledger` to `BODY_IS_CONTRACT` upstream.** That single change
converts several of the softest waivers in this register into ones only a `breaking` entry with a
CHANGELOG line can take.

### 8.3 `classes` is per-entry, not per-cell

`entry_may_take` (`run.rs:681-687`) grants the entry's whole allowed set on **every** matched cell.
Several rationales scope a class to one cell in prose (F-016's `BOOT-P31` *"class `effects.stderr`
only"`*; D-3's *"`ledger|currency|minor-unit-rounding` may not be forgiven by it"*). **The mechanism
cannot honour that.** Either the register gains per-cell classes, or such scoping must be expressed
by splitting the entry.

### 8.4 An entry with no `classes` gets an implicit set

D-1 is the **only** entry with no `classes` field. `allowed_classes("improvement", {})`
(`run.rs:637-660`) yields `{body, headers, effects.stderr, effects.metrics, effects.audit,
norm.rules}` over all 462 cells. **Materially bounded** — because D-1 carries a `transform` it lands
in `set.transforms` and **never** in `set.accepted` (`run.rs:1376-1382`), so it forgives only when the
rewrite makes the two sides fully byte-equal (`cls.is_empty()`, `run.rs:1682`). It cannot forgive on
say-so. **Residual, and worth the owner's eye:** the transform path unions the raw `allowed` into
`cover_t` (`run.rs:1685-1687`) **without** the `money_at_cell` narrowing the normal path applies — so
the judge's own advisory note (*"Those classes are NOT forgiven on those cells"*, `run.rs:1400-1405`)
does not hold on that path. **Recommendation: give D-1 an explicit `classes`.**

### 8.5 Transforms rewrite the CANDIDATE too

`apply_transform` runs over golden **and** candidate (`run.rs:1666-1667`). Two live consequences:

- **F-019** — rule 2 collapses `could not read service-account key file '<arg>'` to `<REF>` on the
  candidate, so a 1.6.0 regression that re-leaked the RS256 key would report ACCEPTED. The rule is
  only needed on the golden side.
- **D-1** — rule 2 deletes ` diag=BUSBAR-\d{4}` from both, so a *changed* diagnostic code is masked.
  Inert today (zero `BUSBAR-[0-9]` across all 916 goldens); live the day the golden is re-recorded.

### 8.6 The two cells built to prove S-9 and S-10 are covered by NEITHER register

Cross-checked every `SKIP` cell against both registers:

```
llm|responses|responses|request|ok_citation           register: —   accepted-gaps: —
llm|bedrock|bedrock|request|ok_cachepoint_document    register: —   accepted-gaps: —
```

Both entries' regexes are anchored `ok(_stream)?$` and cannot reach them. Nothing is red today
(they are `SKIP`), but the entries that describe those behaviours do not reach the cells built to
demonstrate them.

### 8.7 The CHANGELOG gate proves presence, never truth

`xtask/src/gates/changelog_register.rs` checks that each entry's `changelog` string appears verbatim
(whitespace-normalised, `normalize()` at `:699-701`) in the newest `## [x.y.z]` section. Re-run here
under the gate's own anchoring: **all 41 lines are present.** The judge itself only checks that the
key is *truthy* (`run.rs:1152`).

**Neither checks that the line is true.** Three published CHANGELOG statements are false of the
shipping code:

- `CHANGELOG.md:402-405` and `:458` — the hook view *"no longer carries `at`"* (§2).
- `CHANGELOG.md:159-163` — the validation-message bullet, false in **all five** specifics (§B1).
- the PR2-D4 bullet — *"previously billed the key zero tokens"*, contradicted by its own cell's
  golden (§A1).

### 8.8 `accepted-gaps.json` carries no person

Spec #59: *"Adding an entry to the accepted-gaps register ALWAYS requires explicit owner approval —
an agent may NEVER self-approve a gap under the owner's name."* The file's three rows carry keys
`{cells, id, owner, rationale}` — **no `by` field at all**, and `owner` holds a team label
(`"llm-plane"`), not a person. The `gemini-tool-use-token-term` row additionally says recording is
*"blocked on the owner promoting G-1 to kind=breaking"* — a blocker cleared by an agent (§A2).
**Read-only observation; nothing was changed.**

## 9. THE ONE THING THIS AUDIT CHANGED

**`qa/construction.toml` — a `dialect`-kind contradiction, two rulings in one file.**

The file stated both of these:

- **Header, `[gate.plugin_kinds]` preamble (lines 34-42), and the `[gate.census.plugin_kinds]` note
  (~line 1631):** *"THE SEVEN PLUGIN KINDS (DECISIONS #3, locked) … `control` and `dialect` are gone
  (DECISIONS #4/#5) … a dialect is a thing inside a plane with no crate of its own"*; *"a key naming a
  struck kind (control/dialect/…) … is RED"*; *"`dialect` = 0 and `control` = 0 are STRUCK."*
- **`[gate.plane_codec_crates]` preamble (lines 114-120):** *"OWED (PLUGIN-TREE.md, owner
  2026-09-07): these four crates **ARE the dialect kind**, unnamed … The 2026-09-06 decision to FOLD
  each codec into its plane is superseded: **each codec SPLITS into `busbar-plane-<plane>-<dialect>`
  crates.**"*

The second **is D36**, and the spec settles it with no room left:

- **BUSBAR-1.6.0.md #3:** *"**NOT kinds:** control (admin/oauth2 = cleanliness crates, #5), **dialect
  (inside a plane, #4)**, unit."*
- **BUSBAR-1.6.0.md, "Rejected (do not resurrect)":** *"**D36 'dialect as a plugin kind' /
  per-dialect crates** (`busbar-plane-<plane>-<dialect>`). A dialect is not a plugin kind and gets no
  crate of its own (Law 5). **No crate is ever kind 'dialect'.**"*
- And it is the reading the rest of the tree already took: `xtask/src/gates/kind_isolation.rs:239-241,
  401, 473, 5346-5348, 5805` all implement "a dialect is not a kind"; `docs/design/PLUGIN-TREE.md:20,
  184-186, 248-249, 266` says the same.

**The stale statement is the `OWED` block.** It cites the 2026-09-07 PLUGIN-TREE ruling, which
DECISIONS #4 reversed, and it was already false on its own terms — it says *"these four crates"*
while `[gate.plane_codec_crates]` lists two. It was **rewritten to the spec**; the still-true,
D36-independent part (the llm `DECLS` order must be pinned by an oracle boot cell before any
reshaping — it has been silently swapped once) was **kept**. No data key, glob, ceiling or count was
touched; the file still parses and `[gate.plane_codec_crates]` is unchanged
(`{busbar-llm: [busbar-llm-codec], busbar-voice: [busbar-voice-codec]}`).

**Related, NOT changed, flagged instead:** `qa/kind-isolation.toml:3788-3797` ("THE DIALECT COLUMN")
still says *"the kind lands as `busbar-plane-<plane>-<dialect>` when the codec split finishes."* That
sentence is stale in the same way — but the column itself is the vocabulary axis the spec explicitly
**KEEPS** (*"Kept on purpose — do not confuse with the above … The purity gate's 'dialect'
vocabulary axis … STAYS. It is a vocabulary scan, not a claim that any crate is a dialect plugin."*),
and that file was being actively edited by another agent during this audit. Left for the coupled
doc + table + reader reconcile the status ledger already queues.
