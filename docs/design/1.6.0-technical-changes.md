# 1.6.0 technical changes — porting from 1.5.x

**Audience:** anyone who built against busbar 1.5.x internals — a plugin, a `Store`
implementation, a fork, or code that imported `busbar`'s crates or `mcp`/`a2a`/plane types — and
needs it to work on 1.6.0. If you only consume the **HTTP/MCP/A2A wire surface** as an operator,
you want [`CHANGELOG.md`](../../CHANGELOG.md) + [`migration-1.6.md`](../migration-1.6.md) instead;
this doc is the **code/ABI-level** map.

---

## TL;DR — the one change that matters

**In 1.5.x, protocols lived inside the engine.** The LLM dialects, MCP, and A2A were all baked into
one `busbar` crate; you could `use busbar::mcp::…`, match on `enum Plane`, and reach protocol data
structures directly.

**In 1.6.0, every protocol is a plugin, and the engine is a library.** `busbar` split into
**`busbar-kernel`** (the engine, a lib) + `busbar` (a thin bin). The LLM dialects, MCP, and A2A each
live in their own crate (`busbar-llm` + `busbar-llm-codec`, `busbar-mcp`, `busbar-a2a`) and reach the
kernel **only** through a stable seam: a **host-capability vtable**, the **`PlaneDecl`** declaration,
and an **append-only ABI**. The kernel speaks a neutral IR and names **zero** protocol types —
*"core-is-core."*

> **There is no `busbar-core` crate.** An interim `busbar-core` existed mid-cycle and was absorbed
> into `busbar-kernel` before the cut (DECISIONS #19/#37: *"`busbar-core` is deleted"*). If a draft
> of this guide told you to depend on `busbar-core`, the crate it named never shipped — depend on
> **`busbar-kernel`**.

If your code touched protocol internals or depended on the `busbar` crate as a library, it changes.
If it only touched the public record types or the wire surface, most of it still compiles — but the
record types **moved crates** (§2, §7).

---

## 1. The big picture: everything is a plugin

1.5.x was one engine with protocols compiled in. 1.6.0 is a neutral core with **protocol plugins on
one uniform seam** — the LLM plane (`busbar-llm`) was the template, and MCP (`busbar-mcp`) + A2A
(`busbar-a2a`) are its siblings. The invariants (the "Law"):

- **Behavior is independent of linkage.** Compiled-in vs. loaded-from-a-folder is packaging only;
  there is exactly one code path, and the seam is always used.
- **Core-is-core.** Core names zero protocol types — no `crate::mcp::`, no `crate::a2a::`, no LLM
  dialect. This is CI-enforced by seam witnesses.
- **Confinement.** No secret, live `Transport`, `GovState`, `Admission`, or `VirtualKey` ever
  crosses the seam. A plane holds opaque handle-IDs and reaches capabilities by reference.

## 2. New crate topology — what `busbar` became

If your build named a `busbar` crate or module path, start here.

Every name below is a package name you can actually write in a `Cargo.toml` against this tree.

| crate | what it is | 1.5.x origin |
|---|---|---|
| **`busbar-kernel`** | **the engine, now a library** — the loop, plane registry, governance, audit, store, config, and the host seam. **This is what `busbar`-as-a-library became.** | was the bulk of `busbar` |
| **`busbar`** | thin binary (arg parse → boot `busbar-kernel`) | was the whole thing |
| **`busbar-kernel-{identity,scope,budget,ledger,egress,breaker,wal,audit}`** | the 8 workflow crates the kernel drives (authN, authZ, afford, the book, the upstream leg, trip/cooldown, the append primitive, the chain) | were inside the engine |
| **`busbar-core-admin`** | the admin verb surface (`/api/v1/admin/*`) + its OpenAPI | was `busbar::admin` |
| **`busbar-oauth2`** | the OAuth 2.1 authorization-server plane (`oauth_as:`) | was `busbar::oauth_as` |
| **`busbar-substrate-values`** | the pure shared substrate: json/eventstream/media/SigV4 codecs, the proto registry, diagnostics, the signal catalogue | was scattered through `busbar` |
| **`busbar-contract`** | the sealed **shapes** every plugin may name: `PlaneRecord`, `ScopeRef`, `VirtualKey`, `CredentialSecret`, `Redacted<T>`, `constant_time_eq` | was `busbar-api` |
| **`busbar-plugin`** | the unified plugin ABI (hot + cold lanes) | was two separate ABI crates |
| **`busbar-plugin-sdk`** / **`busbar-plugin-loader`** | the plugin-side SDK and the host-side loader | were `busbar-plugin-abi` + loader internals |
| **`busbar-llm`** (+ **`busbar-llm-codec`**) | the LLM plane: engine + `PLANE_DECL` in `busbar-llm`; the six dialect readers/writers and the concrete LLM IR in `busbar-llm-codec` | was `busbar::proto::*` dialects in core |
| **`busbar-mcp`** | the MCP protocol plane | was `busbar::mcp` |
| **`busbar-a2a`** | the A2A protocol plane | was `busbar::a2a` |
| **`busbar-api`** | the residual shared types; **retiring** (#35) — `Redacted`, `constant_time_eq`, `UpstreamCreds` and the signal catalogue are now re-exports of `busbar-contract` | same |
| **`busbar-timing`** | debug-only micro-timing, zero-cost when off | new |

**Porting hit:** if you depended on `busbar` as a library, depend on **`busbar-kernel`**. If you
imported a protocol module, depend on the matching plane crate (`busbar-llm`/`busbar-llm-codec`/
`-mcp`/`-a2a`). If you imported a record type or `ScopeRef`, depend on **`busbar-contract`** — or,
for `McpCallRecord`/`TaskRow`, on the owning plane crate (§7).

> **Naming still moves after 1.6.0.** DECISIONS #34/#37 rename `busbar-oauth2` →
> `busbar-core-oauth2` and `busbar-substrate-values` → `busbar-core-substrate` in one `git mv`
> wave. The names in the table above are the ones on disk today; pin a version, not a naming
> scheme.

## 3. The seam you port against

Three pieces. If you're adapting protocol-side code, this is the whole interface.

### 3a. The host-capability vtable — how a plane reaches core substrate
A plane reaches core substrate **only** through the host vtable
(`crates/busbar-kernel/src/plane_host/`), a
`repr(C)` table of data-in/data-out slots — each takes bytes and returns a `HostCallResult` — so
nothing protocol-shaped crosses the boundary. The capability families:

| capability | what it does |
|---|---|
| `govern_admit` | governance / admission decision for a request |
| `meter_charge` | usage metering / cost charge (carries the itemized `CostBreakdown`) |
| `egress_open` / `poll` / `write` / `close` / `fault` | a governed, SSRF-pinned outbound HTTP call + streaming |
| `breaker_admit` / `breaker_settle` | circuit-breaker admission (returns an `AdmissionId`) + settle |
| `journal_append` / `journal_read` | append to / read back a durable hash-chained plane chain (calllog / task / audit) |
| trust family (`verify_lookup` / `verify_store`, drift-quarantine, approval-redeem) | tool/agent trust + MCP ask-state |
| nested dispatch | a plane invokes another plane through core (replaces `run_operation`; dissolves the old MCP→LLM coupling) |
| `metrics_emit` | emit a telemetry series |
| `clock_now` | the host clock (a plane never reads wall-clock itself) |

**No `secret_resolve` slot** — by design (confinement). Egress carries a **credential *ref***; the
host mints the per-hop bearer / RFC 8693 exchange. The vtable is **append-only**: new slots go at
the tail, never reshaped, so a host and a plane at different ABI minors interoperate.

### 3b. `PlaneDecl` — the plane→core declaration
`busbar_kernel::plane::registry::PlaneDecl` (`crates/busbar-kernel/src/plane/registry.rs:811`) is
the data record a plane publishes so core can mount and
dispatch it without naming its types: key, config-section name, declared **scope kinds**, **wire
formats** (`WIRE_JSONRPC` / `WIRE_HTTP_JSON` / `WIRE_GRPC`), mount path, `config_validate`,
`build`/`hydrate`/`on_swap`, `admin_routes()`+`openapi()`, and the two ingress kinds (route +
stream). The request path itself rides `PlaneDecl::dispatch`.

### 3c. `install_planes()` and the `enum Plane` removal
The binary registers planes at boot with
`busbar_kernel::plane::registry::install_planes(&[&busbar_mcp::PLANE_DECL, &busbar_a2a::PLANE_DECL, …])`
(`crates/busbar-kernel/src/plane/registry.rs:312`, called from `crates/busbar/src/main.rs:301`).
**`enum Plane { Llm, Mcp, A2a }` is removed** — everything keyed on it (dispatch, `PlaneSections<T>`, `Ingress::Mounted`,
config classification) is now keyed on a `&'static str` **registry key** (`"llm"`/`"mcp"`/`"a2a"`).
**If you matched on `Plane::Mcp`/`Plane::A2a`, switch to the key + `plane_decl_for(key)`** (`crates/busbar-kernel/src/plane/registry.rs:582`). Relatedly, `Operation`
collapsed to a **single** `Verb { op: OpShape, name: &'static str }` variant
(`crates/api/src/operation.rs:192`) — the decision is taken on the closed `OpShape` and the wire's
own word is carried through untouched. The old thirteen are now associated **constants**
(`Operation::CHAT` … `Operation::RERANK`, plus `Operation::INVOKE`/`CATALOGUE`/`FETCH`/`TASK`/
`SUBSCRIBE`/`CONTROL`), so a protocol that adds a method adds a `const` in **its own** module
instead of touching a core enum.

## 4. The plugin ABI — one crate, two lanes, append-only

`busbar-plugin` unifies the ABI into two lanes:

- **HOT lane** (MCP, A2A) — a `repr(C)` POD-fast path: POD-by-pointer, ~+1ns/call, **0 alloc**, zero
  per-token host crossings. `ABI_MINOR` (currently the hot-ABI capability counter) advanced
  append-only across the cycle; **`POD_VERSION = 3`** (`crates/busbar-plugin/src/hot/pod.rs:21`).
- **COLD lane** (store, secret, auth, hook, export) — the existing JSON path, unchanged in shape.
  Cold ABI versions, as the constants read today: **store = 4**
  (`cold::ABI_VERSION`, `crates/busbar-plugin/src/cold/mod.rs:173` — the loader's `supported_abi`
  floor for `store` is still 2, so an older store plugin keeps loading), auth = 2
  (`crates/busbar-plugin/src/cold/mod.rs:597`), export = 3
  (`crates/busbar-plugin/src/cold/export.rs:67`), hook = 1
  (`crates/busbar-plugin/src/cold/hook.rs:38`), secret = 1
  (`crates/busbar-plugin/src/cold/mod.rs:581`).

Two rules define the contract you rely on:

- **Append-only.** New fields go at a struct's **tail** (behind a leading `size:u32` + `version:u16`);
  existing fields never move or change meaning. A golden layout test (`abi-layout.golden`) freezes
  every offset; a reblessing is only ever an append.
- **`ABI_MINOR` is a monotonic capability counter, never a refusal reason on its own** — different
  minors interoperate because everything added is trailing.

### The neutral `Store` surface (the change most likely to hit a `Store` impl)
The **14 protocol-named `Store` methods are deleted** and replaced by a **neutral, kind-tagged**
surface: records flow through `append_plane_record` / `list_plane_records` / `get_plane_record` /
`purge_plane_records_before` (`crates/busbar-contract/src/records.rs:1386-1421`) with
`encode`/`decode` and a hash-chained position, tagged by kind — `KIND_CALL`, `KIND_TASK`,
`KIND_TASK_EVENT`, `KIND_AUDIT` (`crates/busbar-kernel/src/plane/store.rs:52-59`) and the per-plane
`KIND_DEMOTION` (`crates/busbar-plane-mcp/src/records.rs:53`). The `ScopeRef::mcp_server` /
`mcp_tool` constructors are dropped — `ScopeRef` (`crates/busbar-contract/src/records.rs:50`) is
generic and each admission site names the scope kind it expects (scope kinds are declared by each
plane's `PlaneDecl`, not hardcoded in a shared crate).

## 5. What moved — module/crate map

| 1.5.x location | 1.6.0 location | notes |
|---|---|---|
| `busbar::mcp::**` (incl. `client/`) | `crates/busbar-mcp/src/mcp/**` | whole protocol body + its unit tests |
| `busbar::a2a::**` | `crates/busbar-a2a/src/a2a/**` | whole protocol body + its unit tests |
| `busbar::proto::*` LLM dialects + concrete IR | `crates/busbar-llm-codec/src/{anthropic,openai_chat,openai_responses,gemini,bedrock,cohere}/` | the kernel keeps only the **neutral** IR seam; the plane engine + `PLANE_DECL` are in `crates/busbar-llm/src/` |
| `busbar::proxy::wire` (ingress reject → native envelope) | `crates/busbar-llm/src/engine/wire.rs` | left the kernel with the rest of the LLM engine |
| `plane/taskstore.rs`, `plane/provenance.rs` | `crates/busbar-a2a/src/taskstore.rs` | A2A task store + event provenance, incl. `verify_task_chain` |
| `McpCallRecord` | `crates/busbar-mcp/src/record.rs:24` | **moved out of the shared api crate** into the owning plane |
| `TaskRow`, `TaskEventRow` | `crates/busbar-a2a/src/record.rs:50,107` | same — the owning plane owns its rows |
| `plane/store.rs` **per-kind** builders (`call_record`, `task_record`, …) | plane crates | the **neutral** trait / `encode` / `decode` **stay** kernel-side |
| `plane_host/**`, `plane/registry.rs`, `plane/mod.rs` dispatch, `plane/config.rs`, `plane/auditlog.rs`, the hash-chained journal | **`crates/busbar-kernel/src/`** | the seam substrate — neutral, names no protocol type |
| `Redacted<T>`, `constant_time_eq`, `ScopeRef`, `VirtualKey`, `CredentialSecret`, `PlaneRecord` | `crates/busbar-contract/src/` | the sealed shapes; `busbar-api` re-exports each at its historical path |

Plane crates are compiled-in rlibs (same shape across `busbar-llm`/`-mcp`/`-a2a`), each exporting
`pub const PLANE_DECL` (`crates/busbar-llm/src/lib.rs:220`, `crates/busbar-mcp/src/mcp/mod.rs:122`,
`crates/busbar-a2a/src/a2a/mod.rs:72`). The admin **audit** chain is **one** hash chain with three
streams on top; the durable **journal**, the **`PlaneStore`** trait, and the **config sibling
container** are neutral and live in `busbar-kernel`.

## 6. If you built against 1.5.x — the porting checklist

- **You depended on the `busbar` crate as a library** → depend on **`busbar-kernel`**. (Not
  `busbar-core`: that crate does not exist — see §2.)
- **You imported `busbar::mcp::*` / `::a2a::*` / an LLM dialect** → depend on `busbar-mcp` /
  `busbar-a2a` / `busbar-llm` (+ `busbar-llm-codec` for a dialect reader/writer), or reach the
  behavior via the host vtable / `PlaneDecl`. **The record structs moved with their planes:**
  `McpCallRecord` is `busbar_mcp::record::McpCallRecord`, `TaskRow`/`TaskEventRow` are
  `busbar_a2a::record::{TaskRow, TaskEventRow}`. `busbar-api` no longer defines them.
- **You imported `ScopeRef` / `VirtualKey` / `PlaneRecord` / `CredentialSecret` / `Redacted<T>` /
  `constant_time_eq`** → they live in **`busbar-contract`** now. `busbar-api` re-exports each at
  its historical path, so `busbar_api::Redacted` still resolves; new code should name the contract
  crate directly.
- **You matched on `enum Plane`** → use the registry key (`"mcp"`/`"a2a"`/`"llm"`) +
  `plane_decl_for(key)`. `PlaneSections`/dispatch/`Ingress` are `&str`-keyed.
- **You implemented a `Store`** → drop the 14 protocol-named methods; implement the neutral
  kind-tagged surface. Remove `ScopeRef::mcp_server`/`mcp_tool` uses. The cold store ABI constant
  now reads 4; the loader's accepted range still starts at 2, so a plugin built against the older
  constant keeps loading.
- **You wrote a plugin or host over the C ABI** → recompile against `busbar-plugin`. Append-only
  means existing behavior is unchanged; you add code only to consume a new trailing slot/field.
  `abi-layout.golden` is the authoritative field set.
- **You called a core substrate helper from protocol code** (egress client build, audit `record_by`,
  usage charge, breaker, catalogue) → route through the host slot (`egress_open`, `journal_append`,
  `meter_charge`, `breaker_admit`, …). Egress: the host owns resolve-then-pin + trust-anchor +
  client-identity + per-hop timeout; a plane hands its guard-judged address, deadline, and
  credential **ref** in — never a secret, never its own client.
- **You matched on `Operation::ToolCall`** → `Operation` has one variant now. Match
  `Operation::Verb { op, name }` and decide on `op` (`OpShape::Invoke`), or compare against the
  `Operation::INVOKE` constant; `name` carries the wire's own word.
- **You scraped `busbar_requests_total` / `busbar_request_duration_seconds`** → both gained a
  **`plane`** label (`llm`/`mcp`/`a2a`); update aggregations.
- **You set operational env vars** → `BUSBAR_PROVIDERS`, `BUSBAR_CONFIG_OVERLAY`,
  `BUSBAR_WORKER_THREADS`, `BUSBAR_UPSTREAM_HTTP1_ONLY`, `BUSBAR_UPSTREAM_H2_PRIOR_KNOWLEDGE` are
  **DEPRECATED, not removed.** Each is still read and still wins over the config key, and each
  fires a one-shot `DEPRECATED_ENV_VAR_HONORED` warning at boot
  (`crates/busbar/src/root/cli.rs:554`, `crates/busbar-kernel/src/config/overlay.rs:88`,
  `crates/busbar/src/main.rs:784-788`, `crates/busbar-kernel/src/appbuild.rs:937-960`). Move to the
  config keys now (`-c`/`--config` and `--providers` are flag-first) — they are honored "for now",
  not forever.
- **You depend on removed config/API surface** → see [`migration-1.6.md`](../migration-1.6.md): hook
  `plugin:`→`module:`; hook `at:`→`phase:`; `persist:` dropped; hook-response `at`→`fires_at`/`phase`;
  `/stats` `limit`→`max_concurrent`; MCP tool `refresh_ttl:`→`verify_ttl:` (verify-on-call).
  `busbar --migrate-config` rewrites config; a persisted overlay auto-migrates at boot.

## 7. What did **not** change

- **The LLM proxy money path is byte-identical.** Its wire bytes and cost accounting are frozen (a
  release gate); the extraction did not touch it.
- **The record types are field-for-field unchanged** (`McpCallRecord`, `TaskRow`, `TaskEventRow`,
  …) — but they changed **crate**, from `busbar-api` to the owning plane
  (`crates/busbar-mcp/src/record.rs`, `crates/busbar-a2a/src/record.rs`). Fix the `use` line; the
  shape and the wire bytes are the same.
- **Append-only ABI** → old compiled plugins keep loading; recompile only for new capabilities.
- **Persisted state boots forward.** No 1.5.x store is bricked; the audit/journal chains restore
  byte-exactly and legacy config overlays auto-migrate at boot.
- **Core-is-core:** governance, metering, the journal, the `PlaneStore` trait, the config container,
  and the host vtable are the stable neutral ground everything builds on.
