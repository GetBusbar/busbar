# 1.6.0 technical changes — porting from 1.5.x

**Audience:** anyone who built against busbar 1.5.x internals — a plugin, a `Store`
implementation, a fork, or code that imported `busbar`'s crates or `mcp`/`a2a`/plane types — and
needs it to work on 1.6.0. If you only consume the **HTTP/MCP/A2A wire surface** as an operator,
you want [`CHANGELOG.md`](../../CHANGELOG.md) + [`migration-1.6.md`](../migration-1.6.md) instead;
this doc is the **code/ABI-level** map.

---

## TL;DR — the one change that matters

**In 1.5.x, protocols lived inside the engine.** The LLM dialects, MCP, and A2A were all baked into
one `busbar` crate; you could `use busbar::mcp::…`, match on `enum Plane`, and reach protocol data
structures directly.

**In 1.6.0, every protocol is a plugin, and the engine is a library.** `busbar` split into
`busbar-core` (the engine, a lib) + `busbar` (a thin bin). The LLM dialects, MCP, and A2A each live
in their own crate (`busbar-llm`, `busbar-mcp`, `busbar-a2a`) and reach core **only** through a
stable seam: a **host-capability vtable**, the **`PlaneDecl`** declaration, and an **append-only
ABI**. Core speaks a neutral IR and names **zero** protocol types — *"core-is-core."*

If your code touched protocol internals or depended on the `busbar` crate as a library, it changes.
If it only touched the public `busbar-api` record types or the wire surface, most of it is
unchanged (§7).

---

## 1. The big picture: everything is a plugin

1.5.x was one engine with protocols compiled in. 1.6.0 is a neutral core with **protocol plugins on
one uniform seam** — the LLM plane (`busbar-llm`) was the template, and MCP (`busbar-mcp`) + A2A
(`busbar-a2a`) are its siblings. The invariants (the "Law"):

- **Behavior is independent of linkage.** Compiled-in vs. loaded-from-a-folder is packaging only;
  there is exactly one code path, and the seam is always used.
- **Core-is-core.** Core names zero protocol types — no `crate::mcp::`, no `crate::a2a::`, no LLM
  dialect. This is CI-enforced by seam witnesses.
- **Confinement.** No secret, live `Transport`, `GovState`, `Admission`, or `VirtualKey` ever
  crosses the seam. A plane holds opaque handle-IDs and reaches capabilities by reference.

## 2. New crate topology — what `busbar` became

If your build named a `busbar` crate or module path, start here.

| crate | what it is | 1.5.x origin |
|---|---|---|
| **`busbar-core`** | the engine, **now a library** — neutral substrate + the seam | was the bulk of `busbar` |
| **`busbar`** | thin binary (arg parse → boot `busbar-core`) | was the whole thing |
| **`busbar-llm`** | LLM dialect plugin (anthropic, openai-chat, openai-responses, gemini, bedrock, cohere) + the concrete LLM IR | was `busbar::proto::*` dialects in core |
| **`busbar-mcp`** | the MCP protocol plane | was `busbar::mcp` |
| **`busbar-a2a`** | the A2A protocol plane | was `busbar::a2a` |
| **`busbar-plugin`** | the unified plugin ABI (hot + cold lanes) | was two separate ABI crates |
| **`busbar-api`** | shared public record/data types (`McpCallRecord`, `TaskRow`, …) — **unchanged home** | same |
| **`busbar-timing`** | debug-only micro-timing, zero-cost when off | new |

**Porting hit:** if you depended on `busbar` as a library, depend on **`busbar-core`**. If you
imported a protocol module, depend on the matching plugin crate (`busbar-llm`/`-mcp`/`-a2a`).

## 3. The seam you port against

Three pieces. If you're adapting protocol-side code, this is the whole interface.

### 3a. The host-capability vtable — how a plane reaches core substrate
A plane reaches core substrate **only** through the host vtable (`busbar-core/src/plane_host/`), a
`repr(C)` table of data-in/data-out slots — each takes bytes and returns a `HostCallResult` — so
nothing protocol-shaped crosses the boundary. The capability families:

| capability | what it does |
|---|---|
| `govern_admit` | governance / admission decision for a request |
| `meter_charge` | usage metering / cost charge (carries the itemized `CostBreakdown`) |
| `egress_open` / `poll` / `write` / `close` / `fault` | a governed, SSRF-pinned outbound HTTP call + streaming |
| `breaker_admit` / `breaker_settle` | circuit-breaker admission (returns an `AdmissionId`) + settle |
| `journal_append` / `journal_read` | append to / read back a durable hash-chained plane chain (calllog / task / audit) |
| trust family (`verify_lookup` / `verify_store`, drift-quarantine, approval-redeem) | tool/agent trust + MCP ask-state |
| nested dispatch | a plane invokes another plane through core (replaces `run_operation`; dissolves the old MCP→LLM coupling) |
| `metrics_emit` | emit a telemetry series |
| `clock_now` | the host clock (a plane never reads wall-clock itself) |

**No `secret_resolve` slot** — by design (confinement). Egress carries a **credential *ref***; the
host mints the per-hop bearer / RFC 8693 exchange. The vtable is **append-only**: new slots go at
the tail, never reshaped, so a host and a plane at different ABI minors interoperate.

### 3b. `PlaneDecl` — the plane→core declaration
`busbar-core::plane::registry::PlaneDecl` is the data record a plane publishes so core can mount and
dispatch it without naming its types: key, config-section name, declared **scope kinds**, **wire
formats** (`WIRE_JSONRPC` / `WIRE_HTTP_JSON` / `WIRE_GRPC`), mount path, `config_validate`,
`build`/`hydrate`/`on_swap`, `admin_routes()`+`openapi()`, and the two ingress kinds (route +
stream). The request path itself rides `PlaneDecl::dispatch`.

### 3c. `install_planes()` and the `enum Plane` removal
The binary registers planes at boot:
`install_planes(&[&busbar_mcp::PLANE_DECL, &busbar_a2a::PLANE_DECL, …])`. **`enum Plane { Llm, Mcp,
A2a }` is removed** — everything keyed on it (dispatch, `PlaneSections<T>`, `Ingress::Mounted`,
config classification) is now keyed on a `&'static str` **registry key** (`"llm"`/`"mcp"`/`"a2a"`).
**If you matched on `Plane::Mcp`/`Plane::A2a`, switch to the key + `plane_decl_for(key)`.** Relatedly,
`Operation` is a neutral 13-variant enum with a **carried verb** (the old `ToolCall` is now
`Invoke`), so method names are no longer a core enum.

## 4. The plugin ABI — one crate, two lanes, append-only

`busbar-plugin` unifies the ABI into two lanes:

- **HOT lane** (MCP, A2A) — a `repr(C)` POD-fast path: POD-by-pointer, ~+1ns/call, **0 alloc**, zero
  per-token host crossings. `ABI_MINOR` (currently the hot-ABI capability counter) advanced
  append-only across the cycle; `POD_VERSION = 2`.
- **COLD lane** (store, secret, auth, hook, export) — the existing JSON path, unchanged in shape.
  Cold ABI versions: **store = 3**, auth = 2, export = 2, hook = 1, secret = 1.

Two rules define the contract you rely on:

- **Append-only.** New fields go at a struct's **tail** (behind a leading `size:u32` + `version:u16`);
  existing fields never move or change meaning. A golden layout test (`abi-layout.golden`) freezes
  every offset; a reblessing is only ever an append.
- **`ABI_MINOR` is a monotonic capability counter, never a refusal reason on its own** — different
  minors interoperate because everything added is trailing.

### Store ABI v2 → v3 (the change most likely to hit a `Store` impl)
The **14 protocol-named `Store` methods are deleted** and replaced by a **neutral, kind-tagged**
surface: records flow through `append_plane_record` / `list_plane_records` / `get_plane_record` /
`purge_plane_records_before` with `encode`/`decode` and a hash-chained position, tagged by kind
(`KIND_CALL`, `KIND_TASK`, `KIND_TASK_EVENT`, `KIND_DEMOTION`, `KIND_ASK`, `KIND_AUDIT`). The
`ScopeRef::mcp_server` / `mcp_tool` constructors are dropped — `ScopeRef` is generic and each
admission site names the scope kind it expects (scope kinds are declared by each plane's
`PlaneDecl`, not hardcoded in the api crate).

## 5. What moved — module/crate map

| 1.5.x location | 1.6.0 location | notes |
|---|---|---|
| `busbar::mcp::**` (incl. `client/`) | `busbar-mcp` | whole protocol body + its unit tests |
| `busbar::a2a::**` | `busbar-a2a` | whole protocol body + its unit tests |
| `busbar::proto::*` LLM dialects + concrete IR | `busbar-llm` | core keeps only the **neutral** IR seam |
| `plane/calllog.rs`, `plane/approvals.rs`, `plane/quarantine.rs` | `busbar-mcp` | MCP per-kind record/sink shapes |
| `plane/taskstore.rs`, `plane/provenance.rs` | `busbar-a2a` | A2A task store + event provenance |
| `plane/store.rs` **per-kind** builders (`call_record`, `task_record`, …) | plugin crates | the **neutral** trait / `encode` / `decode` **stay** in core |
| `plane_host/**`, `plane/registry.rs`, `plane/mod.rs` dispatch, `plane/config.rs`, `plane/auditlog.rs`, the hash-chained journal | **`busbar-core`** | the seam substrate — neutral, names no protocol type |

Plugin crates are compiled-in rlibs (same shape across `busbar-llm`/`-mcp`/`-a2a`), each exporting
`pub const PLANE_DECL`. The admin **audit** chain is **one** hash chain with three streams on top;
the durable **journal**, the **`PlaneStore`** trait, and the **config sibling container** are
neutral and live in core.

## 6. If you built against 1.5.x — the porting checklist

- **You depended on the `busbar` crate as a library** → depend on **`busbar-core`**.
- **You imported `busbar::mcp::*` / `::a2a::*` / an LLM dialect** → depend on `busbar-mcp` /
  `busbar-a2a` / `busbar-llm`, or reach the behavior via the host vtable / `PlaneDecl`. The record
  structs (`McpCallRecord`, `TaskRow`, …) are still in `busbar-api`.
- **You matched on `enum Plane`** → use the registry key (`"mcp"`/`"a2a"`/`"llm"`) +
  `plane_decl_for(key)`. `PlaneSections`/dispatch/`Ingress` are `&str`-keyed.
- **You implemented a `Store`** → drop the 14 protocol-named methods; implement the neutral
  kind-tagged surface (store ABI v3). Remove `ScopeRef::mcp_server`/`mcp_tool` uses.
- **You wrote a plugin or host over the C ABI** → recompile against `busbar-plugin`. Append-only
  means existing behavior is unchanged; you add code only to consume a new trailing slot/field.
  `abi-layout.golden` is the authoritative field set.
- **You called a core substrate helper from protocol code** (egress client build, audit `record_by`,
  usage charge, breaker, catalogue) → route through the host slot (`egress_open`, `journal_append`,
  `meter_charge`, `breaker_admit`, …). Egress: the host owns resolve-then-pin + trust-anchor +
  client-identity + per-hop timeout; a plane hands its guard-judged address, deadline, and
  credential **ref** in — never a secret, never its own client.
- **You matched on `Operation::ToolCall`** → it's `Operation::Invoke` with a carried verb.
- **You scraped `busbar_requests_total` / `busbar_request_duration_seconds`** → both gained a
  **`plane`** label (`llm`/`mcp`/`a2a`); update aggregations.
- **You set operational env vars** → `BUSBAR_PROVIDERS`, `BUSBAR_CONFIG_OVERLAY`,
  `BUSBAR_WORKER_THREADS`, `BUSBAR_UPSTREAM_HTTP1_ONLY`, `BUSBAR_UPSTREAM_H2_PRIOR_KNOWLEDGE` are
  removed → they're config keys now (`-c`/`--config` and `--providers` are flag-first).
- **You depend on removed config/API surface** → see [`migration-1.6.md`](../migration-1.6.md): hook
  `plugin:`→`module:`; hook `at:`→`phase:`; `persist:` dropped; hook-response `at`→`fires_at`/`phase`;
  `/stats` `limit`→`max_concurrent`; MCP tool `refresh_ttl:`→`verify_ttl:` (verify-on-call).
  `busbar --migrate-config` rewrites config; a persisted overlay auto-migrates at boot.

---

## 7. What did **not** change

- **The LLM proxy money path is byte-identical.** Its wire bytes and cost accounting are frozen (a
  release gate); the extraction did not touch it.
- **`busbar-api` record types** (`McpCallRecord`, `TaskRow`, `TaskEventRow`, …) are the same public
  types in the same crate — only the *builders* and *protocol logic* relocated.
- **Append-only ABI** → old compiled plugins keep loading; recompile only for new capabilities.
- **Persisted state boots forward.** No 1.5.x store is bricked; the audit/journal chains restore
  byte-exactly and legacy config overlays auto-migrate at boot.
- **Core-is-core:** governance, metering, the journal, the `PlaneStore` trait, the config container,
  and the host vtable are the stable neutral ground everything builds on.
