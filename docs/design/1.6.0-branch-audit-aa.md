# 1.6.0 branch audit — slice `aa`

Trunk audited against: `consolidated/1.6.0` @ `897074b56` (`HEAD`). Slice file:
`/tmp/branch-slices/slice-aa`, **103 refs** (the first line, `origin`, resolves through
`refs/remotes/origin/HEAD` to **`origin/main`** @ `4f7e9b03e` — a real branch, audited as such).

## Method actually used

Ancestry and `patch-id` are both useless here (the trunk was rebuilt; the rename waves moved every
path), so the audit is **symbol-based**:

1. `base = git merge-base <branch> HEAD`; `git diff $base..<branch>`, keep only `+` lines.
2. From the added lines, extract declaration identifiers (`fn|struct|enum|trait|type|const|static|mod|macro_rules!` + name),
   `SCREAMING_SNAKE` constants, snake_case names with ≥2 underscores (catches test-function names),
   and quoted string literals ≥10 chars.
3. Presence in the trunk was decided against a **token set of the whole `HEAD` tree**
   (`git archive HEAD crates testing xtask docs tests scripts qa examples conformance fuzz bin .github`
   → 58 MB corpus → 81,567 unique word tokens), so identifier matching is exact and word-bounded;
   string literals were matched with `ripgrep -a -F -f` over the same corpus.
   **`Cargo.lock` is deliberately excluded from the corpus** — a hit there is the false positive that
   hid the NAT64 loss.
4. Every absent identifier was attributed back to the branch file that added it, and split into
   PRODUCTION vs TEST files, because "no test by that name" and "no code by that name" are different
   findings.
5. For anything security-, money- or network-shaped, the trunk's **behaviour** was read, not just its
   spellings. That check changed the verdict four separate times (see "Spelling ≠ behaviour" below)
   — in both directions.
