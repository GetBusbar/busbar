# busbar 1.6.0 — METRICS ABI-purity pass: investigation notes (Bucket A′ metrics)

Base: `e393b9e6` (integration base). Goal: drain busbar-llm's 13 `busbar_core::metrics::`
BACKWARDS reaches by giving the plane a `busbar_substrate::metrics` name, keeping the `/metrics`
scrape ONE registry. This is the P4c "scrape-split risk" move — INVESTIGATE-FIRST.

## 1. The 13 gate-facing reaches (baseline `--baseline`, `PLANE_PURITY_HITS_OUT`)

Total BACKWARDS at base = 153; metrics-specific = **13**, in exactly three shapes:

| # | File:line | Reach | Shape |
|---|---|---|---|
| 8 | `engine/pipeline.rs` :1231,1310,1461,1538 | `ROUTE_POLICY_REJECTIONS_TOTAL` | `&str` name const |
|   | `engine/pipeline.rs` :1333,1364,1427,1564 | `ROUTE_POLICY_SELECTIONS_TOTAL` | `&str` name const |
| 1 | `engine/hooks.rs` :308 | `HOOK_CONTENT_TRUNCATED_TOTAL` | `&str` name const |
| 1 | `engine/response_body.rs` :336 | `BILLING_TRUNCATED_TOTAL` | `&str` name const |
| 3 | `engine/proxy_tests/lane_availability_proptest.rs` :261,603,666 | `metrics::init()` | registry init call |

So **10 of 13 are pure metric-NAME string constants** (4 distinct `pub const … : &str`), and **3 are
`init()`** — the registry installer — in a proptest.

## 2. Where the registry lives today, and why it CANNOT move to substrate

`crates/busbar-core/src/metrics.rs` (1250 lines) owns:

* the singleton `static HANDLE: OnceLock<Option<PrometheusHandle>>` + `static ENABLED` (the registry
  handle),
* `init()`/`init_with()`/`build_recorder()`/`describe()`/`spawn_maintenance()` (install path),
* `render()` and `drain_pending()` (scrape path),
* the per-request cached-handle hot path (`incr_requests_total`, `record_request_duration`, and their
  `plane_*` twins — money-path, alloc-gated),
* `refresh_scrape_gauges(app: &App)` + `emit_lane_gauges()` (scrape-time gauges),
* the metric-name constants + `describe_*` registrations.

**The blocker (dep-cycle / scrape-split):** `render()` and `drain_pending()` call
`crate::telemetry::flush_to_recorder()` — the per-thread TELEMETRY BANK, which is `busbar-core`-only
(`crates/busbar-core/src/telemetry.rs:64 use crate::state::App;`, `AppSlots::build` interns slots from
an `App` snapshot). A scrape that did not flush the bank would DROP every banked hot-path
counter/histogram → the exposition bytes change → the scrape effectively splits. And
`refresh_scrape_gauges` reads `app.governance` / `app.cost` / `app.store` / `app.engine_tables_view()`
— all core `App` impl. Substrate sits BELOW core; moving `render`/`init`/the bank down would drag
`App` into substrate = a dependency cycle. **So the registry singleton + install + render CANNOT be
relocated to substrate without splitting the scrape or a dep-cycle.** This is exactly the STOP
condition the task names.

## 3. …but there is NO active scrape-split surface for metrics at this base

The doc §2 dual-compile hazard ("two core copies own two registries, the scrape splits") assumes the
plane's metrics-EMITTING / RENDERING code is dual-compiled into `busbar-core`. It is not:

* `plane_integration.rs` (the 8 cross-plane tests) had its `#[path]` dual-compile REMOVED — its header
  (`:4-9`) states it now links ONE `busbar_core` as a normal dependency. So there is a single registry
  in that binary. Not a split surface.
* The only busbar-llm source still `#[path]`-re-included into core is **proto/ir** witness files
  (`proto/mod.rs`, `ir/mod.rs`) — NONE of which name `busbar_core::metrics`. The engine files that DO
  (`pipeline`/`hooks`/`response_body`) compile only as busbar-llm proper, against ONE core dependency.
* Emissions are moot anyway: every `metrics::counter!/gauge!/histogram!` routes to the `metrics`
  crate's PROCESS-GLOBAL recorder (single, regardless of core copies). Only `render()` reading a
  copy-local `HANDLE` could split, and no dual-compiled path renders through a second copy.

**Conclusion:** the metric-name constants the plane reaches for are just `&str`; moving them to a
`busbar_substrate::metrics` facade (core re-exporting) is byte-for-byte identical and carries ZERO
scrape-split risk. The registry itself neither needs to move nor can move.

## 4. The 3 `init()` reaches are a gate-detection artifact, not a real ABI reach

`lane_availability_proptest.rs` is declared `#[cfg(test)] mod lane_availability_proptest;` in
`engine/mod.rs:120+` — it is genuinely test-only. The gate counts it because its `intest` test
(`scripts/plane-purity-lint.sh:176`) matches filenames on `/_tests?\.rs$/` — and `…proptest.rs` has
no `_` before `test`, and the `#[cfg(test)]` guard lives in `engine/mod.rs`, not in-file, so the
per-file `#[cfg(test)] mod` tracker never fires. The `init()` reach is test-scope in reality.

## 5. Decision

* **EXECUTE (safe, clean, disjoint):** add `busbar_substrate::metrics` owning the 4 metric-name
  constants; core re-exports them from `crate::metrics` (the exact pattern already used for
  `UPSTREAM_*` ← `substrate::telemetry` and `BILLING_TAP_DECODE_FAIL_TOTAL` ← `substrate::handlers`);
  repoint busbar-llm's engine (`pipeline`/`hooks`/`response_body`) onto `busbar_substrate::metrics::*`.
  Drains **10 of 13** (153 → 143 BACKWARDS). Scrape stays ONE registry, byte-identical (constants are
  the same strings, `describe_*` unchanged, emit sites unchanged).
* **STOP + report (registry move):** relocating `init()`/`render()`/the singleton to substrate is a
  genuine scrape-split + dep-cycle blocker (§2) and is NOT required for correctness (§3). The 3
  remaining `init()` reaches are a proptest-naming gate artifact (§4); draining them is a
  gate-detection nuance (rename the file to match `_tests.rs`, or recognise the proptest as
  test-scope), NOT an ABI move — deferred to the caller/gate owner, not done unilaterally.

## 6. Substrate additions (for reconcile)

* NEW file `crates/busbar-substrate/src/metrics.rs` (name constants only — no registry, no `App`).
* `crates/busbar-substrate/src/lib.rs`: `pub mod metrics;`.
* `crates/busbar-core/src/metrics.rs`: `pub use busbar_substrate::metrics::{…}` re-export block (like
  the existing `telemetry`/`handlers` re-exports) — call sites + `describe_*` unchanged.

Disjoint from the concurrent consolidation agent's registry+hooks+TYPE-rename cherry-pick (different
module).
