# 1.6.0 branch audit — slice `ab`

**Scope.** The 103 remote branches listed in `/tmp/branch-slices/slice-ab` (all `origin/delete/keep-*`),
audited against trunk `consolidated/1.6.0` pinned at **`897074b56f63c0e92dc2802097b407ac5d7413e5`**.
The trunk SHA is pinned rather than read as a moving `HEAD` so every "absent from trunk" claim in this
document is reproducible; other agents were committing to the branch while this ran.

**Method.** Ancestry proves nothing here (the trunk was rebuilt) and `patch-id` proves nothing either
(the 1.6.0 rename waves moved every path). So the unit of comparison is the **symbol**, not the path:

1. `base = git merge-base origin/<branch> <trunk>`; `git diff -U0 $base..origin/<branch>` over
   `crates xtask scripts docs qa .github proto` and a second pass over `testing bin .keep-proof.toml
   Cargo.toml CHANGELOG.md .fix` (the second pass exists because `testing/` alone carries 326 of the
   slice's file-touches and was nearly missed).
2. From the `+` lines only: `fn`/`struct`/`enum`/`trait`/`type`/`const`/`static`/`macro_rules!`
   declarations, enum variants, TOML/YAML keys and section headers, and every quoted string literal of
   7–80 characters.
3. Membership is tested against two indexes built once from the pinned trunk: the set of all 77 014
   identifier tokens in `crates xtask scripts docs qa .github proto`, and the set of all quoted string
   literals. A literal that misses the literal index is re-checked as a substring against the whole
   51 MB trunk corpus before it is reported absent, so "absent" never rests on a truncated window.
4. Independently of symbols, every file the branch **adds** is checked against `git ls-tree -r` of the
   trunk, which catches whole crates and whole fixture corpora that carry no distinctive identifier.

Two cross-checks were applied to the output. A symbol appearing in 8 or more branches is **shared
lineage**, not 83 independent findings — the table says so where it applies. And for everything
security- or money-shaped the trunk's copy was **opened and read**, because a name being present
proves only a spelling: see `keep-core-validate` in the survivors section, where the spelling is
present in the trunk and the behaviour is not.

**Buckets.** `EMPTY` = adds no source content (pure deletion/revert). `HARVESTED` = every distinctive
thing it adds is already in the trunk. `SURVIVOR` = at least one distinctive symbol, literal or whole
file is absent from the trunk.
