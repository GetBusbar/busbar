# busbar 1.6.0 — LLM money-path relocation (the "core is a plane-agnostic router" endgame)

Status: AUTHORITATIVE execution plan. Derived from architecture pass at integration tip `63f6feb3`.
Governs: relocating the LLM proxy money path out of `busbar-core` into `busbar-llm` so the acceptance
grep test (`outside crates/busbar-llm: zero llmish tokens`) can reach 0 in core, with the four
composition gates green and the money path byte-identical.

## Why this is the real remaining work

Sub-phase A/B bundled the LLM routing tables behind `App.llm_runtime: NativeRuntime` and renamed the
residual concept to the neutral `PlaneDecl::fallback` capability. But the entire LLM engine (proxy
pipeline + ingress-native + health/metrics/endpoints/admin readers) still physically lives in
busbar-core. The grep test can only reach 0 by moving that code into busbar-llm.

### Key enablers (verified against the tree)
- Neutral gauntlet already exists: `busbar_substrate::plane_host::{run_gauntlet, GauntletPlane,
  GauntletRequest, VerifyOutcome}`. LLM already rides it as `NativePlane` (`ingress/dispatch.rs:190-352`).
- `EngineTables<'a>{ rt: &'a NativeRuntime }` (`state.rs:897`) is a re-sourceable read-seam; its doc
  (`state.rs:849-851, 890-895`) says to flip the SOURCE from `App::llm_runtime` to the plane slot
  without touching readers.
- Opaque slot machinery live: `App::plane_slot(key)` (`state.rs:1012`), `PlaneDecl::build_runtime`
  (`busbar-substrate/src/plane/registry.rs:483`), `runtime_slot_key` (`state.rs:409`). MCP/A2A already
  live entirely in `plane_slots`.
- Dependency direction is favorable: `busbar-llm` normal-depends on `busbar-core`+`busbar-substrate`;
  `busbar-core` names `busbar-llm` only as a dev-dependency. The engine, once in busbar-llm, calls
  DOWN into core — the allowed plane→core edge. The forbidden core→llm production edge is never created.

### Health-clone resolution (settled)
No production code mutates `llm_runtime` in place after `App::clone` (grep-verified: `llm_runtime` is
named in only `state.rs`, `appbuild.rs`, `test_support/mod.rs`, and tests; `appbuild` rebuilds
`NativeRuntime` fresh on every apply, carrying forward Arc-shared live state — it never
clones-then-mutates). So `App::clone`'s deep-copy of the runtime is a TEST-ONLY invariant
(`health_tests.rs:502`). Once the runtime is an `Arc<dyn Any>` slot (shallow-shared on clone),
production stays byte-identical; the one test that asserted deep-copy moves to busbar-llm and is
rewritten against the real `build_runtime` apply path. Chosen over a custom deep-clone slot hook,
which would defend a semantic production does not use.

## Phases (green-per-commit; no commit both MOVES files AND CHANGES behavior — LOCKED §7)

- **Phase 0 — visibility lift (wire, no move, no behavior).** Lift the neutral primitives the engine
  will call across the crate boundary to `pub`: `store::LaneRuntime` + admission methods
  (`store/mod.rs:270`), neutral `proxy` re-exports (`proxy/mod.rs`), `failover` disposition helpers,
  the `finish_*`/audit tail. Prefer a narrow `pub` facade module over blanket `pub` on internals.
  Gate: `cargo build -p busbar-core` + clippy; grep unchanged (88); no golden diff.

- **Phase 1 — neutral MCP→LLM completion seam (wire).** Replace `plane_host/mod.rs:329`
  `drive_openai_completion_over`'s hard-coded `proto="openai"` with a neutral capability
  (`synthesize_completion`) the LLM plane implements; MCP reaches it via the substrate `HostCompletion`
  seam and names no dialect. Impl still in core this commit. Gate: grep drops 3; MCP sampling tests green.

- **Phase 2 — flip EngineTables source to the slot (wire; PIVOTAL byte-identity checkpoint).** Keep
  `NativeRuntime` in core but insert it into `plane_slots[runtime_slot_key(llm_key)]` via the LLM decl's
  `build_runtime`; delete the `llm_runtime` field (`state.rs:437`); re-point `App::engine_tables()` to
  downcast the slot once. Rewrite the health test into a `build_runtime`-driven two-generation test.
  Gate: money-path oracles — `egress_differential_tests`, `crossproto_delivery_billing_tests`,
  `on_exhausted_tests`, `pool_upstream_creds_tests`, health suite; `no-plugins-gate.sh` (zero-plane boot
  tolerates absent LLM slot).

- **Phase 3 — relocate the types to busbar-llm (relocate, zero behavior).** Move `state.rs:14-399,843-965`
  (Lane…QueuedDepth, NativeRuntime, EngineTables) → `busbar-llm/src/engine/tables.rs`. Core readers reach
  them through a neutral `EngineTablesView` trait in substrate (temporary) that `NativeRuntime` impls.
  Gate: pure move; `plane-delete-test.sh --all`; grep drops the state.rs hits; empty golden diff.

- **Phase 4 — relocate the engine pipeline (relocate, zero behavior; largest MOVE, proven by oracles).**
  Move `proxy/engine/{mod,walk}.rs` + `proxy/{wire,select,egress,response_body,usage,hooks,lazy_body}.rs`
  + `NativePlane` + the `ingress/mod.rs` LLM helpers → `busbar-llm/src/engine/`. `NativePlane` becomes a
  busbar-llm `GauntletPlane`; core `run()`/`operation_resolved` build the plane via the LLM decl callback
  instead of naming `NativePlane`. Gate: full `proxy/tests/*`+`engine/tests/*` golden/differential;
  grep drops ~27 (engine/mod, walk, proxy/mod, dispatch gemini hits).

- **Phase 5 — relocate peripheral readers + retire the trait (relocate; largest surface).** Move
  `health.rs`, `metrics.rs`, `endpoints.rs` (`/v1/models`), `arrival_host.rs`, LLM arms of
  `telemetry.rs`/`admin/v1/service.rs` → busbar-llm, contributed via `PlaneDecl::{routes, admin_routes,
  start}` and a NEW metrics/health `PlaneDecl` contribution seam (the only genuinely new abstraction —
  budget design time). Retire the Phase-3 `EngineTablesView` trait; downcast directly in the plane.
  Gate: `/metrics` + `/v1/models` byte-identity (`metrics_tests`, discovery tests); grep drops
  endpoints/metrics/arrival/auth bedrock hits.

- **Phase 6 — arm the gate + delete dead core surface.** Tighten Phase-0 over-exposed `pub` back to what
  planes actually use. Confirm LLM-dialect grep subset is 0. Flip `GREP_GATE_REPORT_ONLY=0` ONLY after the
  sibling mcp/a2a glue cleanup lands. Gate: all four composition gates + armed grep gate green.

## Risk / cost
- ~10–14 commits. Phases 0–2 ~1 each; Phase 4 = 2–3; Phase 5 = 3–5; Phase 6 = 1–2.
- Riskiest to byte-identity: **Phase 2** (behavior change: field→slot, clone semantic shift) — mitigated
  because production never mutates the runtime post-clone and the health test is rewritten same-commit.
  Phase 4 is bulk but a pure move; the golden/differential oracles are exact byte gates.
- Second risk: Phase 5's `/metrics` + `/v1/models` output contracts + the new contribution seam.
- Genuinely NOT byte-identical (flagged): `App::clone`'s internal deep-copy of the LLM runtime becomes
  Arc-share. Behaviorally identical for production (nothing mutates post-clone; apply rebuilds fresh);
  only the one health test's semantic differs and moves to busbar-llm.

`plane/config.rs`, `config/migrate.rs`, substrate `proto.rs`/`arrival.rs`) + the Bucket-A error-envelope
symbol renames (`proxy/mod.rs` `openai_family` → `wire_error`). `GREP_GATE_REPORT_ONLY=0` cannot flip
