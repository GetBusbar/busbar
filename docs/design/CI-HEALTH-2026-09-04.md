## Structural findings

- **`GetBusbar/busbar` main has no branch protection that matters**: 0 required status checks,
  0 required reviews, `enforce_admins: false`. Linear history only. Nothing stops a red push to main.
- The satellite repos require 1 review but **0 status checks** — a red CI is not a merge blocker anywhere in the org.
- `busbar` has **no badges** in its README, so a red main is invisible from the repo page.
- `ci.yml` last ran on main on 2026-08-27 (green); everything on main since is `qa-gate` runs that are
  all **skipped** (14 in two days) because `workflow_run` loads the file from the default branch and
  the gate condition never fires. Main's real signal is stale by a week.
- `release.yml` for v1.5.5 failed once on clippy and was re-run to green; v1.5.4 also failed once.
  Release runs the gate again instead of consuming a gate that already passed on the exact SHA.
- `security.yml` failing on main for two weeks with no consequence: advisories are not a gate.
- Dependabot: 2 open alerts on busbar; no code-scanning analysis configured.
- Three watchers (busbar-go regen, headroom watch, bench audit) break whenever `dev` refactors,
  because they consume `dev` by raw path or by building against it; nothing in the busbar repo
  runs those consumers before the change lands.
- `RELEASE_DISPATCH_TOKEN` is a single org-wide PAT with an expiry; its death took down every
  scheduled release/watch job at once and nothing alerted.

## What this says 1.6.0 must build into CI and release

1. **Main is a release branch, not a work branch.** Required status checks on main and qa: the full
   gate (`cargo xtask gate`), the oracle, the mutation job, security. `enforce_admins: true`. Reviews
   required. A red main is impossible by construction, not by discipline.
2. **One gate, run once, consumed everywhere.** Release and tag jobs must consume the gate verdict for
   the exact SHA (artifact + attestation), never re-run fmt/clippy/test with a chance to diverge.
3. **`qa-gate` must not be a skipped-run generator.** Replace `workflow_run` gating with a required
   check on the PR/push itself; a gate that shows "skipped" 14 times is noise that hides red.
4. **Security is a gate, not a report.** cargo-deny advisories block the merge; a waiver needs a
   dated, signed exception in-repo (the same discipline as the equivalent-mutant register).
5. **Consumer contract tests in the busbar repo.** Every satellite that builds against busbar (hooks,
   stores, auth plugins, SDK regen, bench harness) gets a job in busbar's CI that builds the consumer
   against the candidate SHA before it lands on dev. A dev refactor that moves `openapi.json` or
   changes the hook ABI fails in busbar's own PR, not in three other repos the next morning.
6. **Pinned artifact paths.** The OpenAPI spec and every other cross-repo artifact are published as
   release assets / a stable path, never fetched by source-tree path from a moving branch.
7. **No expiring org PATs in scheduled jobs.** Use a GitHub App installation token (or fine-grained
   tokens with rotation automation) and a canary job that fails loudly the day before expiry.
8. **Fleet health dashboard.** One scheduled job in `.github` that lists every repo's last main run and
   opens/updates an issue when any is red for > 24 h. Today seventeen repos have been red for three
   days with no signal.
9. **Badges on the busbar README** for CI, security, oracle, coverage and the perf gate, so the state
   of main is visible where people look.
10. **Bench board integrity.** The benchmarking audit must run before publish and block publish on
    any invariant violation; a red badge on the public benchmark repo is a marketing problem, not
    just a CI one.
11. **Release process.** `prepare-release (on dev)` → gate consumed → `release-stage` → tag on main
    → satellites dispatched by App token → `verify-deploy` → fleet dashboard green. Each stage
    attests the previous stage's artifact; no stage re-derives.
