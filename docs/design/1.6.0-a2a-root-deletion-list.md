# The A2A root deletion list

**What this file is.** `root-a2a-serve` is now in the binary's `default` feature set, so the A2A
plane's leg is on the request path of the binary an operator runs. The next question is what that
retires: which per-plane files in the composition root, and which of the legacy plugin's own code
paths, are now a SECOND spelling of something the chain already does, and can therefore be deleted
rather than deprecated.

This file is the answer to the half of that question that is **NO**. Every row below was examined
against the code, found NOT deletable at this cut, and carries the evidence for why. A row leaves
this file by being deleted from the tree, never by being re-argued.

**The rule this file obeys.** Where the mount serves the same surface, the per-plane file goes.
Where it does not, the file is listed here and the cut STOPS. A deletion that leaves a surface
served by nothing, or a grant enforced by nothing, is not a deletion — it is a hole with a commit
message.

---

## 1. The four per-plane root files stay, because there is nothing generic to delete them INTO

| file | lines (prod + tests) | what it carries |
| --- | --- | --- |
| `crates/busbar/src/root/units_a2a.rs` | 2080 + 2421 | the plane's ten unit steps over the kernel loop |
| `crates/busbar/src/root/units_a2a_leg.rs` | 1061 + 1506 | the owned `A2aLeg`, its bindings and their source table |
| `crates/busbar/src/root/units_a2a_boot.rs` | 644 + 389 | the boot read of `agents:` and the leg's assembly |
| `crates/busbar/src/root/units_a2a_mount.rs` | 611 + 651 | the claim walk, the four fallthrough arms, the dispatch seam |

**Why none of them is deletable on this base.** There is no generic mount in the composition root
on this base to delete them into. `crates/busbar/src/root/` carries no `plane_mount` module and the
tree names no `MountDispatch` or `MountedReply`:

```
$ grep -rn "plane_mount\|MountDispatch\|MountedReply" crates/busbar/src --include='*.rs'
crates/busbar/src/root/tests/units_mcp.rs:951:fn the_plane_mounts() {
```

— one test function whose name happens to contain the words. The generic mount, the pass-through
reply and the per-plane collectors are on the mount line (`keep-mount-passthrough`, stacked on the
r32c cut) and are not on this branch's base, which is `keep-r31i-a2a-grants @ 01cb29898`. Deleting
`units_a2a_mount.rs` here would delete the only mount there is.

**What this means for the ordering.** The per-plane root files start deleting when the generic
mount is under them, which is the mount line's own delivery — not this one. This cut's contribution
to that is the DEFAULT FLIP: the mount, the leg and the boot composition are now compiled and run
by `cargo test -p busbar` — 66 cells that had never been built under the default feature set — so
the generic replacement lands against a battery that actually reads them.

## 2. The legacy A2A grant body stays, and this is the reason

The r31i cut put the agent grant on the units chain: `A2aUnits::approve` asks
`ResolvedKey::scope_allowed(kind, value)` off the `ResourceLocator` the plane produced, before the
dial (`crates/busbar/src/root/units_a2a.rs`, `grant_held`). The legacy spelling of the same
predicate is the grant step inside `crates/busbar-a2a/src/a2a/inbound.rs::authorize` — the
`Grant::Scope { kind: "agent", name }` it hands `validate_request`, and the
`InboundRefusal::NotInScope` it renders.

That legacy body is **not** dead, for two independent reasons. Either one is sufficient.

### 2a. `authorize` is asked a question the chain never asks — per POOL MEMBER

`crates/busbar-a2a/src/a2a/route.rs:150`:

```rust
let eligible =
    super::inbound::authorize(key, kind, member, regs, generation, now).is_ok()
        && super::creds::authorise_egress(key, member, now).is_ok();
```

This runs inside the failover walk, once per member of a pool, with `member` — not the agent the
arrival named. The chain asks the grant ONCE, on the resource the arrival carries. Deleting the
grant from `authorize` would make every member of a pool eligible to a caller holding a grant on
only one of them, which is a caller reaching an agent it was never granted: strictly worse than the
posture r31i landed. The fix is a route-step cut that puts the per-member eligibility question on
the chain, and it is not this cut.

### 2b. The mount has four arms that hand the request to the legacy router with no chain in front

`crates/busbar/src/root/units_a2a_mount.rs`, in order, each of them a `return inner.oneshot(...)`:

1. the path is in neither the plane's claim table nor the chain's target table;
2. the declared `Content-Length` exceeds the operator's ingress cap;
3. the body could not be read to that cap;
4. the plane's own decode did not recognise an operation in the body.

Every one of those is correct as an arm — the mounted surface already has an answer for each, and
manufacturing one in the root would be the root inventing a status it has no basis for. But on all
four, the legacy grant at `crates/busbar-a2a/src/a2a/receive.rs:216` is the ONLY grant the request
meets. Arm 4 in particular is reachable with a well-formed request on a claimed address whose body
this plane's decode cannot name.

### What must land before this deletion is available

- the per-member eligibility question on the chain (retires 2a);
- arms 1–4 either served by the chain, or proven to reach no agent-scoped operation (retires 2b).

Until both, `inbound::authorize`'s grant step is a second enforcement of the same predicate on the
same key and the same agent — a duplicate, and duplicates that agree are the cheap half of the
problem. It is not a duplicate that can be removed without removing coverage.

## 3. What the mount DOES serve, for the record

`busbar_plane_a2a::claims::CLAIMS`, walked generically by `units_a2a_mount::claims_the_path` — every
claim, with the transport each one names deliberately not read:

- three declared-open surfaces: `/.well-known/oauth-protected-resource/a2a`,
  `/.well-known/agent-card.json`, `/a2a/push`;
- the document binding's named operations: `/a2a/message:send`, `/a2a/message:stream`,
  `/a2a/extendedAgentCard`, `/a2a/tasks`, `/a2a`, `/a2a/`;
- the patterned addresses: `/a2a/tasks/{id}`, `/a2a/tasks/{id}/pushNotificationConfigs`,
  `/a2a/tasks/{id}/pushNotificationConfigs/{id}`, `/a2a/agents/{id}`;
- the framed binding: `/lf.a2a.v1.A2AService/{method}`.

A request on one of these, whose body the plane's decode names, walks the ten steps and reaches the
same router with the same bytes. That is the surface a later cut may delete the legacy spelling of.
