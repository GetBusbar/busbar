# The LLM plane's per-root boot glue: what the mount replaces, and what deletes when

**Status: MARKED, NOT DELETED.** Nothing in this list is removed until `root-llm-serve` is
default-ON and the mounted path is the served one. Deleting any of it before then removes the
surface this node actually serves LLM traffic on.

## Why there is a list at all

`root/units_llm.rs` carries two different things under one roof. The first is the plane's UNIT —
`LlmNode`, `LlmUnit`, its twelve step answers, its exit arm, its late accrual — and none of that is
boot glue, none of it is replaced by a mount, and none of it is on this list.

The second is a per-dialect INGRESS TABLE and the eight fn-pointer targets that fill it. That half
exists only because the composition root has to name an entry point per dialect for the substrate's
arrival seam, and it is exactly what a generic root mount makes unnecessary: the mount asks the
plane's own claim table which requests are this plane's, asks the plane's own decode which unit they
are, and walks one leg. One claim table replaces fourteen rungs transcribed as eight fn pointers.

## The list

Everything below is in `crates/busbar/src/root/units_llm.rs`, under the heading `The mount`, and is
replaced by `root/units_llm_mount.rs` plus `root/plane_mount.rs`:

| item | what it is | what replaces it |
| --- | --- | --- |
| `PATH_INGRESS` | the two path-model dialects as a name→fn table | the plane's own `claims::CLAIMS`, walked by `plane_mount::claims_a_path` |
| `BODY_INGRESS` | the six body-model dialects as a name→fn table | the same |
| `body_arrival` | one body-model arrival, driven | `MountedLeg::serve` over one arrival |
| `body_arrivals!` and its six targets | one bare `fn` per dialect, because a fn pointer cannot capture | nothing: the leg is a value and captures what it needs |
| `path_arrival` | one path-model arrival, driven | `MountedLeg::serve` |
| `gemini_path_arrival`, `bedrock_path_arrival` | the two path-model targets | nothing, for the same reason |
| `NODE` | the process-wide `LazyLock<LlmNode>`, reached because a bare `fn` cannot capture | the leg's own owned node |
| `bind_book` | the boot call that binds the process node to the process book | the leg's own construction |

And in `crates/busbar/src/main.rs`, the three lines that install them:

- `path_ingress.extend_from_slice(root::units_llm::PATH_INGRESS)` (~line 624)
- `body_ingress.extend_from_slice(root::units_llm::BODY_INGRESS)` (~line 649)
- `root::units_llm::bind_book(...)` (~line 1463)

## What must be true first

1. `root-llm-serve` carries a `MountedLeg` impl — see `WHY_NO_LEG_YET` in
   `root/units_llm_mount.rs` for the one seam that blocks it today.
2. The paired money cell is green: one request driven both ways, the sealed facts line compared
   byte for byte between the legacy `LlmNode::answer` path and the mounted path.
3. `root-llm-serve` is default-ON and has been through the same measurement the admin switch was.

Until all three, the table above is documentation of an intent and not a work item.
