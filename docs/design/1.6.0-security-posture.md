# 1.6.0 — Enterprise Security Posture

**Status:** design doc (the security *story* + the audited reality behind it).
**Audience:** enterprise security reviewers (CISO/AppSec), prospective investors, and the
busbar maintainers who have to keep the claims in this doc *true*.
**Scope:** this is a posture and thesis document. The implemented trust boundaries and their
in-code mitigations already live in [`THREAT_MODEL.md`](../../THREAT_MODEL.md) and
[`SECURITY.md`](../../SECURITY.md); this doc reframes them as **structural defenses** and states,
honestly, where each is strong versus partial versus roadmap. Every claim below is cited to real
code (`file:line`) or marked **[ROADMAP]** / **[PARTIAL]**.

---

## 0. The reframe (read this first)

A competitor recently set the enterprise-security "table stakes" as a **rate**: ~79 security
fixes a month, a new Director of Security, a bug-bounty program, security fixes backported across
the last four minor lines, and PII/PCI masking bolted onto every egress path.

That is a treadmill. Every one of those numbers describes an *arms race against a stream of bugs*:
find a leak, mask it; find another, mask it. The rate is impressive precisely because the surface
keeps producing new instances of the same handful of vulnerability *classes* — secret leaked into a
log, plugin reached into the core, malformed input silently corrupted a record, one tenant's blast
radius hit another.

busbar's thesis is different, and it is the pitch:

> **We don't patch N bugs a month. Our architecture makes whole classes of those bugs
> unrepresentable — or bounds their blast radius by construction — and a CI gate keeps them that
> way.**

Where a defense is a *type*, the bug is unrepresentable (you cannot write the code that leaks).
Where a defense is a *gate*, a regression cannot merge (the boundary cannot silently drift). Where
neither is true yet, this doc says so and puts it on the roadmap. A CISO or an investor's technical
diligence *will* verify these — so the credibility of the strong claims depends on being equally
loud about the partial ones.

## 1. Threat model — actors and what each would try

The full boundary map is [`THREAT_MODEL.md`](../../THREAT_MODEL.md). Summarized by *actor*:

| Actor | Trust boundary | What they try |
|---|---|---|
| **Malicious caller** | client → data plane | Wrong-typed / smuggled request bodies to cause silent data loss or mis-routing; auth bypass (incl. timing); over-spend past budget; route to a pool/model they aren't allowed. |
| **Compromised / hostile upstream** | data plane → provider | 30x-redirect vetted credential traffic to an internal address; return a hostile body that escalates into busbar; drain a pool via `Retry-After`. |
| **Malicious / buggy plugin** | host → dynamic plugin (native code) | Panic/unwind across the FFI boundary to crash or corrupt the host; reach a `Store`/`GovCtx`/audit handle it wasn't granted; read another plane's state; park Tokio workers to DoS the node. |
| **Insider reading logs / audits / admin reads** | operator surfaces | Recover a provider key, virtual-key secret, or OAuth client secret from a log line, a metric label, an audit record, or an admin read projection. |
| **Network attacker** | all sockets | SSRF via config-controlled URLs; reach the admin/control plane from the data port; downgrade TLS/mTLS. |
| **Supply-chain attacker** | distribution | Swap a backdoored binary/image onto the release page; replay an older signed plugin. |

The rest of this doc maps each **class** an actor exercises to the busbar mechanism that makes it
unrepresentable or bounds it — with the honest strong/partial verdict from a code audit.

## 2. Structural defenses (audited)

Six defenses. Each states: the **thesis**, the **mechanism (file:line)**, and the **honest verdict**.

### 2.1 Edge validation — malformed input fails fast at the boundary

**Thesis:** a wrong-typed request body cannot cause silent loss or corruption; it is rejected at
the edge with a 400 in the *ingress dialect's own* error envelope, and busbar stays exactly as
lenient as the upstream provider on absent / empty / unknown-well-typed fields.

**Mechanism.** Each of the six LLM dialects validates structural field types inside its request
reader and, on a present-but-wrong-typed field, returns
`IrError { class: ClientError, provider_signal: SIGNAL_IR_PARSE }`:

- `crates/busbar-llm/src/anthropic/reader.rs:237` (`messages` / per-message `content`)
- `crates/busbar-llm/src/openai_chat/reader.rs:173,184` (`messages`, `content`, `tools`)
- `crates/busbar-llm/src/gemini/reader.rs:291,330` (`contents`, `parts`)
- `crates/busbar-llm/src/bedrock/reader.rs:271,298` (`messages`, `content`)
- `crates/busbar-llm/src/cohere/reader.rs:183` (`content`, all roles)
- `crates/busbar-llm/src/openai_responses/reader.rs:128,285,406` (`input`, message `content`)
- Signal single-sourced: `SIGNAL_IR_PARSE = "ir_parse"` at `crates/busbar-substrate/src/proto.rs:224`.

The reject maps to a native-envelope 400 via `IngressReject::BadRequest`
(`crates/busbar-llm/src/chat_handle.rs:529,553`) →
`ingress_reject_response` → `KIND_INVALID_REQUEST` (`crates/busbar-core/src/proxy/wire.rs:193`) →
each dialect's `write_error` (anthropic/openai_chat/gemini/bedrock/cohere/openai_responses writers;
Bedrock also gets `x-amzn-errortype`). **Cross-protocol reuses the same seam**
(`crates/busbar-core/src/proxy/wire.rs:384`, `map_translate_req_reject`): the ingress reader runs
before egress representability, so a wrong-typed body 400s in the *ingress* dialect regardless of
the egress provider. Leniency is pinned by **six parallel `input_hardening_tests.rs` suites** (one
per dialect) that assert *both* the reject *and* that absent / empty-array / unknown-well-typed
inputs still pass (e.g. `crates/busbar-llm/src/openai_chat/tests/input_hardening_tests.rs`,
`…/anthropic/tests/…`, etc., 5–7 tests each).

**Verdict: STRONG on the core thesis, PARTIAL on two sub-claims — do not overclaim.**
- The "silently coerce a malformed body to an empty turn" path is genuinely closed, uniformly
  across all 6 dialects, same- and cross-protocol, with the reject/lenient boundary tested.
- **[PARTIAL] No field path.** The reject carries `{class, provider_signal}` only — no field name.
  The wrapping string is discarded and the 400 body is a fixed generic message
  ("We could not process the content of your request."), pinned by
  `crates/busbar-core/src/proxy/tests/ingress_reject_response_tests.rs:43`. The doc must not claim a
  per-field error path today; it is a roadmap item (§6).
- **[PARTIAL] No dedicated reject metric.** Rejects are observable only via the generic
  `busbar_requests_total{outcome="client_error"}` (`crates/busbar-core/src/ingress/mod.rs:633`,
  `telemetry.rs:92`) — there is no validation-specific counter with a reason/field label.
- **[PARTIAL] Wire-envelope uniformity is proven at the reader/decision level** (all 6 return
  `ClientError`/`ir_parse`); the *rendered HTTP envelope* is only spot-checked for `openai`. A
  per-dialect golden of the 400 body is a roadmap item (§6).

### 2.2 The Secret type — leakage aspires to be unrepresentable, not merely masked

**Thesis:** a secret is a *type*, never a bare `String`, so a secret value structurally cannot enter
a log, audit, or metric. (The type's full design is in
[`docs/design/1.6.0-secret-type.md`](1.6.0-secret-type.md), authored in parallel — this doc
references it and does not duplicate it.)

**Mechanism (what exists in code today).** Two real, well-adopted type mechanisms:
- **`SecretRef`** — the config-layer *reference* type (`crates/secret-ref/src/lib.rs:53`). It holds
  a module + opaque settings, *never the value*; its `Deserialize` structurally rejects a bare
  inline literal and its error omits the value (`lib.rs:144-153`). A pasted-inline secret is
  **unrepresentable in config** — genuinely structural.
- **`Redacted<T: Zeroize>`** — the in-memory resolved-value wrapper (`crates/api/src/redacted.rs`).
  `Debug`/`Display` both print `[REDACTED]` (`:59-70`); it implements **neither `Serialize` nor
  `Deserialize`** (`:16-22`) so it cannot enter a JSON/audit payload implicitly; it zeroizes on drop
  (`:72-76`); the only escape is an explicit `expose_secret()` (`:46-48`); `PartialEq` is
  constant-time (`:92-96`). Broadly adopted: provider `api_key` on `Lane`
  (`crates/busbar-core/src/state.rs:27`), admin token, OAuth `client_secret`
  (`egress_auth/oauth_client_credentials.rs:23`), bearer token, browser-login secret, submitted
  passwords (`crates/api/src/auth.rs:166`), and the whole MCP egress credential set.
- Belt-and-suspenders: `Lane` (`crates/busbar-core/src/state.rs:13`) has **no `Debug` derive at
  all**, and its key field is itself `Redacted<String>`.
- Egress across the plane seam carries a **credential ref, not the secret**: A2A
  `OutboundCredential.secret: SecretRef` (`crates/busbar-a2a/src/a2a/creds.rs:248`), resolved late
  through the neutral `SecretResolve` trait — the plane never holds the concrete resolver.

**Verdict: PARTIAL — strong and largely realized, but not yet universal.** Do not claim "leakage is
unrepresentable" across the whole codebase. Honest residual plaintext:
- The resolver seam itself returns bare plaintext: `resolve → Result<Vec<u8>, String>`,
  `resolve_string → Result<String, String>` (`crates/busbar-core/src/config/secret.rs:79,113`).
  Every resolved secret passes through an unwrapped, `Debug`-able, un-zeroized `String`/`Vec<u8>`
  before anyone wraps it.
- `resolve_settings` substitutes resolved plaintext into a `serde_json::Value::String` to cross the
  plugin ABI (`config/secret.rs:222`) — a fully serializable plain string, protected only by the
  surrounding code not logging it.
- Two live holders remain raw `String` with only a hand-written redacting `Debug` (no `Redacted`, no
  zeroize): `Lease.secret` (`crates/busbar-a2a/src/a2a/creds.rs:321`) and `CredentialSecret.secret`
  (`crates/api/src/store.rs:527`) — the latter is `Serialize` **by design** because it crosses the
  Store ABI as JSON. Redaction there is `Debug`/tracing only.

The older pattern — manual redacting `Debug` impls on plaintext-bearing types — still coexists with
`Redacted` in several places (`store.rs:543`, `busbar-substrate/src/governance/signing.rs:124`,
`busbar-substrate/src/plane/approvals.rs:185`, A2A creds/pushdeliver). **The honest story:** secret
handling is a *type* at the config-reference layer and the primary in-memory layer, and *convention*
(hand-written `Debug`) at the edges. Converging the edges onto the type is the point of the
1.6.0-secret-type work (§6).

### 2.3 FFI / plugin trust boundary — a compromised plane cannot reach core

**Thesis:** a buggy or hostile plane/plugin cannot unwind into the host, cannot reach a `Store` /
`GovCtx` / audit handle, and cannot touch another plane or a secret.

**Mechanism.**
- **catch_unwind fail-closed at every seam, both directions.** Plane→core: every host-vtable slot
  runs its body inside a mandatory `catch_unwind`, mapping a caught panic to the fail-closed value —
  the invariant is stated at `crates/busbar-core/src/plane_host/vtable.rs:16` and enforced per-slot
  across `vtable.rs`, `egress.rs`, `journal.rs`, `trust.rs`, `breaker.rs`, `govern.rs`,
  `dispatch.rs`, `identity_admit.rs`, `pipe.rs`, `guard.rs`. Core→plane (cold ABI): every crossing
  routes through one guard helper — `ffi_guard` / `ffi_guard_confined`
  (`crates/plugin-loader/src/lib.rs:114,131`) — covering `open`/`call`/`close`/`free`/`abi`/`kind`
  plus `Library::new`/`drop`; the hook seam has a belt-and-braces outer guard
  (`crates/plugin-loader/src/hook.rs:132`). The guards are *effective, not cosmetic*: the ABI
  fn-pointers are `extern "C-unwind"` (`crates/busbar-plugin/src/cold/mod.rs:551`), so a Rust
  plugin panic is a defined forced unwind that lands in the guard rather than aborting at the plugin
  frame.
- **repr(C) hot ABI + cold JSON ABI split.** Hot tier is a `#[repr(C)]`, POD-by-pointer, zero-alloc
  seam (`crates/busbar-plugin/src/hot/mod.rs:4`); cold tier is a six-symbol `extern "C"` JSON
  surface for off-hot-path backends (`crates/busbar-plugin/src/lib.rs:11`).
- **The `PlaneHostVtable` trust model.** `#[repr(C)] PlaneHostVtable`
  (`crates/busbar-plugin/src/hot/host.rs:390`) is a frozen-preamble, append-only, versioned table
  of `Option<extern "C-unwind" fn>` slots; args cross as `*const Pod`, results as
  `*mut MaybeUninit<Pod>` or by-value POD — pure data-in/data-out. Handles that cross are opaque ids
  (`AdmissionId`, `IdentityId`, `EgressId`), never Rust references to core internals.
- **Core grants a plane only its own `&dyn Any` slot.** The mount comment you can quote to a
  reviewer: `crates/busbar-core/src/router.rs:428-430` — *"The mount fns are granted only the router
  and their own `&dyn Any` slot — never a `Store`/`GovCtx`/audit handle."* Enforced by the mount
  loop (`router.rs:432-443`) and the registry's type-erased slots
  (`crates/busbar-core/src/plane/registry.rs:580-621`, which boot-refuses a mounted-but-unadmitted
  plane).
- **Confinement.** No secret / `Transport` / `GovState` / `Admission` / `VirtualKey` crosses: card
  secrets are derived and held host-side (`hot/host.rs:504-510`), gov key material crosses only as
  an opaque handle (`hot/host.rs:361,507`), `Transport` is consumed host-side and never crosses the
  `.await` into the plane (`plane_host/mod.rs:323-328`), and `VirtualKey` appears only in
  core-internal signatures, in no vtable slot type.

**Verdict: STRONG.** Every reachable seam is guarded; the trust model is coherent (repr(C)
data-in/data-out, opaque handles only, `&dyn Any` confinement, no privileged core object named in
any slot). **One honest, self-documented limitation:** the panic→fail-closed guarantee holds for
*Rust* plugins; a non-Rust plugin (C/Go/Zig) that cannot unwind still aborts the process
(`crates/plugin-loader/src/lib.rs:215`). That is inherent to FFI and is called out in the code, not
hidden.

### 2.4 Plane neutrality / isolation — a plane defect's blast radius is bounded

**Thesis:** core has zero knowledge of any plane ("core-is-core"), and each plane is independently
removable — so a defect in one plane cannot reach core or another plane.

**Mechanism (CI-enforced gates).** Three *blocking* gates:
- **`plane-purity-lint.sh --check`** (`scripts/plane-purity-lint.sh`, wired blocking at
  `.github/workflows/ci.yml:295`): scans the neutral crates (`busbar-core`, `busbar-substrate`,
  `busbar-api`) and fails RED on *any* side channel — a `#[path=…busbar-{llm,mcp,a2a}…]` include, a
  `busbar_{llm,mcp,a2a}::` symbol, a plane key, a dialect name, or a plane record type. The
  extraction baseline drained from ~1236 hits to 0, and the `plane-purity` qa segment is now
  `active` (`qa/segments.toml`).
- **`plane-delete-test.sh --all`** (wired at `ci.yml:297`): *physically* `git rm -r` each plane
  crate in a scratch workspace and proves the neutral crates + binary still compile — the strong
  form of "independently removable."
- **`proto-deletion-gate.sh`** (wired at `ci.yml:785`): the closest literal enforcement of
  "core-is-core" — a static grep asserting `crates/busbar-core/src` names no protocol crate
  (`proto-deletion-gate.sh:73`), plus boot-level proof that the binary comes up, refuses the deleted
  dialect's config, and still serves the rest.
- Complemented by the weak-form `deletion-test-matrix` job (`ci.yml:812+`).

**Verdict: STRONG for the three blocking gates; PARTIAL where claimed beyond them — be precise.**
- **[PARTIAL] `plane-grep-gate.sh` is report-only**, not blocking (`GREP_GATE_REPORT_ONLY=1`
  default; `qa/segments.toml` runs it `--report`). It measures debt; it does not fail CI. Do not
  cite it as an enforced gate.
- **[PARTIAL] The "freeze witness" (`g6-freeze-witness.sh`) and `plane-abi-neutrality.sh` are not
  wired into CI** — standalone measurement scripts nobody runs on a push (the latter self-admits
  "additive/foundation"). Do not present these as active gates.
- **[PARTIAL] LLM plane is not yet feature-gated.** There is no `plane-llm` feature; the LLM
  `PLANE_DECL` is still compiled into core with a live `busbar-core ↔ busbar-llm` back-dependency
  (`ci.yml:801-806`). The strong-form `plane-delete-test` does exercise all three, but LLM isolation
  is less complete than MCP/A2A. Roadmap: land `plane-llm` (§6).

### 2.5 Audit integrity — a tamper-evident record you can read back

**Thesis:** governance/admin mutations, MCP calls, and A2A task provenance are written to a
tamper-evident, hash-chained record you can read back later — and (with the Secret type) one that
never contains secrets.

**Mechanism.** One shared hash chain, three streams on top:
- `crates/busbar-core/src/audit/mod.rs:451` `verify_chain()` / `:477` `walk()` — a *true* verifier:
  it **recomputes** each record's digest and compares to the stored `hash` (`:517` `DigestMismatch`),
  checks `prev_hash` links (`:511` `LinkMismatch`), checks contiguous `seq` (`:502` `SequenceBreak`),
  and rejects foreign-scope rows (`:496` `ForeignScope`). `seq`/`prev_hash`/`hash` are never
  caller-supplied (`:196-237`).
- Durable "read back later" machinery: the scope-keyed journal
  (`crates/busbar-core/src/audit/journal.rs`) advances position only after a durable append succeeds
  (`:336`), with `restore_from_store`/`read_scoped`/`verify_scoped` surfaces. Boot restores and
  re-verifies each chain (`crates/busbar-core/src/boot.rs:31-39`, including the
  `list_audit → plane_records` migration and seam boot-restore).
- Three streams: admin mutations (`plane/auditlog.rs`), MCP calls (`calllog.rs`), A2A task
  provenance (`busbar-a2a/src/taskstore.rs:953` `verify_task_chain`).

**Verdict: STRONG mechanism, PARTIAL on two honest caveats.**
- The chain is genuinely tamper-*evident* (recompute-and-compare, four distinguishable break kinds).
  Note it is evidence, not prevention — the code says so itself (`audit/mod.rs:52-58`): a host
  compromised at the moment of writing can rewrite a chain consistently.
- **[PARTIAL] Verification runs at boot restore, not on the live read path.** The on-demand
  verifiers (`verify_task_chain`, `verify_principal_chain`, `verify_scoped`) have **no production
  callers** (tests only; the code notes "NO PRODUCTION CALLER … a tamper is detected at the next
  restart and not before", `calllog.rs:803`). The live `GET /audit` endpoint serves the in-RAM
  read-model ring *unverified* (`admin/v1/json/handlers.rs:1841`). Roadmap: mount a "verify now"
  admin verb (§6).
- **[PARTIAL] "Never contains secrets" is field-discipline today, not type-enforced.** Records cover
  hand-chosen digest fields (e.g. a `tool_digest`, *not* tool arguments — `calllog.rs:326-342`), so
  secrets structurally can't enter *by field selection*, not because a `Secret` type guards the
  record. Converging this onto the type is part of the 1.6.0-secret-type work (§2.2, §6).

### 2.6 Governance / authz — the five guarantees

**Thesis:** every request is authenticated, verified against approved destinations, admitted against
budget, and routed only to permitted destinations — enforced in code, in order, before any charge.

**Mechanism.** An ordered ingress gauntlet (`crates/busbar-core/src/ingress/dispatch.rs:183-189`;
"every check that can reject fires BEFORE the budget door" — `ingress/mod.rs:395-401`):
1. **Authentication** — the auth chain fails closed at every branch
   (`crates/busbar-core/src/auth/mod.rs:437-497`; request-path runner fail-closed on panic/join,
   `:519`); constant-time comparison over SHA-256 digests
   (`crates/api/src/auth.rs:250-265`); signed VirtualKey verify with revocation denylist +
   rotation-generation gate (`crates/busbar-core/src/governance/state.rs:107-146`).
2. **RBAC** — `Principal.roles` (`crates/api/src/auth.rs:25`) resolved through
   `role_bindings` (`crates/busbar-core/src/state.rs:739`, populated `appbuild.rs:1775`) into a
   synthesized enforcement `VirtualKey` on the **live request path**
   (`resolve_data_plane_identity`, `auth/mod.rs:1801-1825`), with an explicit **fail-closed
   `NoGrant`** (`:1816` — a principal with roles but no earned key is refused, never admitted
   keyless). Admin-plane RBAC unions grants across bound roles (`admin_scope_for`, `:1196-1236`).
3. **Destination allowlist** — `destination_guard` runs pre-admission
   (`crates/busbar-core/src/ingress/mod.rs:402-451`): pool authorization
   (`VirtualKey::scope_allowed`, `crates/api/src/store.rs:378`, fail-closed cross-kind), re-checked
   against every reachable fallback pool with a cycle guard (`:52`), plus a fail-closed unpriced-model
   gate (`:427` — can't bill ⇒ don't serve).
4. **Budget admission** — the single `admission_door` (`ingress/mod.rs:459-474` → `try_admit`,
   `governance/state.rs:1753-1819`): concurrent gauges via a `fetch_update` CAS loop (no TOCTOU
   overshoot, `:1780-1807`) and windowed limits charged all-or-nothing under ordered shard locks.
   RAII `AdmitGrant` refunds on non-2xx (`governance/mod.rs:292-316`).

**Verdict: STRONG — all five real and wired, not roadmap.** Minor honest caveats (from the code's
own docs): the `constant_time_eq` primitive leaks length unless callers hash first — every in-tree
caller does (`api/src/auth.rs:245`); and hard token-per-minute caps are best-effort (tokens land
post-response, bounded by in-flight requests — `governance/state.rs:1736`).

## 3. The thesis section (for the raise)

**We don't patch N bugs a month; our architecture makes those bug classes unrepresentable or
bounded — and a CI gate keeps them that way.** The class → mechanism → enforcement map:

| Vulnerability class (the treadmill) | busbar mechanism | Why the class shrinks | Gate that holds it |
|---|---|---|---|
| **Secret leaked into a log / audit / metric** | `Redacted<T>` (no `Serialize`/`Deserialize`, `[REDACTED]` `Debug`, zeroize) + `SecretRef` (inline literal unrepresentable in config) | You cannot *write* the code that serializes the secret — the type refuses. Inline secrets can't even be typed into config. | `settings-leak-lint.sh` (admin reads never serve a settings bag's values); `response-header-lint.sh`; the type's own trait bounds. **[PARTIAL — edges still raw `String`, §2.2]** |
| **Plugin/plane escapes into core** | `catch_unwind` fail-closed at every seam + `&dyn Any`-only mount + repr(C) opaque-handle vtable + confinement | A panic can't unwind in; a plane has no handle to `Store`/`GovCtx`/audit to reach; no privileged object is named in any slot. | `blocking-ffi-lint.sh` (no FFI on a Tokio worker); `plane-purity-lint.sh` (blocking); `plane-abi-neutrality` **[unwired, §2.4]** |
| **Silent data loss / corruption from malformed input** | Edge validation: wrong-typed field ⇒ 400 in the ingress dialect's native envelope, uniform across 6 dialects, tested reject-vs-lenient | Malformed input fails fast at the boundary instead of being coerced to an empty/garbled turn. | 6 × `input_hardening_tests.rs`; money-path **byte-identity goldens** (release gate) **[no field path / no dedicated metric, §2.1]** |
| **One plane's defect becomes everyone's blast radius** | Neutral core + independently-removable planes | Core names zero plane types; each plane is `git rm`-removable with core still compiling — a defect can't reach core or a sibling. | `plane-purity-lint.sh --check` + `plane-delete-test.sh --all` + `proto-deletion-gate.sh` (all blocking) **[LLM not yet feature-gated, §2.4]** |
| **Auth bypass / over-spend / mis-route** | The five governance guarantees, ordered before any charge | Every request is authed (constant-time, fail-closed), RBAC-resolved (fail-closed `NoGrant`), destination-checked, and budget-admitted atomically. | ingress dispatch ordering + governance unit suite |
| **Tampered audit / unreadable record** | One hash-chained, recompute-verifying, scope-separated audit chain, re-verified on boot | A silent edit breaks the chain and is caught on restore. | `verify_chain` on boot restore **[not on live read path, §2.5]** |
| **Backdoored release / replayed plugin** | SBOM + SLSA Build L2 attestation + cosign image + embedded ed25519 plugin key + version floors | A swapped artifact fails attestation; an unsigned/older plugin fails the embedded-key check. | `signing-gate.sh`, `release-key-guard.sh`, `build-provenance-gate.sh`, release `branch-green` (no override) |

The load-bearing distinction for a technical investor: **four of these are types or gates** (secret
leak, plane escape, silent-loss, blast-radius), which is *categorically* stronger than a masking
rule you have to remember to apply on every new egress path — the exact thing a 79-fixes-a-month
cadence implies they *don't* have.

## 4. Process commitments a CISO / VC expects

busbar already runs an unusually strong engineering-process story; the security framing is mostly
about *naming* it and filling the named gaps.

### 4.1 A documented security model — **in place**
[`THREAT_MODEL.md`](../../THREAT_MODEL.md) (boundaries, assets, T1–T9 with in-code mitigations),
[`SECURITY.md`](../../SECURITY.md) (private reporting, 48h ack, GitHub Security Advisories + CVE
issuance), and this posture doc. Every mitigation named in the threat model is test-covered.

### 4.2 CI-enforced security gates — **in place** (the "proven-red" discipline)
Every security-relevant lint ships a `--selftest` that runs **first** and must fail red on a planted
violation before the real scan is trusted (`ci.yml` runs this pattern for structure, response-header,
tracing, changelog, workspace-deps, settings-leak, blocking-ffi, plane-purity, no-plugins, and more).
The security-relevant subset:

- **`settings-leak-lint.sh`** — an admin read may carry a settings bag's *key names* but never its
  values (the class that leaked an OIDC `client_secret`, a webhook auth header, a store URL password —
  found four times, now one gate).
- **`blocking-ffi-lint.sh`** — a synchronous call into a `dlopen`ed plugin never runs on a Tokio
  worker (the DoS class found five independent times, now one gate).
- **`plane-purity-lint.sh --check`** + **`plane-delete-test.sh --all`** + **`proto-deletion-gate.sh`**
  — the neutrality/isolation gates (§2.4).
- **`response-header-lint.sh`** — every injected response header from one sanctioned, config-gated
  site (no bypass of the `advanced.response_headers` opt-in).
- **`no-plugins-gate.sh`** — the featureless binary boots and serves with the whole plugin subsystem
  compiled out.
- **`security.yml`** — `cargo-deny` over advisories/licenses/sources/bans, on dependency changes
  **and weekly** (a pinned crate can have an advisory filed *after* merge).
- **`signing-gate.sh` / `release-key-guard.sh` / `build-provenance-gate.sh`** — plugin signing key
  present in the release binary, SBOM + SLSA attestation + cosign image (T8).
- **Release `branch-green`** — refuses to release from a red commit; **no override, no waiver, no
  exception list**, and an indeterminate status counts as RED (`RELEASE.md`).
- Depth: 2,000+ unit tests, an offline acceptance harness, a loom concurrency model
  (`scripts/loom.sh`) for the config-swap invariant, and mutation testing
  (`scripts/run-mutants-ec2.sh`).

### 4.3 Responsible disclosure & bug bounty — **partly in place, partly roadmap**
- **In place:** private reporting (email + GitHub private advisories), a 48h acknowledgement target,
  coordinated disclosure, GitHub Security Advisories with requested CVE IDs, credited reporters.
- **[ROADMAP] Bug bounty.** No paid bounty program yet. Proposal: start with a **published safe-harbor
  + hall-of-fame** (no cash) to establish scope and intake discipline, then graduate to a funded tier
  (e.g. via GitHub Security Advisories / a hosted platform) once the raise closes and a security owner
  exists (§4.4). Scope should track the "Issues of particular interest" list already in
  `SECURITY.md`.

### 4.4 Security ownership — **[ROADMAP]**
No dedicated security hire today. Proposal for the raise: name a **security owner** (fractional or a
first hire post-raise) accountable for the disclosure queue, the backport policy (§4.5), the bounty
graduation, and keeping this doc's claims true. Until then, ownership is the maintainers, explicitly.

### 4.5 Backport policy — **[ROADMAP — proposed here]**
`SECURITY.md` today supports only "latest `main` + most recent tag." A competitor backporting across
four minor lines is a real enterprise expectation. Proposed policy, expressed in busbar's
`dev → qa → main` model (`RELEASE.md`):

1. **Fix on `dev` first**, always — with a regression test *and*, where the class allows, a new or
   tightened CI gate (the busbar habit: turn a bug into a gate, §4.2). This is what makes a busbar
   security fix worth more than a patch — it retires the *class*, not the instance.
2. **Severity-driven backport window.** Commit to backporting a **Critical/High** fix to the **latest
   two minor release lines** (e.g. from `1.6.x` back to `1.5.x`) via a `security/<line>` branch that
   cherry-picks the fix and runs the same `qa-gate` before a patch tag. Medium/Low ride the next
   normal release. (Two lines, not four, is the honest commitment for a team this size — stated as a
   commitment, not aspiration.)
3. **Every backport carries a GitHub Security Advisory + CVE** and a `CHANGELOG` `Security` entry, so
   an operator pinned to a tag can see exactly what a patch tag fixes.
4. **Supported-versions statement** in `SECURITY.md` to be updated to name the backport window
   explicitly (currently it says only "latest `main` + most recent tag").

## 5. Gaps / roadmap (the honest list)

Stated plainly so the strong claims stay credible:

1. **No bug bounty program yet** (safe-harbor/hall-of-fame proposed as step one — §4.3).
2. **No dedicated security hire** (security owner proposed post-raise — §4.4).
3. **No formal backport policy in `SECURITY.md`** (two-line, severity-driven policy proposed — §4.5).
4. **Secret type is not universal (§2.2):** the resolver seam returns raw `String`/`Vec<u8>`;
   `resolve_settings` puts resolved plaintext into a JSON string to cross the plugin ABI;
   `Lease.secret` and `CredentialSecret.secret` are raw `String` with only a hand-written `Debug`.
   Converge these onto `Redacted`/`SecretRef` (tracked by 1.6.0-secret-type).
5. **Edge validation has no field path and no dedicated reject metric (§2.1);** wire-envelope
   uniformity is proven at the decision level but only spot-checked (openai) for the rendered 400
   body. Add per-dialect 400 goldens + a validation-reject metric with a field label.
6. **Audit is verified on boot restore, not on the live read path (§2.5):** the on-demand verifiers
   have no production callers and `GET /audit` serves an unverified ring. Mount a "verify now" admin
   verb and, ideally, verify-on-read.
7. **Audit "no secrets" is field-discipline, not type-enforced (§2.5)** — folds into gap #4.
8. **LLM plane is not yet feature-gated (§2.4):** no `plane-llm` feature; a live
   `busbar-core ↔ busbar-llm` back-dependency. Land `plane-llm` so LLM isolation matches MCP/A2A, and
   arm `plane-grep-gate` (currently report-only) as blocking; wire or retire the freeze-witness /
   plane-abi-neutrality scripts.
9. **FFI panic-safety is Rust-only (§2.3):** a non-Rust plugin that cannot unwind still aborts the
   process — inherent to FFI, documented, not eliminable without a process boundary
   (out-of-process plugin sandboxing is a possible future).
10. **Documented foot-guns remain** (`admin_insecure`, empty auth chain, `allow_all_metadata`) — gated
    behind explicit flags and boot warnings, but an operator can still choose insecurely (already
    out-of-scope in the threat model).

## 6. VC-pitch one-pager — the security story for the raise

**The reframe.** Enterprise LLM-gateway security is being sold as a *rate* — ~79 fixes a month, a
Director of Security, backports across four release lines. That is a treadmill: the same few
vulnerability *classes*, re-found and re-masked forever. **busbar's architecture makes those classes
unrepresentable or bounds their blast radius — and a CI gate keeps them that way.** We compete on
*structure*, not on patch velocity.

**The four structural claims — each a mechanism + the gate that enforces it:**

1. **Secrets can't leak because a secret is a type, not a string.** `Redacted<T>` implements no
   `Serialize`/`Deserialize` and prints `[REDACTED]`; `SecretRef` makes an inline secret
   unrepresentable in config. *You cannot write the code that leaks it.* (Enforced: `settings-leak-lint`,
   the type's trait bounds. Honest edge: the resolver boundary is still being converged onto the type.)
2. **A plugin can't escape into the core.** No panic unwinds across the FFI seam (`catch_unwind`
   everywhere), and a plane is handed *only* its own `&dyn Any` slot — never a `Store`, `GovCtx`, or
   audit handle. (Enforced: `blocking-ffi-lint`, `plane-purity-lint`.)
3. **Malformed input can't silently corrupt data.** Wrong-typed request bodies fail fast with a 400
   in the caller's own dialect, uniformly across six protocols; the money path is frozen to
   byte-identity goldens as a release gate. (Enforced: 6 input-hardening suites + the money-path
   goldens.)
4. **One plane's bug can't become everyone's problem.** The core names zero plane types and every
   plane is physically removable with the core still compiling. (Enforced, blocking:
   `plane-purity-lint --check`, `plane-delete-test --all`, `proto-deletion-gate`.)

Backing them: five in-code governance guarantees (auth, RBAC, destination allowlist, atomic budget
admission — all fail-closed, ordered before any charge), a tamper-evident hash-chained audit, and a
release pipeline that refuses to ship from a red commit with **no override**, shipping an SBOM + SLSA
attestation + signed image every time.

**The honest roadmap (why this pitch is credible and not marketing):** we will stand up a bug-bounty
program (safe-harbor first, funded later), name a security owner post-raise, publish a two-line
severity-driven backport policy, converge the last raw-`String` secret edges onto the type, add a
live audit-verify path, and feature-gate the LLM plane to match MCP/A2A. We are telling you the gaps
because a structural claim you can *verify* is worth more than a number you have to trust.
