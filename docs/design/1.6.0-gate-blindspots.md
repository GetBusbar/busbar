# 1.6.0 — GATE BLIND SPOTS: WHAT EVERY GATE'S CLAIM PROMISES AND ITS SCAN SET DOES NOT CHECK

One question per gate: **what does this gate's printed claim cover that its implementation never
reads?**

This is a list, not a repair. Nothing here is fixed by this document and nothing here was edited
into a gate, a ratchet, a golden or a `qa/*.toml`. Three separate agents are working the repairs
this run; the deliverable here is the complete, ranked list of what they are repairing and what
nobody is.

## WHY THIS IS A CORNER OF THE HOUSE

The owner's standard is that every corner has been checked for missing code, and the gates are
supposed to be that check. In one week the gates themselves produced four proofs that they were
not:

1. `token-sealed` and `token-sealed:admit-token-mint` both printed *"minted only inside the
   kernel"* and both stayed green against a forged mint planted outside the kernel — four literal
   spellings over a twenty-marker set (X-177).
2. `no-deferral`'s Class B listed four comment tags in its authoritative spec and matched them with
   nothing. A green `:unwaived` meant *"every marker I look for is waived."*
3. `prove_red` ran each gate only WITH the plant and never established a baseline. 183 red-ability
   proofs were vacuous and all 183 were passing.
4. `secret-hygiene` scans struct field declarations only; its own selftest asserts that a fn param
   `api_key: String` must NOT be flagged. Two real secret leaks shipped with it watching.

Four for four. The governing sentence is the spec's own, at
`docs/design/BUSBAR-1.6.0.md:2988`:

> **A CRATE THAT IS IN NO LIST IS IN NO GATE.** … The census rows exist precisely to stop a roster
> silently narrowing — but they count the roster, and cannot see a crate that was never enrolled in
> the first place. **Enrolment is the gap no count detects.**

and its companion at `docs/design/BUSBAR-1.6.0.md:2990`:

> **A NEEDLE GATE CANNOT SEE AN UNNAMED THING — shape blindness, not spelling blindness.**

Both sentences were written about specific gates. This census applies them to all 49.

## METHOD, AND THE RULE THAT KEEPS IT HONEST

**Reading a gate's prose is not verifying it.** Every row below is marked:

* **DEMONSTRATED** — a violation the claim covers was planted, the gate was run, and the verdict
  was recorded. Every plant was removed in the same shell invocation under
  `trap … EXIT INT TERM`; the technique is an orphan module under a crate's `src/` that no `mod`
  reaches, so cargo never compiles it. No plant survives this document.
* **MEASURED** — no plant needed: the tree already contains the thing the claim covers, and the
  gate is green about it. Zero-touch.
* **INFERRED FROM THE SCAN SET** — the gap is read off the roots, globs, needle lists and
  exclusions in the gate's own source. Not presented as a demonstration.

A gate that is **STANDING RED** cannot be asked the green→red question at all. For those, the probe
is *"does the gate's report NAME the planted violation?"*, and the row says so.

## PART 1 — THE SIX CROSS-CUTTING GAP SHAPES, EACH DEMONSTRATED ONCE

These six recur across the table in Part 2. Each is proven here so the table can cite rather than
repeat.

### SHAPE A — scan roots too narrow (`crates/*/src` is not the tree)

`qa/construction.toml:15` reads `scan_roots = ["crates/*/src"]`. That is the scan set for **all 113
construction rows**.

**DEMONSTRATED.** Seven identical token forgeries were planted at once and `construction` was run
once:

| # | plant site | needle | verdict |
| --- | --- | --- | --- |
| P1 | `crates/busbar-llm/src/zzz_probe_a.rs` | `Grant::<Dial>::mint(` | **RED — named** |
| P2 | `crates/busbar-llm/tests/zzz_probe_b.rs` | `Grant::<DurableWrite>::mint(` | invisible |
| P3 | `xtask/src/zzz_probe_c.rs` | `Grant::<KeyHandle>::mint(` | invisible |
| P4 | `crates/busbar-contract/src/caps/fixtures/lint_rules.rs` (appended) | `Grant::<Sign>::mint(` | invisible |
| P5 | `crates/busbar-llm/src/zzz_probe_d.rs`, inside `#[cfg(test)] mod` | `Grant::<AdminVerb>::mint(` | invisible |
| P6 | `crates/busbar-llm/src/zzz_probe_e.rs`, `use Grant as G; G::<Recover>::mint(` | alias | invisible |
| P7 | `crates/busbar-llm/benches/zzz_probe_f.rs` | `Grant::<Exit>::mint(` | invisible |

One of seven. The report read
`1 token constructor(s) spelled outside crates/busbar-kernel/src (ceiling 0)`.

P2, P3 and P7 are SHAPE A. They apply to every construction rule, not only `token-sealed`.

### SHAPE B — `production_only` / test classification makes a whole scope invisible

P5 above is the demonstration for construction. The same filter runs in `xtask/src/scan.rs`
(`production_lines` drops every `#[cfg(test)] mod` body) and in `xtask/src/gates/population.rs`
(`TEST_DIRS = ["/tests/", "/test_support/"]` plus `is_test_file`).

**Worth naming separately:** `population.rs` excludes `/test_support/` by path, but
`crates/busbar-kernel/src/lib.rs:317` gates that module `#[cfg(any(test, feature = "test-support"))]`
— it **ships** when the feature is on. Six files under `crates/busbar-kernel/src/test_support/` are
therefore production-reachable source that `settings-leak`, `response-header` and `blocking-ffi`
never open. DEMONSTRATED for `no-deferral` (below); INFERRED for the other three.

### SHAPE C — a blanket `exclude_files` entry

P4 above. `qa/construction.toml:522` reads

```toml
exclude_files = ["crates/busbar-contract/src/caps/fixtures/lint_rules.rs"]
```

**MEASURED, zero-touch, in addition to the plant:** that file already carries
`symbol: "Grant::<Recover>::mint("` (line 84) and `symbol: "take(&Grant::<Exit>::mint("` (line 93).
Both are exact matches for the `token-sealed` pattern set, both sit outside
`crates/busbar-kernel/src`, the file carries no `#[cfg(test)]` and its path carries no test
fragment — and the row is PASS. The exclusion is file-wide, so a real forgery written into that
file is invisible, which the plant then proved.

### SHAPE D — a hand-written literal list where the subject is generic (the X-177 root cause)

Three fresh instances, all demonstrated in Part 2: `kernel-token-wire-purity`'s twelve wire fields,
`plane-pricing-blindness`'s pricing verbs, `blocking-ffi`'s FFI seams, `response-header`'s five
header needles, `duplex-ws-default-edge`'s one WS crate name.

### SHAPE E — text matching defeated by indirection

P6 above (`use … as` alias). Repeated for `seal-witness` and for `no-float-money` (type inference,
which needs no alias at all) in Part 2.

### SHAPE F — a scope pointing at a subject that no longer exists

**MEASURED.** Every repo-relative path literal in `xtask/src/` was extracted and checked against
the tree: 409 distinct paths, **172 of which do not exist**. The overwhelming majority are selftest
fixture paths (overlay plants like `crates/busbar-core/src/planted_scope.rs`) and are correct by
design. Two are load-bearing scan-set entries, and both are on the money path:

* `xtask/src/gates/no_float_money.rs:242` — `crates/busbar-mcp-codec/src` in the `COUNT_READ_ROOTS`
  group *"the tool codec and plane"*. The crate is gone. This is exactly why
  `no-float-money:scan-floor` is standing red today.
* `xtask/src/gates/no_float_money.rs:473` — `crates/busbar-kernel-ledger/src/records.rs` in
  `PERSISTED_RECORD_HOMES`. Gone. The gate tolerates it by design ("scan every home that is there")
  — see the `count-scale-discriminator` row in Part 2 for why that tolerance costs the row its
  subject.

One more, not on a scan path but on an allowlist with no staleness row:
`xtask/src/gates/segregation.rs:44` allows `testing/shadow-oracle/golden/1.5.5/golden-digests.tsv`,
which does not exist. `segregation` owes six rows and none of them is "an allowlist entry still
names something."

**And the structural finding behind SHAPE F:** the gate whose whole job is *"every kind, crate,
path and glob named here resolves to something"* — `qa-names` — reads
`qa/*.toml` and nothing else (`xtask/src/gates/qa_names.rs:114-115`, `QA_ROOT = "qa"`,
`QA_EXT = "toml"`). `qa/` also holds **ten `.json` files** plus `.allow`, `.missing`, `.status` and
`.md` files, all naming crates and paths; and **every scan root quoted in this document is a Rust
constant in `xtask/src/`, which `qa-names` does not read at all.** The instrument for
"does this name still resolve" cannot see the place most names live.

### SHAPE G — report-only

`secret-hygiene` is invoked in `.github/workflows/ci.yml:1466` as
`SECRET_GATE_REPORT_ONLY=1 scripts/secret-hygiene-gate.sh --report`. Its findings block nothing.
The file's own comment says the flip to `0` needs no code edit — which is true and is not the same
as it having happened.
