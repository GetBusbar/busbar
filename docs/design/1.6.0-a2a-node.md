# A2A-NODE — the root-side A2A node, rewritten as MEASURED

The ledger launched this line on the MCP node's precedent: *a root-side node over the landed
`impl Units`, mounted at the composition root, one money-free class first, one class per commit,
each class's legacy arm deleted as it moves, the served bytes identical before and after on the
real binary.* Every one of those rules survives the measurement. Three of the line's **premises do
not**, and this document replaces them with what is on the tree, because a plan that is wrong about
the tree spends a slot discovering it — which is exactly what the MCP row's own estimate did, and
its hand-back says so in capitals.

Base: `ce17e9111` (`wip-mcp-row-10-combined-base`), which carries BIND-1 (the composition root's
one store adapter) and BRK-2 (one breaker for every plane, reached at the verify step). Those are
the only two holds this line needs.

---

## 1. THE FIRST CORRECTION — A2A has no arrival seam, so the node cannot be mounted the way the
## LLM node is

The brief says "wired at main.rs's node_store". That names where the node's STORE comes from
correctly, and it does not name a way in, because on this tree there is no way in.

**How the LLM node is reached.** `root/units_llm.rs:1615` holds `static NODE: LazyLock<LlmNode>`,
and `units_llm.rs:1808/1822` publish `PATH_INGRESS` / `BODY_INGRESS` — tables of
`fn(Arrival) -> Pin<Box<dyn Future<Output = Response> + Send>>`. The composition root installs them
(`main.rs:627`, `main.rs:652`), and SUBSTRATE calls them. The root gets control of an inbound
request because core's ingress asks the root for the handler. That is the whole trick, and it is
the reason the LLM node exists and the other four `impl Units` do not run.

**A2A has nothing of the kind.** Its surface is eighteen `PlaneRouteSpec` rows returned by
`busbar_a2a::a2a::receive::a2a_routes` (`receive.rs:3456-3577`), reached through
`PLANE_DECL.routes`, a plane-owned `fn` pointer the root pushes wholesale at `main.rs:703`. There
is no `A2A_INGRESS` table, no `Arrival`, no `ArrivalPayload` on this axis. `root-a2a-serve` — which
an earlier ledger row names — **does not exist on this tree**: `grep -rn root-a2a-serve crates/`
is empty. `root-a2a` DOES exist and is default-ON, and `main.rs:945-948` states exactly what it is
worth: *"It diverts no byte: the serving path is still the one `register_planes` mounted."* It
builds a scope policy and refuses boot if the policy is short an operation class. That is a seal,
not an ingress. SUB-4b recorded the same fact from the other side: *"A2A invoke: NO kernel path."*

**So the seam this line must build first is the way in.** And the tree offers exactly one that is
not a new mechanism:

> `PlaneDecl` has thirty-three fields, every one of them `pub` and every one of them `Copy`
> (`&'static str`, `bool`, bare `fn` pointers, `Option<fn>`). `PlaneRouteFn` is
> `Arc<dyn Fn(PlaneReqCtx) -> PlaneRouteFuture + Send + Sync>` — an `Arc`'d closure, which CAN
> capture, unlike the bare `fn` the LLM ingress seam is built from. And `install_planes` takes a
> leaked slice, so the decl may be built at runtime.
>
> Therefore the composition root builds **its own `PlaneDecl`**, every field copied from
> `busbar_a2a::PLANE_DECL`, with `routes` replaced by a root-owned function that calls the plane's
> own `routes` fn and then **replaces the handler of the rows whose classes have moved**.

**AND THIS IS NOT A PROPOSAL — IT COMPILES.** The mechanism was written as a throwaway cell in the
root and run before this document claimed it, because a design document that proposes a seam the
borrow checker refuses is worse than one that proposes nothing. What was proved, in the shipped
crate graph and with no new dependency:

```rust
let plane: &'static PlaneDecl = &busbar_a2a::PLANE_DECL;
let composed = PlaneDecl {
    routes: Some(|slot| {
        let mut rows = (busbar_a2a::PLANE_DECL.routes.expect("the plane declares routes"))(slot);
        for row in &mut rows {
            if row.path == "/a2a" {
                let original = Arc::clone(&row.handler);      // the plane's own body, kept
                row.handler = Arc::new(move |ctx| original(ctx));
            }
        }
        rows
    }),
    ..*plane                                                  // every other field, by identity
};
```

`..*plane` works because every one of the thirty-three fields is `Copy`; the `Arc::clone` of the
plane's own handler is what a moved class DELEGATES the unmoved methods to, which is not building
beside — the moved class's arm is deleted from the plane in the same commit, so exactly one body
answers it. The probe was reverted; it lives at `~/Developer/tmp/a2a-node/probe_decl.rs`.

This is not a second mount and it is not a route built beside the plane's. The plane still declares
its own paths, methods and admission bars — `(path, method, auth)` are handed through VERBATIM, so
the `CoreRouteTable` row and the auth middleware's `required_scope` are untouched, which is the
security invariant the neutral route seam exists to preserve. What changes is which body answers.
It is the composition composing what it mounts, and the root's cell rises are to be declared BY
IDENTITY on exactly that ground — the ruling the integrator already gave the MCP node.

## 2. THE SECOND CORRECTION — A2A's "dispatch table" is three tables, and only one of them is a
## class line

MCP's classes are one ops-table-driven `match` (`busbar-mcp/src/mcp/method.rs:169`, `row_for(method)`
then `row.op =>`). A2A has no such thing, and — measured — **`busbar-a2a` has no dependency edge to
`busbar-plane-a2a` and names none of its items.** Stated precisely, because the loose version of
this sentence is wrong: `grep -rn busbar_plane_a2a crates/busbar-a2a/` returns ELEVEN hits, and all
eleven are COMMENTS — every one of them saying which crate owns a constant and, repeatedly, that
the other crate "may not name this crate". The `Cargo.toml` hit is a comment too; the only member
of that family it actually depends on is `busbar-a2a-codec`. The direction is enforced and the
crates say so.

The consequence is the one that matters here: `ops::OP_CLASSES` — the **twelve** classes
`root-a2a`'s boot seal counts (`OP_MESSAGE_SEND`, `OP_MESSAGE_STREAM`, `OP_TASK_GET`,
`OP_TASK_LIST`, `OP_TASK_CANCEL`, `OP_TASK_SUBSCRIBE`, the four `OP_PUSH_CONFIG_*`,
`OP_AGENT_CARD`, `OP_PUSH_EVENT`), and the twelve this line is nominally about — **is never
consulted on the serving path.** The ops table is a scope/pricing declaration; the serving path
re-spells the same vocabulary three more times, by hand:

| # | where | shape | what it decides |
|---|---|---|---|
| 1 | `receive.rs:1067-1073` | inline `matches!` on two literals | the extended agent card on `Target::FromCatalogue` |
| 2 | `local.rs:125-141` + arms at `receive.rs:1403-1481` | listed method → `LocalVerb` | **the verbs busbar answers with no backend hop** |
| 3 | `relay.rs:901-922` | eleven-arm literal match | normalises both dialects for the hop |

**Table 2 is the class line.** It is the only one shaped like MCP's: methods LISTED rather than
prefix-matched ("so a third spelling is a deliberate edit and not something a loose prefix match
swallows" — `local.rs:123`), one enum variant per class, one deletable arm each. Its own module
header defines the set exactly as this line needs it: *"A verb this plane answers WITHOUT a backend
hop."*

    ListTasks              "ListTasks" | "tasks/list"
    CreatePushConfig(V10)  "CreateTaskPushNotificationConfig"
    CreatePushConfig(V03)  "tasks/pushNotificationConfig/set"
    GetPushConfig(V10|V03) "GetTaskPushNotificationConfig" | "tasks/pushNotificationConfig/get"
    ListPushConfigs        "ListTaskPushNotificationConfigs" | "tasks/pushNotificationConfig/list"
    DeletePushConfig       "DeleteTaskPushNotificationConfig" | "tasks/pushNotificationConfig/delete"
    Subscribe              "SubscribeToTask" | "tasks/resubscribe"

## 3. THE THIRD CORRECTION — "money-free first, agent card first" does not survive the measurement

The brief's first class is "agent card / discovery". Measured, the A2A surface splits three ways
and the obvious candidate is the wrong one:

**`GET /.well-known/agent-card.json` and `GET /.well-known/oauth-protected-resource/a2a`** are
`RouteAuth::None` (`receive.rs:3480-3503`). They carry no principal, take no meter, write no audit
row and never enter the gauntlet at all. They are the most money-free thing on the plane and they
are **the wrong first class**: serving one through the node puts the approve step in front of a
DELIBERATELY PUBLIC endpoint. That is MCP's class-6 collision — a credential holding no grant is
permitted no operation — bought in advance, for a class where the 1.5.5 behaviour is not merely
ungoverned but unauthenticated on purpose. This line does not move an open document behind a door.

**The push-config verbs** are the genuinely money-free governed classes: answered out of busbar's
own store, no credential of busbar's leased, no upstream dialled, and already admitted, hook-gated,
budget-checked, metered and audited on the legacy path. `GetPushConfig` and `ListPushConfigs` are
reads; `DeletePushConfig` is a write; `CreatePushConfig` additionally mirrors a callback onto the
backend when its local answer is `200` (`receive.rs:1494+`, `super::pushback`) — an outbound hop,
so it is NOT the first one.

**Two members of table 2 are not what their placement suggests, and both are recorded here so a
later class does not discover them as a surprise:**

* **`ListTasks` is local in its ANSWER, not in its traffic.** `receive.rs:1415-1422` awaits
  `originate::refresh_listed_tasks` — an upstream refresh — before rendering busbar's own rows.
* **`Subscribe` is the only PARTIAL verb.** `None` from `subscribe_refusal` means the task is live
  and this caller's, and the call relays unchanged. Only its two refusals are busbar's.

And two classes the brief lists as money-free are not on table 2 at all: **`tasks/get` and
`tasks/cancel` have no local arm** — they appear only at `relay.rs:906/908`. Every one of them
dials the upstream agent.

### The class order this line therefore takes

    class 1  GetPushConfig       read, no hop, both dialects       <- the first money-free class
    class 2  ListPushConfigs     read, no hop, both dialects
    class 3  DeletePushConfig    write, no hop, both dialects
    class 4  CreatePushConfig    write, no hop, MIRRORS a callback
    class 5  Subscribe           partial: the two refusals only
    class 6  ListTasks           local answer over an upstream refresh
    ---- the hop begins here; everything below reaches an upstream and is the money path ----
    parked   agent card (FromCatalogue), tasks/get, tasks/cancel, message/send, message/stream

`message/send` is A2A's `tools/call` and is LAST for the same reason.

## 4. WHAT THE SEAM COSTS, stated before it is built

`A2aBindings` (`units_a2a.rs:602-700`) has **twenty-four** borrowed halves — auth chain, auth
bindings, trust token, pool view, kind facts, breaker view, resolver, guard policy, denylist, the
pinned agents, the admission door, the bucket chain, the pricer, the byte price, the record legs,
the meter policy, the scope policy, the durability mutex, the pool, the pinned wall epoch, the task
TTL, the pinned MONOTONIC reading, and the sealed origin. A node is what owns all of them for the
length of the process and lends them per unit. The shape already exists and is already tested — the
`Deployment` fixture at `root/tests/units_a2a.rs:1624-1730` assembles exactly this set — so the
seam is a PROMOTION of a proven fixture to production, not a new design.

**And the promotion is where the honesty is owed.** That fixture builds three of its halves as
stand-ins: `AuthChain::new(Vec::new(), false)`, `AuthBindings::without_directory()` and
`Pricer::flat(0)`. Shipping those is precisely what took `no-test-doubles-in-production:doubles`
from 5 to 8 on the MCP node's branch, and its hand-back names it *"a hard blocker for class 13"* —
the class that reaches an upstream. **This line must build the node over the composition's REAL
auth chain, real auth bindings and real pricer, or it must not claim the classes below the hop
line.** Classes 1-6 above the line price nothing and dial nothing, so a node standing on real
halves for them is achievable; a node standing on stand-ins for them is a node that cannot ever be
handed `message/send`.

## 5. The rules this line is held to, unchanged

* One class per commit. Money-free first. `message/send` last.
* Each class's legacy arm **DELETED** as it moves, with the comment recording why it is gone.
  Delete legacy; never build beside.
* The served bytes **byte-identical** before and after, captured on the REAL binary through
  `~/Developer/tmp/a2a-node/capture.sh` (the a2a conformance workflow's own subject boot, held
  open, with the instrument holding the credential). A class whose answer is a constant or a
  refusal is byte-weak by construction and gets the DIFFERENTIAL capped run the MCP line invented.
* **A class whose 1.5.5 bytes collide with a 1.6.0 rule is PARKED with the collision stated.**
  Never resolved by inventing bytes.
* The money path and every recorded family byte-identical, or STOP at the previous class.
* Ceilings only down, except MOVE by identity or a declared FACE under §1.1 in the same commit. The
  root's rises from the node are declared BY IDENTITY — the composition composes what it mounts.
  `busbar-a2a`'s cells never rise. Never a waiver.

## 6. One measurement that has no home yet

**There are ZERO recorded `a2a`-family cells in the 1.5.5 shadow oracle.** The golden corpus at
`testing/shadow-oracle/golden/1.5.5/cells/` is 915 cells over 24 families, and `a2a` is not one of
them; the only filename containing the string is `neutrality__routes__a2a-shaped-404.json`. So the
`^(a2a|…)` arm of this line's family filter matches nothing today, and "the class's recorded cells
are byte-identical" **cannot be discharged by the oracle for A2A at all.** The byte proof is the
real-binary capture, and that is not a substitute chosen for convenience — it is the only evidence
that exists. Recorded here because a green oracle leg on this branch is a green verdict about
cells that were never written, which is the stale-scope trap wearing different clothes.

## 7. THE CLASS-1 STOP — the two steps no unit serves, named rather than re-implemented

The seam is built, the node is mounted, the composition pays for its real chain and its real pricer,
and `MOVED_ONTO_THE_NODE` is still empty. This section says why, because the reason is a pair of
NAMED GAPS and not remaining work, and the rule this line is held to is explicit about what to do
with one: **a step no unit serves is a STOP and is named; it is never re-implemented in the root.**

### What a request for class 1 meets today, in order, from the route inward

Every one of these runs BEFORE `local::get_push_config` is called. Measured in
`crates/busbar-a2a/src/a2a/receive.rs`, `invoke_inner` through `admitted`:

| # | the step | where | what it refuses with | the kernel step that serves it |
|---|---|---|---|---|
| 1 | the route's own auth | `RouteAuth::Key`, middleware | 401 | unchanged by the swap — `(path, method, auth)` pass through verbatim |
| 2 | governance present | `gov.is_governed()` | this plane's `governance_required` | `Authenticate` |
| 3 | the wire gate | `Wire::refuse` | −32005, media type / protocol version | `Decode` |
| 4 | the shared ingress sequence | `ingress::protocol::serve` | origin refusal, −32700 parse, notification 202 | `Decode` / `Encode` |
| 5 | the key is resolved | `gov.key` | `governance_required` | `Authenticate` |
| 6 | **the catalogue SELECTS an agent** | `select(&host, key, &shape)` | **503 when this caller has no approved agent** | **NONE** |
| 7 | **the catalogue ADMITS that agent** | `admit(&host, key, &agent_id, …)` | the catalogue's own refusal | **NONE** |
| 8 | **the operator's hook gate** | `gate_attached` → `gate_decide` | the hook's status, in this plane's vocabulary | **NONE** |
| 9 | **the operator's rewrite pass** | `tap_attached` → `transform_over` | (proceeds; may edit `params`) | **NONE** |
| 10 | governance enabled | `governance_enabled()` | `governance_required` | `Authenticate` |
| 11 | the budget admit | `govern_admit_reason` | 429 "this key's budget is spent" | `Admit` — DUPLICATE, dies with the arm |
| 12 | the class's own document | `local::get_push_config` | its own `TASK_NOT_FOUND` etc. | the answer arm of `serve_class` |
| 13 | the meter and the audit row | `meter_request` + `audit_emit` | — | `Meter` / `Audit` — DUPLICATE, dies with the arm |

Rows 11 and 13 are the ones the ruling describes: plane pre-steps that DUPLICATE kernel steps, and
they die with the arm because the node's loop already serves them over the deployment's own door,
group table and pricer. Rows 2–5 and 10 are served by the loop's own `Authenticate` and `Decode`.

**Rows 6, 7, 8 and 9 are served by NO unit in the tree.** The fourteen `busbar-unit-*` crates are
admission, audit, auth, breaker, cost, egress, egress-auth, ledger, scope, transport-key, trust,
usage, verbs and wal. None of them is a catalogue and none of them is a hook gate. The two gaps,
stated as the things they are:

* **THE CATALOGUE STEP.** Which agent a `Target::FromCatalogue` call resolves to, and whether this
  caller may have it, is decided by `select` + `admit` over the engine's own catalogue. A caller
  with no approved agent is refused **503** at row 6, *before* a class-1 answer that names no agent
  at all is ever computed. Moving class 1 onto the node without this step would turn that 503 into
  a served answer — a caller who is refused today would be answered tomorrow. That is not a byte
  difference in a refusal's wording; it is a refusal becoming a success, which is the widest kind of
  collision this line can buy. The root MAY NOT re-implement it: a catalogue read in the composition
  root is a second opinion about which agents a key holds, and two of those is how a deployment
  comes to admit on one reading and bill on another.
* **THE OPERATOR HOOK STEP.** `gate_decide` and `transform_over` are the operator's own controls,
  fired for EVERY verb on this plane precisely so a control's scope does not depend on which method
  a caller happened to use. A class moved onto the node stops firing them. For class 1 that means an
  operator who attached a screening gate to an agent would find one verb of thirteen no longer
  screened — silently, with no configuration change of theirs.

### What this means for the class order

It means the hop line is not the first boundary. **Rows 6–9 are a boundary ABOVE it**, and every one
of the six local classes sits below it, because every one of them arrives through `admitted` and
meets all four. The class order in §3 is unchanged and still correct; what changes is that NO class
on it can move until the catalogue step and the hook step have a kind-neutral home, or until the
ruling says a moved class is entitled to skip them and names what the 503 becomes.

Both gaps are RECORDED HERE rather than worked around. The alternative shapes were considered and
each is refused by a rule already in force:

* Re-running `select`/`admit` in the root — refused: a second catalogue reading in the composition.
* Calling the plane's own pre-steps from the root before `serve_class` — refused: it is the same
  pre-step running twice for unmoved methods and once for moved ones, and it puts plane-specific
  admission logic in the composition root.
* Swapping the handler DEEPER, inside `admitted` after row 11 — this is the `ServingNode` shape MCP
  actually took, and it is a different seam from the one ruling (1) describes. It would make rows
  6–9 run first and the gaps disappear. **It is the one shape that both discharges ruling (3)'s
  "the serving entry runs the kernel loop" and keeps rows 6–9, and reconciling it with ruling (1)'s
  route-level swap is the decision this line is waiting on.**

### The third thing the first class needs, and it is a boot fact rather than a step

`compose_chain` answers `None` for any chain naming a PLUGIN auth provider, and the node then does
not mount. Today that is inert. With a class moved and its arm deleted, such a deployment would LOSE
the class outright. The ruling is that the node COMPOSES plugin providers so `compose_chain` never
answers `None` for a mounted provider — and the measurement says what that costs: the plugin modules
are opened by `busbar_core::auth::AuthMiddleware::new` through `PluginRegistry::open_auth`, held in
a `pub(crate)` field, and never lent out. The two faces are already the same shape (`name`,
`authenticate`, `cacheable`, and a `Principal` of four identical fields), so the BRIDGE is thin; what
is not thin is the handle. Opening the same plugin a second time from the root would be two
instances of one provider with two caches and two revocation windows, which is the same
two-readings-of-one-configuration defect the pricer and the book were each fixed for. So the honest
discharge is that the composition opens each auth plugin ONCE and lends the same boxed module to the
engine and to the node — a boot re-composition, named here, not started here.
