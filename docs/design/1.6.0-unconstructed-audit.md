## THE RULE, WRITTEN DOWN

> **A CAPABILITY THAT IS NEVER CONSTRUCTED IS A CAPABILITY THAT DOES NOT SHIP.**
> **Its tests prove the code works; they prove nothing about whether it runs.**

The corollary, which is the part that cost three `DONE` rows: **a test suite cannot detect this
class, because the test constructs the capability itself — which is the one thing production does
not do.** A green test file beside an unwired capability is not evidence of shipping; it is the
exact thing that makes the gap invisible.

`1.6.0-commit-residue.md` §11.5 reached the same conclusion from the other direction and asked for
the instrument by name: *"a gate that fails when a public capability has no non-test caller would
have caught `A70` on the commit that introduced it."* **That gate now exists** — see §3.

## 3. THE GATE — `cargo xtask gate unconstructed`

**Files:** `xtask/src/gates/unconstructed.rs` (new), `qa/unconstructed.toml` (new, the declarations),
registered at `xtask/src/gates/mod.rs` (`pub mod` + one `Registration`, batch 2, tier Fast).
**No product code was changed.** CI reaches it through `cargo xtask gate --all` and
`cargo xtask selftest`, which `.github/workflows/ci.yml` already runs.

### 3.1 Why the existing `reachability` gate does not already catch this

`reachability` is the closest instrument and is **not** a substitute. It asks *is this MODULE
reached from `fn main()`, and does this plane have a unit path the root constructs?*
`root/durability.rs` passes **every one of its rows**: the module is reached, `build_for_node` is
called, a chain **is** constructed. The capability that never runs is **one builder call inside a
function that does run** — a granularity module reachability cannot express. The two compose:
`reachability` says the code is reached; `unconstructed` says the capability inside it was switched on.

### 3.2 What counts as a construction site — and why decoration cannot satisfy it

A construction site is **a call, in production code, in the declared scope**. Rejected by shape:

* **`use` statement** — importing a capability is not calling it, and a `use` is precisely what puts
  a capability's name in a file that never invokes it;
* **comment / doc comment / string literal** — every line is read off `ScopeLine::counted`, the copy
  with literal and comment bodies blanked. *A gate that trusts a comment inherits the lie;*
* **type alias** and **attribute** — both name a capability without reaching it;
* **the definition itself** — `fn signing_with(` is where it is BUILT, and reading that as evidence
  it is CALLED is the exact confusion this gate ends;
* **test scope** — `crate::scan::test_scope` (the one answer every scanner here uses) **plus** a path
  rule: under `tests/`, or named `tests.rs`/`*_tests.rs`/`fuzz`/`benches`, is test code whatever the
  contents say.

And the structural guarantee, stronger than any filter: **every `construct` needle must end in `(`**,
checked on the *declaration* before a byte is read. **The gate cannot be *configured* to accept a
non-call.** A future editor cannot quietly weaken a row to `construct = ["signing_with"]` and have it
pass on an import line — the whole declaration is refused, loudly. Proven by control 7.

### 3.3 The three outcomes, kept apart

* **Constructed** → PASS, and the row prints the site.
* **Undeclared and unconstructed** → **RED**, printing every mention it rejected *and the reason for
  each*, so the reader sees *"1 mention, rejected: test path"* rather than a bare absence.
* **Declared `unshipped`** → a **tracked row**: passes, and prints its reason and its switch on every
  run. Strictly more than the source comment it replaces. `unconstructed:stale-declaration` reds the
  moment such a row **acquires** a site (strike it in the commit that wires it) or names a symbol its
  `built` file no longer defines. **The ledger cannot outlive the debt it tracked.**

A declaration is refused if `why` < 40 chars, or if an `unshipped` row's `switch` < 40 chars. *A
shrug is not a reason; a debt with no expiry is the state this file exists to end.*

### 3.4 Stated limits — so nobody reads more into a green row than is there

* It proves a production **call site exists**. It does **not** prove that call is reached from `fn
  main()` — that is `reachability`, and the honest claim is the two together.
* A construction reached only through **macro expansion** is invisible to it. That direction is a
  **false RED**, which someone reads and answers — never a false green.
* A needle is matched as **text**, not resolved as a path; `scope` is what keeps it narrow.
* **It does not see N1's shape** (*constructed, but input hardwired empty*) and claims no coverage of it.
