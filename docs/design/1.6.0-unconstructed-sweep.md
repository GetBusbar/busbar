# 1.6.0 — THE UNCONSTRUCTED SWEEP

**A findings ledger, not architecture.** It states what is declared and never built, where each
thing is declared, where (if anywhere) it is built, and which shape of broken pair it is. It
settles nothing that `docs/design/BUSBAR-1.6.0.md` settles: that file is the spec, this one is a
measurement of the tree against it.

## The law this sweeps

> **A CAPABILITY THAT IS NEVER CONSTRUCTED IS A CAPABILITY THAT DOES NOT SHIP. Its tests prove the
> code works; they prove nothing about whether it runs.**
>
> — `xtask/src/gates/unconstructed.rs`, module doc, and `qa/unconstructed.toml`, restated verbatim.

The governing spec lines this sweep is measured against:

* **`docs/design/BUSBAR-1.6.0.md:321` (Part 2, row #3)** — the seven plugin kinds are
  *store, secret, auth, hook, export, PLANE, TRANSPORT*, each *"a capability core brokers by key,
  swappable … of which core names no concrete instance."*
* **`docs/design/BUSBAR-1.6.0.md:1718–1721` (Part 7, #18b(a))** — the release's own worked example of this
  defect: *"`PluginRegistry::open_export` has **zero callers outside the loader's own tests**, and
  `ExportDispatch(pub Arc<DynExport>)` … **is never constructed anywhere**."* Both are re-measured
  here and both still hold.
* **`docs/design/BUSBAR-1.6.0.md:90` (Part 0, "What \"done\" means", clause 2; restated at `:272`)** — *"Construction
  standing-reds **empty**."*

**Why a sweep and not a test.** A test suite cannot see this class, because the test constructs the
capability itself. A type with sixteen green unit tests and zero production construction sites
passes every one of them and ships nothing. Every green test is evidence *against* noticing.

## The three populations, kept apart

Three answers, never conflated:

1. **constructed in PRODUCTION code** — not a finding;
2. **constructed only in TESTS / fixtures / benches** — a finding, and a different one;
3. **constructed NOWHERE** — a finding, and the sharper one.

"Production" here means: outside `tests/`, `benches/`, `test_support/`, `fixtures/`, `*_tests.rs`,
`tests.rs`, `fuzz/`, `conformance/`, `testing/`, and outside every brace-matched `#[cfg(test)]`
item in an otherwise-production file. Of 1 802 indexed Rust files, 940 are test-population by path
and a further 488 production files carry at least one inline `#[cfg(test)]` region; 51.4 % of all
864 066 indexed lines sit in a test region.

## HOW EVERY ZERO WAS CONTROLLED

A false zero here reads exactly like a clean result — *"no construction sites found"* and *"my grep
was wrong"* produce the same output. Four independent controls were run, and each one caught
something.

### Control 1 — a known-negative and a known-positive, from the spec itself

| control | expected | measured | engine |
|---|---|---|---|
| `ExportDispatch` | ZERO construction (spec `#18b(a)` says so) | 0 prod, 0 test, 2 non-construction mentions (`pub struct`, `impl … for`) | python census + `git grep` |
| `PluginRegistry` | constructed in production | 21 production code references, 11 test | python census + `git grep` |
| `view_with_arena` | unknown | 0 anywhere — a genuine zero | python census + `git grep` |
| `Ledger::dual_writing` | SHIPPED (per `qa/unconstructed.toml`) | 1 production site, `crates/busbar/src/root/durability.rs:773` | `git grep -E "(\.|::)dual_writing\("` |

Two of these controls **changed the tool**. The first run scored `ExportDispatch` at
`code_prod = 1` and `PassThroughBook` at `code_prod = 1`; both hits were `impl Trait for X` header
lines. An `impl` header *names* a type and neither constructs nor calls it, so the scanner now
excludes `impl`-header lines alongside `use` lines. Without that control both would have read as
*constructed in production* and dropped out of this ledger.

### Control 2 — the live gate ledger, scored blind

`qa/unconstructed.toml` declares 19 capabilities (18 of them `unshipped = true`). Scoring those 19
with this sweep's own census, without looking at the verdicts:

**16 of 19 agreed outright.** The three that did not, and why:

* `new` — the gate scopes its needle to `LedgerEntry::new(`; a name-global census sees 3 636
  production and 10 152 test occurrences of `new` across the tree. **A name-global method cannot
  resolve a name this common**, and this ledger says so rather than reporting a number.
* `signing_with` and `open_export` — each scored `code_prod = 1`. Both "production" hits are
  **string literals inside xtask gate source** (`"open_export"` in
  `xtask/src/gates/blocking_ffi.rs:142`; `"record: AuditChain::new().signing_with(key),"` in
  `xtask/src/gates/unconstructed.rs:815`). This census blanks comments but not string bodies. The
  gate's own `ScopeLine::counted` blanks both; the residual false-positive surface is **xtask gate
  sources only**, and it inflates counts rather than hiding findings.

Adjusted for those two known artefacts the agreement is **18 of 19**, with the nineteenth
(`new`) declared unresolvable by this method.

### Control 3 — two independent engines on every candidate

Every one of the 74 raw zero-reference candidates was re-run through `git grep -n -E` over
`crates/ xtask/ tests/ fuzz/ conformance/ examples/ testing/`, with the return code recorded. A
candidate is only listed if **both** engines agree. `git grep` returned `rc=1` (no match) on the
docs leg for 55 of them and `rc=0` with output on the Rust leg for all 74 — so no candidate rests
on an empty-output-with-`rc=0` result, which is the POSIX-ERE `\b` trap.

Three specific traps were avoided by construction:

* **`\b` in `git grep -E`.** POSIX ERE has no `\b`. Every word-boundary query in this sweep is
  written `(^|[^A-Za-z0-9_])NAME([^A-Za-z0-9_]|$)`, never `\bNAME\b`.
* **`grep -c` counts LINES, not occurrences.** Every count in this file is an occurrence count
  taken from a tokeniser, or an explicitly-labelled *file* count.
* **A dict keyed by name collapsing duplicates.** Declarations are stored as a **list** per name and
  duplicate-bearing names are flagged. Three name collisions materially changed an answer and are
  recorded in "Name collisions that changed an answer" below.

### Control 4 — a second tool for the feature closure, after the first gave a false zero

The first feature-activation pass was a hand-rolled Cargo.toml parser. It reported
`busbar-kernel/plane-voice` and `busbar-kernel-identity/sha256` as **activated by no build
configuration**. Both are false. `crates/busbar/Cargo.toml:218` reads
`plane-voice = [… , "busbar-kernel/plane-voice"]` and `:102` reads
`busbar-kernel-identity = { …, features = ["sha256"] }`; the parser mis-handled multi-line
`{ … }` dependency tables. Re-run through **cargo itself** —
`cargo tree --workspace --locked --format "{p}|{f}"` — the default workspace build activates
`busbar-kernel/plane-voice`, `duplex-ws`, `runtime`, `busbar-voice/runtime` and
`busbar-kernel-identity/sha256`. **Every feature claim in this file is cargo-resolved, not
parsed.**

# METHOD, STATED SO IT CAN BE RE-RUN AND FALSIFIED

1. **Index.** Every tracked `*.rs` under `crates/`, `xtask/`, `tests/`, `fuzz/`, `conformance/`,
   `examples/`, `testing/` (1 802 files, 864 066 lines) is split line-by-line into production and
   test regions. Path rules classify whole files; brace-matched `#[cfg(test)]` items classify
   regions inside otherwise-production files.
2. **Declare.** `^\s*pub(\(…\))?\s+(async|unsafe|extern "…")?\s*(struct|enum|trait|fn|type|const|static|union)\s+NAME`
   over every indexed file yields 10 932 declarations under 8 177 distinct names, stored as a
   **list per name** so duplicates are flagged rather than collapsed.
3. **Reference.** Every line is comment-stripped (`//…`), then tokenised with
   `[A-Za-z_][A-Za-z0-9_]*` and matched against the declaration set. Excluded from the reference
   count: the declaration's own line, `use`/`pub use` lines, and `impl …` header lines — each names
   a symbol without constructing or calling it.
4. **Bucket.** `code_prod == 0 && code_test == 0` ⇒ shape 1a. `code_prod == 0 && code_test > 0` ⇒
   shape 1b.
5. **Verify.** Every shape-1a candidate is re-run through `git grep -n -E` with return codes
   recorded, and adjudicated by hand.
6. **Cross-check.** The 19 rows of `qa/unconstructed.toml` are scored blind by the same census;
   18 agree (see Control 2).

**What this method cannot see, stated rather than discovered:**

* **Macro expansion.** A construction that only exists after macro expansion is invisible. This
  direction produces FALSE REDS — a reader answers them — never a false green. The plugin crates'
  `busbar_plugin_sdk::export_*_plugin!` self-registration is the main instance in this tree, and it
  is why shape 4A is stated as *"the contract trait has no implementor"* rather than *"the kind has
  no implementation"*.
* **Function pointers, vtable slots and FFI.** A capability reached through an `extern "C-unwind"`
  slot is invisible; `xtask/src/gates/unconstructed.rs`'s header names `metrics_emit` as the case
  that bit a previous sweep.
* **A name shared by two types.** Resolved by hand for the four collisions found; a name as common
  as `new` is declared unresolvable rather than reported.
* **String literals in xtask gate sources.** Comments are blanked, string bodies are not, so a gate
  that names a symbol in a needle inflates that symbol's production count. Two instances found, both
  identified in Control 2.
* **Reachability from `fn main()`.** This sweep proves a call site exists or does not; it does not
  trace the call graph. `cargo xtask gate reachability` does that, and its four live reds are
  carried here as shape 2 rather than re-derived.
