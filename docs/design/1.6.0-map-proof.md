## 0. THE METHOD — count-in = count-out, per source

For every place work can be recorded, three numbers:

| | meaning |
|---|---|
| **COUNT IN** | what the source mechanically contains, extracted by a command printed in this file |
| **COUNT OUT** | how many of those reached **the master list** (defined in §1) as a row somebody owns |
| **DELTA** | `IN − OUT`. A non-zero delta is either an extraction bug or a dropped item. Finding those is the entire point. |

**A delta is not a failure to be hidden. An unexplained delta is.** Every non-zero delta below is
either reconciled in prose or named as unreconciled. Nothing is rounded, nothing is asserted from
memory, and every number carries the command that produces it.

### 12.3 The one structural finding, if only one survives

**There is no mechanism that turns a commit body into a map row.** 307 commits in 36 hours, 242
recorded residue findings, bodies carrying ship blockers, live breaches and instrument defects — and
nothing reads them back. Every other delta in this table was manufactured by that gap.

Sources **S1, S2a and S7 reconcile precisely because each has a counter that refuses**:
`DONE_GROUPS_DECLARED` fails the run the moment it stops matching `begin_group`; the marker sweep is
a fixed regex over a fixed file; the decision list is `^## N.`-numbered. **Every source with a
refusing counter reconciled. Every source without one did not.** That is the whole result, and it
predicts the fix.

The corollary the tree already wrote down, in `eb36d1695`: *"a gate that cannot be shown failing is
not evidence."* The same applies to a map: **a map with no counter that can go red is not a map, it
is a list.**
