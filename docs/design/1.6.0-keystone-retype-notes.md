# 1.6.0 KEYSTONE — retype the busbar-llm engine hot path off `&Arc<busbar_core::state::App>`

Scratch design notes for the ABI-purity KEYSTONE pass. Base ref: `e57f6413` (ABI-purity P7),
plane-purity `--baseline` = **181 BACKWARDS**. Goal: the engine no longer names
`busbar_core::state::App`, and the telemetry / ingress / hooks / proxy reaches that hang off the
`&App` borrow are drained, ALLOC-FREE. This is the single largest/riskiest ABI-purity move; the
alloc-gate (`crates/busbar-llm/src/engine/proxy_tests/alloc_gate.rs`) is the hard backstop.

## 1. How the engine obtains `&Arc<App>` today (Phase A.1)

* The universal ingress entry (`native_ingress::operation_ingress` / `ingress_path_model`) receives a
  `busbar_substrate::ingress::arrival::ArrivalCtx` (a type-erased `dyn Any`), and DOWNCASTS it to
  core's `busbar_core::ingress::arrival_host::ArrivalPayload` (`native_ingress.rs::payload`). That
  payload carries `app: Arc<App>`, `gov: PlaneRequestCtx`, `caller_token`. **This is the ROOT
  boundary** where the plane acquires its `&Arc<App>`.
* From there `&p.app` threads down through `operation_ingress_inner` → `forward_with_pool[_parsed[_inner]]`
  (pipeline.rs) → `walk.rs` / `wire.rs` / `select.rs` / `hooks.rs` / `response_body.rs` /
  `lazy_body.rs` / `usage.rs`, and independently into `health::spawn_probers`/`probe_lane`.
* The engine uses `app` for exactly two families of thing:
  1. **Its OWN concrete routing tables** — `app.engine_tables()` (the `AppEngineExt` trait in
     `engine/tables.rs`, a `plane_slot` downcast to the plane-owned `NativeRuntime` — 79 call sites)
     and the breaker store `app.store` (`Arc<dyn busbar_core::store::LaneRuntime>` — 48 sites),
     `app.governance`, `app.cost`, `app.groups_registry`, `app.tap_hooks*`, `app.rewrite_hooks`,
     `app.global_gates`, the pool-hook down-facades `app.pool_{policy,gates,rewrites}`.
  2. **Host capabilities** reached today by passing `app` to core FREE FUNCTIONS:
     `busbar_core::telemetry::{breaker_trip,upstream_attempt,upstream_failure,failover,translation}`,
     `busbar_core::ingress::{finish_rejected,finish_admitted,destination_guard,admission_door,pool_label,not_found_message}`,
     `busbar_core::proxy::{ingress_error,agnostic_error_envelope}`, `app.next_request_id()`.

The neutral replacement already exists: `busbar_substrate::plane_host::EngineHost` (a large `Send +
Sync` trait, `#[async_trait]`) + `EngineTablesView`/`LaneView`/`EMPTY_VIEW`. Core implements it as
`busbar_core::plane_host::EngineHostImpl { app: Arc<App>, handle: Option<AppHandle> }`, minted via
`busbar_core::plane_host::engine_host(&Arc<App>) -> Arc<dyn EngineHost>` (one heap alloc per mint).

## 2. THE ALLOC-FREE CARRIER (Phase A.2) — the keystone decision

**The engine hot path never calls the two async host methods** (`identity_admit`,
`synthesize_completion`). Those are the ingress-auth pre-filter and the MCP→completion bridge — both
strictly ABOVE the forward engine. Everything the engine reaches (govern-admit, breaker admit/settle,
meter-charge, telemetry, next-request-id, plane-slot reads) is a SYNC method. So the carrier does not
need an owned `Arc<App>` for `spawn_blocking`; it can be a **borrowed** host.

**Carrier = a stack `BorrowedEngineHost<'a> { app: &'a Arc<App> }` in busbar-core, coerced to
`&dyn EngineHost`.** Constructing it is a stack move of one reference — ZERO heap allocation. It impls
the FULL trait: sync methods borrow `&**self.app`; the two async methods `Arc::clone(self.app)` ONLY
when actually called (never on the engine path), so the trait stays object-safe with no per-call
wrapper mint. Core exposes `pub fn borrow_engine_host(app: &Arc<App>) -> impl EngineHost + '_` beside
`engine_host`.

Alloc argument, proven against the real gate:
* GATE 1 (surgical, `alloc_gate_translate_write_stable`, exact `== 0`): drives
  `translate_request_cross_protocol` directly. That fn needs only the routing TABLES, never a host
  capability, so it is retyped to take `EngineTables<'_>` (or `&NativeRuntime`) — NO host, NO mint on
  this path. Stays exactly 0.
* GATE 2 (coarse, `alloc_gate_openai_passthrough_forward`, `<= 107`, measured 87): drives
  `forward_with_pool`. The borrowed host is constructed at the REQUEST BOUNDARY, which for this gate
  is the test body (before `CountingJemalloc::reset()`), and for production is the ingress layer above
  `forward_with_pool`. Either way the measured window sees ZERO new heap allocs from the carrier: a
  stack `BorrowedEngineHost` + `&dyn` coercion allocate nothing. The `EngineTables` handle is an
  `Arc::clone` of the `plane_slot` (atomic refcount bump, **not** a heap allocation).

Result: the carrier is strictly alloc-free. NO owned-Arc host, NO per-token/per-request heap mint on
any measured path. If a future duplex/`SessionScope` path needs the owned host, it takes the existing
`engine_host(app)` at ITS boundary — orthogonal to this pass.

`EngineTablesView` is the COLD scrape/discovery seam (it allocates its projections); the hot engine
keeps reading the concrete `NativeRuntime` fields via `EngineTables<'_>` threaded from the boundary
(one `plane_slot` Arc-clone + downcast at entry). The two are NOT merged.

## 3. Threading strategy (Phase B) — leaves first, host ALONGSIDE app during migration

Each engine fn's `app: &Arc<App>` becomes, per its needs, `host: &dyn EngineHost` and/or
`tables: EngineTables<'_>`. Because a fn's callers live in OTHER files, migration threads `host`/`tables`
ALONGSIDE the surviving `app` param, converting reads file-by-file; `app` is dropped from a signature
only once all its uses in that fn are converted. `native_ingress` (the ROOT boundary) is LAST: only
then does the entry stop taking `&Arc<App>` and instead receive the host from core (via a
substrate-side arrival payload carrying `Arc<dyn EngineHost>` — see §5, the ArrivalPayload hazard).

Dependency order (leaves → root): health, usage, lazy_body, response_body → select, walk, wire, tables,
hooks → pipeline, mod → native_ingress.

## 4. New seam methods (bidi-aware — express against a SCOPE, mirror `request_finished`)

Draining the app-hanging reaches needs these NEW `EngineHost` methods (each a byte-identical wrapper
over the existing core free fn — same-dispatch relocation, not new behaviour). Shape them "against a
scope" so the same method serves a future per-frame `SessionScope` governance without foreclosing D1/D2/D3
(do NOT add duplex/cost_reserve slots now):

* Telemetry (drains the 16 `busbar_core::telemetry::*` reaches):
  `telemetry_breaker_trip(pool_label,lane)`, `telemetry_upstream_attempt(pool,lane)`,
  `telemetry_upstream_failure(pool,lane,disposition)`, `telemetry_failover(pool,disposition)`,
  `telemetry_translation(ingress,egress)`. (These are pure `App`-snapshot metric emits — no `HostCtx`,
  mirror `request_finished`.)
* Store: expose the breaker store as a neutral view. `App::store` is `Arc<dyn LaneRuntime>` where
  `LaneRuntime` is a `busbar_core::store` trait — RELOCATE the `LaneRuntime` trait to
  `busbar_substrate::store` (core re-exports) so the engine names `busbar_substrate::store::LaneRuntime`,
  and add `fn lane_store(&self) -> &dyn LaneRuntime`. (~48 `app.store` sites become `host.lane_store()`.)
* Ingress/proxy neutral builders (`proxy::ingress_error`, `agnostic_error_envelope`,
  `ingress::not_found_message`): these take NO `app` and are pure response/​string builders — RELOCATE
  to `busbar_substrate::{proxy,ingress}` (core re-exports). The app-taking ones
  (`finish_rejected/finish_admitted/pool_label/destination_guard/admission_door`) become host methods
  scoped by the request (they read the snapshot + emit the request-completion metric family).
* `next_request_id` — already on `EngineHost`.

## 5. Boundary types (dual-compile / Any hazards) — FLAG, do not force

* `busbar_core::ingress::arrival_host::ArrivalPayload` (native_ingress.rs:649-650, the `ArrivalCtx`
  `downcast_ref`). This is the **Any-boundary the retype pivots on**: to stop naming it, core must
  carry the host in a SUBSTRATE-owned arrival payload (`Arc<dyn EngineHost>` + `gov` + `caller_token`)
  that the engine downcasts instead. This is a core-side change (the payload is constructed in core's
  arrival host) and is dual-compile sensitive — do it in the native_ingress (LAST) commit, or FLAG and
  leave if it cannot cross without a TypeId hazard.
* `busbar_core::hooks::{ResolvedPolicy, FallbackHook, wire::HookStageProjection}` — these carry a
  core-owned resolved-policy handle (an `Arc<dyn RoutingPolicy>` over a dlopen plugin). They CANNOT be
  reconstructed plane-side. Keep the value behind a seam method returning a substrate view, or (if the
  projection is pure data) RELOCATE `HookStageProjection` to substrate. `ResolvedPolicy`/`FallbackHook`
  in signatures are read through the pool-hook down-facades (`app.pool_{policy,gates,rewrites}`) — route
  those through a host method returning an opaque handle. FLAG any that cannot cross.
* `busbar_core::config::{PolicyOnError, OnExhausted, GroupCfg, ...}` and
  `busbar_core::{proto,handlers,metrics}::*` are the **RESIDUAL** (registry ~74 + config enums ~16 +
  metrics ~13) — chained AFTER this keystone, NOT drained here.

## 6. Residual accounting (the STOP target)

Start 181 BACKWARDS. This keystone drains ~78: state::App + UpstreamClients (~7), telemetry (16),
ingress (17), proxy (11), hooks (12), store/governance/cost/egress_auth/auth/admin/limits (~15). Final
residual ≈ **103**: the registry (proto/handlers ~74), config enums (~16), metrics (~13), plus any true
Any-boundary straggler flagged in §5. Drive `--baseline` DOWN monotonically, one engine file per commit,
verifying the 5 money-path oracles byte-identical + the alloc-gate green + `--selftest` green EVERY commit.
