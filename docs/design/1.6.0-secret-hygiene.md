# 1.6.0 — secret hygiene: complete + enforce the `Redacted` / `SecretRef` vocabulary (secrets never enter logs, audits, or metrics)

**Owner intent (verbatim):** "secrets can never enter logs or audits. Secret ID yes, not THE
secret. Secrets in busbar core need to be on type [a secret type] not `String` to preserve this." The
vision's audit leg is "audited into a record you can read back later" — reading back must surface a
secret's **identity/reference**, never its plaintext. A competitor (LiteLLM) just shipped PII/PCI
masking across every egress path (spend logs, debug logs, logging-only responses) as *runtime*
masking; busbar makes it a **TYPE guarantee** — a value that is a secret is a different Rust type
from a value that is not, and that type structurally cannot reach a log/audit/metric sink. That type
already exists (`Redacted<T>`); this doc completes its adoption and enforces it.

## Vocabulary (ENFORCED — one name per concept, zero synonyms)

This is the naming law the gate and the migration enforce. Any deviation found in the audit is
listed as a **consistency violation** to fix (§1.4).

| concept | THE name | never |
|---|---|---|
| a secret **VALUE** held in memory | **`Redacted<T>`** (`busbar_api::Redacted`) — `Debug`/`Display` = `[REDACTED]`, value only via `.expose_secret()`, zeroize-on-drop | a bare `String`/`Vec<u8>`/`Option<String>`; a new `Secret<T>` value wrapper; any other synonym |
| a secret's safe-to-log **IDENTITY** (goes in logs/audits/metrics) | **`SecretRef`** (`busbar_secret_ref::SecretRef`) or a plain non-secret id string (`key_id`, `AccessKeyId`) | the value; a `Redacted` (never log the value even redacted-by-accident) |
| resolving identity → value | **`SecretResolver`** / the `SecretResolve` seam (`SecretRef` → `Redacted<T>`) | — |

**The `Secret*` prefix is reserved for the REFERENCE / RESOLVER / CONFIG machinery** — `SecretRef`,
`SecretResolver`/`SecretResolve`, `SecretError`/`SecretErrorKind`, `SecretModule`, `SecretForm` — and
is **never** used to name a value wrapper. There must be **no competing `Secret<T>` value type**; the
one secret-value type is `Redacted<T>`.

**Status.** This is a design + audit doc only. No code changed. A live refactor is touching
`busbar-core`/`busbar-llm` concurrently (the "everything is a plugin" pivot, see
[`1.6.0-technical-changes.md`](1.6.0-technical-changes.md)); the implementation plan in Part 4 is
sequenced to land **after** that pivot's `api_key_plaintext` DTO lands.

**Key finding up front — THE TYPE ALREADY EXISTS; do not build a new one.** busbar already ships the
secret type this task asks for, in two halves:

- **the VALUE wrapper — `busbar_api::Redacted<T: Zeroize>`** (`crates/api/src/redacted.rs`): a
  working redacting/zeroizing/**non-serializing** secret wrapper (tested in
  `crates/api/src/tests/redacted_tests.rs`), already threaded through most in-memory secrets (state
  `api_key`, oauth `client_secret`, minted bearer, MCP subject/upstream tokens, the auth-plugin
  submitted credential — see §1.1);
- **the IDENTITY / "secret id" — `SecretRef`** (`crates/secret-ref/src/lib.rs`): the non-secret
  stable reference (`env:VAR`, `file:/path`, `module '<name>'`) that IS safe to log and audit — the
  "read it back later" half of the owner's ask;
- resolved through **`SecretResolver`** / the `SecretResolve` seam (`crates/api/src/secret.rs`,
  `busbar-core/src/config/secret.rs`); `zeroize` is already a workspace dep (`Cargo.toml:273`).

Adoption is **partial**. The work is therefore **not to invent a type** — it is to (1) **complete
adoption**: close the remaining bare-`String`/`Vec<u8>` secret holes the audit below enumerates,
(2) **enforce it**: add a gate so the tree cannot regress to a bare-`String` secret, and (3) confirm
`Redacted` + `SecretRef` are sufficient **as-is** and recommend at most minor additions (Part 2).
The freshest hole — the in-flight `api_key_plaintext: String` on the substrate build-input DTO —
does not exist in-tree yet and is the first conversion target once it lands.

### 1.2 CRITICAL — the in-flight `api_key_plaintext` path

The pivot introduces `api_key_plaintext: String` on the substrate build-input DTO
(`crates/busbar-substrate/src/plane_host/build_input.rs`, `LlmBuildInput`/`LlmLaneInput`). **It is
not in the tree yet** (`grep -rn api_key_plaintext crates/` → 0 hits;
`crates/busbar-substrate/src/plane_host/build_input.rs` does not exist). When it lands, resolved
plaintext provider keys will flow **core → plane** through it:

```
config SecretRef  →  SecretResolver.resolve_string()  →  LlmBuildInput.api_key_plaintext: String
   →  build_runtime lowering  →  upstream auth header (Authorization / x-api-key / SigV4)
```

This is a **new** bare-`String` secret on a DTO that (per the pivot) will be `Debug`/serde-touched
across the build seam — the single most important field the secret-hygiene work must convert, because
it is the freshest and it crosses a crate boundary. Note this **partially contradicts** the existing
FLAG-4 confinement (`plane_host/creds.rs` was built specifically so the plane holds an opaque
`credential_ref` and the *host* owns plaintext); if the pivot really moves plaintext across into the
plane's build input, converting the field to `Redacted<String>` is the *minimum*, but the **preferred**
fix is to carry a **`SecretRef`** (id) on the DTO and resolve plane-side via `SecretResolve`, like the
mint path already does — so no bare secret ever exists on the DTO. **Flag for the pivot author**
(Part 4, step 2).

### 1.3 Leak SINKS — can a secret reach each?

| sink | mechanism | can a secret reach it? |
|---|---|---|
| **(a) `derive(Debug)`** | any struct transitively holding a secret | **YES via A** (`IssuedKey`, derives Debug, bare `secret: String`). NO for B–F (no Debug, or manual redacting Debug). This is the one active hole. |
| **(b) `tracing`/`log`/`eprintln!`/`println!`** | formatting a secret-holding struct or field | Reachable **only** through (a): a `tracing::info!(?issued_key)` or `{issued_key:?}` prints A's token. Every `Redacted` field is safe here by construction. No direct `println!(secret)` found in production. |
| **(c) AUDIT record path** | `AuditRecord` (`crates/api/src/store.rs:816`); `PlaneAuditLog` (`plane/auditlog.rs:266`); `calllog.rs`; plane-record `body` bytes (`store.rs:886+`) | `AuditRecord` fields are metadata only (action/resource/outcome/principal/hash) — **no secret field** (`store.rs:814` states this). RISK is the **opaque `PlaneRecord.body`** (caller-serialized bytes): a plane could `serde_json::to_vec` a struct that embeds a secret. Prevented **structurally** if the secret is `Secret`/`Redacted` (neither implements `Serialize`, so a body that embeds one won't compile). |
| **(d) metric labels** | `counter!`/`gauge!`/`histogram!` in `metrics.rs` | **NO** — labels are a finite operator-controlled enumeration by documented contract (`metrics.rs:30-42`); no secret-typed value is passed as a label today. Gate keeps it so. |
| **(e) `serde::Serialize` on a secret-holder** | hits wire/disk/log | **YES by design** for E (`CredentialSecret`, store ABI) and G (`CreatedKeyView`, once-shown mint response). Both are **intended** plaintext egresses, not accidents. Everywhere else, `Redacted`'s absence of `Serialize` prevents it. |

**Summary of real exposure:** exactly one *accidental* live vector (**A**, `IssuedKey` derives
Debug over a bare token), a cluster of bare-but-not-yet-logged holds (**B, C, D**), two
Debug-safe-but-not-typed values (**E, F** — F has a timing-`Eq` bug), two intentional serde egresses
(**E, G**), and one incoming offender (**§1.2 `api_key_plaintext`**).

### 1.4 Vocabulary consistency violations (against the enforced naming law)

Two classes: (i) **bare-`String` secret VALUES** — every §1.1 item A–I where the value is a bare
`String`/`Vec<u8>`/`Option<String>` instead of `Redacted<T>` (that whole table IS the value-side
violation list; fixed by Part 4). (ii) **`Secret*`-prefix used for a value, or a value-wrapper
synonym** — the naming-law violations proper:

- **No competing `Secret<T>` value type exists today** — good; the one value type is `Redacted<T>`.
  (An earlier draft of *this* doc proposed a `Secret<T>` wrapper + `SecretId`; that proposal is
  **withdrawn** to keep `Redacted<T>` the sole value name.)
- **`CredentialSecret`** (`crates/api/src/store.rs:523`) — a **type name using the `Secret` suffix
  for a value-bearing record** (it carries `secret: String`). Tension with the law, but this is an
  established **store-plugin-ABI** record (serde is load-bearing) and the `Secret` here reads as
  "credential + its secret material", not as an in-memory value wrapper. **Verdict: allowed
  exception**, documented — do *not* rename (ABI-breaking); the gate allowlists it (§Part 3). Its
  in-engine `.plaintext()` output should still be wrapped in `Redacted` post-lookup.
- **`SecretForm`** (`store.rs:439`), **`SecretModule`/`SecretError`/`SecretResolve`**
  (`crates/api/src/secret.rs`) — all **reference/resolver/config machinery**, correctly using the
  `Secret*` prefix per the law. No violation.
- **field named `secret: String`** on `Mint` (`plane_host/creds.rs:46`, wrapped in `Zeroizing` —
  acceptable value protection), `Lease` (`a2a/creds.rs:320`), `IssuedKey` (`self_keys.rs:33`),
  `CredentialSecret` (`store.rs:527`) — these are *field* names, not type synonyms; the law targets
  the value *type*, so a field literally named `secret` is fine **provided its type is
  `Redacted<T>`/`Zeroizing`** (or an allowlisted serde exception). Today `Lease.secret` and
  `IssuedKey.secret` are bare `String` → value-side violations (class i), fixed in Part 4.

**No synonym for the `Redacted` value wrapper was found** (no `Sensitive`, `Masked`, `Protected`,
`SecretString`, etc. naming an in-memory value type). The vocabulary is clean on the type-name axis;
the debt is purely (i) incomplete adoption.

## Part 2 — the type is `Redacted<T>` + `SecretRef`: sufficiency assessment (do NOT build a new type)

**Recommendation: keep `Redacted<T>` + `SecretRef` exactly as they are.** They already satisfy every
property the owner named. Do **not** introduce a new `Secret`/`SecretString` type and do **not** adopt
the `secrecy` crate — both would be a lateral rewrite that re-touches every already-correct call site
(§1.1) for zero new guarantee, and `secrecy` would still need a bolt-on for the identity half that
`SecretRef` already provides. The only additions this doc recommends are **minor and optional**
(§2.3). Below is the property-by-property check.

### 2.1 Does `Redacted<T>` deliver the required properties? — YES

| required property | delivered by `Redacted<T>`? | evidence |
|---|---|---|
| (a) `Debug`/`Display` redact — never the value | **YES** — both print `"[REDACTED]"` | `redacted.rs:59-70` |
| (b) NOT `Serialize`/`Deserialize` (can't hit audit/wire/disk) | **YES** — deliberately implements neither; comment calls it structural | `redacted.rs:15-22` |
| (c) value reachable ONLY via a greppable `.expose_secret()` | **YES** — the sole accessor, documented as the audit point | `redacted.rs:46-48` |
| (e) `zeroize`-on-drop | **YES** — `T: Zeroize`, `Drop` overwrites | `redacted.rs:72-76` |
| (f) `Clone`/`Eq` sane — constant-time `Eq` | **YES** — `Eq` routes through `constant_time_eq`, avoiding prefix-timing | `redacted.rs:92-98` |
| ABI safety — must not serialize into cold JSON **or** hot `repr(C)` lane | **YES structurally** — no `Serialize` ⇒ cold lane won't compile a struct embedding it; not `repr(C)`/not POD ⇒ hot lane rejects it | — |
| home crate shared by all crates incl. single-compiled substrate | **YES** — lives in leaf `busbar-api`, re-exported `busbar_api::Redacted` (`lib.rs:45`); depended on by core/substrate/llm/mcp/a2a/plugin. **Keep it there — do not move to `busbar-core`.** | `crates/api/src/lib.rs:45` |
| no-panic / edge-validator posture | **YES** — no `unwrap`/panic; `expose_secret` is an infallible borrow | — |

### 2.2 Does the "Secret ID yes, not THE secret" / read-back-later half exist? — YES, via `SecretRef`

Property (d) — "carries or pairs with a non-secret STABLE IDENTITY that IS safe to log and audit" —
is already met by **`SecretRef`** (`crates/secret-ref/src/lib.rs:53`). It holds only
`{ module, settings }` (no secret material — stated at `lib.rs:34`), derives `Debug`/`Serialize`
safely, and exposes `.describe()` → `env:ANTHROPIC_API_KEY` / `file:/run/secrets/x` /
`module '<name>'` (`lib.rs:112`). **This is the exact "secret id" the owner means:** the audit/read-back
path records the `SecretRef` (or its `.describe()`), never the resolved value.

The one structural nuance: `Redacted<T>` and `SecretRef` are **separate** values today — the wrapper
does not itself carry its ref. In practice that is fine, because the code paths that hold a
`Redacted` already hold the corresponding config `SecretRef`/`key_id`/`AccessKeyId` right next to it
(the lane, the credential row, the virtual key). The audit-write pattern is therefore a **convention**
— "log the `SecretRef`, never the `Redacted`" — not a type guarantee that the two travel together.

### 2.3 The only gaps + the minor, optional additions recommended

1. **Adoption is incomplete** (the real gap — Part 1 §1.1 items A–I). This is a *migration* problem,
   not a *type* problem. Fixed by Part 4.
2. **No compile-time pin that `Redacted` stays non-serde.** Someone could add
   `#[derive(Serialize)]`-adjacent glue in a future edit. Recommend a **compile-fence test** in
   `busbar-api` asserting `Redacted<String>: !Serialize`/`!Deserialize` (Part 3, Check 3). Minor,
   additive.
3. **The id/value pairing is a convention, not enforced.** *Optional, only if the owner wants the
   pairing to be structural:* add a thin helper that binds them at the audit boundary — **not** a new
   wrapper type:

   ```rust
   // Optional convenience in busbar-api — NOT a replacement for Redacted. Pairs a held secret with
   // the SAFE reference to record when auditing/logging "which secret was used", so a call site
   // physically cannot log the value where it means to log the id.
   pub struct Held<T: Zeroize> { pub reference: SecretRef, secret: Redacted<T> }
   impl<T: Zeroize> Held<T> {
       pub fn new(reference: SecretRef, secret: Redacted<T>) -> Self { Self { reference, secret } }
       pub fn expose_secret(&self) -> &T { self.secret.expose_secret() }
       /// Safe to log/audit — the identity, never the value.
       pub fn reference(&self) -> &SecretRef { &self.reference }
   }
   // Debug derives safely: `reference` is non-secret, `secret` prints `[REDACTED]`.
   ```

   The doc's recommendation is to **defer** `Held` unless a concrete audit call site needs it — the
   convention + the gate (Part 3) already close the practical risk without new surface. For
   **minted/stored** secrets (bearer, sigv4, issued key) whose identity is a `key_id`/`AccessKeyId`
   rather than a config `SecretRef`, the same helper can take a plain reference string; again, only if
   a real call site needs the pairing enforced.

### 2.4 What legitimately stays serde / bare `String` (not `Redacted`)

- `CredentialSecret.secret` (§1.1 E) — must serialize across the **store plugin ABI**. Keep as-is
  (manual redacting `Debug` at `store.rs:543` + `Serialize`); after a store lookup, wrap the
  `.plaintext()` output (`store.rs:538`) in `Redacted` for in-engine handling so live memory holds a
  `Redacted`, not a bare `&str`.
- `CreatedKeyView.token` / SigV4 fields (§1.1 G) — the **once-shown mint response**; `Serialize` is
  the whole purpose. Allowlisted intentional egress (Part 3).
- the auth **wire** boundary `CompleteLoginRequest.submitted` — the documented single plaintext
  crossing (`crates/busbar-plugin/src/cold/auth.rs`), filled from `Redacted` via `.expose_secret()`
  (`:420`). Stays a plain `String` on the wire type by design.

## Part 3 — the GATE: `scripts/secret-hygiene-gate.sh`

Modeled on `scripts/plane-grep-gate.sh` (substring scan, comment/doc/test stripping, path-scoped
allowlist). Conservative by design — false positives are silenced by the allowlist, never by
weakening the rule. Three checks, each fails the build with a file:line and a remedy.

**Check 1 — no bare secret field.** For each known-secret identifier
(`api_key`, `api_key_plaintext`, `client_secret`, `private_key`, `signing_key`, `access_token`,
`subject_token`, `bearer`, `password`, `credential_secret`, `secret_access_key`, and a bare field
literally named `secret`/`token` on a struct whose name matches `*Key*|*Cred*|*Token*|*Secret*`),
in production `.rs` under `crates/`, flag a declaration of the form
`<ident>: String | &str | Vec<u8>` that is **not** wrapped in `Redacted<…>` / `Zeroizing<…>`. Remedy:
wrap the value in **`Redacted<T>`** (the one value type); if it must appear in a log/audit, carry a
**`SecretRef`**/id instead. This check also bans any *new* `Secret<T>`-named value wrapper (the naming
law: `Redacted` is the only value type). Allowlist entries (token × path × reason):
- `crates/api/src/store.rs` `CredentialSecret.secret` — store-ABI serde egress, manual redacting Debug.
- `crates/busbar-core/src/admin/v1/contract/schema.rs` `CreatedKeyView`/`token` — once-shown mint API.
- the auth wire boundary `CompleteLoginRequest.submitted` — documented single plaintext crossing.

**Check 2 — no secret at a log/audit/metric site.** Fail if `.expose_secret()` appears on the same
statement (a bounded window, e.g. same line or within the macro's paren span) as any of:
`tracing::` / `log::` / `println!` / `eprintln!` / `dbg!` / `panic!` / `counter!` / `gauge!` /
`histogram!` / `metrics_emit` / `journal_append` / an `AuditRecord`/`PlaneAuditLog` constructor.
Also fail on a `{:?}`/`{}`/`?ident`/`%ident` of a *known-secret-typed local* inside a `tracing`/`log`
macro. This is the "`.expose_secret()` used at a log/audit/metric site" rule.

**Check 3 — `Redacted` never gains serde.** A compile-fence test in `busbar-api`
(`crates/api/src/tests/redacted_no_serde.rs`) that asserts `Redacted<String>` is **not** `Serialize`
and **not** `Deserialize` — e.g. a `trybuild` "must-not-compile" case, or a negative trait probe:

```rust
// A blanket helper impl'd for all T; a competing `impl<T: Serialize> NotSerialize` would make this
// ambiguous ONLY if Redacted were Serialize — the coherence conflict is the assertion.
trait NotSerialize {}
impl<T> NotSerialize for T {}
fn _assert_not_serialize(s: &Redacted<String>) { fn is<T: NotSerialize>(_: &T) {} is(s); }
// Plus a trybuild `compile_fail` fixture: `serde_json::to_string(&redacted)` MUST fail to compile.
```

Wire `secret-hygiene-gate.sh` into `scripts/full-gate.sh` / CI alongside the other grep gates; ship it
**warn-only for one commit**, then **flip to blocking** in the same commit that finishes the last
conversion (Part 4, step 7), so the tree is green when the gate arms.

## Part 4 — implementation plan (sequenced AFTER the in-flight pivot lands)

Green-per-commit; each step names its files (from Part 1) and the oracle that proves no behaviour
change. **Money-path oracles must stay byte-identical** — the plaintext still reaches the upstream
header via `.expose_secret()`; only the *type* changes. Steps that change what an **audit record**
contains (value/nothing → id) are **intended** changes needing a golden update — called out
explicitly and kept distinct from money-path goldens, which must NOT move.
