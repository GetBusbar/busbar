# 1.6.0 — COMMIT-BODY RESIDUE: the 242 findings that live only in a commit message

> **What this is.** `docs/design/1.6.0-map-proof.md` §5 read **all 307 commit bodies** in the
> 36-hour window and extracted **242 residue findings** — facts, defects, owed work and
> corrections that exist in a commit message and nowhere else. It measured the master list at
> **≤ 45 rows** and declared Δ ≥ 197 the single largest unreconciled source in the tree. It did
> not triage them. **This document is the triage.**
>
> **The mechanism, stated once.** An agent lands a fix and records three more findings in the
> body — prominently, in good faith, because they could not fix them. Nobody reads 307 bodies.
> The finding is recorded, never actioned, and *looks handled because it is written down
> somewhere*. There is no gate that fails when a body says "owed" and no map row appears.
>
> **Read §2 first.** It is the OPEN-actionable list, severity-ordered, and it is the point.

## 1. THE HEADLINE — AND A CORRECTION MADE IN THE HOUR IT TOOK TO WRITE THIS

**As first measured for this triage, `HEAD` did not compile, and the reason was a security fix
left uncommitted in the shared checkout. It was closed at `56e62a635` while this file was being
written. The finding is kept, corrected in place rather than quietly deleted, because the
correction is the best evidence this document has for its own thesis.**

### 1.1 WHAT WAS TRUE

`crates/busbar/src/main.rs:577-578` called two items that did not exist at `HEAD`:

```sh
git show 37951e062:crates/busbar/src/main.rs | sed -n '577,578p'
#   let secrets = root::transports::ConfiguredSecrets::new(resolver, refs);
#   let journal = root::transports::BookAccessJournal::new(book, &durability_token);

git show 37951e062:crates/busbar/src/root/transports.rs \
  | grep -c 'ConfiguredSecrets\|BookAccessJournal'      # -> 0
```

The definitions existed only in the working tree, where `git status` had read
`` M crates/busbar/src/root/transports.rs`` all session. They are the fix for `6d3bda8a3` —
*"**every TLS private-key read in production is unaudited** … This contradicts an explicit owner
ruling — that plugins cannot touch secrets because the kernel is in charge of auditing them."*
`233ca7a3e` had already named the hazard in its own body: *"ConfiguredSecrets is not at HEAD. It
arrives with another agent's in-flight work on `crates/busbar/src/{main.rs,root/transports.rs}` in
this shared checkout."* Nobody acted on that sentence for the rest of the session — which is the
mechanism this whole document is about.

`56e62a635` is *after* the pin this triage's input was taken at (`a197ad2f5` / `a0b808b79`), so it
is a post-pin closure like every other in §5. `main.rs` hands the journal to `provision_servers`,
which calls `record_access` per cert / key / client-CA. **The build break is closed and the TLS
private-key audit seam is live on the production path.** The row is `D117`.

### 1.3 WHY IT STAYS IN THE FILE

Three reasons, and the third is the point.

1. **A correction is recorded, never quietly fixed.** That rule is this tree's own — `74b8640dd`,
   `0a82aa4ec`, `027f8ae31`, `f3d15e652`, `6a0d55ffc`, `5b3ea85b0` and `df3c19c8a` all exist
   because an author wrote down that they had been wrong. Deleting the row would leave a reader
   unable to tell a finding that was never real from one that was closed.
2. **The class recurs and is not fixed.** `56e62a635`'s own subject — *"commit the half of
   `2bb1e8531` I left behind — HEAD did not build"* — is the third recorded instance in this
   window of a caller landing without its callee in a shared checkout, after `1b6c9d4ba` /
   `99dd34503` (a blanket `git add` sweeping three agents' work) and `1059d3c36` / `2573c9a98`
   (a commit staged from a tree that predated another and reverted it). `0ce782715` documented
   the hazard; nothing enforces it. There is no gate that fails when a symbol is referenced at
   `HEAD` and defined only in a worktree.
3. **This triage measured a shared tree and the tree moved under it — exactly as
   `1.6.0-map-proof.md` §0.1 warned it would.** That proof pinned every figure at
   `016422be7` for this reason. This file pins its *input* at `a197ad2f5` and checks its DONE rows
   against a moving `HEAD`, which is the honest trade for a triage whose whole job is to ask
   "is this still true?" — and the cost of that trade is one row that had to be corrected within
   the hour. It is recorded here in full rather than absorbed.
