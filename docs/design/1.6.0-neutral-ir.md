## 0. The decision (corrected)

**There is one IR *concept*, and CORE speaks exactly one neutral view of it.** Concretely:

- **Core never holds the concrete content.** Core reads only a **neutral projection**: `IrFacts`
  (screening content/shape/verb), a neutral `RouteView` (selection signals), and `TokenUsage`
  (metering). That projection is the "one IR" every core seam speaks.
- **The concrete message is per-family and lives in its plugin** — chat IR (`IrRequest`/`IrBlock`/…) in
  `busbar-llm`; the invoke/subscribe shape (opaque `serde_json::Value` content) for mcp/a2a. Core never
  names a concrete family type.
- **Byte-identity is carried by retained raw bytes, NOT by reconstructing from the IR.** An opaque
  `raw` carrier (pristine request bytes / verbatim stream frames) rides alongside; the codec seam
  short-circuits it on the same-dialect path. Reconstruction from content provably drifts (key reorder +
  float lexeme), so the raw carrier is load-bearing, not decorative.
- **Streaming is plugin-internal.** A stream frame is NOT an IR; it is the plugin's `IrStreamEvent`/
  `IrDelta` family. Core sees a stream as **bytes in → bytes out + neutral `usage`/`terminal_error`
  taps**.

So "everything speaks IR" is true **at the core seam** (one neutral projection) — while the concrete,
lossless, family-specific representation is owned end-to-end by the plugin and never crosses into core.
This is the codebase's *neutral projection + opaque plane payload* pattern (plane slots, session store,
cost labels), which is why it is the right shape and not a novel gamble.

## 1. Why the first draft was wrong (and the corrected model)

Two over-reaches in the first draft, both refuted by shipped code:

**(A) "One content tree; the writer renders exactly what the gate screens."** FALSE (D2, Q-B). The code
already runs **two** content layers, deliberately: a **lossless writer carrier** (`Vec<IrBlock>` for
chat — image bytes, provider ciphertext, citations, `thoughtSignature`) and a **deliberately-lossy,
security-motivated screening projection** (`ContentItem` via `facts::project`, which drops Image/Media to
no item and collapses provider ciphertext to `OPAQUE_CONTENT_MARKER`). Non-chat planes already carry
content as plane-opaque `serde_json::Value` (`ir/invoke.rs:57,161`; `a2a/receive.rs:895`). A standing
code rule (`facts.rs:50-52`, `invoke.rs:66-69`) *forbids* a cross-family content superset. **Correction:**
content is per-family / plane-opaque; the neutral seam core reads is the `IrFacts` projection, and
`gate-view ⊂ writer-view` is a **disclosure invariant** (a gate must never see MORE than the writer
sends, and deliberately sees less).

**(B) "One lossless IR round-trips every dialect byte-identically; `write(read(bytes))==bytes` is an IR
property."** FALSE (D1, D4, D11, Q-E). Byte-identity is delivered by **retained raw bytes**: the
non-streaming pristine short-circuit (`proxy/wire.rs:395,607-612`) and the streaming verbatim frame
re-emit (`proto/stream.rs:76-82,136-145`). The code's own comment (`wire.rs:608`) states an IR round-trip
introduces key-ordering/float drift; `extra` is a `BTreeMap` (no `preserve_order`) so unmodeled keys
re-serialize alphabetically. **Correction:** byte-identity rides an opaque `raw` carrier the codec
short-circuits on same-dialect; neutral fields are for gate/route/meter only. The witnesses that prove
this are the `wire.rs` pristine short-circuit and streaming verbatim passthrough — NOT
`roundtrip_fidelity`/`translate_parity` (which prove structural non-loss / are self-pinned, D11).

## 2. The `IR` shape (decided)

```rust
// Per-family concrete IR lives in the plugin. Sketch of the CHAT family in busbar-llm:
pub struct IrRequest {                 // (and IrResponse, per-family)
    pub content: Vec<IrBlock>,         // OWNED, lossless, family-specific (Q-F: owned, no lifetime)
    pub params:  Map<String, Value>,   // ext — provider knobs (Q-A: Map, not Box<dyn Any>)
    pub raw:     Option<Bytes>,        // pristine request bytes for same-dialect byte-identity (Q-E)
    // ... family fields the writer needs ...
}
```

**Q-A — `ext` = `params: Map<String, Value>`** (D8). `Box<dyn Any>` strips `PartialEq/Clone/Debug/
Default`, breaking the whole-IR equality witnesses (`assert_eq!(ir, rt_ir)`), and its only upside
(serialization) is unexercised (no IR type is `Serialize`). `IrRequest.extra` already proves a
`serde_json::Map` coexists with all four derives (`ir/mod.rs:133`).

**Q-F — content is OWNED** (`Vec<IrBlock>`, no lifetime) on request, response, and per stream frame
(D7). The request IR is boxed `'static` across `.await` (`hooks.rs:85`) and the response/stream IR lives
in an `S: Stream + Send + 'static` body (`response_body.rs:133`); a borrowed `Vec<Part<'_>>` cannot
compile there. The borrowed shape survives **only** as a transient screening view (`ContentItem<'a>`/
`Cow`) materialized per gate call and dropped before any await — not the stored field.

The neutral views CORE reads off any family IR (this is the "one IR" core speaks):
- `IrFacts` — `verb()`, `wants_stream()`, `end_user()`, `shape()`, `content() -> Vec<ContentItem<'_>>`
  (the transient screening projection).
- `RouteView` — §3.
- `TokenUsage` — the neutral billing totals (already landed: `billing::TokenUsage`).

## 3. `RouteView` — the neutral selection surface (decided, was NOT neutral)

The first draft's "RouteView = target hint + operation" was refuted (D5, D6, Q-2): core's own failover
and candidate projections name intrinsically-LLM token concepts.

- **`Disposition::ContextLength`** (`engine/mod.rs:2142`, `breaker.rs:99`) reroutes by comparing model
  **context windows in tokens** (`context_max`) — a decision core makes itself.
- **`Shape.max_tokens`** (`facts.rs:255`) and the `Candidate` projection's `context_max`/`cost_per_mtok`
  (`hooks.rs:314,607`) name tokens, context, and per-mtok cost.

**Correction:** the genuinely-neutral bones STAY in `RouteView` — the opaque `u64` affinity hash, SWRR
weights, concurrency permits, budget, latency, the `bool` stream flag, the pool-name interchange pin.
The LLM-shaped signals **move into `PlaneExt` / a plugin-side candidate projection** read only by the
LLM plugin's ranking, and the context-window failover is re-expressed as a **neutral plane-declared
capacity signal**: RouteView gains an **opaque size scalar** + a plane-declared **"capacity exceeded"**
disposition, so the reroute becomes *"target capacity < request size"* with no token concept in core.
(Alternatively the whole disposition becomes an LLM-plugin failover contribution — decide at build.)

## 4. The codec/vtable seam (decided — 5+ methods, not 2)

Q-G's "read(bytes→IR) + write(&IR→bytes) suffice" was refuted (D3, D9, Q-G, Q-D): the real seam is 5+
methods and core today names `IrStreamEvent`, `IrUsage`, `StreamDecodeState`, `IrReq`, `IrError`,
`EgressPrep`, and *constructs* `IrStreamEvent::Error` (`wire.rs:861`). The `StreamTranslate` translator
(~1117 lines, `proto/stream.rs`) is the single largest core IR construction site (D9).

**The seam that makes "the full concrete IR never crosses into core" actually TRUE:**
- **Request:** `read(bytes) -> IR` (plugin) → core reads `IrFacts`/`RouteView` → `write(&IR, target) ->
  bytes` (plugin). Egress semantics (`prepare_for_egress`: max_tokens defaulting / tool-id decode /
  extra-key clearing, and `egress_representable`) **move plugin-side** (`wire.rs:421-558` today).
- **Streaming:** relocate the entire `StreamTranslate` + streaming codec into `busbar-llm`. Core holds
  an opaque translator handle exposing only neutral calls: `feed(bytes)`, `finish() -> bytes`,
  `usage() -> Option<TokenUsage>`, `terminal_error() -> Option<&str>`, `aborted() -> bool`. The
  terminal-error frame becomes a neutral `IrError`-based entrypoint (`IrError` = `breaker::
  CanonicalSignal`, already neutral) instead of core constructing `IrStreamEvent::Error`.
- **Construction sites (Q-D):** the health-probe body, synthetic error/rejected completions, and the
  `StreamTranslate` events all become plugin vtable calls; none may leave core naming a concrete family
  type. The cardinal invariant — `grep -r 'IrRequest\|IrResponse\|IrBlock\|IrStreamEvent\|StreamDecodeState\|EgressPrep' crates/busbar-core/src` returns zero production hits — is the freeze witness.

## 5. Byte-identity: the proof obligation (corrected)

The obligation is **not** `write(read(bytes))==bytes` from the IR. It is: **the `raw` carrier is
retained and the codec seam short-circuits it on the same-dialect path**, so same-dialect passthrough is
byte-for-byte the original, and cross-dialect goes through the plugin's own reader→writer (never core).
New witness to add: `write(read(bytes))==bytes` on a body with **reordered + extra keys and awkward float
lexemes**, asserting the raw carrier — not reconstruction — is what holds identity. The existing pristine
short-circuit and verbatim-frame tests are the real byte-identity witnesses; `roundtrip_fidelity`/
`translate_parity` prove structural non-loss, not identity (D11).

## 6. Why this is the RIGHT design (post-hardening)

- **It is what the code already is, made honest and neutral.** The two-layer content (lossless family
  carrier + lossy neutral screening view), the retained-bytes identity channel, and the neutral
  usage/error taps all already exist. The design removes the *core's naming* of concrete types, not the
  proven mechanisms.
- **Minimal, honest core.** Core's four jobs define exactly the neutral projection + `RouteView` +
  `TokenUsage` + the opaque `raw`/translator handles. Remove the LLM plugin and the LLM representation is
  gone — the acceptance test's deepest form, now *actually* true (once §4's relocations land).
- **Closes a class.** A new plane is a codec (`read`/`write`/streaming handle) + a neutral `IrFacts`/
  `RouteView` projection. Gate/route/meter/forward span it with zero core change.
- **One mental model for the seam.** Core speaks the neutral IR projection; plugins pass their family's
  concrete IR. No engineer at the core boundary juggles Facts/Req/Resp — they read the projection.

## 7. The corrected thesis (verbatim, for ratification)

> One neutral **whole-message** IR **per family**, carrying an **opaque `ext` (`Map<String,Value>`)** and
> an **opaque retained-raw-bytes / raw-frame carrier**. Core reads only a **neutral projection**
> (`IrFacts` / `RouteView` / `TokenUsage`) — never the concrete content, never a concrete stream type.
> **Byte-identity is preserved by the raw carrier**, not by content+ext reconstruction; for same-dialect
> the neutral fields serve gate/route/meter only. Stream frames are a **plugin-internal**
> `IrStreamEvent`/`IrDelta` family; core sees a stream as bytes + neutral usage/error taps. Content is
> **owned**, per-family (chat `IrBlock`; invoke/subscribe opaque `Value`); the borrowed shape exists only
> as a transient screening view.

## 8. Cutover gate (the five required changes)

The cutover (G6 step 3) proceeds only after the doc reflects — and the code will deliver — all five:
1. Name the retained-raw-bytes/raw-frame carrier as the byte-identity mechanism (D1/D4/D11; Q-E). ✅ §0/§5.
2. Content per-family; `IrFacts` the neutral seam; drop "one content tree" (D2; Q-B). ✅ §1/§2.
3. Fold streaming (5+ methods) + egress semantics into the seam; relocate `StreamTranslate` +
   streaming codec + `prepare_for_egress`/`egress_representable` into `busbar-llm` so core names no
   concrete type (D3/D9; Q-D/Q-G). ✅ §4 (design); **code pending**.
4. Neutralize routing: capacity metric + opaque size scalar in `RouteView`; token/context/per-mtok/tool
   into `PlaneExt`/plugin ranking (D5/D6; Q-2). ✅ §3 (design); **code pending**.
5. `ext = Map<String,Value>`; content owned (D8/D7; Q-A/Q-F). ✅ §2.
