# 1.6.0 — THE DENOMINATOR: giving this release a yardstick it did not write

> **The finding this document answers.** `docs/design/1.6.0-map-proof.md` Appendix H.9:
> *"A completeness proof needs a denominator that the work being measured did not create. This
> release does not have one."* `1.6.0-map-audit.md` reached the same place from the arithmetic:
> *"three reach Δ = 0 by partitioning a set against itself."* **Any partition of *n* sums to *n*.**
>
> **This document does not argue with that. It goes and builds the missing denominator, measures
> the release against it, and publishes the number — which is low.**
>
> **`docs/design/1.6.0-map-proof.md` is READ-ONLY to this document.** Every change it needs is
> recorded in §9 and none is made. Nothing here was blessed, re-recorded or regenerated: no golden,
> no `accepted-differences.json`, no `accepted-gaps.json`, no `openapi.json`/`.gz`, no `qa/*.toml`.
> Every file named below was read through `git show <rev>:<path>` or `git ls-tree`, never written.

### 0.1 THE SECOND STOP IS AN ORPHANED COMMIT, AND THAT IS A FINDING ABOUT THE CHECKOUT

**`6459f0368` is no longer reachable from the branch.** Another agent **amended** history under this
measurement, and the commit that records it says so in its own subject:

```sh

#    22b2a5be0 branch-sweep: commit forward, never amend — AN AMEND HERE REWROTE ANOTHER AGENT'S COMMIT
#    feee181c8 THE LIST + THE DELETE LIST …          <- 6459f0368 rewritten, same subject, new SHA
```

**Every figure taken at `6459f0368` still reproduces exactly, from an orphaned object.** That is not
luck — it is the whole reason §0.1 of the map proof insists on `git show <rev>:<path>` over reading
disk. **A measurement pinned to a SHA survives a rewrite of the branch that contained it; a
measurement pinned to "the working tree" does not survive the next `git checkout`.** The pin
discipline was tested here by an event nobody planned, and it held.

**This is a shared checkout with ~20 agents and the working tree carries their uncommitted edits.**
Three of the files this document measures were dirty at the pin — `.github/workflows/ci.yml`,
`crates/busbar-core-admin/src/v1/json/openapi.json`, `qa/design-bindings.json`. **Every one was read
from the object store, never from disk.** A number here that you cannot reproduce from
`git show 6459f0368:<path>` is a defect in this document; report it rather than work around it.

## 1. THE TEST, HELD STRICTLY

The brief's rule, and it is the whole of the method:

> **Could the number have come out differently if the work had gone differently?**
> **If a source can only ever sum to itself, it is not measuring anything.**

Applying it honestly produces **three grades of denominator, not two**, and the distinction is
load-bearing because the map's defect is one specific grade and the repair is a different one.

| grade | definition | what it can prove | what it cannot |
|---|---|---|---|
| **A — TEMPORALLY EXTERNAL** | A fixed object that existed **before the work began** and that the work cannot modify. The `v1.5.5` tag tree; a binary with a published `sha256`. | **PRESERVATION.** "1.6.0 did not break what 1.5.5 promised." Falsifiable at every element. | **Nothing about work that did not exist at 1.5.5.** It cannot enumerate what was built, because it predates it. |
| **B — MECHANICALLY SELF-ENUMERATING** | A population produced by an **instrument that reads the tree, not the work's claims** — `git ls-files`, `git rev-list`, a TOML parse, a filesystem `stat`. The work creates the members; it **cannot conceal one from the instrument**. | **COVERAGE.** "Nothing in this population was skipped." A skip shows up as a non-zero Δ that the document cannot suppress. | **Correctness or intent.** A file can be visited and still be wrong. |
| **C — AUTHORED** | A list somebody wrote. Its membership is a choice made by the same effort being measured. | **CONSISTENCY.** "This document agrees with that document." | **Anything at all about omissions.** If the list forgot an item, so does the check. Δ = 0 is guaranteed before evidence. |

**The map's fifteen sources are measured almost entirely against Grade C, and that is the defect.**
Grade C is not worthless — a consistency check catches transcription error, and several of the
map's do. **It is worthless *as a completeness proof*, which is the claim §0 makes.**

**The repair is not "find a Grade A denominator for everything."** That is impossible and saying so
is part of being honest: **98% of this tree did not exist at 1.5.5** (§3.3), so no artefact
predating the effort can enumerate it. **The repair is to say, per source, which grade it is, and to
let the headline count only the sources that clear C.**

### 1.1 THE ONE SUBSTITUTION THAT IS NOT ALLOWED, AND WHY IT KEEPS HAPPENING

**A Grade-C denominator that is regenerated from the code looks exactly like Grade B and is not.**
If an instrument's baseline is a committed file, and that file is refreshed by the same change it is
supposed to judge, the instrument measures the change against itself. Δ = 0, every time, forever.

**This is not a documentation problem. It is this repository's default measurement posture, and §8.2
proves it in the gate that guards the config grammar.**

into an annotated tag, dated 2026-08-20 — **thirty-two days before the 1.6.0 consolidation window

### 2.2 THE BEHAVIOURAL CENSUS — 916 CELLS RECORDED FROM A BINARY WITH A PUBLISHED DIGEST

The second half of the Grade-A denominator, and the stronger half, because it is **behaviour** and
not **shape**. `testing/shadow-oracle/golden/1.5.5/meta.json`, verbatim:

```json
{ "binary": "<oracle-cache>/1.5.5/busbar", "version": "busbar 1.5.5", "recorded": 916,
  "binary_sha256": "84bde0a047fe368b661e9f6f14b2916390c40b71a6d91cdff1dbfa350aaf80e7",
  "harness_rev": "b3a611c…", "host_triple": "x86_64-unknown-linux-gnu",
  "at": "2026-09-16T22:22:15Z" }
```

**PROVENANCE IS NOT AUTHORSHIP, AND THIS IS THE DISTINCTION THE WHOLE CANDIDATE TURNS ON.** The
directory `testing/shadow-oracle/` was **created during the 1.6.0 effort** — born `fad15d006`,
2026-09-04, and it does not exist at the tag (`git ls-tree -r a71b21e9f -- testing/shadow-oracle`
→ **0 paths**, against a control of 35 paths under `qa/` at HEAD). A naive reading stops there and
rejects it as internal.

**That reading is wrong, and the reason is the `binary_sha256`.** The *file* was written by the
effort; the *values in it* were transcribed from a binary the effort did not build and cannot
change. A recording of an external object is Grade A **for the values it recorded**, in exactly the
way a photograph of a document is evidence about the document. The digest is what makes it checkable
rather than asserted.

**But its reach is narrow, and the narrowness is measured, not estimated:**

```sh

git ls-tree -r --name-only ${N} -- testing/shadow-oracle/golden/1.5.5/cells | wc -l   # -> 916

| `a2a` | 468 | **0** | 468 |

**`mcp` and `a2a` — 1,380 cells, 59.5% of the declared corpus — have zero external witness, and the
reason is structural rather than an oversight:** every `a2a` row's own SKIP text says
*"UNSUPPORTED: a2a is proven by its conformance rig, not recorded here."* 1.5.5 had no mcp plane and
no a2a plane, so **no recording of 1.5.5 can exist for them.** That is honest and it is also
absolute: **the two largest planes in this release cannot be proven not to have regressed, because
there is nothing to have regressed from.** They need a *forward* proof (the conformance rig), not a
parity one, and the map should never count them toward a parity number.

**916 is the true size of the behavioural Grade-A denominator. Not 2,318.**

### 2.3 WHY THIS ONE, IN ONE PARAGRAPH

`a71b21e9f` is the only artefact in reach that **predates the effort, is immutable, and states a
promise the release explicitly makes** — the governing rule the customer-surface sweep already
quotes: *"Customer-visible behaviour stays identical to the published 1.5.5 unless the owner signed
off a specific change with a reason."* That sentence is a testable claim with an external subject,
and §2.1/§2.2 turn it into 564 + 916 = **1,480 falsifiable elements**. Of the 564 static ones,
**553 preserved, 4 removed-but-unpublished, 7 relocated (§8.1) — and the 7 are a real finding that
Δ = 0 would have hidden.** That is the proof that the denominator is doing work: **it moved.**

### 3.2 REJECTED AS THE PRIMARY, KEPT AS TIER TWO: the mechanical census of the tree

`git ls-files '*.rs'` → **1802**. **This clears the strict test and it is the best Grade-B
denominator the release has.** The population is emitted by git; the sweep cannot shrink it; a
skipped file surfaces as a non-zero Δ no prose can absorb. **And I re-derived it rather than

```

**Zero tracked `.rs` files are unjudged, and the zero is trustworthy because the intersection beside
it is 1802.** The 8 the other way are all accounted for and none is a phantom verdict: **5** are the
untracked files the sweep names and deliberately excludes (`…kernel-identity/src/tests/hardening.rs`,

(`busbar-kernel/src/config/tests/txn_fence.rs`, `txn_loom.rs`), and **1** is a wrapped prose cell
(`busbar-voice/src/tests/*` (10) + …`). 5 + 2 + 1 = 8.

**This is the only Δ = 0 in this release that is both externally denominated and independently
re-derived by a party that did not produce it.** It is not the primary denominator for one reason
only: **the work created 1766 of the 1802 members.** It proves *"nothing in the tree was skipped."*
It cannot prove *"nothing that should be in the tree is missing"* — the class of defect that matters
most, and the one no census of the tree can ever reach.

### 3.3 REJECTED AS A DENOMINATOR, ACCEPTED AS *EVIDENCE*: the oracle corpus at 2,318

**The 2,318-cell corpus fails the strict test and the 916-cell golden passes it.** Splitting them is
the single most important thing in this section, because the release quotes 2,318 as though it were
one number.

- **The 2,318 is authored.** `cells.json` is generated by a generator the effort wrote and moved
  into the judge at `oracle-rust.pin`'s 2026-09-22 note. If the effort had chosen different cells
  there would be a different 2,318. **It can only sum to itself.** Grade C.
- **The 916 is recorded.** From a binary with a published `sha256`, at a stated instant. **Grade A**,
  per §2.2.

**And the release publishes neither honestly.** `CHANGELOG.md:33` tells the customer the oracle
measured **"780 cells"**; the tree holds **2,318** in `cells.json`, **916** golden files and **917**
ids in `owed-baseline.txt`. **Four numbers for one claim in a customer-facing file.** That is the
customer-surface sweep's observation and my re-derivation agrees with it to the row. The one that
belongs in a completeness proof is **916**, and none of the four is labelled as such.

### 3.4 REJECTED OUTRIGHT: the spec's locked decisions

`BUSBAR-1.6.0.md` Part 2's OWNER-LOCKED rows, the 76 spec markers, the numbered OWNER DECISIONS.
**This is the purest Grade C in the release and it fails the strict test in one line: if the work had
gone differently, the effort would have written different decisions, and the count would still
match.** Appendix H already proved the mechanism — three of the four master-list components are
**sections of `BUSBAR-1.6.0.md`, which is simultaneously S1's source**.

**Rejected. And it must not be repaired by moving the rows to a different file.** M4 was moved into
`1.6.0-LEDGER.md` at `b3643b73d` and the move changed nothing about its grade: source and yardstick
are still one effort. **Relocating a Grade-C denominator produces a Grade-C denominator.**
