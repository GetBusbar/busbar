## CONTROLLING EVERY ZERO — stated, because I am made of greps

Every zero and every count below was controlled against a case known to be non-empty. Explicitly:

- **A real zsh history-modifier bite, caught and fixed.** `git cat-file -e $P:scripts/…` failed with
  `bad substitution` — zsh parsed `:s` as a modifier. Every subsequent reference uses `${P}:`.
  The two commands issued before the fix (`$P:docs/…`) are validated by their non-empty output
  (76 and 21), not by assumption.
- **`grep -c` counts LINES, not occurrences.** S1 is 76 *lines* and **81 occurrences**; the document
  says `grep -cE` and means lines, and states the 81/5 split itself. S8's 168 is a **per-term sum of
  line counts**, not a distinct-line count — a single regex over the same scope gives 165 lines /
  169 occurrences. I reproduced the document's metric only after establishing that its metric is the
  one it declares.
- **POSIX ERE has no `\b`.** The document's own §11 reproduce command uses `[\s:|-]` inside a
  bracket expression, where `\` and `s` are literal members. I did not reuse it; I wrote
  `[[:space:]:|-]` and cross-checked the row list by eye (33 lines printed and counted).
- **Non-empty controls run:** `grep -cE 'BUSBAR'` → 4; `'^## '` in the owner-decisions file → 25 vs
  21 matched; `fn ` across `crates/` → 25,348; lines containing `1.6.0` in the spec → 76; pipe lines
  in `1.6.0-LEDGER.md` → 1,343 against 78 R-rows; `qa/*.toml` file list → 10; gate scope files → 757.
- **A dict keyed by id collapsing duplicates:** the R-row parse was checked for contiguity
  (`R1..R78`, no gaps, no repeats) rather than trusted as a count.
- **A parser artifact caught before it became a finding.** My first R-row state parse returned
  59 OPEN / 10 PARKED-OWNER / 4 IN-FLIGHT / **5 unparsed** against a claimed 62 / 11 / 4 / 1. The 5
  were `R19` *"OPEN — resolved into BR-S3"*, `R58` *"OPEN — DEADLINE"*, `R64` *"OPEN — ABSENT, not
  RED"*, `R76` *"ANSWERED — …"*, `R77` *"PARKED-OWNER — ACTION"*. Resolved: **62 + 11 + 4 + 1 = 78**,
  exactly as claimed. **This was my error, not the document's**, and it is recorded because an
  auditor who reports an unresolved parse gap as a disagreement has manufactured a false red.
