# P01-prior — 83 files named by a prior sweep, never given a per-file verdict

**Method.** For every file below, `git grep -n -F -f <patterns>` was run against every
`docs/design/1.6.0-*.md` (verified with a positive control: the same run against a known-good
path returns hits; a boundary check was added so the bare `Cargo.toml` pattern does not swallow
`crates/*/Cargo.toml` substring matches). Every one of the 83 paths returned at least one hit,
confirming this slice's premise — each was *mentioned*, not yet *verdicted*. Each hit was read in
its source document to decide whether it is a **real verdict backed by a command** (a grep count,
a `git blame`, a gate run, a direct read, a diff) or a **bare mention** (the file named in passing
while a different file or claim was under test — most commonly `docs/design/1.6.0-branch-sweep-ledger.md`,
whose rows are verdicts on *dead branches*, not on this file's state in trunk). Where a prior
document already ran the check, that finding is **reused and cited**, not re-derived — this is why
almost every `ROWS` cell is `-`: the defect already has a home in `1.6.0-THE-LIST.md`,
`1.6.0-LEDGER.md`, or a named sweep, and minting a new X-id would double-count it.

The single heaviest repeat contributor is `docs/design/1.6.0-unconstructed-sweep.md`. Its
Shape-1a ("declared, zero references anywhere") and Shape-1b ("declared, constructed only in
tests") rows are **already aggregated into `1.6.0-THE-LIST.md` X-259** ("400 capabilities declared
and never constructed... 10 sit on the money path"). Every file below with such a row cites X-259
plus the specific `unconstructed-sweep.md` line — the instance is real and VERIFIED, it just is
not a *new* row because X-259 already owns the population.

One genuinely new check was performed and produced a finding no prior document had assembled in
