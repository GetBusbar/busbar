## 5. Dead cells — the census, and the surprising result

**Result: the oracle corpus contains essentially zero dead cells, and that is a structural property
worth stating.** The rot found in the 62 ratchets elsewhere in the tree is not present here,
because the corpus is *generated*, not hand-maintained, and the generation is gated:

```bash
./bin/oracle cells --check     # ci.yml:1401, in the generated-artifact-drift job
```

Run read-only at this SHA against the locally-built pinned engine
(`busbar-release@ab88903`, `testing/shadow-oracle/oracle-rust.pin`):

```
ok  testing/shadow-oracle/cells.json is internally consistent (2318 cells, 25 families)
ok  testing/shadow-oracle/cells.json matches the generator (2318 cells)
rc=0
```

A hand-maintained ratchet rots because nothing regenerates it. This corpus is regenerated from
`qa/method-inventory.json` + `qa/field-inventory.json` + `fixtures/openapi-1.5.5.json` on every
push and byte-compared. **Dead cells cannot accumulate.**

Three independent dead-subject probes, all returning clean:

**(a) Admin method subjects vs the live OpenAPI.** 1 of 67 corpus `admin.ops` method names has no
live `operationId`: `admin-token`, which is the pseudo-method of
`admin.ops|admin-token|wrong-destination` (the admin Verify cell), not a route. **0 real dead
admin subjects.**

**(b) BOOT codes.** 237 distinct codes; 10 return no in-code hit
(`BOOT-152b`, `BOOT-P32`…`BOOT-P40`). Controlled: `BOOT-P32..P40` are documented as a *range* row
in `docs/design/inventory/1.5.5-config.md:546` (`crates/secret-ref/src/lib.rs:133-238`) and
`BOOT-152b` is the live subject of register entry `F-016`. **0 dead BOOT subjects.**

**(c) Register rationale pointers.** 5 entries cite repo paths that no longer exist post-fold — see
§7. Those are dead *evidence pointers*, not dead cells.
