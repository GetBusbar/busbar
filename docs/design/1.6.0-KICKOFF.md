# 1.6.0 — THE RULE BOOK FOR THE CODING SESSION

> **THIS SESSION RUNS UNATTENDED.** Nobody is watching. **Never ask a question mid-run** — not
> in chat, not with a question tool, not by pausing for confirmation. When you hit something only
> the owner can decide, **queue it and keep going** (§1.7–§1.13). A session that stops to ask has
> stopped; a session that queues has 99 other slots it can still finish.

Every line is binding. Where this disagrees with a checklist, this wins. Where it disagrees with
a Law in `docs/design/BUSBAR-1.6.0.md` or an owner ruling, those win.

**Every number in this book was produced by running the instrument, not by reading a document.**
An earlier draft asserted five figures from greps and all five were wrong. If you are about to
state a count, run the thing that counts it.

### Unattended operation — the contract

**1.7** **Never ask the owner anything mid-run.** No question tool, no "should I", no waiting for
a reply. You have every ruling you are going to get; what is missing gets queued, not asked.
**1.8** **Queue instead.** Append one row to `docs/design/1.6.0-QUESTIONS.md` with: the slot, the
item, what you could not decide, what you did instead, and what it costs if your choice is wrong.
That file is the single queue the owner reads. It is the ONLY channel for a question.
**1.9** **Then carry on.** Mark that item BLOCKED in the slot log and move to the next item. Move
to the next slot. Move to the next phase if the phase can still exit without it.
**1.10** **Decide when you can, and record it.** A choice you can make from the code, the spec or
an existing ruling is not a question — make it, note the assumption in your §15.8 row, and keep
going. Queue only what genuinely needs the owner's authority: money that changed, a
customer-visible behaviour change, a cost you were not authorised to incur.
**1.11** **"Stop" in this book means stop THAT ITEM, never the session.** The only thing that
halts the whole run is §1.12.
**1.12** **The one halt.** If a phase cannot exit and every remaining slot in it is blocked on the
same cause, drain every other phase-independent slot first, then stop and write the reason at the
top of the questions file. Nothing else halts.
**1.13** **Report at phase boundaries, not per slot.** The slot log is the running record; a
report to the owner is one summary per phase, plus the questions file at the end.

## 5. MODEL PER SLOT

**5.1** The model is in the slot's row. Use it. Do not substitute.
**5.2** The rule — **67 opus · 19 sonnet · 14 haiku**:

| model | assigned when |
|---|---|
| **opus** | the slot touches **money** or **the oracle**, or carries any **HIGH** |
| **sonnet** | worst severity is **MEDIUM** |
| **haiku** | all **LOW / NIT** |

**5.3** Money is matched on **the defect statement as well as the path**. Path tokens alone
(`ledger`, `cost`, `budget`, `price`, `meter`, `settle`, `hold`, `audit`) miss read-time money —
a change to what a customer is charged, in a file whose name says nothing about money. The text
match adds *billed · invoice · charged · priced · rate-card · spend · token-count · metered ·
overdraft · refund · settles · unpriced*. **56 items** are money under the combined rule.
**5.4** The oracle is matched on path (`golden`, `accepted-differences`, `openapi`,
`shadow-oracle`, `conformance`) **and** statement (*oracle · golden · byte-identity · openapi*).
**18 items** are oracle.
**5.5** No agent may retier its own slot downward. If you believe a slot is mis-tiered UP, leave
it — an extra opus costs money; a missed one costs an invoice.

## 6. PUSHING

**6.1** Push `predev` continuously, after every slot. It has no CI and costs nothing.
**6.2** Do not push `dev` before Phase 0 exits.
**6.3** Push `dev` **once per phase boundary**. Not per wave, not per slot.
**6.4** **Exception — a slot flagged 💰money or 🔍oracle pushes `dev` alone.** A batched push
destroys the attribution for a changed number.
**6.5** 6.3 and 6.4 are reconciled by ORDER, not by a budget: run every non-money, non-oracle slot
in a phase, push once; then run the money/oracle slots of that phase one at a time, pushing after
each. Phase 2 therefore costs more pushes than Phase 4 and that is correct.
**6.6** **Turnstile.** `predev`→`dev` runs through `turnstile.yml` in the sibling repo
`GetBusbar/busbar-release`, fired by a `repository_dispatch` of type `turnstile-admit`.
`TURNSTILE_DISPATCH_TOKEN` **is provisioned and validated** (dispatch returns 204; the same token
is refused 403 on `main`'s branch protection, by design).
**6.7** `turnstile-dispatch.yml` is `workflow_dispatch`-only **deliberately** — predev carries no
automatic CI, and admitting a candidate runs the full battery suite. Do not add an `on: push`
trigger to it. That would run the batteries dozens of times a day against unfinished trees and is
a standing money leak.
**6.8** Never push `dev` by hand to route around a denial. A denial you bypassed is a gate you
deleted.
**6.9** Never push `qa`. Never push `main`.

## 8. MONEY

**8.1** Money is binary. Would a bank auditor pass it? If not it is wrong. Fix it.
**8.2** Do not ask about money. Be right about it.
**8.3** Ledger ≠ money. Planes write the ledger; money is a view on the ledger × the ratecard.
**8.4** The ledger is exactly what the plane did. 17 output tokens means 17.
**8.5** Money is never wrong. The ledger or the ratecard is wrong. Fix that.
**8.6** An unpriced class **REFUSES**. It does not silently answer zero.
**8.7** Never self-approve a changed money figure. PARK it per §15.4, queue it per §1.8, mark
the item BLOCKED, and **go to the next item**. Do not stop the session and do not push that slot.
**8.8** 8.7 covers **read-time** money too — a change to what a customer is charged counts even
when no stored byte moved.

## 9. THE ORACLE

**9.4** Exception, and only this one: **Law 9, arming at today's number.** Writing a measured

## 15. THE THINGS AN AGENT WILL HIT — ruled, so nobody has to guess

**15.1 A slot needs a file another slot owns.** It does not touch it. It records the dependency in
its report and the architect sequences the two slots. Two agents editing one file is the failure
the partition exists to prevent.
**15.2 An item is a false positive.** Do not fix it and do not delete it. Mark it STRUCK in the
TODO with the measurement that refuted it. A finding removed without a reason is indistinguishable
from one nobody looked at.
**15.3 The fix is a deletion.** "Done" is: the code is gone, every caller is gone, and a test
asserts the *behaviour* that replaces it — a refusal, an error, an absence that something checks.
Deleting code and asserting nothing is not a fix.
**15.4 A money figure changed.** Stop. Write `docs/design/1.6.0-PARKED/<item>.md` with the cell,
the diff, the root cause and a recommendation. Do not push. Do not self-approve.
**15.5 Where an exit test lives.** In the crate it tests, in that directory's existing test module
— which your slot owns by §4.2. For a bare script with no harness, wire the script's own
`--selftest` and make CI call it. Never a new top-level test crate.
**15.6 Who owns a newly created file.** The slot that created it, permanently. Record it in the
report so the next wave's partition includes it.
**15.7 Two slots' commits conflict.** They cannot — they own disjoint directories. If it happens,
the partition is wrong. Stop **that wave**, re-run the proof in §4.3, re-cut the affected slots,
and continue — do not resolve the conflict by hand and do not stop the session.
**15.8 A slot reports** by appending one row to `docs/design/1.6.0-SLOT-LOG.md`: slot, items,
verdict per item (FIXED / STRUCK / PARKED / BLOCKED), the exit test path, and the RED proof from
§16. This is the only status channel.
**15.9 Phase 0 cannot be completed.** Drain every Phase 0 slot that is not blocked on the same
cause first — a partial floor is worth more than none. Then queue it per §1.8, naming which of the
three §13 breakages resisted and exactly what was measured. This is the §1.12 halt: Phase 1 does
not start regardless, so there is nothing left to drain.
**15.10 The owner still owes** the items listed in the TODO's "WHAT THE OWNER STILL OWES" table.
Check it before declaring a phase blocked — the blocker may not be yours.

## 16. PROVING A TEST GOES RED, WITHOUT RACING

**16.1** §3.5 requires a RED proof. The shared checkout is being written by every other slot, so
"the unfixed tree" is not a thing you can point at there.
**16.2** Prove it in your own worktree, pinned to the phase's start commit:
```sh
git -C <repo> worktree add --detach /private/tmp/slot-<TAG> <phase-start-sha>
# write the test there, run it, capture the failure
git -C <repo> worktree remove --force /private/tmp/slot-<TAG>
```
**16.3** Record the command and its non-zero exit in your §15.8 row. That is the proof.
**16.4** Then apply the fix and the test in the shared checkout and commit both together.
**16.5** Remove your worktree when done. Never leave one holding uncommitted work.
