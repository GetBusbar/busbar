# THE MAP — 1.6.0

**What this file is.** The complete list of what stands between HEAD and 1.6.0 dev-green, and the
proof that the list is complete. Two numbers live here and nowhere else:

1. **MAP %** — how much of the corpus has been swept with an instrument proven able to return NO.
2. **X** — the count of findings. Green is `X = 0`.

When the map reaches 100% it is **LOCKED**: no new sweeps, only `X → 0`. Anything discovered after
the lock is a defect *in this map* and is recorded as such, not quietly appended.

---

## 0. WHAT BUSBAR 1.6.0 IS, IN ONE SENTENCE

> A customer can teach busbar a new protocol by dropping a file into a folder — and busbar's core
> does not know that protocol exists.

Everything else is a consequence: core is a thin engine naming zero plane types; every plugin obeys
the same two rules whatever its kind; money is exactly right to a bank auditor's standard; and the
customer sees no difference from 1.5.5 unless the owner signed off on a specific change.

The 23 groups in `scripts/verify-1.6.0-done.sh` are **how we check** that sentence is true. They are
not the goal. If someone splits a group tomorrow there are 24 and nothing about busbar changed.

## 1. THE DEFECT CLASS — "HALF HERE, HALF THERE"

Every finding in this release has had the same shape: **a broken pair.** One half exists, is
correct, and is tested. The other half is missing, stale, or different. The code looks right
wherever you open it; the bug is that the *other* copy is the one that runs.

| capability ↔ construction | `signing_with` (`busbar-kernel-audit/src/record.rs:356`) has zero non-test callers; the audit chain ships unsigned |
| declaration ↔ wiring | `reachability` gate: 19 rows, incl. "a module of the composition root is reached by nothing" |

## 2. THE TWO LAWS OF MEASUREMENT

Everything in this file obeys both. They are not style; they are why the earlier maps were wrong.

> **An instrument that cannot produce a NO is not a check.**
> Zero is the passing answer to every ban. A gate that scans no files passes. A grep with a typo
> finds nothing and looks clean. Before any count is believed, hold one known instance out of the
> instrument's reach and confirm it reports the absence. 11+ proven instances of this class.

> **A capability that is never constructed is a capability that does not ship.**
> Its tests prove the code works, not that it runs. **A test suite cannot detect this class**, because
> the test constructs the capability itself. Only a trace from the composition root can.

Two corollaries earned the hard way in this repo:

- **Never `head`/`tail` a result whose total you are about to report.** A truncated grep hid a struct
  definition and nearly produced a false "this type does not exist". A gate truncates offenders in
  *path order*, so an 8-item sample is structurally incapable of showing a distribution — an 8-item
  read was reported as "7 of 8"; the truth over all 113 was 36.
- **A silent tool failure and a real zero must never be the same output.** `git diff
  --pathspec-from-file` exited 129 with empty stdout, which read as "identical to HEAD" for all 95
  branches. `set -o pipefail`, and check exit codes separately from output.

**No published COUNT IN in this project has ever reproduced at its own pin.** S2b's 33 was 25. S2c's
44 was 42. S3's 242 was never enumerable. S4's 2,444 was two rows high. S10's 15 is now 5. Re-derive
every number; never inherit one.

### Why the branch corpus is 2 sweeps and not 816

816 branches × N files is the wrong work unit. The right one is the distinct `(path, blob)` pair:
**46,828** pairs not in HEAD, spanning only **4,039 distinct paths** — **1,386 genuinely novel**
(basename appears nowhere in HEAD) and **2,653 renamed/moved/evolved**. If `x.rs` is byte-identical
across 100 branches, it is read once.

Three methods failed before this one. Patch-id is useless — the rename waves moved every path. Only
**3 of 819** branches are ancestors of HEAD, so `git log trunk..branch` is meaningless for the rest.
**Symbols survive renames; paths do not** — that is the whole method.

Prior bucketing was EMPTY 14 / HARVESTED 133 / SURVIVOR 669. **669 is an upper bound, not a
measurement** — one slice showed a 15% false-SURVIVOR rate from ripgrep leftmost-first shadowing
(1,445 false absences) before the instrument was rebuilt.

## 5. RULES THAT BIND EVERY AGENT ON THIS MAP

- **Money is binary — right or wrong.** Bank-auditor standard: would it pass? If not it is wrong.
- **The ledger is the truth; money is a view on the ledger × the rate card.** Money is never wrong —
  the ledger or the rate card is wrong. Say which.
- **Never self-approve a billed byte (#10/#59).** PARK it: cell, diff, root cause, recommendation.
- **A row without EVIDENCE is not a row.**
- **A gap and a failure must never be the same output.**
- Never push `dev`, `qa` or `main`. Snapshot before any delete. No AI attribution on any commit.
