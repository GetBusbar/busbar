# MONEY IS ONE FUNCTION, SO THERE SHOULD BE ONE TEST OF IT

**Status: PREPARED, NOT LANDED.** Held until the streaming fold releases
`crates/busbar/src/root/units_voice.rs` and `units_a2a.rs`. #19 requires the move be provable
byte-identical by `git show --stat -M -C` reporting `R`, which a file being rewritten underneath it
cannot be.

---

## 0. THE ARGUMENT

The owner's framing, and it is a stronger claim than any line count:

> *"oracle being blind to money isnt a problem so long as its not blind to ledger and rate card
> right? … money is just a function … one test and it works or doesnt"*

**money = f(ledger, rate_card).** Money is not a thing to observe; it is a derivation. A pure
function needs exactly one test: hand it a known ledger and a known card, assert the known figure.

**The defect is that `f` exists four times.** Measured across the four composition-root unit
modules:

| the same ruling | copies | evidence |
|---|---|---|
| `balance()` | **4, byte-identical** | `units_a2a:816`, `units_llm:1531`, `units_mcp:1700`, `units_voice:1798` — all exactly `TotalsKey::new(BucketId::new(principal.as_str()), CapDimension::NanoUnits, BucketScope::All)` |
| the settle block | **4** | `units_a2a:841`, `units_llm:1555`, `units_mcp:1384`, `units_voice:1822` — same `budget_window(WINDOW_DAY, …)`, same `StepName::Meter`, same five-line justifying comment |
| provenance (`rate_card_version`) | **2 identical + 3 literals** | `units_a2a:904-918` ≡ `units_mcp:1502-1515`; `units_llm:1578`, `units_voice:1840`, `units_voice:1944` were hardcoded `0` |
| `Estimate` construction | **3** | `units_a2a:1057`, `units_mcp:834`, `units_voice:1287` |
| the admit block | **3, statement-for-statement** | `units_a2a:1350-1372` ≡ `units_mcp:914-928` ≡ `units_voice:1606-1625`, plus the identical fail-closed `None`-chain arm at `units_a2a:1345-1349` ≡ `units_voice:1599-1603` |
| `Evidence` construction | **4** | same 14-field record; differs only in the `located`/`accrued_floor`/`class` triple |
| `fee_evidence` | **4** | differs only in the `client_open_or_one_shot` predicate |
| `audit_finish` | **3, byte-identical** | 4-arm `FinishClass → FinishClass` match |
| `NANOS_PER_CENT` + compile assert | **2, byte-identical** | `units_a2a:1165-1166`, `units_voice:163-164` |

**So today money needs four tests — and the four can disagree.** That is not hypothetical in this
tree:

- Two admin endpoints answered different money for the same window on 2026-09-22, for exactly this
  reason.
- `units_voice.rs:1645-1647` accrues **raw milliseconds** into the nano-denominated `AccrualMeter`
  while `units_a2a.rs:1441` does the same job correctly — and the voice file already knows the
  conversion, applying `meta::audio_seconds_in` to the *same counter* 111 lines later at `:1758`.
- `rate_card_version: 0` shipped in the one live module until `aa81f48b0`. `0` is
  `HistorySeq::OPENING`, a real entry — a confident wrong answer, not a null.

**THE GOAL IS ONE FUNCTION SO THERE CAN BE ONE TEST, SO IT CANNOT DISAGREE WITH ITSELF.** Deleting
~5,700 lines of never-executed code is a *consequence*, and it is the weaker claim — it does not
survive someone asking "why not leave the duplication and just fix the bugs." This does: four
implementations are four chances to be wrong and four places to remember when the ruling changes.

**The acceptance test is the owner's sentence.** If this plan does not end with a *single* test that
hands `f` a known ledger and a known card and asserts a known figure, standing where four
implementations used to be, it has not finished the job.

## 1. WHY THIS IS GREENFIELD, NOT A FOUR-WAY MIGRATION

Measured two independent ways — a constructor-call-site trace and `cargo xtask gate reachability`'s
`unit-path` rows (`qa/reachability-evidence.md`) — which agree exactly:

| module | lines | status |
|---|---|---|
| `units_llm.rs` | 1,930 | **LIVE.** `main.rs:610/628/1768`. The only one that serves bytes and settles money. |
| `units_mcp.rs` | 1,884 | **DEAD.** Declares no `impl … Units for` at all. Sole production caller is `seal()`, whose body opens `let _ = plane;`. |
| `units_a2a.rs` | 1,784 | **DEAD.** `A2aUnits` built at 2 sites: its own constructor and one test. |
| `units_voice.rs` | 2,047 | **UNIT HALF DEAD** (`VoiceUnit`: 49 sites, 48 tests). Node half live. |

**Three of the four have never billed anybody.** So the consolidation writes one implementation,
points the one live path at it, and deletes the rest — it does not migrate four production callers.

## 2. WHAT IS GENUINELY PER-PLANE

Only **data**, and it is already in the right place: the 15 declared meter classes across the five
planes (`key`, `family`, `direction`, `default_divisor`), the op-class strings, and the fact keys —
all `const` in each plane's `meta.rs`, all already crossing the ABI as `MeterClassDecl`.

Per #71 that is the plane's *whole* money obligation. Nothing else on the list above is per-plane;
it is per-plane-shaped only because it was written four times.

## 3. THE SEAM

```rust
/// money = f(ledger, rate_card). ONE implementation, so there can be ONE test.
pub struct MoneyStep<'a> {
    /// What the plane DECLARED — data, from its own meta.rs (#71).
    classes: &'a [MeterClassDecl],
    /// What the plane REPORTED — raw counts per declared class, and nothing else (#43).
    counts: &'a UsageLocators,
    /// WHEN — the resolution key for the dated history (#79). MILLISECONDS.
    arrived_ms: u64,
    /// The snapshot pinned at the door, never re-taken at settle.
    card: Option<&'a PinnedHistory>,
}
```

It owns, in exactly one place: card resolution by `arrived_ms`; `Estimate`/hold sizing; the admit
block; nano-denominated accrual; the provenance stamp; unit keying; settle onto the `MoneyBook`
seam; and the `Evidence` / `AuditInputs` / `fee_evidence` records.

What remains per-plane is a small **value**, not code:

```rust
pub struct PlaneMoneyDecl {
    classes: &'static [MeterClassDecl],   // already in meta.rs
    op_to_class: &'static [(OpClassId, MeterClassId)],
    fee_policy: FeePolicy,                // PerRequest | PerSession | None
}
```

`FeePolicy` is the whole of the `fee_evidence` divergence: voice's
`client_open_or_one_shot && shape.is_handshake()` is `PerSession`; the other three are `PerRequest`.

## 4. THE HUNKS, IN LANDING ORDER

Each step is independently green, and steps 1–3 are pure lifts with no behaviour change — so
`git show --stat -M -C` reports `R` for them, which is #19's requirement.

**Step 1 — the byte-identical five (zero risk, no behaviour change).**

| lift | from | to |
|---|---|---|
| `balance()` | `units_a2a:816`, `units_llm:1531`, `units_mcp:1700`, `units_voice:1798` | `money::balance(principal)` |
| `audit_finish` | `units_a2a:1173`, `units_mcp:1663`, `units_voice:2007` | `money::audit_finish(class)` |
| `NANOS_PER_CENT` + assert | `units_a2a:1165-1166`, `units_voice:163-164` | `money::NANOS_PER_CENT` |
| `read_through_poison` | `units_a2a:750` + 25 inlined `unwrap_or_else(|e| e.into_inner())` | `money::read_through_poison` |
| provenance | `units_a2a:904-918`, `units_mcp:1502-1515`, `units_llm::card_in_force` | `money::card_in_force(card, arrived_ms)` |

The fourth copy of provenance already exists and was deliberately written to MATCH rather than to
differ (`aa81f48b0`), so this lift is a deletion of three duplicates, not a merge of four dialects.

**Step 2 — the admit block.** `units_a2a:1345-1372` becomes `money::admit(...)`; `units_mcp:914-928`
and `units_voice:1599-1625` are replaced by calls. The only real divergence is that
`Admitting::chain` is non-`Option` in mcp (`units_mcp:893`) so it has no fail-closed arm — the
consolidated one takes `Option<&BucketChain>` and keeps a2a/voice's arm, which is strictly safer.

**Step 3 — the settle block onto the `MoneyBook` seam.** llm's shape is already correct
(`&dyn MoneyBook`, `root/durability.rs:424-449`). a2a and voice take the lock inline; mcp takes
`&mut Durability`. Move all three onto llm's.

**Step 4 — accrual, and it FIXES A LIVE-SHAPED BUG ON THE WAY.** One `accrue(class, raw_count)`
where the kernel applies the class's declared divisor and the card's unit price. This removes
`units_voice:1645-1647`'s millisecond-into-nano-meter accrual by construction: a plane hands a raw
count and a class, and never multiplies.

**Step 5 — `Estimate`, `Evidence`, `AuditInputs`, `fee_evidence`** parameterised by
`PlaneMoneyDecl`.

**Step 6 — delete `units_mcp.rs`, `units_a2a.rs`, and `units_voice.rs`'s unit half.** ~5,700 lines,
all proven unreached twice.

**Step 7 — THE ONE TEST.** Known ledger × known card → known figure. This is the acceptance
criterion, not a nice-to-have.

## 5. TWO HAZARDS THAT BITE EXACTLY HERE

1. **Seconds vs milliseconds.** `bindings.now` is whole **seconds**; `effective_from` is
   **milliseconds** (`root/kernel.rs:435`). A resolution handed the seconds reading matches only the
   from-zero opening entry and reports it forever — the `rate_card_version: 0` bug wearing a
   different hat, and it would pass a "reads a history" review. `units_llm::Arrived` carries both
   readings for this reason; the consolidated seam must take `ms`, and its test must assert the
   seconds value resolves *wrong* so the binding is pinned.
2. **Two clock readings for one unit.** `units_voice.rs:1842` and `:1924` take *different* `mono`
   readings for one unit's posting and its record; a2a and llm each pin one. Pin one.

## 6. WHAT ALREADY GUARDS THE END STATE

`cargo xtask gate plane-pricing-blindness` (#43/#71, Part 7 §13(3)) enforces that a plane never *values* — no
card resolution, no pricing, no unit-key minting, no hold arithmetic. **That is what makes `f` the
only place money is computed:** a plane that prices is a fifth copy of the function nobody tested.
The gate is RED on 15 findings today across `busbar-llm` and `busbar-voice`, every one of them an
act this plan moves kernel-side, and it goes GREEN exactly when `qa/plane-pricing-blindness.toml`
empties — which is when this plan is done.
