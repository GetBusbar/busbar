# The Duplex Plane & OpenAI Realtime — busbar 1.6.0 design

Status: **DRAFT / in-progress.** Working branch: `integration/plane-extraction`.
Owner: Matthew. This document specs a new plane *shape* — the **duplex/session plane** —
and its first instance, an **OpenAI Realtime** voice plane. It is a sibling to
`1.6.0-protocols-as-plugins.md` (the plane/plugin ABI) and depends on that work: a duplex
plane is still a plane, and it must ride the same one gauntlet and the same hot ABI. Every
current-state claim below is cited against the tree from a 6-agent ground-truth audit
(2026-09-01).

---

## 0. The question that started this

> What would it take, in our LLM protocols, to support **OpenAI Realtime** — the WebSocket
> `/v1/realtime` session API + `client_secret` → WebRTC in the browser, with tools mid-call?
> Bidirectional live voice. Not one-shot transcribe/TTS. And: LiteLLM can already sit in
> front of this — why might we not, and **what other gaps of the same shape exist**? I need
> to be gap-free.

The short answer: Realtime is **not a codec problem, it is a transport problem.** Our LLM
plane is a request/response translator with no duplex transport. Realtime is a persistent,
stateful, full-duplex session. It is the most visible instance of a whole *class* of modern
LLM-protocol capabilities that break our stateless-request/response assumption — and closing
just Realtime while leaving the class open means getting surprised one protocol at a time.
This doc closes the class.

**The load-bearing conclusion:** Realtime would be busbar's **first true network-duplex
plane.** The substrate was visibly *designed anticipating* a duplex plane — the scope names,
the WorkItem carrier tags, the byte-pipe host-fn signatures are all reserved for exactly this
— but the runtime that fills them does not exist. This is a principled build on prepared
ground, not a wiring job and not a hack.

## 1. Ground truth — what busbar has today (cited)

Measured against the four assumptions a stateless request/response proxy makes, which each
capability below either satisfies or breaks:

- **[REQ/RESP]** one reply per request
- **[STATELESS]** server holds no session; the client replays history
- **[JSON-ONLY]** the body is one JSON object
- **[SHORT-LIVED]** a single sub-timeout connection

### 1.1 The current capability surface (parity table)

Complexity = effort **to reach parity in busbar**, not general difficulty.
Legend: **Done** · **Low** (config/passthrough) · **Med** (new IR/handler or state store) ·
**High** (new transport or lifecycle engine).

| Tool calling (in-body + streamed arg deltas) | ✅ normalized `InputJsonDelta`, cross-dialect id remap; *relay only* | ✅ | **Done** |
| Embeddings | ✅ openai/gemini/bedrock/cohere | ✅ | **Done** |
| Rerank | ✅ cohere/bedrock | ✅ | **Done** |

**Reading of the table.** busbar is at or above LiteLLM on everything one-shot or
response-streaming — and *better* where it counts: it genuinely cross-translates dialects
through a lossless IR rather than normalizing everything to OpenAI shape. The gaps cluster
exactly on the **stateful / duplex / async-handle** rows. The one item that is genuinely
net-new regardless of proxy choice is the **request-completion webhook receiver** (LiteLLM's
webhooks are spend-alerts only).

### 1.2 Operation & IR surface (`crates/api/src/operation.rs`, `crates/busbar-llm/src/ir/`)

- Every operation is `Operation::Verb { op: OpShape, name }`. `OpShape` ∈
  `Invoke | Catalogue | Fetch | Task | Subscribe | Control`; **only `Invoke.may_stream()`
  is true** (`operation.rs` `OpShape::may_stream`).
- **All 7 LLM verbs are `Invoke`** (`CHAT, EMBEDDINGS, MODERATION, IMAGE, TRANSCRIPTION,
  SPEECH, RERANK`). `Subscribe`/`Control` exist but are used only by MCP/A2A;
  `CATALOGUE/FETCH/TASK/CONTROL` are **declared-but-no-codec** reservations.
- **Only the chat IR (`ir/types.rs`) carries streaming/multi-turn shape** (`IrStreamEvent`,
  `IrDelta`, turns, tools). Every leaf op (`embeddings/rerank/moderation/image/audio`) is
  `turn_count: 1, has_tools: false`, `wants_stream() == false`. `TranscriptionReq`/
  `SpeechReq` carry a *vestigial* `stream: bool` with no streaming codec behind it
  (`ir/audio.rs`).
- "STREAMING IS NOT AN OPERATION" — it's an `OperationHandler` fact, per the operation
  module header. This is important: our own model already says the transport/interaction
  pattern is orthogonal to the verb.

### 1.3 Transport axis (`crates/busbar-substrate/src/transport.rs`)

- `enum Transport { Http, JsonRpc, HttpJson, Grpc, Stdio }`. **No WebSocket variant.**
- The enum has exactly **one dispatch consumer**: `Transport::upstream_wire()`, used only on
  the MCP client egress leg to pick `StreamableHttp`/`Stdio`. The A2A variants are consumed
  only as telemetry labels (`Transport::name()`). **There is no code mapping a `Transport`
  variant to an ingress listener or an egress driver.**
- Egress is **reqwest one-shot** (`busbar_core::proxy`) + the MCP subprocess pipe. There is
  no persistent network-socket client anywhere.

### 1.4 Streaming pipeline — already a genuine event-relay (the biggest asset)

- Core seam: `crates/busbar-core/src/proto/stream_translator.rs` `trait StreamTranslator`
  (byte-in/byte-out; core never names a concrete IR).
- Plane impl: `crates/busbar-llm/src/proto_stream.rs` `StreamTranslate::feed` translates one
  wire frame at a time through a single intermediate **`IrStreamEvent`** IR (not pairwise),
  re-frames to the client dialect via each ingress `StreamFraming` vtable
  (`proto_codec.rs:512`), and emits on the same poll tick. Only buffering is a bounded
  frame-reassembly buffer (`MAX_BUF`), not the full body.
- Byte forwarding: `crates/busbar-core/src/proxy/response_body.rs` `FirstByteBody::poll_next`
  — one upstream chunk in, translated chunk out, immediately.
- **All 6 dialects implement streaming writers.** Cross-dialect streaming works (client
  Anthropic ⇄ upstream OpenAI). Tool-call arg deltas normalize to
  `IrDelta::InputJsonDelta` and re-frame across dialects. **Same-protocol streams re-emit
  upstream bytes verbatim**, running IR only as a usage side-channel.
- **Gaps for duplex:** the pipeline is **unidirectional** — `FirstByteBody` is a *response*
  `Stream`; the request path is whole-JSON `IrRequest`, not an event stream. The
  `IrStreamEvent` vocabulary is **response-shaped** (no client→server events). No
  tool-execute/suspend/resume. State is single-turn.

**Verdict:** property #2 (below) is *largely built for the response direction.* This is the
asset that makes a duplex plane tractable rather than greenfield.

### 1.5 Byte-fidelity & payloads (`crates/busbar-core/src/proxy/wire.rs`, `walk.rs`)

- **Same-dialect requests have a true zero-copy byte-verbatim fast path**
  (`wire.rs:415-643`): when `ingress_protocol == egress_name && pristine`, the original
  bytes are re-emitted by refcount bump — no reorder, no float reformat, no field injection.
  "Pristine" is invalidated only by four enumerated causes (router shim-key strip, model
  rewrite when the body's `model` ≠ the resolved lane wire-model, path-model shim strip,
  Vertex-Anthropic path reshape). Cross-dialect is **never** pristine — it fully rebuilds the
  body from IR.
- Multipart in: real byte-preserving parser (`openai_chat/handler.rs`, `MAX_MULTIPART_PARTS
  = 64`). Binary out: `MediaBlob` + typed `WireBody`.
- Opaque body fields (`cache_control`, thinking `signature`, encrypted reasoning, vendor
  extras via `SourceScopedExtra`) are **first-class same-protocol, dropped-with-diagnostic
  cross-protocol** — loudly, never silently (`chat_handle.rs` `IR_DROP_*` banners).
- **Headers are NOT forwarded.** The egress header map is rebuilt fresh from lane credentials
  + `CONTENT_TYPE`/`USER_AGENT`/`ACCEPT` (`walk.rs:579-642`, `egress.rs:229-276`). Client
  `anthropic-beta` / `OpenAI-Beta` / `anthropic-version` are dropped on **all** paths. This
  is not a translation problem — headers simply aren't proxied. **Flagged as an independent
  fidelity defect**, separate from the duplex work.

### 1.6 Sessions / handles / async — stateless end to end

- OpenAI Responses (`crates/busbar-llm/src/openai_responses/`) is `CELLS =
  &[(Operation::CHAT, &CHAT)]` — treated as one-shot chat. `previous_response_id`,
  `conversation`, `truncation`, `include`, `prompt`, `prompt_cache_key`,
  `safety_identifier`, `background` land in `ir.extra`, get a diagnostic, then
  `ir.extra.clear()` (`chat_handle.rs:272-297`). No response-id store, no server-side
  conversation state.
- `crates/api/src/store.rs` is a **governance** store (keys/budgets/metering/audit), not a
  conversation/handle store. No conversation/thread/run/batch/file-id persistence anywhere.
- No batch API. No inbound webhook receiver in core/LLM (`export/webhook.rs` is outbound
  fire-and-forget only).
- **The one real async-job/handle engine in the repo is `crates/busbar-a2a/src/taskstore.rs`**
  — process-wide registry with cross-request handles (`TASKS`), a lifecycle state machine
  (`submit`/`transition`), retention/GC (`sweep`, `MAX_RETAINED_TASKS = 4096`),
  durable-store rehydration (`restore_from_store`), and an inbound-push cursor. It lives in
  the A2A plane. **It is the blueprint for property #3**, not reusable in place.

### 1.7 The duplex machinery that already exists (reservations, not runtime)

- **MCP is genuinely duplex — but only over stdio.** Its bidirectional loop is bespoke and
  lives in `busbar-mcp`, not the substrate: the client leg (`mcp/client/stdio.rs`
  `StdioChild::call`) has *no correlation table and no reader task* (serializes behind a
  `Mutex`, documented); the server leg (`mcp/stdio_serve.rs` `Session<W>`, `run_session`) is
  a real inflight/pending/route-reply/out-mutex duplex session but is MCP-framed and **not
  wired to `SessionScope`**. A **blueprint to copy, not a library to call.**
- **A2A holds no connection.** Its "session" is the durable task table correlating separate
  HTTP requests; "streaming" is SSE over an HTTP response; `Subscribe` is a **webhook
  callback URL**. **WebSocket is not refused by policy — it is simply not implemented**
  (`a2a/serve.rs` `servable_bindings` only publishes jsonrpc/http+json/grpc).
- **`SessionScope {}` is dormant** (`plane_host/scope.rs:366`) — an empty `#[non_exhaustive]`
  stub whose own doc says *"the riders that add a duplex/session plane wire this out."* Grep
  finds only its definition and two re-exports; nothing constructs it.
- **Reserved ABI carriers exist:** `WorkItem` `InboundKind::Stream` + `EmitKind::Unsolicited`
  (`hot/workitem.rs`, *"WIRED for duplex-session"*); byte-duplex host-fns
  `PipeReadFn`/`PipeWriteFn` + `DispatchScope::register_pipe` (`hot/host.rs`) — though the
  host `egress_write` is `unimplemented!("…stub")`.
- **Ingress is an axum HTTP request router** (`ingress/{arrival,jsonrpc,protocol}.rs`).
  Planes mount via `PlaneRouteSpec { path, method, auth, handler }` where
  `PlaneResponse = axum::response::Response`. An `axum WebSocketUpgrade::on_upgrade` handler
  *can* be returned from a route (a **foothold**), but it hands a raw socket to a plane
  closure that bypasses the `plane_host` scope machinery.

## 2. Why LiteLLM can and we can't (yet)

**LiteLLM is a stateful WS↔WS bridge; busbar's plane is a stateless request/response
translator with no socket to hold.**

LiteLLM (Realtime GA since v1.85.0) terminates the client WebSocket, opens a fresh upstream
WebSocket routed by model name, and pumps opaque events across it (with logging/cost/
guardrails on the stream). It also mints ephemeral `client_secret`s
(`POST /v1/realtime/client_secrets`) and brokers the SDP handshake
(`POST /v1/realtime/calls`) so browser WebRTC keeps keys server-side. It routes Realtime to
OpenAI/Azure/Gemini/Vertex/Bedrock/xAI.

Two things follow for us:

1. **The gap is structurally in busbar's transport assumption, not upstream availability.**
   Nearly every row in §1.1 is a *feature* LiteLLM already proxies; what we lack is the
   duplex socket, the event-relay in the request direction, and the handle store.
2. **Even LiteLLM leaves the whole client side to you** — browser WebRTC/WS client, mic
   capture + 24 kHz playback, tool execution, VAD config, reconnection. That work is
   unavoidable regardless of proxy. busbar's differentiator is not "do the client for you";
   it is "be the one governed, audited, key-holding gauntlet in front of every plane,
   Realtime included."

(Note: the repo treats LiteLLM as a *competitor*, not a dependency. "We use litellm to proxy
voice today" is the current external stack that busbar is absorbing.)

## 3. The four properties that close the whole class

Every gap row in §1.1 collapses into four plane capabilities. Build these and busbar stops
getting surprised one protocol at a time.

1. **Duplex, long-lived transport.** A first-class WebSocket path (and WebRTC brokering) with
   a session object and ephemeral-token minting. Closes Realtime + realtime transcription.
   *The single biggest structural add; Realtime is its forcing function.*
2. **Event-streaming in both directions.** Treat a session as a stream of typed events
   forwarded incrementally, never reassembled into one body — in the **request** direction as
   well as the response direction. Closes mid-stream tools and is a prerequisite mindset for
   #1. **We already have the response half** (§1.4).
3. **Session / handle + async-push management.** A store for server-side handles
   (`previous_response_id`, thread/run/batch/`file_id`), a poller, and an **inbound webhook
   receiver**. Closes stateful sessions, batch, background. **Model it on the A2A
   `taskstore`** (§1.6).
4. **Opaque binary/multipart carriage with byte-exact passthrough.** Carry multipart + raw
   binary and forward request bodies without rewriting/reordering/re-serializing/injecting.
   **We already have this same-dialect** (§1.5); the caveat is that *translation* and
   *byte-fidelity* are mutually exclusive by construction — see §6.

## 4. Target architecture — the duplex plane

### 4.1 It is still a plane, and it still rides the one gauntlet

The Protocols-as-Plugins vision says every request is authenticated, its destination
verified, approved under grant, admitted against budget, routed, and audited — the one
`operation::run` gauntlet. A duplex session does not get to skip this. The design decision is
**where the gauntlet runs for a long-lived connection**:

- **Session-open is one gauntlet pass.** The WS upgrade / `client_secret` mint is a normal
  `operation::run`: authenticate the caller, verify the destination (which upstream/model the
  session may talk to), approve under grant, admit an *opening* budget reservation, and open
  the audit record. This is the natural home for the existing stages 1–4/6.
- **Per-turn events are metered and audited against the open session, not re-authenticated.**
  Each `response.done` carries `usage` (audio vs text token classes — meter off it, §5) that
  debits the session's budget lease and appends to the session's audit chain. Barge-in,
  tool-calls, and truncations are audit events on the same record.
- **This maps onto reserved shapes:** the session is an `OpShape::Subscribe`/`Control`-class
  interaction (long-lived, not one `Invoke`), it owns a populated `SessionScope`
  (connection-lifetime state + the budget lease + the audit chain handle), and it carries
  work as `WorkItem { InboundKind::Stream, EmitKind::Unsolicited }`.

**One-way-door flag:** the "session-open gauntlet + per-turn meter/audit against the lease"
split is the load-bearing contract, exactly analogous to the A2A task lifecycle (open →
transition* → settle) already shipping in `taskstore`. It must be designed against
`operation::run` (see `1.6.0-protocols-as-plugins.md` §10) so a duplex session is "one open
pass + N metered events," not a bypass of the gauntlet.

### 4.2 Component map (what to build)

```

        ▼

 │ busbar duplex plane (new)                                      │

 │            OR mint /realtime/client_secrets (JSON, gauntlet)   │
 │                                                                │

 │    - server→client event IR  (extend IrStreamEvent)           │

 │    - barge-in truncation bookkeeping (audio_end_ms)           │

 │                                                                │
 │  egress: persistent WS client to api.openai.com (NEW)          │

 │                                                                │

 │                                                                │

 │     side so the browser is never trusted)                     │
 └──────────────────────────────────────────────────────────────┘
```

### 4.3 Two topologies (both keep keys server-side)

- **Server-to-server WS bridge** — busbar terminates the client WS and holds a persistent
  upstream WS with the real key. busbar sees every event: full metering, guardrails, audit.
  This is the topology that fits the gauntlet cleanly.
- **Browser WebRTC** — busbar mints the ephemeral `client_secret` (a JSON POST that *is* a
  normal gauntlet pass) and brokers the SDP offer (`POST /v1/realtime/calls`,
  `application/sdp` — non-JSON body, preserve the `Location: /v1/realtime/calls/rtc_…`
  header). Audio then flows browser↔OpenAI peer-to-peer (busbar sees no media). To keep tools
  and instructions trustworthy, busbar attaches a **sideband control WSS keyed by the
  `rtc_<call_id>`** with the real key — tool execution and `session.update` locking run
  server-side; the browser can't override them. This is the "tools mid-call, safely" pattern
  and is a *second* long-lived socket the plane manages.

### 4.4 OpenAI Realtime specifics the plane must encode (target GA, not beta)

- **GA drops `OpenAI-Beta: realtime=v1`**, nests config under `session.audio.input/output.*`,
  uses object audio formats (`{"type":"audio/pcm","rate":24000}`), `output_modalities`, and
  renames events to `response.output_audio.delta` / `response.output_text.delta`. Beta
  tutorials will mislead — pin to `developers.openai.com` GA docs.
- **Event taxonomy:** client→server (`session.update`, `input_audio_buffer.append/commit/
  clear`, `conversation.item.create`, `conversation.item.truncate`, `response.create`,
  `response.cancel`); server→client (`session.created/updated`,
  `input_audio_buffer.speech_started/stopped`, `response.output_audio.delta`,
  `response.output_audio_transcript.delta`, `response.function_call_arguments.delta/done`,
  `response.done` with `usage`, `error`, `rate_limits.updated`).
- **Tools mid-call:** model streams `response.function_call_arguments.delta`→`done` (+ full
  item in `response.done`); return `conversation.item.create{function_call_output, call_id}`
  then `response.create`. `call_id` is the join key. A tool-call response often produces **no
  audio** until a result is fed back.
- **Barge-in bookkeeping (the subtle part):** on `input_audio_buffer.speech_started` the
  plane cancels the in-flight response and sends `conversation.item.truncate` with
  `audio_end_ms` = audio the user *actually heard*. On WebSocket **busbar must track playback
  position itself** (the server generates audio faster than realtime); on WebRTC the server
  truncates automatically.
- **VAD:** expose `server_vad` (threshold/`silence_duration_ms`) and `semantic_vad`
  (eagerness). Treat user-audio transcription as an **async side-channel** — never gate turns
  or tools on it.
- **Metering:** audio and text are **separate token classes** (audio dominates); read
  `response.done.usage` and `rate_limits.updated` per turn. Sessions cap ~60 min, 32k context.

### 4.5 Build-vs-adopt for the media plane

The event schema is the easy part; the **media plane is the real work** (mic capture, 24 kHz
resample, jitter-buffered playback, truncate-on-barge-in). Open-source orchestrators
(**Pipecat**, **LiveKit Agents**) already own that leg *behind* OpenAI Realtime, including
WebRTC/SFU + SIP telephony. **Decision to make before writing WebRTC code:** does busbar own
the media pump natively (maximal control, maximal net-new), or does it own the
mint + sideband-control + policy and let Pipecat/LiveKit own the browser+media leg
(dramatically less net-new)? Recommendation leans adopt-for-media, own-the-gauntlet — it
keeps busbar in its lane (the governed control/keys/routing layer) and off the treadmill of
audio-pipeline maintenance.

## 5. Reuse vs net-new

**Reusable today (assets):**
- The response-direction **event-relay** (`StreamTranslator` seam + `IrStreamEvent` +
  `StreamFraming` vtable) — property #2's response half, done.
- Same-dialect **byte-verbatim carriage** + multipart parser + `MediaBlob` — property #4's
  substrate, done.
- The A2A **`taskstore`** lifecycle/retention/rehydration/push engine — property #3's
  blueprint.
- MCP's `Session<W>` duplex loop — a proven pattern to copy for the pump.
- Reserved ABI: `WorkItem` duplex carrier tags, `SessionScope` slot, `PipeReadFn/PipeWriteFn`
  signatures, axum WS-upgrade foothold.

**Net-new (the actual runtime):**
- A substrate-owned **bidirectional event pump** (today only inside `busbar-mcp`, stdio-only).
- **`Transport::WebSocket`** variant *and* the missing Transport→listener/dialer dispatch
  seam (only consumer today is `upstream_wire` on MCP).
- WS **ingress-upgrade** acceptance wired to the pump + a populated `SessionScope`.
- A persistent-socket **egress WS client** (egress is reqwest one-shot today; host pipe fns
  are stubs).
- A **client→server event IR vocabulary** (current `IrStreamEvent` is response-shaped) and an
  **incremental audio-frame IR** (current `MediaBlob` is one-shot blob-in/blob-out).
- The **mid-call tool loop** (suspend/inject `function_call_output`/resume) and barge-in
  truncation bookkeeping.
- Session-lifecycle **budget lease + audit chain** semantics (open → meter* → settle) modeled
  on `taskstore`.

## 6. The translation-vs-fidelity tension (record it, don't paper over it)

busbar's identity is read→IR→translate. But byte-exact passthrough (property #4) and
translation are mutually exclusive by construction: the moment you translate a dialect you
cannot be byte-identical, and same-dialect fidelity is the only place cache-prefix hits,
thinking-signatures, and beta flags survive intact. Today this is handled honestly —
same-dialect is byte-verbatim, cross-dialect drops the untranslatable *loudly* with
`IR_DROP_*` diagnostics. The duplex design must carry the same doctrine: a Realtime session is
**effectively same-dialect passthrough** (nobody cross-translates a live OpenAI voice session
to Anthropic — Anthropic has no realtime surface at all), so the plane should lean on the
**verbatim event-relay** path, not a lossy cross-dialect IR, for the media/event stream. The
IR is for *metering and audit taps*, not for reshaping the wire — mirroring how same-proto
streaming already runs IR as a usage side-channel while re-emitting bytes verbatim.

**Independent defect to fix regardless of Realtime:** client beta/version **headers are
dropped on all paths** (§1.5). Any plane that wants header fidelity (Realtime's GA vs beta
selection, Anthropic betas) needs a header-forwarding seam. This is small and should land on
its own.

## 7. Phased build plan (each phase green on `integration/plane-extraction`)

Ordered lowest-risk first; each independently compilable/testable/committable; the
Protocols-as-Plugins composition gates + plane-purity stay green at every commit. **This
program depends on `1.6.0-protocols-as-plugins.md` R1 (`operation::run`) landing first** — a
duplex plane needs the one gauntlet to hang session-open off of.

### Phase 0 — header fidelity + small debts (independent)
- Add a **client-header forwarding seam** (allowlist incl. `anthropic-beta`, `OpenAI-Beta`,
  `anthropic-version`), egress + response side. Fixes §1.5 defect; unblocks GA/beta selection.
- **DoD:** a client beta header reaches upstream; golden asserts it; no cross-dialect leak.

### Phase 1 — the duplex transport primitive (`Transport::WebSocket`)
- Add the `Transport::WebSocket` variant + the missing **Transport→listener/dialer dispatch

## II.1 The gap is THREE orthogonal axes, not one "class"

Part I's §3 collapses every gap row into "four properties." That over-fuses. The rows in the §1.1
parity table actually break along **three independent axes**, and conflating them overstates the
transport work for rows that need none of it. Realtime is the only capability that needs all three at
once; that is exactly why it is the forcing function — but the fix for each axis is separable, ships
separately, and rides a *different* reserved seam.

| Axis | The invariant it breaks | Reserved seam it rides | Rows that need it |
|---|---|---|---|
| **A. Duplex transport** | one-request→one-response; no client→server frames after the initial body; connection is sub-timeout | `Transport` variant + a new **arrival kind** + `pipe_read`/`pipe_write` + `WorkItem{Stream,Unsolicited}` + `SessionScope` | Realtime, realtime transcription, Gemini Live |
| **B. Continuous governance** | the gauntlet runs **once** at admission; budget is charged **post-hoc**; audit is **one row per request** | `run_gauntlet` once at open **+** the hot vtable per frame (`meter_charge` / `govern_admit_reason` / `journal_append_scoped`) against `SessionScope` **+** the reserved `cost_reserve`/`cost_settle` lease | Realtime (mandatory); any long-lived session |
| **C. Stateful handles / async** | server holds no session; client replays history; no server-side handle, poller, or inbound push | `DurableScope` (park-at-`202`/resume) + `workhandle_open`/`resume` + the durable `journal_*_scoped` family — **already shipping for A2A** | stateful Responses, batch, background, Files API, **and** Realtime's session record |

**Consequences of separating them:**

- **Realtime = A + B + C.** It is the only row that forces all three, which is why it is the headline.
- **Batch / Files / stateful Responses / background = C only.** They are **request/response with a
  server-side handle** — they need *no duplex transport and no per-frame governance*. Part I's §3/§7
  lumps them into the "duplex class" (Phase 5, "on the same pump"); that is wrong-shaped. They ride
  the A2A `taskstore` / `DurableScope` engine that **already exists** (§1.6 is right that it is the
  blueprint — but it under-sells that for axis C it is nearly the *product*, not a blueprint to
  re-copy). None of them should wait on WebSocket.
- **Header fidelity (§1.5 / Phase 0) is a fourth, fully orthogonal defect.** It is neither duplex nor
  stateful nor session — it is "we rebuild the egress header map and never forward client betas." Part
  I already flags it as independent; Part II agrees and de-links it entirely from this program. It can
  land on its own on any release.

## II.2 The exhaustive gap set — which invariants break, verified against the tree

Grounded on the actual seams (paths verified this pass). Each item names the file that proves it.

**Axis A — duplex transport:**

1. **`Transport` has no duplex variant.** `crates/busbar-substrate/src/transport.rs` — the closed enum
   is `{ Http, JsonRpc, HttpJson, Grpc, Stdio }`. Every variant is **one-exchange** (even `Stdio` is
   framed as newline-delimited JSON-RPC request/response). *Correct in Part I.* Note the module's own
   doctrine: variants are **bought when a request drives them**, not guessed — so the fix is a variant
   *added by the realtime plane's first driven session*, not a speculative pre-add (see §II.5).
2. **Egress is one-shot.** `busbar-core::proxy` is a `reqwest` request/response pool; there is no
   persistent-socket client. The `pipe_read`/`pipe_write` **hot-vtable slots exist and are real
   host-wired** (used today by MCP stdio via `mcp/stdio_serve.rs`) — they are the byte-duplex egress
   primitive, keyed by a `PipeId`, host-moves-bytes / **plane-frames-on-top**. *This is a bigger asset
   than Part I credits* (see II.4 correction #1).
3. **Ingress is an axum request router.** The catch-all resolves an `Arrival` (the neutral
   `crates/busbar-substrate/src/ingress/arrival.rs` seam) and converges on the one gauntlet. There is
   **no WS upgrade acceptor** and no arrival kind that yields a long-lived socket instead of a
   `Response`. The "third axis is decided at the arrival" (`busbar-core/src/ingress/dispatch.rs:332`) —
   today it can only *say* `Http`, and the comment already anticipates that "the stdio and gRPC
   arrivals get their own entry points": **a duplex arrival is the same shape of add.**
4. **The client→server direction has no event vocabulary.** `IrStreamEvent` is response-shaped
   (`busbar-llm/src/proto_stream.rs`); `FirstByteBody` is a *response* `Stream`; the request is one
   whole `IrRequest`. *Correct in Part I.* This vocabulary is **plane-owned** and must stay so — core
   never learns `input_audio_buffer.append`.

**Axis B — continuous governance:**

5. **`run_gauntlet` is a once-through verify→drive→`Response`.**
   `crates/busbar-substrate/src/plane_host/mod.rs` — `run_gauntlet(req, plane)` calls
   `verify_destination` then `drive(...) -> axum::response::Response`. It models **one admission and
   one (possibly streaming) response**. A 20-minute session that is metered and audited per frame is
   **not** "one Response." *This is the single unary-shaped seam* — but it does **not** foreclose duplex
   (see II.4 correction #4 and II.5 decision D3): session-*open* is exactly one `run_gauntlet` pass, and
   per-frame governance rides the hot vtable, not the gauntlet return type.
6. **Budget is charged post-hoc, not leased.** The hot `meter_charge` slot *debits after the fact*.
   For realtime you must be able to **hard-stop mid-session** when a budget is exhausted (you cannot
   refund audio already streamed). The primitive for that — a **reserve-then-settle lease** — exists
   in core as `CostHold::reserve` / `settle_partial` (`crates/busbar-core/src/plane/cost.rs:304`) and
   is **deliberately reserved as an append-only hot-vtable extension**: `crates/busbar-plugin/src/hot/
   host.rs:533` and `hot/pod.rs:636` both say `cost_reserve`/`cost_settle` (a `CostHold`) is *"an
   append-only EXTENSION POINT for a future high-rate carrier."* **Part I misses this entirely** — it
   describes a net-new "budget lease" when the lease type ships today and the ABI already names the
   slot to expose it. This is the most important correction for the 1.6.0 ABI decision.
7. **Audit is one row per request.** The durable journal is hash-chained and per-record; a session
   needs a **chain of frames under one scope**. The seam for that already exists —
   `journal_append_scoped(kind_id, scope="session-<id>", suffix)` mints seq/prev_hash/hash under one
   `String` scope (`hot/host.rs:220`), restore/verify/compact included. A per-session audit chain is a
   **registered stream + a String scope**, not new journal machinery. *Part I's §1.6 gestures at this;
   Part II makes it precise: the audit primitive is done; only the plane's record shape is new.*

**Axis C — stateful handles / async:**

8. **No server-side handle/session store, poller, or inbound webhook receiver in the LLM plane.**
   *Correct in Part I.* But the engine exists: A2A's task lifecycle (`open → transition* → settle`,
   retention/GC, durable rehydration, inbound-push cursor) rides `DurableScope`
   (`crates/busbar-substrate/src/plane_host/scope.rs:376` — "the async plane parks a handle at a `202`
   and resumes it later by nested lookup") + the `workhandle_open`/`resume` slots + the durable
   `journal_*_scoped` family. Axis C for the LLM plane is **wiring this existing engine into a new
   plane**, not building a new one. The genuinely net-new piece (Part I is right here) is the **inbound
   webhook *receiver*** — busbar has outbound webhooks only (`export/webhook.rs`).

## II.3 The plane-faithful solution — how a duplex plane rides the one gauntlet

The design that keeps core plane-agnostic ("core moves duplex frames through the same gauntlet
primitives; it knows nothing about audio or voice"):

**Session-open is one gauntlet pass; per-frame governance is the hot vtable against `SessionScope`.**

```
WS upgrade arrival ──▶ run_gauntlet(open)                 [ONE pass: identity → verify_destination
   (a new substrate arrival kind,       │                  → govern_admit_reason (reserve opening
    NOT a plane-route escape hatch)      │                  budget) → journal open the session scope]
                                         ▼
                    SessionScope { pooled upstream socket (PipeId),
                                   CostHold lease, journal scope "session-<id>",
                                   correlation table call_id→response_id }
                                         │
         per client→server frame ──▶ pipe_read → plane frames event → govern check
                                     (govern_admit_reason per frame, cheap) →
                                     pipe_write to upstream
         per server→client frame ──▶ pipe_read upstream → plane frames →
                                     WorkItem{ emit: Unsolicited } to client →
                                     on response.done.usage:
                                        cost_settle(lease, exact)   [B: metered lease]
                                        journal_append_scoped(...)  [B: per-frame audit chain]
                                     if lease exhausted → hard close  [B: mid-session stop]
                                         │
                    connection close ──▶ SessionScope::Drop reclaims the lease + socket;
                                         journal seals the session record   [C: durable handle]
```

- **The core owns identity / destination-verify / budget-admit / audit — applied continuously.** Open
  runs stages 1–4/6 once via `run_gauntlet`. Each frame reaches the *same* host slots
  (`govern_admit_reason`, `meter_charge`/`cost_settle`, `journal_append_scoped`) — so a duplex session
  is **"one open pass + N metered/audited frames,"** never a gauntlet bypass. This is the exact
  contract Part I §4.1 states; Part II confirms it is *expressible on the shipped seams* with one
  ABI add (the reserve/settle slots).
- **The plane owns everything protocol-shaped.** The client↔server event IR, the audio-frame framing,
  barge-in truncation bookkeeping, `call_id` correlation, VAD config, the audio/text token-class split
  — all live in a **new plane crate** (`busbar-realtime`), never in core/substrate. Core moves opaque
  framed bytes over `pipe_read`/`pipe_write` and mints seq/hash for an opaque suffix. The grep-neutrality
  test (Part I §8.6) stays green because core names no realtime noun.
- **`LiveHostFactory` is the per-frame host handle.** `plane_host/mod.rs:214` — *"Handed to transports
  that re-mint per frame,"* already consumed by MCP stdio_serve. A duplex pump re-mints the host each
  frame so a mid-session config swap (a budget change, a key rotation) is seen. Part I does not name
  this; it is the mechanism that makes per-frame governance pick up live config.
- **Fidelity doctrine (Part I §6) is correct and load-bearing:** a Realtime session is effectively
  same-dialect passthrough (nobody cross-translates a live OpenAI voice session — Anthropic has no
  realtime surface). The pump runs the **verbatim byte relay** for media; the IR is a **metering/audit
  tap**, not a reshaper. This mirrors how same-proto streaming already runs IR as a usage side-channel.

**Two topologies (both keep keys server-side), unchanged from Part I §4.3 and endorsed:** the
server-to-server WS bridge fits the gauntlet cleanly and should ship first; browser WebRTC is the
ephemeral-`client_secret` mint (a normal JSON gauntlet pass) + SDP broker + a **sideband control WSS**
so tools/instructions stay server-authored. Part II adds one constraint: **the WS upgrade must be a
substrate *arrival*, not an `axum` upgrade returned from a `PlaneRouteFn`** (see correction #2).

## II.4 Where Part I is right, and where it is wrong

**Right (keep):** Realtime = transport not codec; the response-direction event-relay is the real asset;
the A2A `taskstore` is the axis-C blueprint; MCP's `Session<W>` is the pump pattern to port; the
translation-vs-fidelity tension and the verbatim-relay doctrine; the header-fidelity defect as
independent; the GA-vs-beta Realtime specifics (dropped `OpenAI-Beta`, `session.audio.*`, barge-in
`audio_end_ms` playback-position tracking, audio/text token classes, `call_id` join key); the
two topologies and keys-server-side framing; the build-vs-adopt-media recommendation (own the
gauntlet, adopt Pipecat/LiveKit for the media pump).

**Wrong or imprecise (corrected):**

1. **"the host `egress_write` is `unimplemented!(…stub)`" (§1.7) — misreads the STUB fixture for the
   live host.** `PlaneHostVtable::STUB` (`hot/host.rs:606`) is a *compile-surface fixture* whose every
   slot is `unimplemented!()` **on purpose** — it exists only to type-prove the signatures. The **live**
   host wires the real slots; `pipe_read`/`pipe_write` are genuinely functional today (MCP stdio uses
   them). The byte-duplex egress primitive is **not** a stub — it is shipping. This materially reduces
   the "net-new" column: the duplex *egress bytes* mostly exist; what is new is a *WebSocket*-framed
   `PipeId` driver and the ingress-upgrade acceptor.
2. **The "axum `WebSocketUpgrade::on_upgrade` foothold" (§1.7) is a trap, and Part I half-endorses it.**
   There is **no** WS code anywhere in the tree (verified: zero `WebSocketUpgrade`/`on_upgrade` uses).
   A `PlaneRouteFn` returns `axum::response::Response`, so one *could* return an upgrade — but that hands
   a raw socket to a plane closure that **bypasses `SessionScope`, the lease, and the audit chain**,
   i.e. it bypasses the gauntlet. That is an anti-pattern, not a foothold. Part II is unambiguous: the
   duplex socket enters through a **substrate arrival kind** that populates `SessionScope`, never
   through a route handler's return value.
3. **The "budget lease" is described as net-new (§4.1/§5); it ships today.** `CostHold::reserve` /
   `settle_partial` (`plane/cost.rs`) is the lease, and `cost_reserve`/`cost_settle` are the
   **already-reserved** hot-vtable extension point (`hot/host.rs:533`, `hot/pod.rs:636`). The net-new
   work is *exposing* the two slots and wiring the plane's per-frame settle — not inventing lease
   semantics. **This is the correction that most changes the 1.6.0 decision (§II.5-D2).**
4. **Fusing the four "properties" over-scopes the transport work.** Property #4 (opaque binary
   passthrough) is **orthogonal fidelity, already done same-dialect** — it is not a duplex requirement
   and should not sit in the duplex property set. Property #3 (stateful handles) is **axis C**, needs no
   duplex transport, and is *nearly built* for the LLM plane via `DurableScope` + the A2A engine — it
   should not wait behind WebSocket in a "Phase 5 fast-follow." Only properties #1 (transport) and the
   *request-half* of #2 (client→server events) are genuinely duplex-blocked.
5. **`run_gauntlet` returning one `Response` is called out as a risk but not resolved.** Resolution:
   it is **not** a foreclosure. `run_gauntlet` is a *free fn* and `GauntletPlane` is a *trait*; a
   session-oriented sibling entry (`run_gauntlet_session` / a `GauntletSession` impl that returns a
   `SessionScope` handle instead of a `Response`) is an **append-only add beside them**, and session-open
   itself is still exactly today's one pass. No existing seam reshapes.

## II.5 Scope: 1.6.0 vs later, and the ABI decisions to LOCK NOW

**Recommendation: the realtime/duplex plane is a 1.7.0 plane, NOT a 1.6.0 deliverable.** 1.6.0's thesis
is "protocols are plugins; add one, nothing else changes." Shipping a voice plane inside 1.6.0 would
(a) blow the release's scope, (b) drag in the media-pump build/adopt decision, and (c) mix a concrete
protocol into the release whose whole point is the *neutral seam*. The correct 1.6.0 outcome is the one
the ABI was visibly designed for: **prove the seam is duplex-ready and do not close it.** "VPN tomorrow
is one plugin"; realtime must be the same — a 1.7.0 crate on an unchanged core.

**But three things must be true of the 1.6.0 ABI or a duplex plane later becomes a re-architecture.**
These are the decisions to lock now, while the ABI is still open:

- **D1 — Freeze the `WorkItem` duplex carrier tags. (ALREADY LOCKED — keep the CI witness.)**
  `InboundKind::Stream` + `EmitKind::Unsolicited` (`hot/workitem.rs`) are the duplex carrier, and the
  module's tests assert the tags exist and that `WorkItem` can represent a duplex inbound+emit. **Do
  not** let any "simplification" collapse `WorkItem` to `(ptr,len)+sink` — the file's own header warns
  that would force a breaking reshape on the first exotic carrier. *Action: none but vigilance; keep
  the witness test in the release gate.*

- **D2 — Decide the metering lease extension NOW; add the two slots when the plane lands. (THE ONE
  REAL DECISION.)** `cost_reserve`/`cost_settle` are reserved but **not present** in `PlaneHostVtable`.
  For realtime's hard mid-session budget stop they are **mandatory** (post-hoc `meter_charge` cannot
  gate a stream you have already emitted). The 1.6.0 decision: **ratify the reservation and freeze the
  two signatures in this doc** (append-only trailing `Option` slots + an airlock MINOR bump), so the
  1.7.0 plane *adds* them rather than *reshaping* the vtable. Per the tree's own doctrine ("do not add
  a slot until a real carrier needs it"), do **not** ship the slots in 1.6.0 — but do **bless the shape**
  so the later add is mechanical. This is the only ABI item Part I would have let slip.

- **D3 — Keep `SessionScope` and the gauntlet append-only-open. (ALREADY LOCKED — keep it stub +
  `#[non_exhaustive]`.)** `SessionScope {}` (`scope.rs:366`) is an empty `#[non_exhaustive]` stub whose
  own doc says the riders that add a duplex plane wire it out; the per-connection state slot is then an
  append, never a reshape. Likewise `run_gauntlet`/`GauntletPlane` are a free fn + trait a session entry
  sits beside. *Action: none but vigilance; do not "tidy away" the dormant scope or make the gauntlet's
  one-`Response` return the only shape.*

Everything else a duplex plane needs is **already shipping and needs no 1.6.0 decision**: the byte-duplex
`pipe_read`/`pipe_write` slots, the per-session audit via `journal_append_scoped`, the per-frame host
re-mint via `LiveHostFactory`, the `DurableScope` park/resume engine, and the `OpShape::Subscribe`/
`Control` long-lived interaction shapes. The `Transport` variant is a *core* add the realtime plane
drives when its first session lands (transport is a substrate-owned axis by design, not a plane type),
so it needs no pre-reservation — only the doctrine of adding it on the commit that arms it.

**Net 1.6.0 action items:** (1) ratify + freeze the `cost_reserve`/`cost_settle` signatures in this doc
(**D2** — the only build-adjacent decision); (2) keep the D1/D3 witnesses in the release gate so the
reserved carriers cannot be "simplified" away; (3) optionally land the orthogonal **header-fidelity**
fix (Part I Phase 0) whenever convenient — it blocks GA/beta selection and is unrelated to everything
above. The realtime plane itself, both topologies, the media build/adopt call, and axis-C's LLM-plane
handle store all move to a **1.7.0 program** on this unchanged, duplex-ready seam.
