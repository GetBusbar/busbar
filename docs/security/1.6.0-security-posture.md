# 1.6.0 — Security Posture

**Status:** posture document: the security story, and the audited state of the code behind it.
**Audience:** enterprise security reviewers, technical diligence, and the Busbar maintainers who keep
these claims true.
**Scope:** the implemented trust boundaries and their mitigations live in
[`THREAT_MODEL.md`](../../THREAT_MODEL.md), which is authoritative; disclosure and backports live in
[`SECURITY.md`](../../SECURITY.md). This document groups those mitigations into the structural
defenses they add up to and states, for each, where it is strong, where it is **[PARTIAL]**, and what
is **[NOT BUILT]**. Every claim names the code or test that backs it.

**Citation freshness.** Every path below was re-resolved against the 1.6.0 `dev` tree on 2026-10-25.
The tree is a thin kernel (`busbar-kernel*`, `busbar-contract`, `busbar-core-connector`,
`busbar-core-admin`, `busbar-core-oauth2`), the in-tree LLM plane (`busbar-plane-llm`), the plugin
loader (`plugin-loader`) and the composition root (`busbar`). The MCP, A2A, decisions and streaming
planes, the transports, and the auth, store, secret, hook and export plugins are separate
repositories pinned in `Cargo.toml`; a citation into one of them names the plugin.

---

## 0. The reframe

Enterprise security is often sold as a rate: so many fixes a month, backports across many lines,
masking bolted onto every egress path. That is a treadmill against a stream of instances of the same
few classes: a secret in a log, a plugin reaching into the core, malformed input silently
corrupting a record, one tenant's blast radius hitting another.

Busbar's thesis is to shrink classes rather than chase instances: where a defense is a **type**, the
bug is hard to write; where it is a **test that runs on every change**, a regression cannot merge;
where neither is true yet, this document says so. A reviewer will check these claims, so the strong
ones are only credible if the partial ones are stated as loudly.

---

## 1. Threat model: actors and what each would try

The full boundary map is [`THREAT_MODEL.md`](../../THREAT_MODEL.md). By actor:

| Actor | Trust boundary | What they try |
|---|---|---|
| **Malicious caller** | client → data listener | Wrong-typed or smuggled bodies to cause silent loss or mis-routing; auth bypass (including timing); over-spend past budget; reach a pool, tool or agent they are not granted. |
| **Hostile upstream** | kernel → provider, tool server, agent | Redirect credential traffic to an internal address; return a body that escalates into Busbar; drain a pool via `Retry-After`; change a tool or agent definition after approval (rug-pull). |
| **Malicious or buggy plugin** | kernel ↔ plugin (native code, in process) | Crash the host across the ABI; reach state it was not granted; read a credential; open its own sockets. |
| **Insider reading logs, audits, admin reads** | operator surfaces | Recover a provider key, signing key or client secret from a log line, metric label, audit record, admin read or the store. |
| **Network attacker** | all sockets | SSRF and DNS rebinding through configured or request-derived URLs; reach the admin plane from the data port; downgrade TLS. |
| **Supply-chain attacker** | distribution | Swap a backdoored binary, image or plugin; replay an older signed plugin. |

## 2. Structural defenses (audited)

### 2.1 Edge validation: malformed input fails fast at the boundary

**Thesis:** a wrong-typed request body cannot cause silent loss; it is rejected with a 400 in the
ingress dialect's own error envelope, while Busbar stays as lenient as the provider on absent, empty
or unknown well-typed fields.

**Mechanism.** Each of the six LLM dialect readers (`crates/busbar-plane-llm/src/codec/<dialect>/reader.rs`)
returns the shared parse error (`ir_parse_error`, `crates/busbar-plane-llm/src/codec/dialect.rs`) on a
present but wrong-typed structural field. The reject is rendered as the dialect's invalid-request
envelope (`ingress_reject`, `crates/busbar-plane-llm/src/exchange/attempt.rs`; `KIND_INVALID_REQUEST`,
`crates/busbar-contract/src/protocol.rs`; Bedrock also sets `x-amzn-errortype`). Cross-protocol
requests reach the same reject before the egress dialect is considered. Six
`input_hardening_tests.rs` suites (5 to 10 tests each, under `crates/busbar-plane-llm/src/codec/*/tests/`)
pin both the reject and the leniency. JSON nesting is capped at depth 128.

**Verdict: STRONG on the thesis.**
- **[PARTIAL] No field path.** The 400 body is a fixed message, pinned by
  `crates/busbar-plane-llm/tests/exchange_attempt.rs`.
- **[PARTIAL] No dedicated reject metric.** Rejects show only as
  `busbar_requests_total{outcome="client_error"}` (`outcome_of`, `crates/busbar-kernel/src/telemetry.rs`).
- **[PARTIAL]** The rendered envelope is spot-checked for `openai` only.

### 2.2 Secrets as a type

**Thesis:** a secret is a type, not a bare `String`, so it does not drift into a log, audit record or
metric.

**Mechanism.**
- **`SecretRef`** (`crates/busbar-contract/src/secret_ref.rs`) is the config-layer reference: a
  module plus settings, never the value. Its deserializer refuses a bare inline literal and its error
  omits the value. An explicit `{ literal: … }` form exists for plugin settings
  (`resolve_settings`), so "an inline secret is unrepresentable" holds for `SecretRef` fields only.
- **`Secret<T>`** (`crates/busbar-contract/src/redacted.rs`) wraps resolved values: `Debug` and
  `Display` print `[REDACTED]`, it implements neither `Serialize` nor `Deserialize` (a compile-time
  fence), zeroizes on drop, exposes its value only through a kernel-minted seal, and compares in
  constant time. Provider credentials on the request path are `Secret<Vec<u8>>`
  (`crates/busbar/src/root/door_steps.rs`); the per-attempt input that carries them has a hand-written
  redacting `Debug` (`crates/busbar-kernel/src/plane_driver/route_input.rs`).
- Tests that run on every change hold the line: `a_secret_named_field_is_never_a_bare_string`,
  `an_exposed_secret_never_reaches_a_log_metric_or_audit_sink` and
  `no_struct_carries_a_raw_settings_bag` (`crates/busbar-contract/tests/source_rules/secrets.rs`).

**Verdict: [PARTIAL] — strong where adopted, not universal.**
- The kernel's resolver returns bare `Vec<u8>` / `String` (`crates/busbar-kernel/src/config/secret.rs`,
  `resolve`, `resolve_string`) before anyone wraps the value.
- Plugins receive their credentials as plaintext. Declared secret settings reach a plugin's `open`
  as bytes wiped after the call (`crates/plugin-loader/src/boot.rs`); a `{ env: }` or `{ file: }`
  reference at a setting the plugin did **not** declare secret is resolved into the plugin's settings
  as plaintext. A plugin that declares a credential kind can read plaintext credential secrets through
  the host's `records.secret` service (`crates/busbar-contract/src/abi/host/service.rs`,
  `crates/plugin-loader/src/dispatch/services.rs`).
- `CredentialSecret.secret` is a `String` with a hand-written redacting `Debug`, and recoverable
  credentials are stored as `v1:plain:<secret>` (`crates/busbar-contract/src/records.rs`,
  `crates/busbar-kernel/src/governance/state.rs`). It is explicitly allow-listed by the source rule
  above.
- **[NOT BUILT]** The credential chip (sealed `Cred`/`Seal` types, SDK auth recipes, refusal of
  references at undeclared fields, store weak-auth refusal, an at-rest key `credentials.at_rest`) is
  designed and in review; none of it is in this tree. See THREAT_MODEL T10.

### 2.3 The plugin boundary

**Thesis:** a buggy plugin cannot corrupt the host through the ABI, and a hostile one cannot get
loaded without passing the operator's trust policy.

**Mechanism.**
- **One ABI, one loader.** Every kind speaks a `repr(C)` memory ABI of slot tables with a size
  header (`crates/busbar-contract/src/abi/`); compiled-in and dropped-in plugins are loaded and
  validated by the same code (`crates/plugin-loader/src/dispatch/load.rs`): door magic, ABI version
  (exactly the host's; 1.5.5 JSON-contract plugins are refused), table slot count and size, and null
  slots are checked before any call. Every answer's size, text and arrays are validated, and a
  malformed answer is a fault (`crates/plugin-loader/src/dispatch/validate.rs`).
- **Host services are a numbered table** (`crates/busbar-contract/src/abi/host/service.rs`): clock,
  records, destination judgement, signing, verification, trust, randomness and so on. The host keeps
  key material: A2A card signing goes through the host `sign` service, so the plane holds no key.
  Host-side service slots run inside `catch_unwind` and answer a fault
  (`crates/plugin-loader/src/dispatch/services.rs`).
- **Sockets are host-owned.** Outbound connections go through the kernel's connector and its
  destination guard (`crates/busbar-core-connector/src/guard.rs`).
- **Trust policy for dropped-in plugins** (off by default, signed manifests, publisher allowlist,
  version floors, verified bytes staged in a sealed `memfd`): THREAT_MODEL T9,
  `crates/plugin-loader/src/sign.rs`, `crates/plugin-loader/src/stage.rs`.

**Verdict: [PARTIAL] — the ABI contract is strong; it is a contract, not a wall.**
- Slots are `extern "C"`. A plugin catches its own panics in the SDK's door trampolines
  (`crates/busbar-contract/src/abi/sdk/boundary.rs`); a panic that escapes a plugin built without the
  SDK aborts the process.
- Plugins run in Busbar's process. Native code can read process memory, the environment and files,
  and can open its own sockets; "plugins dial only through the connector" is enforced at build time
  for this project's plugins (a dependency gate), not at runtime. There is no plugin sandbox in 1.6.0.
- Compiled-in plugins are not signature-checked; they are first party by the builder's choice.

### 2.4 Plane neutrality: a plane defect's blast radius is bounded

**Thesis:** the kernel has no knowledge of any plane, and each plane is removable.

**Mechanism.** The kernel has no dependency on the LLM plane; `busbar-plane-llm` is an optional
dependency of the binary only (`crates/busbar/Cargo.toml`, feature `plane-llm`). The MCP and A2A
planes are optional kernel features. The `deletion-matrix` check, run on every change, builds the
kernel and contract with each plane and with none (`.ci/default.yaml`).

**Verdict: [PARTIAL].** The deletion matrix is the weak form of "independently removable": it proves
the kernel compiles without a plane, not that no source names one. The earlier source-scanning
purity gates were removed from this tree with the rest of the gate tooling.

### 2.5 Audit integrity: a tamper-evident record you can read back

**Thesis:** governance and admin mutations, tool calls and agent task provenance are written to a
hash-chained, signed record that can be verified later.

**Mechanism.** Records are hash-chained and each recomputed on verification
(`crates/busbar-kernel-audit/src/record.rs`, `verify_chain`, `verify_window`: digest, link and
sequence breaks are distinguished), and signed with the deployment keyset (Ed25519,
`verify_strict`, `crates/busbar-kernel-audit/src/sign.rs`); ledger checkpoints are signed in a
separate domain (`crates/busbar-kernel-ledger/src/checkpoint.rs`). Boot restores and re-verifies
each chain (`crates/busbar-kernel/src/boot.rs`, `crates/busbar-kernel/src/host_chains.rs`). An
external party can verify through `GET /api/v1/admin/verify` and the audit head, range and keys
endpoints (`crates/busbar-core-admin/src/verb.rs`). Format:
[audit-chain digest v4](../audit-chain-digest-v4.md).

**Verdict: STRONG mechanism, two [PARTIAL]s.**
- **Evidence, not prevention.** The signing key is minted on first boot and kept in the same store
  as the chain (`crates/busbar/src/root/keyset.rs`), and the chain is its own anchor; someone who
  holds the store and the key can re-sign history.
- **Reads are not verified.** `GET /api/v1/admin/audit` serves its ring without recomputing
  (`crates/busbar-core-admin/src/v1/json/handlers.rs`). Verification is at boot and on demand.
- "No secrets in the record" is field selection (records carry digests such as a tool digest, not
  arguments), not type enforcement.

### 2.6 Governance and authorization

**Thesis:** every request is authenticated, authorized, destination-checked and budget-admitted in
order, before any charge.

**Mechanism.** The ordered request steps are in `crates/busbar/src/root/door_steps.rs`.
1. **Authentication** fails closed (`crates/busbar-kernel-identity/src/chain.rs`;
   `crates/busbar-kernel/src/auth/mod.rs`, including a panic in an auth step). Virtual keys are
   Ed25519-signed tokens checked for signature, expiry, revocation and generation
   (`crates/busbar-kernel/src/governance/signing.rs`, `governance/state.rs`, `verify_token`). Digest
   comparison is constant-time (`constant_time_eq`, `crates/busbar-contract/src/redacted.rs`).
2. **RBAC.** Principal roles resolve through `role_bindings` into an enforcement key on the request
   path (`resolve_data_plane_identity`, `crates/busbar-kernel/src/auth/mod.rs`); a principal whose
   roles grant nothing is refused (`NoGrant`). A roleless principal, or one under a module with no
   bindings table, is admitted keyless as in 1.5.5.
3. **Destination authorization.** Pool scope (`VirtualKey::scope_allowed`,
   `crates/busbar-contract/src/records.rs`) is checked for the pool and every reachable fallback, with
   a cycle guard, and an unpriced model is refused (`door_steps.rs`).
4. **Budget admission.** Spend is derived from metered usage times the rate card and checked against
   the cap under the same held locks as the charge (`GovState::try_admit_estimated`,
   `crates/busbar-kernel/src/governance/state.rs`).

**Verdict: STRONG, with stated limits.** Under the default `admission: exact`, the estimate is not
reserved, so concurrent in-flight requests can each overshoot a cap by up to one request (more for
streams without `cut-stream`); token-per-minute caps are best-effort for the same reason. A
config with no `auth:` block runs an open relay for the LLM plane, bannered at every boot.

## 3. The thesis, mapped

| Vulnerability class | Busbar mechanism | Held by |
|---|---|---|
| **Secret leaked into a log, audit or metric** | `Secret<T>` and `SecretRef` (§2.2) | the type's trait bounds; `source_rules/secrets.rs` tests on every change. **[PARTIAL]** plugins and the store still see plaintext; the chip is **[NOT BUILT]** |
| **Plugin escapes into the core** | one validated `repr(C)` ABI, host-owned keys and sockets, signed dropped-in plugins (§2.3) | load-time validation; signature policy. **[PARTIAL]** in-process, no sandbox |
| **Silent loss from malformed input** | edge validation in six dialects (§2.1) | six `input_hardening_tests.rs` suites; the behavioural oracle against 1.5.5 |
| **One plane's defect reaches everyone** | kernel with no plane dependency (§2.4) | `deletion-matrix` on every change. **[PARTIAL]** |
| **Auth bypass, over-spend, mis-route** | ordered, fail-closed request steps (§2.6) | governance and auth test suites |
| **Tampered audit** | hash-chained, signed records (§2.5) | verification at boot and on demand. **[PARTIAL]** not on read |
| **Tool or agent rug-pull** | verify-on-call against the kernel's trust book ([tool and agent trust](../tool-and-agent-trust.md)) | trust book and plane tests |
| **Backdoored artifact, replayed plugin** | signed plugin manifests, embedded release key, version floors; SLSA provenance per `dev` commit | `sign.rs` tests. **[NOT BUILT]** the 1.6.0 release publication step (`.ci/qa.yaml`) |

## 4. Process commitments

### 4.1 A documented security model — **in place**
[`THREAT_MODEL.md`](../../THREAT_MODEL.md), [`SECURITY.md`](../../SECURITY.md) (private reporting,
48-hour acknowledgement, GitHub Security Advisories with CVEs, safe harbor, named security contact,
backport policy) and this document.

### 4.2 Checks on every change — **in place, with a gap**
Every change into `dev` is judged by ModernCI against `.ci/default.yaml`: preflight, clippy with
warnings denied, compile, tests, doctests, the deletion matrix, `cargo deny` (advisories, licenses,
sources, bans) and the feature-gated suites, including the loom concurrency model. Security
properties formerly held by separate gate scripts now live as ordinary tests, chiefly
`crates/busbar-contract/tests/source_rules/` (secrets, money, config).

**[GAP]** The gate tooling (`xtask`) was removed from this tree, but the `preflight` and `gates`
checks in `.ci/default.yaml` and several checks in `.ci/dev.yaml` (the `dev` → `qa` move) still
invoke it, so those checks cannot pass until they are rewritten. cargo-vet is initialised (`supply-chain/`) but no check runs it. One fuzz
target exists (`fuzz/`) and nothing runs it. There is no CodeQL or cargo-audit job.

### 4.3 Responsible disclosure and bug bounty — **disclosure in place; no paid bounty**
Private reporting, coordinated disclosure, advisories with CVEs, credit, and a published safe harbor
are in [`SECURITY.md`](../../SECURITY.md). **[ROADMAP]** a hall of fame, then a funded bounty.

### 4.4 Security ownership — **named; bus factor 1**
The maintainer, Matthew Jackson, owns the disclosure queue and the policy (`SECURITY.md`). Broadening
ownership is a growth item.

### 4.5 Backport policy — **published**
Fix on `dev` first with a regression test; Critical and High fixes are backported to the latest two
minor lines with an advisory, a CVE and a `CHANGELOG` `Security` entry (`SECURITY.md`).

## 5. Gaps (the honest list)

1. **Credential custody (§2.2, THREAT_MODEL T10).** Plugins receive plaintext credentials;
   references at undeclared plugin fields resolve to plaintext; recoverable credentials are stored as
   plaintext; no store refuses a weaker auth method than its server offers. The chip that addresses
   these is designed and **[NOT BUILT]** in this tree.
2. **Plugins run in process (§2.3).** No sandbox; a malicious plugin can read memory and open
   sockets. Accepted for 1.6.0; the controls are T9's load policy.
3. **Release publication (§3).** `.ci/qa.yaml` is not written, so this tree does not yet produce
   signed, attested release artifacts.
4. **CI references removed tooling (§4.2).**
5. **Hook rewrites fail open.** A request-stage rewrite that cannot be applied is dropped and the
   original body is sent (`crates/busbar-plane-llm/src/exchange/project.rs`, `apply_rewrite`).
6. **OAuth2 consent on the data listener.** The authorization server's consent screen requires an
   admin credential but is mounted on the data listener (`crates/busbar-core-oauth2/src/routes.rs`),
   outside the admin listener's mTLS requirement.
7. **Audit reads are not verified (§2.5),** and the chain's signing key lives in the store it signs.
8. **Edge validation** has no field path and no dedicated metric (§2.1).
9. **Documented foot-guns remain** (`admin_require_mtls: false`, an empty auth chain,
   `security.allow_all_metadata`, `allow_unsigned`, `allow_third_party`), behind explicit settings
   and boot warnings.

## 6. The security story, in one page

**We compete on structure, not on patch velocity.**

1. **Secrets are a type where Busbar holds them.** `Secret<T>` cannot be serialized and prints
   `[REDACTED]`; `SecretRef` keeps inline secrets out of config. Plugins and the store still see
   plaintext in 1.6.0 (gap 1).
2. **Plugins cross one validated ABI and a signature policy.** Dropped-in plugins are off by
   default, signature-checked against an embedded key, floored against replay, and loaded from the
   exact bytes verified. In-process native code is trusted once loaded (gap 2).
3. **Malformed input fails fast** in the caller's own dialect, uniformly across six protocols, and
   1.6.0 is compared cell by cell against the published 1.5.5 binary.
4. **Every outbound connection is judged.** One connector dials every destination, after checking
   the name and every address it resolved to, so SSRF and DNS rebinding are refused in one place.
5. **Tools and agents are verified on call** against the definition an operator approved, and a
   changed one is quarantined.

Backing these: fail-closed authentication, RBAC, destination authorization and budget admission in
order before any charge, and a hash-chained, signed audit record. The gaps in §5 are listed because a
claim a reviewer can verify is worth more than one they have to trust.
