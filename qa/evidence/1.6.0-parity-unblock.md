# 1.6.0 — PARITY, UNBLOCKED: what was actually blocking it, what now refuses, and what it measured

**Subject:** group 14 of `scripts/verify-1.6.0-done.sh` — `PARITY`, the shadow oracle, this build
against the **published 1.5.5 binary**. The only instrument in the release whose baseline was fixed
32 days before the work began and cannot be moved by the people being measured.

**Nothing in this document blessed, recorded, repointed or re-recorded anything.** No golden was
written. `accepted-differences.json` and `accepted-gaps.json` are untouched. Every divergence below
is a **PARK** for the owner. All eleven bless/repoint variables and every `BUSBAR_ORACLE_*` were
verified empty before any command ran, and the only flag added to the instrument — `--strict` — can
make it fail, never pass.

---

## 0. THE ANSWER, IN FIVE LINES

1. **The blocker named in the denominator audit is not on disk and has not returned.**
   `target/release/busbar` is a **regular file**, not a symlink. The symlink was real; it is gone.
2. **Three different blockers are live, and all three are the same defect class.** The verdict was
   read from an exit code that **cannot fail**; the golden was trusted **without identification**;
   the subject was a **relative path** the build does not control.
3. **The recurrence question has a sharper answer than "yes".** The symlink did not come back. The
   *class* did — in three disguises the symlink guard would not have caught either. **The missing
   thing was never a symlink check. It was that nothing anywhere asserted what had been measured.**
4. **The instrument now refuses.** Sixteen planted refusals, each with an accepted twin, all green.
5. **A real external measurement exists and is reproduced here: 913 owed cells compared, 905 PASS,
   8 FAIL.** It is a measurement of a **2026-09-22 21:34 build of this branch**, not of HEAD, and
   this document says so everywhere it says the number.

## 2. THE THREE LIVE BLOCKERS

### BLOCKER 1 — THE VERDICT WAS READ FROM AN EXIT CODE THAT CANNOT FAIL

The group scored itself with:

```sh
step "replay: candidate vs golden" ./bin/oracle replay --golden "$GOLDEN" --candidate "$CAND" --out …
```

`step` treats exit 0 as pass. `./bin/oracle replay` dispatches to `busbar-oracle diff`, whose
return code is computed in the pinned engine at `run.rs:2511`:

```rust
let mut rc = 0;
if opts.strict {
    if owed.is_empty()        { … rc = 1; }        // nothing was compared
    else if diverging_total>0 { … rc = 1; }        // unaccepted divergences
}
Ok(DiffOutcome { rc, rows, stderr })
```

**`rc` is zero unless `--strict` is passed, and the group does not pass it.** Measured on this
tree, read-only, against the recording pair already on disk:

| invocation | exit | what it reported |
|---|---|---|
| `replay … ` (as the group calls it) | **0** | 8 unaccepted divergences — and a green |
| `replay … --strict` | **1** | `diff-cells: strict: 8 unaccepted divergence(s)` |
| `replay … --id-filter 'zzz-no-such-cell'` | **0** | `owed 0 · diverging 0` — **a perfect report about nothing** |
| `replay … --id-filter 'zzz-no-such-cell' --strict` | **1** | `strict: no owed cells matched the filter — nothing was compared` |

**Row three is the false zero, reproduced.** A run that compared **zero** cells writes a report
whose `totals.diverging` is `0` and exits `0`. To any caller reading the exit status — which is
exactly what `step` does — it is indistinguishable from a flawless parity proof.

`--strict` is not a loosening flag and is not new: the sibling `manual-keep-proof.yml` has passed it
since it was written, and names it in its own step title. **The group whose entire claim is the
comparison is the one place it was missing.**

**Collateral, NOT changed here — PARK-CI.** `.github/workflows/ci.yml:3206` and
`.github/workflows/oracle-proof.yml:234` call the same `replay` without `--strict`, under step
titles that say *"(0 divergences, gaps named)"*. **Those jobs are green on divergence today.** The
repair is the same word. It is left to the owner deliberately: arming it turns a per-push CI gate
red for every agent on the tree at a moment when the build is already red, and that is a release
decision, not an unattended one.

### BLOCKER 2 — THE BASELINE WAS TRUSTED WITHOUT IDENTIFICATION

```sh
if [ ! -s "$GOLDEN/ledger.tsv" ]; then
  step "record the golden (1.5.5)" ./bin/oracle record --bin "$HOME/.cache/busbar-oracle/1.5.5/busbar" …
fi
```

The golden is re-recorded **only when the directory is empty** — so on every machine that has run
this once, the baseline is *whatever recording is sitting in `target/`*, accepted sight unseen.
Nothing read its `meta.json`.

This is live right now: **`$HOME/.cache/busbar-oracle` has been deleted from this machine.** The
published 1.5.5 binary the re-record arm reads is not present, so any run here takes the reuse arm
by necessity — the unchecked one.

The recording survives, and it turns out to be provable:

```
golden meta.json binary_sha256 = 48e2800cc1fbf229104d73c23039ba4d4a703c0a8db9e7872e22fec33f9b1e48
testing/shadow-oracle/golden-digests.tsv:
  1.5.5   busbar-aarch64-apple-darwin   48e2800cc1fbf229104d73c23039ba4d4a703c0a8db9e7872e22fec33f9b1e48
```

**The baseline is the published 1.5.5 darwin artefact, by a digest this repository commits.** That
was true before this work and nothing in the tree checked it. It does now.

**Two baselines exist and they are not the same recording.** `testing/shadow-oracle/golden/1.5.5`
— the committed golden, 916 PASS rows — was recorded from `84bde0a0…`, the **x86_64-linux** 1.5.5
binary. A local run on this host re-records from `48e2800c…`, the **aarch64-darwin** 1.5.5 binary,
and gets **913**. The three-cell difference is exact and named:

```
plugins.store-persist|store-mysql       PASS (committed)  →  SKIP (here)
plugins.store-persist|store-postgres    PASS (committed)  →  SKIP (here)
plugins.store-persist|store-valkey      PASS (committed)  →  SKIP (here)
   "named gap: the fixture this cell needs is not in the tree yet"
```

Three durable-store cells this laptop has no fixtures for. They degrade to a **named gap**, never to
a silent pass — the recorder behaves correctly. But it means **a local PARITY denominator is 913,
not the 916 the corpus documents quote**, and a reader comparing the two numbers without this
paragraph would be comparing different baselines on different hosts.

### BLOCKER 3 — THE SUBJECT WAS A RELATIVE PATH THE BUILD DOES NOT CONTROL

```sh
step "cargo build -p busbar --release --locked"   cargo build -p busbar --release --locked
step "record the candidate (target/release/busbar)" ./bin/oracle record --bin target/release/busbar …
```

Those two lines name the same file **only when cargo's output directory is `./target`**.
`CARGO_TARGET_DIR`, `CARGO_BUILD_TARGET_DIR`, or a `[build] target-dir` in any `.cargo/config.toml`
above the checkout sends the build elsewhere while the recorder still opens the literal path. That
is the mechanism the symlink exploited, and the symlink is only one of its shapes: **any** file at
that path is taken as the subject, and the divergence count is then published as a statement about
this tree.

And there was a second, independent hole underneath it: **the recorder stamps the binary it executed
into the recording's own `meta.json` as `binary_sha256`, and nothing ever read it.** Even a correct
`--bin` argument proved nothing about the bytes behind it.

Two further consequences, both true today:

- **`step` is fail-soft by design.** A failed release build marks the group red and **the record step
  still runs**, recording whatever binary is lying at the path. The group's red says "build failed";
  the report it goes on to write says nothing about that at all.
- **The binary carries no provenance.** `./target/release/busbar --version` prints
  `busbar 1.6.0` and a profile line, and **no commit**. Identity (a digest) is recoverable; *origin*
  (which tree) is not. Every guard below pins identity; **nothing can pin origin after the fact**,
  which is why the build has to name its own artefact at the moment it produces it.

## 3. THE GUARD — WHAT NOW REFUSES, AND HOW IT WAS FALSIFIED

All in `scripts/verify-1.6.0-done.sh`. The shape follows the file's existing house rule: **each
refusal is a named function, driven by the group and planted by `--selftest`, with an accepted twin
beside it** — so a guard that always refuses fails its twin and a guard that never refuses fails its
plant.

| function | refuses when | why it exists |
|---|---|---|
| `parity_build_and_resolve` | the release build fails, **or succeeds and names no artefact** | takes the subject's path **from cargo** (`--message-format=json-render-diagnostics` → `"executable":"<path>"`), never from a literal. Cargo emits it on a no-op build too, so the artefact of *this* invocation in *this* tree is a fact the build states. Returns non-zero, so the record is unreachable from a failed build. `bin/oracle::resolve_bin` already resolves the **judge** this way; this resolves the **subject** the same way |
| `assert_candidate_bin_sane` | the path is **a symlink** (naming its target), is missing, is not a regular file, is not executable, or is empty | the explicit refusal for the shape that already got a foreign build in front of this instrument once |
| `assert_recorded_subject` | the recording's `meta.json` `binary_sha256` ≠ the digest taken of the resolved artefact **before** the record | closes the same hole from the far side, independently of how the path was chosen. Would have caught the symlink with the old hard-coded path still in place |
| `assert_golden_is_pinned` | the golden's `binary_sha256` is not a digest this repo commits in `golden-digests.tsv` for the baseline version | a baseline nobody can identify is not an external baseline |
| `assert_parity_verdict` | `totals.owed == 0`, **or** `totals.diverging != 0`, or the report is unreadable | the verdict comes from the report the differ wrote, not from an exit code — so the claim does not rest on one flag in one pinned engine |
| `--strict` on the replay | (upstream) divergences, or an empty owed set | makes the engine's own rc mean what the step label says |

Plus one refusal outside PARITY: **TELLER-STEPS** takes the literal `target/release/busbar` in its
`elif [ ! -x … ]` arm, and `-x` follows a symlink. A new arm ahead of it refuses a link by name
rather than judging whatever tree it points at.

`PARITY_BASELINE_VERSION=1.5.5` is a plain assignment, **not** `${…:-1.5.5}`: a variable an operator
can set is one more way to choose what this group compares against.

### 3.1 The falsification — `bash scripts/verify-1.6.0-done.sh --selftest`

Hermetic (temp-dir fixtures, no build, no network, seconds). **All sixteen green; the whole selftest
exits 0.**

```
  [ok]     a real, unlinked, executable artefact is the subject
  [ok]     a SYMLINK standing where the candidate binary should be -> REFUSED
  [ok]     a candidate path that does not exist -> REFUSED
  [ok]     a build that named no artefact at all -> REFUSED
  [ok]     a candidate that is not executable -> REFUSED
  [ok]     a recording that names the binary this run built
  [ok]     a recording that names a DIFFERENT binary -> REFUSED
  [ok]     a recording that names no binary at all -> REFUSED
  [ok]     a subject with no digest to compare against -> REFUSED
  [ok]     a golden whose digest this repository commits
  [ok]     a golden whose digest this repository does not commit -> REFUSED
  [ok]     a golden checked against a digest table that is not there -> REFUSED
  [ok]     a report with cells compared and none diverging
  [ok]     a report carrying unaccepted divergences -> REFUSED
  [ok]     a report that compared ZERO cells (the zero that is not one) -> REFUSED
  [ok]     no report at all -> REFUSED
```

### 3.2 The same guards, against the real artefacts on disk

Fixtures prove the rule; the tree proves it bites.

```
assert_golden_is_pinned  target/oracle/recordings/golden …
  → rc 0   "golden binary sha256 48e2800c… is pinned in golden-digests.tsv for 1.5.5"
assert_recorded_subject  target/oracle/recordings/candidate  $(sha256 target/release/busbar)
  → rc 0

  → rc 1   "compared 913 owed cell(s) of a 2318-cell corpus: 8 diverging, 289 accepted, 1405 unbaselined"

assert_parity_verdict    <the null-filter report, whose totals.diverging is 0>
  → rc 1   "the replay compared ZERO cells. A run that measured nothing and a run that found
            nothing print the same zero; this one measured nothing — refusing"
```

The last line is the point of the whole exercise: **a report whose `diverging` is `0` is refused,
because its `owed` is `0`.**

## 4. WHAT WAS MEASURED — AND WHAT IT IS A MEASUREMENT OF

### 4.1 What was run, and why a HEAD run was not

A full PARITY at HEAD was **not** run, and no number below is claimed to be about HEAD. The reasons
are named rather than summarised:

1. **The workspace build is red** (a trait-sealing change against the workspace test seals; another
   agent owns it).
2. **The checkout is not HEAD.** `git status --porcelain` → **85 modified files**, across
   `crates/busbar-mcp`, `crates/busbar-kernel-ledger`, `crates/busbar-core-admin`, `xtask/src/gates`
   and more, from ~20 agents working concurrently. A candidate recorded here would be a recording of
   a tree that exists in no commit and will never exist again.
3. **The machine cannot honestly host it.** Load average 55–77, ~40 `rustc` and ~50 `cargo` live. A
   release build in the shared `target/` takes cargo's build-directory lock and stalls every one of
   them; a cold release build in a scratch worktree competes with the agents fixing the red build.
4. **The baseline binary is not on the machine** (§Blocker 2) — a re-record is unavailable offline.

`cargo metadata --locked --offline` **does** resolve (rc 0), so the lockfile is not a blocker; the
four above are.

### 4.2 What WAS run: a strict re-diff of the recording pair on disk — read-only

Both recordings were taken on 2026-09-22 (golden 21:45, candidate 21:56) under one harness revision.
The differ was re-run over them **with `--strict` and nothing else changed**, into a fresh output
directory under `/tmp`. Nothing was recorded and nothing was written into the tree.

**Provenance, so the zero is controlled:**

| | |
|---|---|
| golden binary | `48e2800cc1fbf229104d73c23039ba4d4a703c0a8db9e7872e22fec33f9b1e48` — **pinned** in `golden-digests.tsv` as `1.5.5 / busbar-aarch64-apple-darwin` |
| candidate binary | `9717f7d3ba16b90782ee3bd0e15c10b7f8df068360c2f4b0b7d6fd510ba7d35a` — `target/release/busbar`, mtime **2026-09-22 21:34:17**, a release build of this branch **from a tree that is not HEAD and cannot now be identified** (the binary stamps no commit) |
| harness rev | `1d3efdedd5b85a187d734c8bbb0bfd1d6523146c4e2d13e215cb987cc08a3bc9`, identical on both sides — the same-revision guard was armed, not waived |
| corpus | `testing/shadow-oracle/cells.json`, 2,318 cells |
| register | `testing/shadow-oracle/accepted-differences.json`, 41 entries, **unmodified** |
| totals | **byte-identical** to the 2026-09-22 report on disk — the re-diff reproduces it exactly |

**The arithmetic, which must close and does:**

```
1405 UNBASELINED  +  905 PASS  +  8 FAIL  =  2318 rows      (the whole corpus, one row each)
                     905 PASS  +  8 FAIL  =   913 owed
```

**913 cells compared. 905 byte-identical to published 1.5.5. 8 unaccepted divergences. 289 further
divergences forgiven by the owner's register. 1,405 cells with no 1.5.5 recording at all.**

**This is a real external result and it is not zero.** It is also not a result about HEAD. Whoever
re-takes it at HEAD, with the guard now in place, will get a number that *is* — and if the
instrument cannot prove its subject, it will refuse instead of printing one.

## 5. THE EIGHT — PARKED, NOT ADJUDICATED

**Every one is owed** (each id is present in `owed-baseline.txt`). **None is approved here.** Money
is binary and is never self-approved; the register is never edited by an agent.

### PARK-P1 · `billing|rate-card|history-mid-window` — **MONEY. OWNER ONLY.**

*classes:* `body`, `effects.script` · *weight 10*

```
/spend_after_a                 golden  25,000,000  →  candidate   2,500,000
/spend_after_b                 golden 500,060,000  →  candidate  27,500,000
/spend_final                   golden 750,090,000  →  candidate 277,530,000
  (same figures repeated under usage_after_a/b and usage_final, by_key / by_model / total)
```

**Root cause — two candidates, and this document does not choose between them.**
(a) The owner's register **already accepts this cell's money change**: entry **`D-3 …dated
rate-card history`**, `kind: breaking`, with a CHANGELOG line, scoped to exactly this id. Its
`classes` are `["effects.usage","body"]`. The divergence also lands in **`effects.script`** — a
class `D-3` never named — **so the cell fails on a class gap, not on an unapproved change.**
(b) The cell declares **no `clock` pin** (`"clock": null` in `cells.json`), and the pinned engine's
own note records that the clock fields stopped normalising precisely because an unpinned rate-card
epoch over an unpinned billing window could compare equal when it should not. The two recordings
were taken **11 minutes apart**. On a cell named *history-mid-window*, that is a live alternative
explanation for the magnitudes.

**Recommendation (owner):** pin the clock on this cell and re-take — that settles (b) outright. If
the figures survive, extend `D-3`'s `classes` to name `effects.script`, or split the class.
**Neither action is an agent's to take.**

### PARK-P2 · `ledger|amend|adjusting-entries` · PARK-P3 · `ledger|amend|refused-unsigned`

*classes:* `status`, `headers`, `body` · a **ledger** path

```
status            404  →  403
/error/code       "not_found"          →  "forbidden"
/error/message    "resource not found" →  "insufficient scope: this endpoint requires `full`"
content-length    61 → 92
```

**Root cause.** The register's entry **`D-4 …the signed amend verb`** (`kind: improvement`) accepts
`["body","headers"]` on `^(ledger\|(amend|currency)\|…)`. It does **not** name `status`, so the
status change is unforgiven and the cells fail. The change itself is consistent with the scope fix
landed on 2026-09-22 (`9e8dea58b`, "enabling key authentication granted every caller full admin
scope"): the endpoint now refuses on scope **before** the resource lookup.

**Why this cannot be waived as an improvement.** The register's own differ refuses an entry that
accepts `status` without `kind: breaking` **and** a `changelog` line. **This is a user-visible
contract change on a ledger path** and 404→403 moves in both directions at once — it is a tighter
authorization check, and it also reveals the existence of an endpoint that 1.5.5 hid.
**Recommendation (owner):** rule on it; if accepted, it needs a breaking entry and a CHANGELOG line.

### PARK-P4 · `admin.ops|GetAudit|ok` · PARK-P5 · `teller|audit-record`

*classes:* `body` / `effects.script`

```
/items/{0,1,2,3}/scheme        golden null  →  candidate 2
/audit_after/items/0/scheme    golden null  →  candidate 2
/newest_entry/scheme           golden null  →  candidate 2
```

A new populated field on the **audit record**, on two independent surfaces (the admin read and the
Teller's captured side effect). **No register entry covers `admin.ops|GetAudit|ok` at all.** The
audit record is evidence-bearing, so a field that changes from `null` to a value is a contract
change a consumer can see. **Recommendation (owner):** if intended, one additive entry covering both
cells, with the CHANGELOG line the register requires.

### PARK-P6 · `boot.refusal|BOOT-181|boot`

*classes:* `body`, `effects.stderr`

```
body line 3      golden ''  →  candidate "<TS>  WARN the root's listener slots were not
                                provisioned: TLS cert contains no certificates (expected a PEM

stderr line 19   "[error] TLS configuration error for '127.0.0.1:<PORT>': TLS configuration error
```

Two things, and the second is a defect in its own right: an extra WARN line on stdout, **and the

### PARK-P7 · `neutrality|NEUT-U-auth|validate`

*class:* `effects.stderr`

```
… auth: unknown field `bogus_key`, expected one of `signing_key`, `chain`, …          (1.5.5)
… auth: unknown field `bogus_key`, expected one of `signing_key`, `operator_pub`, …   (this build)
```

An additive config field surfacing in a diagnostic's expected-field list. Lowest severity of the
eight. `D-1 diagnostic codes` matches the family but only transforms the `BUSBAR-nnnn` prefix, so
the residual text is correctly unforgiven. **Recommendation:** accept as additive, or normalise the
field list in the cell.

### PARK-P8 · `boot.refusal|BOOT-135|boot`

*class:* `effects.stderr`

```

… cannot read manifest member: incomplete deflate stream     (this build)
```

**Almost certainly a dependency's error text, not busbar's** — a decompression crate's message
changed between releases. **Recommendation:** confirm the origin; if it is a dependency, the cell
should normalise the tail of that line rather than the register forgiving it, so the *next* change
in that message is still caught.

## 6. THE SCOPE SENTENCE — WHAT A GREEN PARITY PROVES, AND WHAT IT DOES NOT

Put beside every green, always, in the exact words the run itself now prints
(`compared N owed cell(s) of a 2318-cell corpus`):

> **A green PARITY proves that one LLM-only deployment of this binary replays the recorded 1.5.5
> requests byte-for-byte. It proves nothing about four of the five planes.**

Unpacked, from `1.6.0-oracle-coverage-sweep.md` and confirmed against this run's own report:

- **916 owed cells of a 2,318-cell corpus** — **1,405 cells (61%) have no 1.5.5 recording at all.**
  They are reported `UNBASELINED`, never `PASS`; the report says so itself: *"a green run says
  nothing about them."*
- **On this host the owed set is 913, not 916** — three `plugins.store-persist` cells have no local
  fixture (§Blocker 2). A run's denominator is whatever its own report states.
- **Per plane: `mcp` 0 PASS / 912 SKIP. `a2a` 0 / 468.** `streaming` and `decision` are **not planes
  in the corpus at all.** Core 776/13, llm 140/9. **The MCP and A2A planes are proven by their
  conformance rigs or not at all; PARITY does not see them.**
- **545 of the 916 owed cells (59.5%) are pre-authorised to differ** by the register — **437 under a
  single class-less entry.** A green includes 289 forgiven divergences in this very run.
- **94 of the 916 owed cells assert a money figure, and 90 of them assert the same value.** The
  money surface PARITY covers is narrow and highly repetitive.
- What it *does* prove, and nothing else in the release does: **the 913 cells it compared were
  compared against an artefact published before this work began and unmodifiable by it**, and 905 of
  them are byte-identical.

**A green number without this paragraph is how this release got into trouble. The instrument now
prints the denominator beside the verdict so the two cannot be separated.**
